## ✨ 主な機能

- 📴 **完全オフライン** — ネットワーク通信はゼロ（設定の手動「アップデートを確認」のみ例外）。書籍・表紙・読書進捗はすべて端末内に保存。独自プロトコル `ireader://` が id でファイルを配信し、ローカルパスを露出しません
- 📚 **マルチフォーマット対応** — PDF・EPUB・CBZ / ZIP 漫画アーカイブ・画像ベースの漫画 MOBI を取り込み、ライブラリ・コレクション・続きから再開を共通利用。PDF は pdf.js の canvas 描画、EPUB は epub.js のページ割り（画像主体の漫画は見開き表示、テキスト主体は流し組みページ割り）、CBZ / ZIP と MOBI はメインプロセスが必要に応じて読み出して 1 ページずつ配信し、PDF のページ送り機構を丸ごと再利用。読書設定とショートカットも共通です
- 🌐 **3 言語インターフェース** — 設定 → 一般 → 言語で「システム設定に従う / 中文 / English / 日本語」を選択可能。切り替えは即時反映され、再起動後も保持。日付・時間・複数形・書名の並び順も現在の言語に合わせて変化します
- 📖 **没入型リーディング** — 単ページ / 見開き、右→左（日本漫画）と左→右（韓国漫画）の 2 方向、canvas で描く紙のめくれアニメーション。純黒のビューポートが画面を覆い、上下のバーは端に近づくと現れて自動で隠れます。幅合わせの長いページはホイールで連続スクロールでき、端まで来るとページ送り
- 🔖 **続きから再開** — 書籍ごとにページ・表示モード・方向・ズームを個別に記録し、開き直すと前回の位置に戻ります
- 🗂️ **コレクション管理** — シリーズごとに漫画を整理。1 冊は同時に 1 つのコレクションに所属。コレクション内から直接インポートでき、ホームからあいまい検索 + 全選択で追加できます
- 📊 **読書統計** — 総読書時間・今日の読書・連続日数を一覧でき、直近 7 / 30 日の棒グラフと書籍ランキングを表示。時間は自動で記録され、ランキングは今日 / 累計を切り替え可能
- ⚡ **スムーズな描画** — オフスクリーン canvas 描画 + LRU ビットマップキャッシュでキャッシュヒットはミリ秒単位。スライダーでページをまたいでドラッグしても描画コストゼロ、前後のページ組をバックグラウンドで先読み

## 📥 ダウンロードとインストール

[**Releases**](../../releases) ページからお使いのプラットフォームのインストーラーをダウンロードしてください：

| プラットフォーム | インストーラー | 状態 |
| --- | --- | --- |
| macOS 12+（Apple Silicon で確認済み） | `IReader-<バージョン>-mac.dmg` | ✅ 利用可能 |
| Windows 10+（確認済み） | `IReader-<バージョン>-win.exe` | ✅ 利用可能 |

> **macOS の署名について**：現在のビルドは ad-hoc 署名です（`identity: "-"`、Apple 開発者証明書は不要）。ブラウザからダウンロードして初回起動時に「悪意のあるソフトウェアかどうかを確認できません」と表示された場合は、**システム設定 → プライバシーとセキュリティ** で「このまま開く」を一度クリックしてください。
>
> **Windows の未署名について**：インストーラーは未署名です。初回実行時に SmartScreen でブロックされた場合は、「詳細情報」→「実行」で許可してください。

**アプリ内アップデート**：インストール済みのユーザーは 設定 → このアプリについて で「アップデートを確認」をクリックできます。Windows は差分アップデートに対応（変更部分のみダウンロードし、完了後にワンクリックで再起動してサイレントインストール）。macOS は開発者証明書による署名がないためアプリ内インストールに対応せず、新しいバージョンが見つかるとブラウザで Releases ページを開いてダウンロードします。

<details>
<summary><b>📚 完全な機能一覧</b></summary>

#### ライブラリ（ホーム）

- **インポート**：PDF / EPUB / CBZ / ZIP / MOBI を複数選択、またはフォルダーを選んで再帰スキャン（隠しディレクトリとシンボリックリンクはスキップ）。正規化した絶対パスで重複を排除し、形式は拡張子から自動判定。CBZ / ZIP 内の画像はファイル名の自然順で読書順、MOBI は本文の `<img recindex>` 参照順を読書順とし、解析できない場合はレコード順に戻ります
- **表紙**：インポート後、表紙キューが各書籍の 1 ページ目をディスクに書き出し（480px JPEG）、順次表示。失敗時はプレースホルダー
- **カード**：表紙、書名、読書進捗（パーセント + バー）、最終読書日時
- **並び替え**：最近読んだ順（既定）/ 追加日時 / 書名。設定は保持されます
- **カード操作**：開く、コレクションへ移動、名前変更、削除（ファイルも削除するか選択、確認あり）、見つからないファイルの再リンク

#### コレクション

- ホームでコレクションを作成。カードの高さは書籍カードと同じで、右側にページの束の縁。表紙は書名順の最初の 1 冊
- コレクションをクリックするとコレクションビュー：収録書籍（書名順）、コレクションを解散（収録作品は未分類に戻る、確認あり）
- コレクション内から直接 **漫画 / フォルダーをインポート**（新しい取り込みは自動でそのコレクションに所属）
- **ホームから追加**：複数選択ダイアログで未分類の書籍をコレクションへ移動。書名のあいまい検索（スペース区切りの複数語、大文字小文字を区別しない）と **全選択** に対応
- **続きを読むサイドバー**：コレクションビューの右側に、収録作品の中で最近読んだ 1 冊を表示（大きな表紙とページの厚みを持つ立体ブック風）。前へ / 次へボタンでフォーカスを移動し、表紙をクリックで再開

#### リーダー

- **ページ組**：単ページ `[1][2][3]…`、見開きは既定で表紙を単独ページ `[1][2,3][4,5]…`（設定でオフ可能）
- **方向**：RTL（日本漫画）は組内の 1 ページ目が右、LTR（韓国漫画）は左。クリック領域は方向に合わせて反転（矢印キーは固定の意味、ショートカット参照）
- **ズーム**：幅に合わせる / 高さに合わせる（既定、ページがビューポートを満たす）/ 原寸 100% / カスタム 25%–400%（`Ctrl/Cmd+ホイール` または `=`/`-` で 10% 刻み）。ビューポートを超える場合はドラッグで移動
- **ページめくれアニメーション**：canvas で描く紙のめくれ（450ms、折り目の影と紙端のハイライト）。連続ページ送りでは前のレイヤーをキャンセルし、`prefers-reduced-motion` に従います
- **ホイールで読む**：幅合わせやカスタムズームでページがビューポートより縦に長い場合、ホイールはまず内容をスクロールし、上端 / 下端でさらに約 80px スクロールするとページ送り。進むときはページ先頭、戻るときはページ末尾に揃えます。`Shift+ホイール` は横方向の移動（下で右、上で左）、左右の端に達すると上下スクロールに切り替わり、縦の端でもページ送り可能。横にオーバーフローがない場合は通常のホイールと同じ
- **描画パイプライン**：オフスクリーン canvas → LRU ビットマップキャッシュ（描画シグネチャ付き 12 枚）→ 画面に貼り付け。設定に応じて前後 0–4 組をバックグラウンドで先読み
- **EPUB リーディング**：epub.js のページ割り。画像主体の漫画は見開きで中央に寄せ（表紙は単独中央）、ズーム 50%–200%。テキスト主体は流し組みページ割りと文字サイズ段階。続きから再開ではレイアウト状態（単/見開き、方向、文字サイズ / ズーム）を復元
- **CBZ リーディング**：アーカイブ内の画像をファイル名の自然順でページ送り（1 → 2 → 10、ゼロ詰め対応）。インポート時にページ数を把握し、1 ページ目を自動で表紙に。PDF のページ組 / キャッシュ / アニメーション機構を全て再利用
- **MOBI リーディング**：依存ライブラリなしの自前パーサー（PalmDB レコード表 + MOBI ヘッダー + EXTH + PalmDOC LZ77 解凍）で、本文の画像参照順にページ送り。インポート時にページ数を把握し、1 ページ目を自動で表紙に。CBZ と同じ画像ページ処理を共有します。対象は**画像ベースの漫画 MOBI** のみで、テキスト主体・暗号化された MOBI は開く際に非対応であることを告知します
- **パフォーマンス保護**：スライダーで多数のページをまたいでドラッグしても描画コストゼロ（離すと 2 ページを並列描画）。無効化された描画ループの遅延結果はキャッシュのみに保存し画面には出しません

#### 読書統計

- 入口：設定 → データ → 読書時間の統計
- 概要：総読書時間、今日の読書（昨日との比較付き）、連続読書日数
- 直近 7 / 30 日の日別棒グラフ。1 回だけ取得し、切り替えても再取得しません
- 書籍ランキング：今日 / 累計の 2 つの基準で、時間・割合バー・最終読書日時を表示
- 計測：リーダーページでは 30 秒ごとに確定し、ページが非表示・ウィンドウが非フォーカス・読み込み失敗のときは自動で一時停止。日付をまたぐと正しい日に分割

#### 設定

| 設定項目 | 値 | 既定値 |
| --- | --- | --- |
| 表示言語 | システム設定に従う / 中文 / English / 日本語 | システム設定に従う |
| 既定の表示モード | 単ページ / 見開き | 単ページ |
| 既定の進行方向 | LTR / RTL | RTL |
| テーマ | ライト / ダーク / システム設定に従う | システム設定に従う |
| 先読みページ組数 | 0–4 | 2 |
| 見開きモードで表紙を単独ページに | オン / オフ | オン |

## 🧭 アーキテクチャ

Electron の 2 プロセス構成で、フロントエンドとバックエンドを分離：

```
レンダラー（Vue 3 SPA）
  ライブラリ / リーダー / 設定 / 読書統計 の 4 ルート
  PDF：pdf.js worker → オフスクリーン canvas → LRU キャッシュ → 画面へ
  EPUB：epub.js で解凍 → ページ割り描画（画像主体の書籍は spine ページモデル）
  CBZ / MOBI：画像を 1 ページずつ取得（メインプロセスで必要に応じて解凍 / 本文解凍 + 画像レコード直接読み出し）→ PDF と同じ canvas パイプライン
  i18n：3 言語辞書 + Intl フォーマット。locale の変更で UI 全体を再描画
        ▲ IPC（contextBridge の型安全 API、contextIsolation + sandbox）
メインプロセス（Node.js）
  ライブラリ / コレクション / 進捗 / 設定サービス、表紙の保存、ログ
  ireader:// カスタムプロトコル（id で PDF / EPUB / CBZ / MOBI のページと表紙を配信し、ファイルパスを露出しない）
        ▲
  {userData}/ireader.db（SQLite WAL）+ {userData}/covers/
```

```
├── electron/          # メインプロセス：main / preload / db(repos+マイグレーション) / services / ipc
├── src/               # レンダラー：views / stores / services(pdf·epub·pageCache·pageCurl·spread) / components
├── src/i18n/          # 3 言語辞書、時間/日付フォーマット、エラーコード対応表
├── shared/types.ts    # 共有型（Book / Collection / Settings / Result…）
├── pics/              # 画面キャプチャ
└── build/             # パッケージ用リソース（アイコンなど）
```

セキュリティ基準：レンダラーはサンドボックス有効、`contextIsolation: true`、`nodeIntegration: false`。ローカルファイルは `ireader://pdf/{id}`、`ireader://epub/{id}`、`ireader://cbz/{id}/{page}`、`ireader://mobi/{id}/{page}`、`ireader://cover/{id}` から id でのみ取得できます。

<details>
<summary><b>🗄️ データモデル（SQLite、増分マイグレーション）</b></summary>

- `books`：書名、形式（拡張子から派生）、正規化パス（一意）、ページ数、表紙パス、追加 / 最終読書日時、`collection_id`（NULL = 未分類）
- `collections`：コレクション（id、タイトル、作成日時）
- `reading_progress`：書籍ごとに 1 行（ページ、モード、方向、ズーム、cfi/percentage（EPUB 位置）、変更は 1 秒デバウンスで保存し、終了時に強制書き込み）
- `reading_stats`：読書時間の日次集計（書籍ごと・日ごとに 1 行、ミリ秒で加算。書籍削除で連鎖削除）
- `settings`：key-value（JSON）

マイグレーションは `PRAGMA user_version` のバージョン番号 + 順次スクリプト（現在 v4：コレクション所属、進捗 cfi/percentage、読書時間統計）。追記のみで書き換えません。

## 💻 ローカル開発

```bash
npm install        # 依存関係をインストール（postinstall で better-sqlite3 を electron-rebuild）
npm run dev        # 開発環境を起動
npm test           # Vitest ユニットテスト
npm run typecheck  # vue-tsc 型チェック
```

> 注意：`better-sqlite3` は Electron の ABI 向けにビルドされたネイティブモジュールです。システムの Node で直接実行すると `ERR_DLOPEN_FAILED` になります。スクリプトでデータベースを操作する場合は `ELECTRON_RUN_AS_NODE=1 npx electron <script>` を使用してください。

Issue と Pull Request を歓迎します。

要点：

- macOS は現在 **ad-hoc 署名**（`identity: "-"`、証明書不要。`hardenedRuntime: false` により ad-hoc 下でライブラリ検証が Electron の署名済み framework を拒否するのを回避）：ダウンロード後の初回起動で「悪意のあるソフトウェアかどうかを確認できません」と表示されたら、システム設定 → プライバシーとセキュリティ で「このまま開く」を一度クリック
- `asarUnpack` に `better-sqlite3` を含めています（.node ネイティブバイナリは asar 内から読み込めません）
- Windows NSIS ターゲットは設定済みで実機確認も完了

### GitHub Releases への公開

インストーラーは git リポジトリに含めず（`.gitignore` が `release/` を無視）、**GitHub Actions が自動でビルド・公開**します。`v*` 形式のバージョンタグを push すると起動し、まず型チェックとテストを実行し、その後 macOS / Windows の両方でビルドして成果物を Release に添付し、更新説明を自動生成します。

**標準リリース手順**（git ワークツリーがクリーンであること）：

```bash
# 1. バージョンを上げる（変更の性質に応じて 3 つから選択。package.json の version を更新し、
#    バージョン番号をメッセージとするコミットと v プレフィックスのタグを自動作成。手書き不要）：
npm version patch          # パッチ +1、バグ修正          1.0.1 → 1.0.2
npm version minor          # マイナー +1、新機能          1.0.1 → 1.1.0
npm version major          # メジャー +1、破壊的変更      1.0.1 → 2.0.0

# 2. ブランチとタグを push（タグが自動リリースのトリガー）：
git push origin main --follow-tags

# 3. 進捗確認と検証：
gh run list --workflow Release --limit 1   # 最新ビルドの状態（run-id を控える）
gh run watch <run-id> --exit-status        # 任意：ターミナルで進捗を監視
gh release view v<新バージョン>             # Release と両プラットフォームの成果物を確認
```

ビルドは約 5〜10 分。進捗はリポジトリの **Actions** ページでも確認でき、完了すると Releases ページに Release が表示されます。

**失敗したリリースを再実行する場合**（タグが古いコミットを指しているため Actions ページの re-run は無効。タグを打ち直す）：

```bash
git push origin :refs/tags/vx.y.z   # リモートの古いタグを削除
git tag -f vx.y.z                   # ローカルのタグを修正後の最新コミットに付け直す
git push origin vx.y.z              # タグだけを push してビルドを再トリガー
```

ローカルで手動ビルド（代替）：`npm run build` の後、
`gh release create v<バージョン> "release/<バージョン>/IReader-<バージョン>-mac.dmg" --title "v<バージョン>" --notes "更新内容"`。
