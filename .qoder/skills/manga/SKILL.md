# manga 漫画下载转 PDF

把「收集参数 → 抓取整章图片 → 合成 PDF → 校验 → 汇报」标准化。工具脚本位于本 skill 的 `scripts/` 目录，无需改动项目源码。

## 步骤 1：收集必填参数（缺一不可）

skill 需要两个参数，**任一缺失都必须先询问用户，不得使用默认值或猜测**：

| 参数 | 说明 | 缺省时处理 |
|---|---|---|
| `url` | 漫画**章节阅读页**地址，形如 `http://www.yymanhua.com/m374992/` | 询问要下载的章节地址 |
| `out` | PDF 保存路径（`.pdf` 文件路径，或目标目录） | 询问要存到哪里 |

规则：

1. 用户只给了一个参数时，把已知信息说清楚，再问另一个（例如「PDF 想存到哪个目录？可以是桌面或任意文件夹」）。
2. 用户给的是**作品目录页**（形如 `http://www.yymanhua.com/266yy/`，包含多话列表）而非章节页时，说明本 skill 一次处理一话，并询问要下载哪一话（可先抓目录页列出最近若干话供选择）。
3. 用户说「存到桌面」这类口语位置时，落到具体绝对路径（如 `C:\Users\<用户名>\Desktop`）后再执行。
4. 用户要求一次下载多话或整部作品时，先确认范围与输出方式（每话一个 PDF，或合并成一本），再逐话执行本流程。

## 步骤 2：执行下载与合成

在工作区根目录执行（一条命令完成下载 + 生成 PDF）：

```powershell
python .qoder\skills\manga\scripts\manga2pdf.py --url "<章节URL>" --out "<保存路径>"
```

可选参数：

- `--workdir <目录>`：图片缓存目录，默认 `%TEMP%\manga_<章节号>`；重跑同一命令会复用已下载图片，只补缺失页。
- `--dpi <数值>`：PDF 分辨率，默认 150（约 1080px 宽 → A4 版面比例），只影响打印尺码，不改图片像素。
- `--max-pages <N>`：只处理前 N 页，用于快速试探站点结构或验证流程。
- `--keep-images`：保留下载的图片。**默认不保留**——生成 PDF 后脚本会自动删除下载的图片（含缓存目录），磁盘上只留 PDF。

清理策略：

- 全部页成功 → 删除所有下载图片；缓存目录为空时一并移除。
- 有缺页（退出码 3）→ **自动保留**图片并打印其位置，重跑同一命令即可复用已下载页、只补缺页。
- 需要人工复查图片（确认是正文而非广告页）时加 `--keep-images`，复查完自行删除缓存目录。

退出码语义：`0` 全部成功；`2` 参数错误或站点结构变化；`3` 有缺页但已生成 PDF（重跑同一命令可补齐）。

## 步骤 3：校验产物

1. 读脚本输出：`PDF`、`页数`、`大小`、`已清理下载的图片`（或 `缺页`）行；退出码非 0 时先排查再汇报。
2. 抽检首页图确认抓的是正文：默认会清理图片，需要看图时先用 `--keep-images` 跑一遍（或读上一次保留的缓存）；应为该话第一页正文（通常是彩色扉页）；若看到「加载中」「404」「站点广告页」，说明抓取被拦截或结构变化，需排查而非交付。
3. 校验 PDF 文件有效性（页对象数应等于脚本报告的页数）：

```powershell
python -c "d=open(r'<PDF路径>','rb').read(); print(d[:8], len(d), d.count(b'/Type /Page')-d.count(b'/Type /Pages'))"
```

## 步骤 4：汇报结果

输出：PDF 绝对路径、页数、文件大小、是否完整（有无缺页），并确认「下载的临时图片已自动清理」；仅当有缺页或用了 `--keep-images` 时才说明图片残留位置，提醒可删。若用户还需要放进 IReader 文库，提示可直接用应用内的「添加书籍」导入该 PDF。

## 站点机制与故障排查（改脚本前必读）

- **阅读页本身没有图片**：`div#cp_img` 是空容器，图片由 `chapterimage.ashx` 接口动态取回。
- **接口需要签名**：参数含该页 HTML 里的 `YYMANHUA_VIEWSIGN_DT`(`_dt`) 与 `YYMANHUA_VIEWSIGN`(`_sign`)，**每页签名不同**，必须逐页抓 HTML 后再请求接口，不能复用第 1 页的签名。
- **接口返回混淆 JS**：形如 `eval(function(p,a,c,k,e,d){...})` 的 Dean Edwards packer。用 `scripts/jsunpack.py` 离线静态解包（**绝不执行远端脚本**），解包后取 `pix` 基址 + `pvalue` 文件名列表 + `key` 拼出图片地址。
- **每页返回多张图**：第 1 张是当前页，后续是站点预加载的下一页，全部拼起来会把页数翻倍且顺序错乱——**只取首图**。
- **图片有防盗链**：下载图片时 Referer 必须是该图片所属的阅读页 URL，否则 403。
- **页码 URL 规律**：第 1 页 `/<章节ID>/`，第 N 页 `/<章节ID>-pN/`；总页数取自 `YYMANHUA_IMAGE_COUNT`。

常见失败对照：

| 现象 | 原因 | 处理 |
|---|---|---|
| HTTP 403 | 缺 UA / Referer | 检查 `fetch()` 请求头 |
| 「接口未返回图片地址」 | packer 变体或站点改版 | 保存返回体，检查 `resolve_image_urls` 的正则与解包结果 |
| 「页面结构变化：缺少变量」 | 页面变量改名/改版 | 重新抓 HTML 定位变量名并更新 `parse_var` 调用 |
| 页数与实际不符 | 站点分页方式变化 | 对照阅读页底部「頁碼 N/总页数」核对 |
| 保存到桌面等目录报 PermissionError | 工作区外写入受沙箱限制 | 申请完整权限重跑，或先输出到工作区再让用户移动 |

## 红线

1. 下载内容仅供用户个人离线阅读，不批量抓取全站、不转售分发。
2. 产物（PDF / 图片）不放进 `src/`、`electron/`、`shared/` 等源码目录，也不提交进 git。
3. 交付时磁盘上只保留用户要的 PDF；下载的临时图片必须已清理（缺页需重跑、或用户明确要求 `--keep-images` 时除外，并如实说明位置）。
4. 不修改站点请求的鉴权逻辑去绕过付费或登录限制；遇到 VIP 锁页如实告知用户无法获取。
5. 依赖 `Python 3` + `Pillow`；缺失时先征询用户再安装。
