## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 侧栏书籍视觉参考 demo（硬皮书 + 可翻开封面） | 新建 `ContinueReadingBook.vue`：结构与角度照搬 `demos/CodePen Home CSS Animated books`（硬壳封面 + 5 张纸页 + 硬壳封底 + 书脊，12 片 4px `#999` 断面），按 `k = 0.8625` 换算到 138×190、`perspective: 860px`；**合上态保持 `scale 1` 的 34° 斜视**（规则见 §4.2 / §5.2） | 合上态是斜放的硬皮书：能看到封面被压窄的透视、四周灰黑断面与右侧层叠纸页边；翻开不越出侧栏 |

**核心验收口径**：合上态必须呈现硬皮书的 34° 斜视立体感与封面四周灰黑断面；hover 侧栏书后封面扇到 -188°、整本后退缩小一档并露出左右两面内页；PDF / CBZ / MOBI / EPUB 的缩略图页码恒等于 `book.progress.page`（右页为 `page + 1`）；翻开全程 `.collection-side` 不出现横向滚动条、不越出侧栏遮挡左侧书网格。

## 二、非目标（本期不做）

- **不做 demo 的完全翻开（-145°）+ 内页逐张飞出**：横向量级为 `0.82 × 书宽`，260px 侧栏必然裁切或遮挡左侧网格（几何推导见 §4.2），与用户确认采用「半开 + 书右移」。
- **不做文字型 EPUB 的排版截图**：EPUB 取图口径是「该 spine 页 XHTML 里的那张图」，纯文字页（无 `<img>` / `<image>`）取不到图，按无图回落封面。要还原文字排版必须跑 epubjs rendition 再截图，代价与收益不匹配。
- **不做缩略图落盘缓存**：需新增协议域 + 提交 IPC + 缓存清理，工程量约为现状 2~3 倍；本期用渲染层内存缓存（§5.3）满足切书体验。
- 不改侧栏宽度（260px）、内边距（`20px 24px`）、窄屏隐藏规则（`≤860px`）、标题与上下本按钮文案。
- 不改 `BookCard` / `CollectionCard` 视觉与 `cardTilt` 倾斜服务；不把「翻开」做成指针跟随倾斜（两者叠加会失控）。
- 不改 `shared/types.ts` 与 DB schema：`PageThumbSource` 是渲染层内部类型，不是 IPC 契约。主进程仅新增 `epubService.ts` 一处只读取图服务，`ireader://` 只新增 `epubpage` 子协议（§4.1）。
- 不新增 i18n 文案（复用 `library.openBook`、`library.book.progress`、`common.noCover`）。
- 不做书脊立体面片与封底 3D 面片：demo 用 4px 板厚网格 + 90° 旋转面拼出厚度，参数与书宽强耦合；本期用「三级 `box-shadow` 描边 + 一条左侧书脊条」复刻同一观感（§11.8）。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ──────────────────────────────────────────────┐
│ LibraryView.vue（合集视图）                                          │
│   ├─ sideBook / sideIndex（既有：名称升序书单 + 最近阅读为默认焦点）    │
│   └─ sidePhase 状态机（idle | closing | entering）← §4.3             │
│        ▼                                                             │
│ ContinueReadingBook.vue                                            │
│   props: { book: Book; phase: SideBookPhase }                        │
│   emits: { open: [bookId: number] }                                  │
│   ├─ 3D 结构：照搬 demo ─ hardcover_front（封面正面 + 内侧=左页）          │
│   │           · page × 5（第 2 张=右页）· hardcover_back · book_spine     │
│   ├─ bookProgress.ts     → progressPercentOf / thumbPageOf（纯函数）   │
│   └─ pageThumbnail.ts    → resolvePageThumb（纯函数）                  │
│          ├─ cbz | mobi → <img src="ireader://{fmt}/{id}/{page}">      │
│          ├─ epub       → <img src="ireader://epubpage/{id}/{page}">  │
│          ├─ pdf        → loadPdfWithTask → renderPageToCanvas         │
│          │                （离屏 canvas → toDataURL，模块级 LRU 缓存）  │
│          └─ 取图失败 → coverUrl 回落                               │
└──────────────────────────────────────────────────────────────────────┘
        ▼ ireader:// 协议（新增 epubpage 子协议）
   /pdf/{id} · /cbz/{id}/{page} · /mobi/{id}/{page} · /epubpage/{id}/{page} · /cover/{id}
```

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 翻开幅度 | 封面 `rotateY(-34deg) → -188deg`，整本 `translateX(49px) scale(0.74)` | 净角 8° 才能让左面正对观众放内容；缩小即「后退一档」，既解决胯页超宽，又保住合上的大尺寸（§4.2） |
| 内页角度 | 封面 `-188°` 与右页 `-8°` 成一对同角 | 两面斜角一致时宽差只有 4.3px、高差 0.05px；早期 -200°/-20° 组合的宽差达 18.5px，视角割裂 |
| 页缘厚度 | 照搬 demo：每块板两面各让 1.75px，12 片 `#999` 断面 `li::before/::after` | 板厚与书宽同系数缩放（3.5px），改尺寸只需改一处 `k`；断面不产生额外 z 位移，不与 3D 排序打架 |
| 投影 | 拼在厚度面上的 `box-shadow`（`--book-lift`），禁用 `filter: drop-shadow` | `filter` 会让元素成为 flatten containing block，破坏子元素的 `preserve-3d`（封面将无法 3D 翻开） |
| 缩略图来源 | CBZ / MOBI / EPUB 走主进程逐页取图，PDF 渲染层离屏渲染，不落盘 | 前三种格式的页就是包内现成图片，直接给 `<img>` 零成本；PDF 无现成图只能渲染；不为主进程新加缩略图缓存与清理任务 |
| hover 命中区 | 绑在不移动的 `.book-stage` 上，只有内部 `.book` 做位移缩放 | 若命中区随书右移，指针会瞬间离开元素造成翻开/合上抖动 |
| 换书过渡 | 父级 `sidePhase` 状态机 + 组件受控展示 | 切换目标书由父级掌握，组件保持无副作用；动画时序不外泄到服务层 |
| EPUB 取图 | 主进程按 spine 解压单页图，`ireader://epubpage/{id}/{page}` | 漫画 EPUB 单本可达 170MB，渲染层整本加载（fetch + JSZip）会吃几百 MB 内存且侧栏是 `immediate` 预取；按需解压单页实浏 30ms 左右，与 cbz/mobi 同构（§11.5） |
| 降级出口 | 减弱动效 / `hover: none` 不翻开，封面叠进度胶囊 | 这两类环境下内页永远不可见，必须有等效信息出口 |

## 四、核心算法 / 口径

### 4.1 缩略图解析口径（`pageThumbnail.ts`）

```ts
/** 单页取图描述：渲染层内部类型，不进 shared/types.ts */
export type PageThumb =
  | { kind: 'image'; url: string }                                  // CBZ / MOBI / EPUB 逐页图片协议
  | { kind: 'pdf'; bookId: number; page: number }                   // pdf.js 离屏渲染
  | { kind: 'cover'; url: string | null }                           // 取不到图兜底

/**
 * 翻开后两面：current 先读到的页（页码小）、next 后读到的页；
 * order 决定两者落哪侧：ltr 左先读（current 在左）、rtl 右先读（current 在右）
 */
export interface PageThumbSource {
  current: PageThumb
  next: PageThumb | null   // 末页为 null，该面留白
  order: 'ltr' | 'rtl'
}

/**
 * 页序方向：已读过的书跟 progress.direction，未读过的书用全局 defaultDirection；
 * 纵向条漫（ttb）没有跨页概念，取 progress.rowOrder，缺省左→右。
 */
export function pageOrderOf(book: Book, defaultDirection: Direction): 'ltr' | 'rtl' {
  const direction = book.progress?.direction ?? defaultDirection
  if (direction === 'ttb') return book.progress?.rowOrder ?? 'ltr'
  return direction
}

/**
 * 决定翻开后两面各显示哪张图。
 * 页码口径与阅读器一致：progress.page 是 1 基页面号（双页模式为页组首页）。
 */
export function resolvePageThumb(book: Book, defaultDirection: Direction = 'rtl'): PageThumbSource {
  const page = thumbPageOf(book)
  const current = thumbOf(book, page) ?? { kind: 'cover', url: book.coverUrl }
  const inRange = book.totalPages <= 0 || page + 1 <= book.totalPages
  const next = inRange ? thumbOf(book, page + 1) : null
  return { current, next, order: pageOrderOf(book, defaultDirection) }
}
```

`thumbOf` 分支（返回 null 则由调用方回落封面）：

| 格式 | 返回 | 取图路径 |
|------|------|----------|
| CBZ / MOBI | `{ kind:'image', url:'ireader://{fmt}/{id}/{page}' }` | 既有逐页协议，包内第 page 张图 |
| PDF | `{ kind:'pdf', bookId, page }` | pdf.js 离屏渲染 |
| EPUB | `{ kind:'image', url:'ireader://epubpage/{id}/{page}' }` | 主进程按 spine 索引取该页 XHTML 的图（见下） |
| 其余 / 取图失败 | `null` | 回落封面 |

无进度的书不特殊处理：`thumbPageOf` 已把「无 progress / 非法页码」归一到第 1 页，所以四种格式在无进度时都是**第 1 页 + 第 2 页**（`inRange` 在 `totalPages = 0` 时先放行，取不到图再由 `<img @error>` 兜底）。

**左右排布跟着漫画阅读方向走**（这是内容落位的唯一依据，与取图无关）：

| 页序方向 | 左面 | 右面 | 适用 |
|----------|------|------|------|
| `rtl`（默认） | `next`（page + 1） | `current`（page） | 日漫：右先读，往左翻 |
| `ltr` | `current`（page） | `next`（page + 1） | 韩漫：左先读，往左翻 |

- 方向来源优先级：`book.progress.direction`（阅读器里改方向会写进进度）→ 全局 `settings.defaultDirection`（未读过的书）→ `rowOrder`（ttb 条漫，缺省 ltr）。
- 封面恒从右侧向左翻 180°，**两种方向的动画完全一致**，只换两面内容：rtl 时翻过去的那页（左侧）是下一页，符合日漫「读完右页再读左页」的预取惯性。
- 取图失败时只有**先读面**回落封面，后读面直接留白——否则 rtl 下会把封面画到“下一页”那一侧，看着像又没生效。

EPUB 取图口径（`electron/services/epubService.ts`，与 cbzService 同构）：

1. 页码定义：`progress.page = spine 索引 + 1`，与阅读器 `stores/epubReader` 写进度的口径严格一致（实书校验：310 页书的 `page 91 / 310 = 29.4% ≈ DB 的 29%`）。
2. `container.xml` → OPF → `<itemref>` 顺序得 spine 表，非 XHTML 项（音频 / 字体）**留空串占位**，否则后续页码会与阅读器索引错位；spine 表按 `mtime + size` 缓存（上限 8 本）。
3. 取该页 XHTML 的 `<img src>`，退化到 SVG `<image href / xlink:href>`；相对路径做 `../` 与 URL 解码后按条目名取。
4. 按需解压单张图返回（不整本加载）：170MB 实书实测单页 28~37ms。
5. 无图页 / 条目缺失 / 越界 → 404，渲染层 `@error` 回落封面。

页码归一（`bookProgress.ts`，纯函数）：

```ts
/** 内页缩略图页码：有进度取 progress.page，否则 1；越界钳制到 [1, totalPages] */
export function thumbPageOf(book: Book): number {
  const raw = book.progress?.page ?? 1
  const total = book.totalPages > 0 ? book.totalPages : Number.MAX_SAFE_INTEGER
  return Math.min(total, Math.max(1, Math.floor(raw) || 1))
}

/** 阅读进度百分比：EPUB 取 percentage，PDF/CBZ/MOBI 按页折算；无进度返回 null */
export function progressPercentOf(book: Book): number | null {
  const { progress, totalPages } = book
  if (!progress) return null
  if (progress.percentage != null) return Math.min(100, Math.round(progress.percentage))
  if (!totalPages) return null
  return Math.min(100, Math.round((progress.page / totalPages) * 100))
}
```

> `progressPercentOf` 是 `BookCard.vue` 现有 `progressPercent` computed 的原样抽取（当前实现 L183-190），抽取后 `BookCard` 改为调用它，行为零变化，避免两处口径漂移。

PDF 离屏渲染（含 DOM，不进单测）：

```ts
/** 渲染指定页为 JPEG dataURL；页数越界 / 文档损坏时 reject，由调用方回落封面 */
export async function renderPdfPageThumb(url: string, page: number, targetWidth = 300): Promise<string>
```

实现要点：

1. `loadPdfWithTask(url)` 拿 `doc` 与 `task`，`finally` 中 `await task.destroy()`（不销毁会残留 pdf.js worker 内存）。
2. `renderPageToCanvas(doc, page, { canvas, targetWidth })` 复用现有渲染入口（含 dpr 处理与取消语义）。
3. `canvas.toDataURL('image/jpeg', 0.82)` 返回；`targetWidth = 300` 足够 148px 宽内页在 2x 屏清晰，同时把 JPEG 体积压在几十 KB。

### 4.2 翻开几何预算（决定「不溢出」的硬约束）

翻开态就是一次翻页：封面绕书脊扇到左边变成左页（内侧即当前阅读页），右页是下一页。结构与角度全部照搬 `demos/CodePen Home CSS Animated books`（书 160×220、`perspective: 1000px`），按 `k = 138/160 = 0.8625` 换算到 138×190。

合上时保持原尺寸斜视，翻开时整本「后退」一档 —— 这是解决胯页超宽的主手段，而不是把书本身改小：

| 量 | 取值 | 说明 |
|----|------|------|
| 书框 | 138 × 190 | demo 的 0.8625 倍；所有 `translateZ` / 偏移量同系数换算 |
| 透视 | `perspective: 860px`（挂在 `.book` 上） | demo 1000 × 0.8625；合上与翻开共用同一台相机，缩小即后退 |
| 合上角度 | 封面 `-34°` / 封底 `-15°` / 纸页 `-28°…-36°` / 书脊 `60°` | demo 原参数：封面右缘与下缘露出层叠纸页边 |
| 合上尺寸 | `scale 1` | 封面视觉投影约 119 × 211px，横向跨 [109, 229]（含厚度面） |
| 翻开尺寸 | `translateX(49px) scale(0.74)` | 摊平后视觉中心比书体中心偏左 66px，右移 `66 × 0.74 ≈ 49` 居中；缩完胯页 200.5px 宽、左右各留 30px |
| 翻开角度 | 封面 `-188°` / 封底 `-8°` / 纸页前 2 张 `-8°`、后 3 张 `-188.5°…-189.5°` | 净角 8°：左面正对观众可放内容，两面斜角一致（宽差 4.3px、高差 0.05px） |
| 左右页实测 | 左 98.0 / 右 102.3（高 140.9） | 透视近大远小，左页窄 4.3px，1x 下不可辨 |
| 硬壳厚度 | 板厚 3.5px（两面各让 1.75px）+ 12 片 `#999` 断面 | 合上时就是封面四周那圈灰黑轮廓，翻开时是纸页 / 板边的厚度 |
| 接地投影 | 合上 `7px 2px 34px 10px var(--book-shadow)`，翻开 `6px 3px 30px 12px rgba(0,0,0,.2)` | demo 的 `80px 20px #666` 收窄到 1/3，否则在 260px 白卡上铺成一道脏带 |

> 侧栏 `.collection-side` 未设 `box-sizing: border-box`，`width: 260px` 即内容区宽度（padding 24 在外侧），所以胯页 200.5px 还有 59.5px 余量。`scale 0.74` 的目的不是「勉强塞进去」，而是让翻开像把书推远一档，与合上的大尺寸形成对比。

### 4.3 换书过渡状态机（父级 `LibraryView.vue`）

```
                 click prev/next（!switching）
   idle ─────────────────────────────► closing ──(240ms)──► 换 sideCursor ──► entering ──(320ms)──► idle
     ▲                                                                              │
     └──────────────── 组件入场动画结束（phase 由父级定时器推进）───────────────────────┘
```

```ts
const sidePhase = ref<SideBookPhase>('idle')
const sideSwitching = ref(false)

async function shiftSideBook(delta: 1 | -1) {
  if (sideSwitching.value) return                       // 连点合并，避免堆叠动画
  const next = sideIndex.value + delta
  if (next < 0 || next >= collectionBooks.value.length) return
  if (reducedMotion) { sideCursor.value = next; return } // 减弱动效：瞬时切换
  sideSwitching.value = true
  sidePhase.value = 'closing'
  await wait(240)                                        // 旧书合上 + 下沉淡出
  sideCursor.value = next
  sidePhase.value = 'entering'
  await wait(320)                                        // 新书上浮入场
  sidePhase.value = 'idle'
  sideSwitching.value = false
}
```

- `wait()` 用可取消的 `setTimeout` 封装，`onUnmounted` 时清空全部计时器，避免卸载后写 ref。
- 上下本按钮在 `sideSwitching` 期间 `disabled`（视觉沿用现有 `:disabled { opacity: .4 }`）。
- `reducedMotion` 一次性判定（与 `CardTilt` / `StatCard` / `ReaderView` 一致，不监听媒体变化）。

### 4.4 边界场景防护清单

| 场景 | 行为 |
|------|------|
| 书无阅读进度 | 内页显示封面图；不渲染进度条与百分比 |
| EPUB 书 | 内页显示封面图 + 进度条（百分比取 `percentage`） |
| 缺失文件书（`missing`） | 内页照常显示图；点击走既有 `openBook` 缺失拦截 → `MissingFileDialog` |
| 无封面（`coverUrl === null`） | 纸色占位层 + `common.noCover` 文案，不开 `img` 请求 |
| CBZ / MOBI 页码越界 | 协议返回 404 → `img @error` → 回落封面图 |
| PDF 渲染失败（加密/损坏） | `renderPdfPageThumb` reject → 回落封面，不弹错误、不打断侧栏 |
| 快速连点上／下一本 | `sideSwitching` 合并；缩略图渲染用自增 token，旧结果丢弃 |
| 切换后旧书渲染迟到 | token 不匹配直接 return，不写 `sideThumb` |
| 书被移出合集 / 删除（`sideBook` 变 null） | 显示 `library.collection.noBooks`；卸载组件并 `task.destroy()` |
| 侧栏不可见（`≤860px`） | 组件卸载（`display: none` 父级），不发起 PDF 解析 |
| 窗口失焦 | hover 消失，CSS 自然合上；PDF 任务保留在缓存，不重算 |
| 减弱动效 / 触屏 | 不翻开，封面叠进度胶囊（§8.4） |
| 打开书返回合集 | `sideCursor` 回到 `null`（既有 `openCollection` 行为），焦点回到最近阅读书 |

### 11.3 缺陷修复：合上态封面被白板盖住

反馈截图里合上态是一块米白白板、左侧只露出十几像素的封面 —— 根因不是 CSS 写错，而是 **`transform-style: preserve-3d` 里的 z-index 会被 3D 深度排序覆盖**：

| 元素 | 变换 | 右边缘实际 z | 结果 |
|------|------|--------------|------|
| `.hd-front`（平放封面） | `rotateY(0) translateZ(8px)` | +8（整面共面） | 应当在前，实际被盖 |
| `.hd-back`（demo 的封底） | `rotateY(-15deg) translateZ(-8px)` | +39 | 盖住封面 |
| `.page-1..5`（demo 的合上角） | `rotateY(-28~-36deg)` | +71~+89 | 盖住封面 |

原因：负角度绕左边缘旋转会把**右半边甩向观众**（`z = 宽度 × sin θ`），所以“看起来在后面的封底 / 纸页”在 3D 空间里其实跑到封面前面，`z-index: 100` 完全不起作用。demo 之所以正常，是因为它的封面本身也掀到 -34°（右侧 z≈+93），始终比纸页更靠前。

只要把封面改成平放（0°），就必须同步把封底、纸页也归成 0°，否则它们必然反压：

1. `.hd-back` → `rotateY(0) translateZ(-8px)`（真正在封面之后）；
2. `.page-1..5` 合上态全部 `rotateY(0)`；翻开只小幅张开（-16/-22/-14/-12/-10°），靠角度差在右侧漏出书口纸边；
3. 纸页不再扇到左侧 —— 否则 -106~-126° 的纸页比 -130° 的封面更靠前，左页内容又会被盖；
4. `.spine-inner` 加 `backface-visibility: hidden` + `rotateY(180deg)`，否则 `#333` 内面会在封面左缘露出 8px 黑条。

附带两处修正：

- `perspective` 由 demo 的 1000px 提到 1400px：左侧远边 z≈112，1000px 下放大 13% 会顶出侧栏；书宽相应由 152 收到 146。
- 封面内侧**不能**再加 `scaleX(-1)`：`-130° + 180°` 的净角度是 +50°，本来就是普通斜看、不镜像；加了反而变成反字。

## 11.4 返工：改为真正的 180° 翻页跨页

§11.2 / §11.3 的「封面掀到 -130° + 五张纸页小幅张开」虽然不再白板，但用户实测又提两条：

1. **没有翻页动画** —— 封面只转 130°，纸页只张 10~22°，看起来像“卡片平移”，不像翻书；
2. **左页空白、右页是封面** —— 纸页扇开后左面没有内容（前一页在 page 1 时为空），且读者看到的第一页本身就是封面图。

改法：放弃 demo 的「硬壳 + 五张纸页扇形」，换成最直白的一次 180° 翻页。

| 层 | 合上 | 翻开 | 说明 |
|----|------|------|------|
| `.book-book`（宽 126） | `translateX(0)` | `translateX(63px)` | 书体只平移，不再扇页 |
| `.cover`（转轴 left center） | `translateZ(2px) rotateY(0)` | `rotateY(-180deg)` | 真翻页；-180° 后整面落到左半 |
| `.cover-face` / `.cover-inner` | 正面可见 / 背面隐藏 | 正面隐藏 / 背面可见 | 两面卡片，`backface-visibility: hidden` |
| `.page-right`（当前页的下一页） | 被封面完全盖住 | 露出 | z=0，永远比封面 z=+2 靠后 |
| `.spine-fold` | `opacity: 0` | `opacity: 1` | 书脊折痕（宽 `W*0.1`，以交界线为中心） |

页码口径同时改成 **左页 = 当前页、右页 = 下一页**（`PageThumbSource` 的 `previous` 改名 `next`）：

- 用户举例的「第一页图片、第二页图片」就是这个顺序；
- 第 1 页时左页不再是空白（之前用前一页，第 1 页必然空）；
- 也顺带解掉了「右边是封面」的困惑 —— 第 1 页本身往往就是封面图，右页换成第 2 页后看到的就是正文。
- 末页 / 无进度书仍无下一页，右面留白纸（不显示“无封面”文案）。

为什么这个结构不会再犯 §11.3 的错：

- 0° 和 -180° 两个极限角度下封面都**完全落在 z=0 平面**（绕 y 轴旋转不产生 z 位移），`translateZ(2px)` 已提前施加，所以合上时封面恒定比右页靠前 2px，不再靠 `z-index`；
- 翻开后封面与右页的 x 区间不重叠（[-126,0] 与 [0,126]），不存在深度竞争；
- 左右两页等大（实测差 0.16px）、都正对观众，没有透视压缩。

代价：胯页 2W 必须塞进 260px 侧栏，书宽从 146 降到 126（合上时小一点），换翻开后左右各 126 铺满。

实测（`.probe/book-preview.html` 同步复刻）：合上 `[67,193]` 干净蓝封面无黑条；翻开左页 `[3.8,130]`（`#e8c9a0` 占位）、右页 `[130,256]`（`#f2efe6`），中缝 gap 0、文字不镜像、无溢出。

## 11.5 返工：EPUB 补上逐页取图

§11.4 上线后用户仍提「展开后还是封面」，追问一句「你是不是忘记 epub 格式文件了」才定位到根因：

**§4.1 旧实现只认 CBZ / MOBI / PDF，EPUB 一律返回 `null` → 两面都回落 `coverUrl`。** 用户书架里正在读的书恰好是漫画 EPUB，所以看到的就是封面。

### 两版方案为何反转

| 方案 | 做法 | 结论 |
|------|------|------|
| A 渲染层取图 | 用 epubjs `loadEpubBook` + `section.load` + `archive.createUrl`，在渲染层拿页内图片 URL | **否决**：实书校验发现单本 **170MB**（zip 内 310 页全彩图），渲染层整本 `fetch` + 解压索引 会吃几百 MB 内存；侧栏 watch 是 `immediate: true`，一进首页就加载，不可接受 |
| B 主进程按需解压 | 新增 `electron/services/epubService.ts`，用 yauzl 按需解压**单页图**，通过 `ireader://epubpage/{id}/{page}` 供给 | **采用**：与 cbzService 完全同构，渲染层只是普通 `<img>`，零内存代价 |

方案 A 的实现（`src/services/epubPageThumb.ts`）已整体删除，不留死代码。

### 实现要点

1. **纯函数下沉**：`normalizeZipPath` / `extractPageImageRef` / `parseSpineDocumentPaths` / `decodeXmlText` 不依赖 zip 与 DOM，全部可单测；zip 只负责「按名字取条目」。
2. **spine 对齐**：`documents` 数组下标严格等于 spine 索引（`progress.page - 1`）；非 XHTML 项按 `media-type` 判定后留空串占位 —— 否则音频/字体会把后面的页码整体前移。
3. **协议分流**：`protocol.ts` 的 `cbz | mobi | epubpage` 共用 `servePagedImage`，新增 `expectedFormat` 参数做格式闸门（`epubpage` → 校验 `detectFormat === 'epub'`），避免拿错格式的 bookId 去解压。
4. **缓存策略**：只缓存 spine 表（`mtime + size` 判新鲜度，上限 8 本），不缓存图片字节 —— 图片交给浏览器 HTTP 缓存与 `<img>` 即可。
5. **失败语义**：无图页 / 条目缺失 / 越界一律 `null` → 404，组件 `@error` 回落封面，不抛异常、不弹错。

| 指标 | 结果 |
|------|------|
| `countPages` | 310（首次 40ms） |
| `readPage(91)` | 668KB `image/jpeg`，31ms |
| `readPage(92)` | 719KB `image/jpeg`，37ms |
| 页码口径 | DB `page=91` + `percentage=29` → `91/310 = 29.35%` 对得上 |
| 图像内容 | 导出落地为 jpg 后目视确认为漫画内页（非封面） |

### 校验结果

`vue-tsc --noEmit` 无错；`vitest run` 32 文件 / 473 用例全绿（新增 `epubService.test.ts` 15 例，`pageThumbnail.test.ts` EPUB 断言同步改为 `ireader://epubpage/...`）。

中途修掉的两个实现缺陷：

| 现象 | 原因 | 处理 |
|------|------|------|
| `readPage` 返回类型报 `Buffer<ArrayBufferLike>` 不可赋予 `Buffer<ArrayBuffer>` | 显式标注了过窄的泛型参数 | 返回类型回到 `Buffer`，与 cbz/mobi 一致（protocol 处统一 `new Uint8Array` 拷贝） |

## 11.6 调整：无进度书也渲染第 1 / 2 页

用户补充要求：「如果当前无进度，则分别渲染第一页和第二页」。

旧实现里 `thumbOf` 有一行 `if (!book.progress) return null`，导致 PDF / EPUB 的新书（未读过）两面都回落封面，与「展开要看到页面内容」的初衷相背。

改法（`src/services/pageThumbnail.ts`）：删掉这道进度闸门，统一由`thumbPageOf` 把「无 progress / 非法页码」归一到第 1 页——于是四种格式在无进度时都是 **第 1 页 + 第 2 页**（CBZ / MOBI 本就是这个行为，本次只是把 PDF / EPUB 也拉齐）。

连带口径：

- `PageThumb` 的 `cover` 分支现在只承担「取图失败 / 未知格式」兜底，不再表示「无进度书」；
- 右页边界只看 `totalPages`：`totalPages = 0`（未知）时先取 `page + 1`，取不到图由 `<img @error>` 置留白；
- 代价：未读过的 PDF 首次进合集会在后台渲染两页缩略图（各几百 ms），仍受 `§5.3` 的 8 条 FIFO 缓存约束；
- 单测同步：`pageThumbnail.test.ts` 的 PDF 无进度 / EPUB 无进度 / 封面缺失三例全部改为正向断言（该文件 8 例全绿）。

## 11.7 调整：左右两面按漫画阅读方向落位

用户补充要求：「左右页内容要根据漫画阅读左右方向确定」。

旧实现把「左面 = 当前页」写死在组件里（§11.4 为了解「左面空白」而定的口径），但那只是 **ltr（左先读）** 的排列。日漫默认 `rtl`：一屏里先读的页在**右**边，翻过去的那页（左）才是下一页。用户的书都是 `rtl`（DB 里 `reading_progress.direction` 实测均为 `rtl`），所以看到的页序是反的。

改法：把页序方向下沉为纯函数 `pageOrderOf(book, defaultDirection)`，`PageThumbSource` 新增 `order` 字段；组件只做一行映射：

| `order` | 左面 | 右面 |
|---------|------|------|
| `ltr` | `current` | `next` |
| `rtl` | `next` | `current` |

方向来源优先级：`progress.direction`（阅读器里改方向会写进进度）→ 全局 `settings.defaultDirection`（未读过的书）→ `progress.rowOrder`（ttb 条漫，缺省 ltr）。组件从 `useSettingsStore()` 读 `defaultDirection`，不新增 props。

**为何动画不用镜像**：真实漫画翻页无论 ltr 还是 rtl，都是「把右侧那页往左翻过去」，所以封面恒绕左侧书脊翻 180°；与方向无关的只有**两面内容怎么排**。若同时镜像结构，就得再维护一套转轴/阴影/书脊几何，收益与风险不成比例。

**失败兜底随之改为方向无关**：原来是「左面失败→封面、右面失败→留白」，方向一旦能互换，这个不对称就会在 rtl 下把封面画到“下一页”那侧（又变成「展开还是封面」）。现在抽成 `urlOf(...)` + `markFailed(...)`：只有**先读面**回落封面，后读面直接留白。

校验：`vue-tsc --noEmit` 无错；`vitest run` 32 文件 / 476 用例全绿（`pageThumbnail.test.ts` 重写为 11 例，其中 `pageOrderOf` 三例覆盖方向优先级）。

## 11.8 调整：回到 demo 的斜视姿态与封面灰黑轮廓

用户反馈：「书籍风格还是参考 demo，倾斜一点，要有封面周围的灰黑色轮廓」。

背景：§11.3 为了解「封底/纸页反压封面」，把封面、封底、纸页全部改成了 0° 平放；§11.4 又把结构换成 180° 翻页，合上态就成了**完全正对观众的平面卡片**，没有 demo 那种斜着摆的立体感；同时原有 1px `--border` 描边在深色封面上几乎看不见，封面像直接“浮”在侧栏里。

### 改法

| 项 | 改前 | 改后 |
|----|------|------|
| 姿态角 | 合上 0° / 翻开 0° | `.book-book` 加 `rotateY(-28deg)`，翻开收窄到 `-10deg`（demo 封面是 -34°） |
| 透视 | 1600px | 900px（demo 1000px），让斜视有近大远小 |
| 封面切边 | `1px solid var(--border)` 级别的隐形描边 | 三级 `box-shadow` 环：`--book-rim-inner` → `--book-rim-paper` → `--book-rim-edge` |
| 书脊 | 只有翻开时才出现的 `spine-fold` 渐变 | 新增 `.book-spine`（左缘外 4px、宽 8px、深灰三段渐变），合上时常显、翻开淡到 28% |
| 封面形制 | 四周圆角 `3px 5px 5px 3px` | 左缘直角、右缘 4px（书脊侧应为直边），并加 `::after` 的 -135° 白纱高光 |
| 翻开态切边 | 与合上同厚 | 收薄一档（2/3/4.5px → 1/2/2.5px）：否则两页各一道 4.5px 环，中缝叠成 8px 黑缝 |

### 没用 demo 的板厚面片

demo 的厚度是 12 个 `4px` 宽 `:before/:after` 面片用 `rotateY(90deg) translateZ(158px)` 这类**硬编码书宽的常量**拼出来的（书宽 160），换成 126 要逐条重算；而且这些面片是真实的 3D 子元素，与 §11.3 的深度排序问题属于同一类风险。`box-shadow` 环不产生 z 位移、不参与排序，同样的观感代价低得多。

### 为什么翻开态留 -10° 而不是归 0°

- 归 0° 会把书“摆正成一张图”，与用户要的「倾斜一点」相背；
- 代价是左右页不等宽（透视近大远小，实测差约 13px），这恰好是真实翻开书的样子；
- 想要严格对称只需改一个变量：`--book-tilt-open: 0deg`。

### 几何复核（倾斜后仍然不溢出）

| 场景 | 结果 |
|------|------|
| 合上 | 投影 `126 × cos28° ≈ 111px` ＋切边 4.5px，居中于 212 内容区，四边留白充足 |
| 翻开 | 胯页 2W = 252px，-10° 后投影 `252 × cos10° ≈ 248px`，比 252 更窄 |
| 翻转过程中 | 转轴（书体左边）在容器 x = 130，封面斜边 126 < 130；任意角度下 `130 - d·cosθ·s ≥ 4px`，不会超出锁栏 |

切边颜色走 `style.css` 的主题变量：浅色 `rgba(0,0,0,.18) / #b6b2a9 / #46443f`；深色 `rgba(0,0,0,.55) / #6a675f / #16150f`（黑底上必须提亮纸叠层，否则硬壳轮廓直接消失）。书脊条固定深灰，不进主题——它永远靠着亮色封面。
