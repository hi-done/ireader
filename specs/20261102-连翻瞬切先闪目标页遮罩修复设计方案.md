## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|---|---|---|
| 1 | 快速翻页（如 1→2→3，第二下落在上一场动画播放中）时，不得先瞬间露出第三页 | 连翻 `burst` 首帧改为「**先取起点快照并上屏遮罩 → 再导航 / 渲染**」；连翻期间目标页始终在遮罩之下 | 按原复现节奏（约 300~600ms/下）连翻 3 页：在卷曲开始前，第二、三页画面始终不可见（肉眼 + 逐帧录屏） |
| 2 | 保留「停手后仍有唯一一次翻页动画」的既有特性 | 补播会话本身不变（仍记录起点页 / CFI 与起点快照、仍 `BURST_SETTLE_MS=220`），只把「补播动画起点 = 屏幕画面」作为硬约束 | 停手约 220ms 后仍出现唯一一次卷曲，起点为连翻首帧画面，终点为最终页 |
| 3 | 补播不得改变落点与进度 | 沿用既有「补播只做视觉回放、不导航」语义，本次不新增任何导航调用 | 补播前后页码、滑块位置、CFI 完全一致；退出重进仍在最终页 |
| 4 | 任何清理路径都不得残留遮罩 | 遮罩生命周期 = 连翻会话生命周期；所有 `clearBurstSession()` 调用点统一揭除遮罩，`discardTurn()` 只揭除「单次翻页」自己的遮罩 | 首尾页连点、净位移为 0、滑块接管、Home / End、换书、改窗口尺寸、退出阅读页后，阅读区均无冻结画面残留 |
| 5 | PDF 与 EPUB 表现一致 | 新增 `services/turnCover.ts` 单例遮罩服务，两端共用定位 / 层级 / 幂等揭除；补播闸门共用同一 `canReplayBurst` | 两引擎按同一份冒烟清单各验证一遍，观感一致 |
| 6 | 遮罩不可用时不得退化成「先闪后播」 | `canReplayBurst` 新增 `covered` 必填判据：没有遮罩就不再补播（退化为纯瞬切） | 人为让截图失败（或缩短超时）后连翻：页面直接瞬切，不出现「目标页先现、旧页再卷回来」 |

**核心验收口径**：在「点击落在上一场动画播放中」的真实节奏（约 300~600ms/下）下连翻 3 页，目标页在卷曲首帧画出之前始终不可见；停手约 220ms 后只出现一次卷曲，起点画面 = 连翻首帧画面；全程无遮罩残留、无落点 / 进度变化。

## 二、非目标（本期不做）

1. **不改连翻判定与补播时机**：`RAPID_GAP_MS=160`、`RAPID_QUIET_MS=500`、`BURST_SETTLE_MS=220`、`TurnPolicy` 状态机与动画启动预算（320 / 1200ms）零改动。
2. **不给连翻期做「画面跟手」**：用户已确认取「冻结式补播」——连翻期间阅读区停在连翻起点画面（页码 / 进度即时更新），换取绝不先闪目标页。若要改回跟手，属于另一轮需求。
3. **不改滑块松手补播**：滑块拖动本身是连续可见动作，松手后「回到拖动起点再卷到终点」是既有既定行为，不在本次诉求内；本次仅保证滑块接管时揭除连翻遮罩。
4. **不做动画接力 / 续播**：补播仍是一次独立卷曲，不从被打断动画的进度续播。
5. **不改卷曲视觉**：`pageCurl.ts` 的 450ms、`easeInOutCubic`、投影 / 暗化 / 高光与 `zIndex` 语义均不动。
6. **不优化截图耗时**：`window:captureRegion` 主进程实现与 `captureRegionToCanvas` 不改；本次只改变「何时等待截图」。
7. **不新增设置项 / 依赖 / IPC / DB 字段**：无 `shared/types.ts`、`electron/**` 改动；不引入 jsdom 等测试环境依赖（新增依赖属工程红线）。
8. **纵向（ttb）链路不参与**：PDF 纵向由 `VerticalScrollView` 接管、EPUB 纵向走连续流，均在动画管线之前早退，行为不变。

## 三、总体设计

### 3.1 现状与根因（已核对源码）

连翻 `burst` 路径是「**先瞬切上屏、后补播动画**」，而补播动画的起点是**连翻首帧快照**，两者顺序相反，于是屏幕先出现目标页、再被旧页盖回去重卷一次：

**PDF（`src/views/ReaderView.vue`）**

| 时刻 | 事件 | 屏幕 |
|---|---|---|
| t0 | 第 1 次点击（1→2），`policy.decide` → `animate` | 第 1 页 |
| t0+~120ms | `renderCurrentSpread` 完成 → `playTurnCurlHoldingAi({from:1, to:2})` | 卷曲 1→2 |
| t0+300ms | 第 2 次点击 → `runTurnPassInner`：`wasAnimating=true` → `cancelTurnCurl()` | 第 2 页（卷曲被揭除） |
| t0+300ms | `decide` → `{mode:'snap', burst:true}`；`renderCurrentSpread({fade:false})` 立即把第 3 页贴到显示 canvas | **第 3 页闪出** |
| t0+520ms | `finishBurstCurl()`：`from = burstFromSnap`（第 2 页）→ `playTurnCurlHoldingAi({from:2, to:3})` | 又回到第 2 页，再卷到第 3 页 |

**EPUB（`src/views/EpubReaderView.vue`）**

| 时刻 | 事件 | 屏幕 |
|---|---|---|
| t0 | 第 2 次点击落在动画播放中 / 间隔 <160ms → `doDrainTurns` 判定 `{snap, burst}` | 第 2 页 |
| t0 | `beginBurstSession(from)` 只把截图 `Promise` 挂到后台（**不 await**），随即 `jumpTo(target)` | — |
| t0+~100ms | `jumpTo` 触发的 epub.js 重建完成，目标页已挂在 iframe 里，且**没有任何遮盖** | **第 3 页闪出** |
| t0+~320ms | `finishBurstCurl()`：`await burstFromPromise` → `playTurnCurl({from:2})` | 又回到第 2 页，再卷到第 3 页 |

两端共性根因（一句话）：**瞬切结果先上屏，补播动画又从旧页重新盖回去再卷开**——补播动画的起点不再等于补播开始前的屏幕画面。

触发条件：`TurnPolicy.decide` 在 `animating=true`（点击落在上一场动画播放中）、相邻翻页间隔 <160ms、或闩锁期内返回 `snap + burst`。由于单次动画总耗时 = 快照 + 渲染 / 导航 + 450ms，正常阅读节奏下第二下几乎必然落在动画播放中，因此稳定复现。

### 3.2 分层数据流（改造后）

```
┌─ 输入层 ───────────────────────────────────────────────────────────────┐
│ 热区点击 / 键盘 / 滚轮 / 底栏按钮（滑块单独会话，本次不改）              │
└──────────────┬───────────────────────────────┬────────────────────────┘
               │ EPUB                          │ PDF
               ▼                               ▼
   requestTurn → pendingDelta         watch(currentDisplayPages) → runTurnPass
   drainTurns 串行消费                 turnGen「最新请求胜出」
               └──────────────┬───────────────┘
                              ▼
                TurnPolicy.decide → { mode:'snap', burst:true }
                              ▼
   ┌────────────────────────────────────────────────────────────────────┐
   │ burst 首帧：取起点快照                                            │
   │   PDF：snapshotForTurn() 同步合成                                  │
   │   EPUB：captureRegionToCanvas()（await，超时 BURST_COVER_TIMEOUT_MS）│
   │        → attachTurnCover({ owner:'burst' })  ← 新增：先遮住          │
   ├────────────────────────────────────────────────────────────────────┤
   │ 后续每个 burst 轮次：正常导航 / 渲染（发生在遮罩之下，用户不可见）    │
   └──────────────┬─────────────────────────────────────────────────────┘
                  ▼
      停手 BURST_SETTLE_MS（220ms）且队列空闲
                  ▼
      canReplayBurst（新增 covered 判据）
        ├─ false → removeTurnCover() + 清会话（不补播，退化为纯瞬切）
        └─ true  → playTurnCurl({ from: 起点快照, zIndex: 1 })
                        ▼ 首帧画出后（doubleRaf）
                  removeTurnCover() → 卷曲透明区透出实时最终页
                        ▼
                  turnAnimator 单例（自然结束 / 新输入揭除）
```

要点：

- **唯一新增不变量**：补播动画开始播放前，屏幕上必须仍是补播起点画面。实现手段就是「连翻期遮罩」。
- **遮罩只在连翻期存在**：单次动画路径（EPUB `animatedTurn` 的冻结帧、PDF 的 `to` 快照）机制不变，只是 EPUB 冻结帧改为接入同一遮罩服务。
- **遮罩与卷曲同层**：两者 `zIndex` 均为 1，卷曲覆盖层后 append 故在遮罩之上；工具栏 `z-index` 2 / 3 全程叠在两者之上，观感与现状一致。
- **补播不导航**：与上一版一致，遮罩下的 DOM / 位图已在最终页，卷曲只负责「把视觉补回来」。

### 3.3 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 治理方式 | **遮罩式补播**（先遮后卷），不删除补播特性 | 用户已确认：直接消除「屏幕画面 ≠ 动画起点」这个矛盾；删除补播会让上一版明确要求「跳到位后展示一次动画」的特性失效，属于功能回退 |
| 遮罩实现 | 新增 `src/services/turnCover.ts` 单例服务，带 `owner: 'turn' \| 'burst'` | 两端定位 / 层级 / 幂等揭除只有一份实现；`owner` 让 `discardTurn()` 只揭除单次翻页自己的遮罩，绝不误揭连翻遮罩（这是本方案最容易踩的坑） |
| 遮罩层级 | `zIndex: 1`（与卷曲覆盖层同级，后 append 在其上） | 沿用既有层级约定：工具栏 `z-index` 2 保持可见；动画期间不存在「遮罩盖住工具栏」问题 |
| 遮罩几何 | 建立时按目标 `bbox` 锁定，连翻期**不跟随内容滚动** | 「冻结」语义：连翻期 `resetPageScroll` / 内容滚动都在遮罩之下静默发生，用户看到的画面不动 |
| EPUB 截图时机 | 由「异步后台截、不等」改为「**首帧 await 截图后再导航**」 | 不 await 就会先导航渲染，必然闪目标页；等待期屏幕本来就是这张画面（遮罩内容与之相同），用户无感，不构成可感知延迟 |
| 无快照 / 截图失败 | 放弃遮罩 **且放弃补播**，退化为纯瞬切 | 宁可不播动画，也绝不允许「先闪目标页再播旧页卷曲」；由 `canReplayBurst` 的 `covered` 判据强制，避免漏判 |
| PDF 译文框 | 遮罩窗口内沿用 `holdAiOverlay()` 会话级门控 | 遮罩下 DOM 已是新页，译文框浮在冻结画面上会「位置属于新页、底图是旧页」；会话级持有可保证遮罩揭除后才恢复 |
| 遮罩等待上限 | 新增 `BURST_COVER_TIMEOUT_MS = 600` | 全屏 `capturePage` 往返实测 200~300ms，600ms 覆盖慢机；超时视为截图失败，进入「不补播」分支 |
| 补播前的清理顺序 | 先读走会话快照 → 播卷曲 → 首帧后揭罩 → 最后清字段 | 现状 `finishBurstCurl()`（PDF）一开始就调 `clearBurstSession()`，若该函数统一揭罩，就会在起播前把画面掀开 → 必须把「会话字段清理」与「遮罩揭除」拆开 |

## 四、核心机制与边界防护

### 4.1 `turnCover.ts`（新增，单例遮罩）

```ts
// 补播遮罩单例：连翻瞬切期间把阅读区冻结在连翻起点画面，
// 保证「停手补播动画的起点 = 屏幕当前画面」，对应本文档 §4.2
export type TurnCoverOwner = 'turn' | 'burst'

export interface TurnCoverOptions {
  /** 定位参考（与 pageCurl 的 container 一致：.reader-view，position: relative） */
  container: HTMLElement
  /** 覆盖区域（与 pageCurl 的 target 一致：PDF 的 pageArea / pageContent、EPUB 的 .epub-area） */
  target: HTMLElement
  /** 起点画面快照（物理像素 + style 逻辑尺寸，与 pageCurl 的 from 同源） */
  canvas: HTMLCanvasElement
  owner: TurnCoverOwner
}

/** 上屏遮罩（先揭除旧遮罩，全局单例）；几何按 target 当前 bbox 锁定 */
export function attachTurnCover(options: TurnCoverOptions): void

/**
 * 揭除遮罩（幂等）。
 * @param owner 只揭除该归属的遮罩（不传 = 无条件）
 * @param el    只揭除该画布的遮罩（不传 = 不校验）；用于「首帧后揭罩」的迟到回调，
 *              避免揭掉后续新会话刚贴上的遮罩
 */
export function removeTurnCover(owner?: TurnCoverOwner, el?: HTMLCanvasElement): void

/** 当前是否有遮罩（补播闸门 covered 判据） */
export function isTurnCoverActive(): boolean

/** 双 rAF：等一帧提交后的合成输出更新（卷曲首帧画出后揭罩）；两端复用，删除视图内各自实现 */
export function doubleRaf(): Promise<void>
```

实现要点：

- 定位算法与 `pageCurl.ts` 的 overlay 完全一致：`left/top` 由 `target.getBoundingClientRect()` 减 `container.getBoundingClientRect()` 得到，`width/height` 取 target 的 CSS 尺寸，`position: absolute`、`pointerEvents: none`、`zIndex: 1`。
- 模块级单例 `{ el, owner } | null`，与 `turnAnimator.ts` 风格一致；`attachTurnCover` 内部先无条件揭除旧遮罩，杜绝叠层。
- 不监听滚动 / `resize`：窗口尺寸变化时视图侧 `clearBurstSession()` 会揭罩（尺寸变了遮罩本来也已过期）。

### 4.2 补播闸门扩展（`turnPolicy.ts`）

```ts
/** 连翻首帧截图等待上限（ms）：超时即视为无遮罩，放弃补播 */
export const BURST_COVER_TIMEOUT_MS = 600

export interface BurstReplayGate {
  tokenValid: boolean
  reducedMotion: boolean
  hasSnapshot: boolean
  /** 新增：遮罩是否已上屏；false 时补播会把旧页盖回已露出的目标页 → 必须拒绝 */
  covered: boolean
  startIndex: number | null
  finalIndex: number
  startCfi: string | null
  finalCfi: string | null
  queueBusy: boolean
  pendingDelta: number
  curlActive: boolean
  dragging: boolean
}

export function canReplayBurst(gate: BurstReplayGate): boolean {
  if (!gate.tokenValid || gate.reducedMotion || !gate.hasSnapshot) return false
  if (!gate.covered) return false // 核心不变量：补播起点必须等于屏幕画面
  // …其余判据（startIndex / queueBusy / pendingDelta / curlActive / dragging / 页与 CFI 判重）保持不变
}
```

### 4.3 连翻会话状态（两端同构）

```ts
// EPUB
let burstStartIndex: number | null = null
let burstStartCfi: string | null = null
let burstFrom: HTMLCanvasElement | null = null   // 由 Promise 改为已就绪画布（首帧已 await）

// PDF
let burstFromSnap: HTMLCanvasElement | null = null
let burstFromViewport: boolean | null = null
let burstStartIndex: number | null = null
let burstAiHeld = false                          // 译文框会话级门控是否已持有（PDF）
```

会话生命周期不变（建立 → 每轮重置停手计时 → 停手判定 → 补播 / 放弃 → 清理），**唯一新增规则**：`clearBurstSession()` 末尾统一 `removeTurnCover('burst')` + 释放译文框门控；`finishBurstCurl()` 走「先读走快照」的特例路径，不调用带揭罩的清理。

### 4.4 边界场景防护

| 场景 | 行为 |
|---|---|
| 连翻首帧截图失败 / 超过 `BURST_COVER_TIMEOUT_MS` | 不上遮罩；会话标记为「有起点但无快照」→ 导航照常瞬切；停手时 `covered=false` / `hasSnapshot=false` 拒绝补播；`clearBurstSession()` 揭罩（无遮罩则空操作） |
| 系统减弱动态 | ① 不截图不上遮罩、② 补播被闸门拒绝（既有语义）；连翻全程纯瞬切 |
| 首 / 尾页连点（`effective === 0`） | 该轮不导航，但**必须仍 `scheduleBurstSettle(token)`**：否则 `requestTurn` 已清掉停手计时器，遮罩会永久停留（现存代码因无遮罩而未暴露此问题） |
| 连翻净位移为 0（前进再后退） | 闸门 `finalIndex === startIndex` / CFI 相同 → 拒绝补播；**拒绝路径必须先揭罩再返回**（此时遮罩内容正是当前页，揭除无视觉变化） |
| 补播在播时新输入 | `requestTurn` → `isTurnCurlActive()` → `discardTurn()` 揭除卷曲（`owner:'turn'`，不会误伤连翻遮罩，此刻也不存在连翻遮罩）→ 新一轮按策略决定 |
| 连翻期滑块接管 | `onSlide` / `onSlideInput` / `requestJump` → `clearBurstSession()` 揭罩，只保留滑块自己的补播 |
| 换书 / 改窗口尺寸 / 卸载 / 切 ttb | `doOpen` / `onResize` 防抖回调 / `onBeforeUnmount` / `isVertical` watch → `clearBurstSession()` 揭罩 |
| `openSeq`（EPUB）/ `turnGen`（PDF）失效 | 会话与遮罩由上述清理点统一收口；`doubleRaf` 中揭罩带 `el` 身份校验，不会揭错新会话的遮罩 |
| PDF 最后一轮渲染未落定（`shown?.index !== reader.currentIndex`） | 既有放弃分支 → `clearBurstSession()` 揭罩，避免旧画面永久冻结 |
| PDF 滚动模式（`isVerticallyScrollable()`） | 遮罩按 `pageArea` 可视矩形锁定；连翻期 `resetPageScroll` 在遮罩下发生，遮罩不跟随 → 用户视角画面不动，符合「冻结」语义 |

## 九、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|---|---|---|
| 连翻期画面不跟手 | 取「冻结式补播」 | 用户已确认；连翻期间只有页码 / 进度即时变化。若日后希望「跟手 + 不闪」并存，需要另一套方案（逐轮揭示 + 逐轮截图，成本显著上升），列为本方案之外的扩展点 |
| EPUB 首拍多一次等待 | 首帧 `await` 截图（50~300ms）后再导航 | 等待期屏幕上本来就是遮罩内容（同一画面），用户不可感；代价是首个 `burst` 轮次的内部耗时变长 |
| 截图失败即无动画 | 失败 / 超时 → 不补播、纯瞬切 | 与「绝不先闪后播」相比，牺牲一次动画可接受；诊断面板保留 `burst cover fail` 便于定位 |
| 遮罩残留风险 | 单例 + `owner` + 身份校验 + 所有清理点统一 `clearBurstSession()` | 遮罩是最坏的失败形态（永久冻结画面），因此把「会话清理」做成唯一出口；`doubleRaf` 揭罩带画布身份校验，防止迟到回调揭掉新会话的遮罩 |
| `doubleRaf` 揭罩时机 | 卷曲首帧画出后（双 rAF）揭除 | 与 EPUB 既有冻结帧手法一致；早一帧揭会露出遮罩下的新页（等效于原 bug） |
| 遮罩不随滚动 / 布局同步 | 建立时锁定几何 | 保证「冻结」语义；窗口尺寸变化直接揭罩（会话清理），避免用过期的遮罩几何 |
| 补播期间遮罩与卷曲同层 | 均 `zIndex: 1` | 卷曲后 append 故在遮罩之上，首帧画面与遮罩逐像素一致，切换无跳变 |
| 滑块补播仍「先闪后播」 | 本期不动 | 用户诉求只针对快速翻页；滑块拖动本身连续可见，松手补播的「回到起点再卷」是既有既定观感 |
| `covered` 是必填判据 | 断言在纯函数内 | 避免将来新增补播触发点时忘记校验遮罩；单测同时守护 |

1. PDF `runTurnPassInner` 的 `decision.mode === 'snap' && !decision.burst`（模式 / 方向 / 缩放重排）与 `!reader.spreads[index]` 早退都不会重新 `scheduleBurstSettle`，旧计时器因 `gen !== turnGen` 只 return 不清会话 → 遮罩会永久停留。清理判据改为 `decision.mode === 'animate' || !decision.burst`，并让页组缺失分支先清会话。
2. EPUB `doDrainTurns` 的 `snap && !burst` 分支（减弱动态 / 拖动降级）同样不会补播，补 `if (!decision.burst) clearBurstSession()`。
