# AI 框选翻译功能设计方案

> 状态：设计稿（待实现）
> 目标版本：v1.4.2（版本号不在本方案内变更，由发版时确定）
> 范围：设置页 AI 配置（多模型服务管理 / 翻译语言 / 总开关）、阅读页框选翻译交互、译文与版式持久化、主进程统一外网请求点

| 9 | 右下角可拖拽调整翻译框尺寸 | 右下角 resize 手柄（`nwse-resize`），松手落库 | 拖大拖小后切页再回来，尺寸保持 |
| 10 | 翻译框内文本居中显示 | 文本区 flex 居中 + `margin:auto` 内层（保证溢出时可滚） | 短译文正中、长译文可滚动 |

| 12 | 工具栏按钮旁下拉：该本漫画译文一键全部隐藏 / 全部折叠 / 全部展开 | AI 按钮右侧 `▾` 下拉，3 项（全部隐藏 / 全部折叠 / 全部展开）：隐藏态下「全部隐藏」置灰，折叠 / 展开两个动作自带恢复显示 | 各自生效；全部隐藏后不再出现「全部显示」，点折叠 / 展开即重新显示译文框 |
| 13 | 上传框选图片给大模型翻译，提示词贴合漫画（书名、专名一致） | `electron/services/aiReply.ts` 的 `buildTranslatePrompt`（书名 + 目标语言 + 专名一致 + 纯 JSON 输出） | 同一本书两次框选同一人物，译名一致；日志可见提示词含书名 |
| 14 | 未识别到文字时返回「未识别到文字内容」灰色兜底 | `text === ''` → 灰色兜底文案框，不落库 | 框选空白画面出现灰色兜底文案 |
| 15 | 根据框选尺寸与文字内容一并返回建议文字大小 | 模型返回 `fontRatio`（文字行高 / 图高），渲染 `fontRatio × 页显示高度` 钳制 10~96px 后**再按框内可用空间等比收缩**（下限 10px，仍溢出则滚动） | 大字气泡的译文明显大于小字气泡；缩放后字号同比变化；任意框（含手工缩小的框）内文字都完整贴合不溢出 |

**核心验收口径**：在 PDF 书双页模式下框选一格日文对白 → 3 秒内（网络正常）框内出现中文译文且字号贴合气泡；切到单页、再缩放到 200%、再切回来，译文框始终贴合原气泡位置（偏移 ≤ 2px）；退出应用重进后译文框、字号、折叠状态原样恢复。

## 二、非目标（本期不做）

- **不支持 EPUB 与「上→下」纵向滚动（ttb）**：EPUB 为文字重排，框选对象不是图片，需先做窗口合成截图且与文字选择交互冲突；ttb 的行盒是窗口化挂载 + 无限滚动画布，覆盖层要参与其挂载生命周期，回归面过大。二者后续按同一份归一化坐标模型扩展即可（扩展点见 §13）。
- 不做整页/整章自动识别与批量翻译：单次请求成本与误伤率高于用户主动框选。
- 不做译文人工编辑（直接改字）、不做译文导出/复制按钮：需求未提，先保证「框选 → 看到译文」主链路。
- 不做流式输出：一次请求一次返回，避免渲染层增量拼接与落库时序复杂化。
- 不做重试按钮与请求缓存：同区域重复框选会重复计费，接受（§13 风险表）。
- 不做多协议适配（Anthropic / Gemini 原生协议），仅 OpenAI 兼容的 `/chat/completions`。
- 不做本地模型推理、不内置任何模型或提示词模板下载。
- 不改动 EPUB 阅读器（`EpubReaderView.vue` / `epubReader` store）、`protocol.ts`、`pageCache` / `turnPolicy` / 翻页动画管线。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 支持形态 | 仅横向单/双页（PDF / CBZ / MOBI） | 归一化到「页」的坐标模型在单双页与缩放下天然成立；EPUB 与 ttb 需另建坐标系，本期不做（§2） |
| 接口协议 | 仅 OpenAI 兼容 `/chat/completions`（图片走 `image_url` data URL） | 一套实现覆盖 OpenAI 与各家兼容网关及本地 Ollama；多协议适配的收益集中在少数官方端点，不值得翻倍测试面 |
| 请求发起方 | 主进程 `aiService`（Node 全局 `fetch`） | 渲染层直连受 CORS 与 CSP 约束，且 API Key 与请求逻辑应收敛到唯一出网点，与 `updaterService` 的网络边界同构 |
| 配置存储 | `Settings.ai`（多条 provider + `activeProviderId`），随 settings JSON 明文入库 | 复用既有 `settings:all / patch` 与 `DEFAULT_SETTINGS` 合并机制，旧库天然兼容；safeStorage 方案需另开 IPC 与掩码态，本期不做（§13） |
| 记录存储 | 新表 `ai_translations`，一页多行，坐标为 0~1 归一化值 | 与 `reading_stats` 同为「按书聚合的小数据」；归一化坐标使单/双页、缩放、方向切换零额外处理 |
| 页码口径 | 存真实页码（`spread.displayOrder` 值，1 基） | 与 `reader.spreads` / `buildSpreads` 的现有页码口径一致；单双页重排、RTL 镜像后同一页仍命中同一条记录 |
| 字号口径 | 存 `font_ratio`（文字行高 / 页高），渲染时 `× 页显示高度` 作为建议上限，再由渲染层按框内空间收缩 | 需求要求「文字大小」随框与页面自适应；存 px 在缩放/单双页切换后会失真；模型给的比例常偏大，只用建议值会溢出框体 |
| 隐藏状态 | 会话级（`hiddenAll` 只在当前书、当前阅读会话有效，不落库） | 隐藏是「临时看清画面」的观察动作，落库反而会让用户下次打开误以为译文丢失；折叠是逐框的版式意图，必须落库 |
| 兜底文案 | `text === ''` 时不落库，仅作临时框展示 | 识别失败不是用户产出的内容，落库会污染记录与后续统计；代价是翻页后消失（§13 风险表） |
| 交互冲突 | 选词模式期间停用热区翻页、拖拽平移、滚轮翻页 | 拖框与「按住拖拽平移」「左右 1/3 热区翻页」在事件层面重叠，必须先隔离，否则框选一次就翻一页 |
| 下拉菜单 | 阅读页自建轻量菜单，不复用 `SelectMenu` | `SelectMenu` 是「值选择器」（显示当前值 + 高亮项），这里是动作菜单（隐藏/折叠/展开），语义不同，硬套会引入无意义的选中态 |

## 四、核心算法与口径

### 4.1 坐标归一化（框选 → 存储）

坐标系：**以单页 canvas 的显示盒为参照**（`getBoundingClientRect`，CSS px），归一化为 0~1 的 `(x, y, w, h)`。因为单双页切换、缩放、方向切换改变的都是显示盒尺寸与排列，而「页内相对位置」不变。

```ts
// 伪代码：page 显示盒内的鼠标拖拽 → 归一化矩形
const box = pageWrapEl.getBoundingClientRect()           // 单页显示盒（CSS px）
const x = Math.min(startX, curX) - box.left
const y = Math.min(startY, curY) - box.top
const w = Math.abs(curX - startX)
const h = Math.abs(curY - startY)
if (w < MIN_SELECT_W || h < MIN_SELECT_H) return null     // 24 × 16，过滤误触
const rect = clampToUnit({ x: x / box.width, y: y / box.height,
                           w: w / box.width, h: h / box.height })  // 越界夹取到 [0,1]
```

渲染方向相反，全部用百分比内联样式，避免依赖 `ResizeObserver`：

```ts
style = { left: `${rect.x * 100}%`, top: `${rect.y * 100}%`,
          width: `${rect.w * 100}%`, height: `${rect.h * 100}%` }
```

| 场景 | 归一化坐标的表现 |
|------|------------------|
| 单页 ↔ 双页切换 | 显示盒宽度变化，百分比自动贴合同一气泡 |
| 适宽 / 适高 / 自定义缩放 | 同上；字号另按 `font_ratio × 页高` 同比缩放 |
| 阅读方向 ltr / rtl 切换 | `displayOrder` 改变画布排列顺序，但页码与页内位置不变，记录按页码命中 |
| 窗口尺寸变化 | 同上（百分比布局） |
| 页面图片宽高比变化（不同书） | 记录按 `book_id + page` 隔离，不跨书复用 |

### 4.2 裁剪与压缩口径

```ts
// aiCrop.ts：从显示 canvas 的**位图**裁切（不是从屏幕上截），位图分辨率 = CSS × DPR，OCR 更准
const sx = rect.x * canvas.width,  sw = rect.w * canvas.width
const sy = rect.y * canvas.height, sh = rect.h * canvas.height
const scale = Math.min(1, MAX_SIDE / Math.max(sw, sh))       // MAX_SIDE = 1024
// 目标画布：Math.max(1, round(sw*scale)) × round(sh*scale)
// 白底填充后再 drawImage：JPEG 无 alpha，透明区会变黑，先铺 #fff
return out.toDataURL('image/jpeg', 0.82).split(',')[1]        // 仅 base64，不含 data: 前缀
```

- 上限 1024px 长边 + JPEG 0.82：单次载荷通常 30~250KB（base64 后 ~40~340KB），符合「IPC 只传小载荷」约束（对照 `cover:submit` 的 ArrayBuffer 形态）。
- 不落盘原图：裁剪结果用完即弃，只在 SQLite 里存译文文本。

### 4.3 字号推导与钳制

```ts
export const DEFAULT_FONT_RATIO = 0.06
export const MIN_FONT_RATIO = 0.02
export const MAX_FONT_RATIO = 0.15

/** 页面显示高度 × 比例，钳制到 [10, 96] px；非法值回退默认比例 */
export function computeFontPx(fontRatio: number, pageHeightCss: number): number {
  const ratio = Number.isFinite(fontRatio) ? clamp(fontRatio, MIN_FONT_RATIO, MAX_FONT_RATIO) : DEFAULT_FONT_RATIO
  return Math.round(clamp(ratio * pageHeightCss, 10, 96))
}
```

`pageHeightCss` 由覆盖层自身 `getBoundingClientRect().height` 读取（覆盖层 = 页盒，二者同尺寸）。

`computeFontPx` 只给出**建议上限**：模型返回的 `fontRatio` 常按气泡原字大小给出，套到用户框选的矩形里会偏大。渲染层（`AiTranslationLayer.fitAll`）再按框内可用高度做一次等比收缩：溢出时以 `clientHeight / scrollHeight` 为系数缩字，最多 4 轮，下限 `MIN_FONT_PX`（10px），到下限仍溢出才启用滚动。收缩结果按框缓存，文本 / 框尺寸 / 页尺寸 / 折叠状态变化时重算；尚未实测（如刚展开、刚翻回本页）时先按框高的 52% 兜底，避免用建议值撑满框。

### 4.4 模型响应解析（主进程纯函数）

模型被要求只输出 JSON：`{"text":"译文","fontRatio":0.06}`。现实会返回 ```json 围栏、前后废话、被 `max_tokens` 截断的半截 JSON，甚至只回一句纯文本译文，因此解析按四级容错收口：

```ts
export function extractReply(content: string): AiTranslateResult {
  if (content 含 '{') {
    const json = 第一个 { 到最后一个 }（无闭合括号时截到结尾）
    try { return 正常解析(json) }                 // 围栏 / 前后废话天然被切掉
    const salvaged = salvageReply(json)            // 截断、尾随逗号：正则抽 "text" 与 "fontRatio"
    if (salvaged) return salvaged
  }
  const plain = plainFallback(content)             // 纯文本译文（≤ 200 字、不含 {}、非拒绝语）直接收入
  if (plain) return plain
  throw { code: 'AI_REQUEST_FAILED', message: '模型返回内容无法解析' }
}
```

`MAX_TEXT_LEN = 2000`（防模型失控输出撑爆 UI）。`text === ''` 是合法的「未识别到文字」结果，不是错误。解析失败时 `aiService` 会写一条 `[ai] 解析失败 model=… chars=… head=…` 日志（`head` 为模型原文前 200 字），用于区分「接口层失败」与「模型没按 JSON 输出」。

### 4.5 边界场景防护清单

| 场景 | 行为 |
|------|------|
| 未启用 AI 或未配置 provider | 阅读页 AI 按钮禁用并提示「AI 翻译未开启，请到 设置 → 数据 → AI 配置 开启」；主进程 `ai:translate` 抛 `AI_NOT_CONFIGURED` 兜底 |
| 框选过小（< 24×16） | 视为误触，不发起请求、不生成框 |
| 拖框越出页面 | 夹取到页内（`clampToUnit`），不产生负宽高 |
| 请求超时（60s）/ 断网 | 抛 `AI_REQUEST_FAILED`，临时框变错误态（红色文案 + 可删除），不落库；主进程日志记 `[ai] 请求失败 … reason=…` |
| 服务商默认开启思考（DeepSeek） | 请求体显式 `thinking: { type: 'disabled' }`；端点返回 400 且 body 提到 thinking 时自动去掉重试一次。否则思维链会吃光 `max_tokens`，`content` 为空 → 解析失败 |
| 模型未按 JSON 输出 | 依次尝试：完整 JSON → 截断/非法 JSON 正则抢救 → 纯文本译文（≤ 200 字、非拒绝语）→ 兜底抛 `AI_REQUEST_FAILED` 并写日志（含原文前 200 字） |
| 401 / 403 | 抛 `AI_AUTH_FAILED`（提示检查 API Key） |
| 图内无文字 | `text === ''` → 灰色兜底「未识别到文字内容」，不落库，翻页即消失 |
| 翻译途中切页 / 切书 / 离开阅读页 | 结果返回时若 `bookId` 已变则丢弃并记 info 日志，不落库（避免在用户看不见的页上悄悄写入） |
| 翻译途中点删除 | pending 框直接移除，请求结果丢弃（按框 key 校验） |
| 同一区域重复框选 | 允许，产生多条记录（§13 风险表：接受重复计费） |
| 一页多个框重叠 | 按 `created_at` 升序渲染，后建的在上层 |
| 调整框尺寸超过页边界 | 夹取到页内，最小 40×28 px（归一化后按页尺寸换算） |
| 书被删除 | `ai_translations` 行随外键 CASCADE 删除 |

### 6.2 通道定义

| 通道 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `ai:translate` | `AiTranslatePayload` | `AiTranslateResult` | 用户框选触发的一次翻译；**不落库**，落库由渲染层拿到结果后调 `ai:save` |
| `ai:test` | `{ provider: AiProviderConfig }` | `AiTestResult` | 配置页「测试连接」：用草稿配置发一条最小文本请求 |
| `ai:list` | `{ bookId: number }` | `AiTranslationRecord[]` | 打开书时一次拉全量 |
| `ai:save` | `AiTranslationInput` | `AiTranslationRecord` | 新增或更新（折叠 / 调整尺寸 / 改写版式都走它） |
| `ai:remove` | `{ id: number }` | `void` | 删除单条（需求 11「删除则清除该记录」） |

**服务层校验规则**（`aiService`）：

- `ai:translate`：
  - 读 `settingsRepo.getAll().ai`，`enabled === false` 或找不到 `activeProviderId` → 抛 `AI_NOT_CONFIGURED`；
  - `bookId` 为正整数且 `libraryService.getById` 存在，否则 `FILE_NOT_FOUND`；
  - `page` 为正整数（1 基），否则 `INVALID_PARAMS`；
  - `imageBase64` 为非空字符串且长度 ≤ 4_000_000（≈3MB）→ 否则 `INVALID_PARAMS`；
  - `bookTitle` 截断到 200 字。
- `ai:save`：`bookId` 存在；`page ≥ 1`；`rect` 四值有限且落在 `[0,1]`、`w/h ≥ 0.01`；`text` 长度 ≤ 2000（超出截断）；`fontRatio` 收敛到 `[0.02, 0.15]`；带 `id` 时该行必须存在，否则 `INVALID_PARAMS`。
- `ai:list`：`bookId` 存在，否则返回空数组（书刚被删除属正常竞态，不报错）。
- `ai:remove`：`id` 为正整数。
- `settings:patch`（既有通道）：当 `partial.ai !== undefined` 时，校验 `targetLang ∈ AI_TARGET_LANGS`、`enabled` 为 boolean、`providers` 为数组且每项 `baseUrl` 以 `http://` / `https://` 开头、`apiKey` / `model` / `name` 为字符串；校验后交给 `normalizeAiSettings` 归一化再入库，非法则 `INVALID_PARAMS`。

按「任务 A」六步落地顺序：`shared/types.ts` → `electron/preload.ts`（新增 `ai` 域）→ `electron/ipc/handlers.ts`（`ai:translate` / `ai:test` 用 `wrapAsync`，其余用 `wrap`）→ `src/services/ipc.ts` 镜像封装 → store / view 消费 → 本功能不改书库数据，无需 `notifyLibraryChanged`。

### 7.1 aiService（新建 `electron/services/aiService.ts`）

职责：配置解析、参数校验、单点外网请求、错误码映射、repo 编排。handler 只做编排与转发。

```ts
async function requestChat(provider: AiProviderConfig, content: unknown[], timeoutMs = 60_000) {
  const url = `${provider.baseUrl.replace(/\/+$/, '')}/chat/completions`
  const res = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${provider.apiKey}` },
    body: JSON.stringify({ model: provider.model, messages: [{ role: 'user', content }],
                           temperature: 0.2, max_tokens: 800 }),
    signal: AbortSignal.timeout(timeoutMs),          // 超时即 AbortError
  })
  if (res.status === 401 || res.status === 403) throw { code: 'AI_AUTH_FAILED', message: '...' }
  if (!res.ok) throw { code: 'AI_REQUEST_FAILED', message: `HTTP ${res.status}` }
  return res.json()   // fetch 抛错（断网 / 超时）在调用方统一转 AI_REQUEST_FAILED
}
```

`translate(payload)` 编排：校验 → 取 provider → `buildTranslatePrompt` → `requestChat` 带 `[{type:'text'},{type:'image_url', image_url:{url:'data:image/jpeg;base64,...'}}]` → 取 `choices[0].message.content` → `extractReply` → 返回 `{ text, fontRatio }`；全程 `logger.info/warn` 记录模型名、耗时与错误码（**不记录 apiKey、不记录 base64 图片**）。

`test({ provider })` 编排：用草稿 provider 发一条 `[{type:'text', text:'回复 OK'}]` 文本请求，成功返回 `{ model, latencyMs }`；错误码同上。

1. 角色：漫画翻译助手，识别图中全部对白/旁白/拟声词；
2. 上下文：书名《{title}》，人名、地名、招式名等专有名词在同一本书内保持通行译法一致；

5. 图内无可译文字时输出 `{"text":"","fontRatio":0.06}`。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 纯离线红线 | 新增唯一外网点 `aiService`（用户框选/测试连接触发），无后台与轮询 | 与既有「检查更新」同构，但外发的是漫画截图，属隐私敏感：配置页固定展示隐私提示，README 后续补说明 |
| API Key 明文存储 | 随 `Settings.ai` 明文写入 `library.db` | 同机可读；safeStorage 加密需独立 IPC 与掩码态，本期不做。将来可加：`ai:key` 专用通道 + 加密列，前端只显示末 4 位 |
| 兜底文案不落库 | 识别失败只留临时框，翻页后消失 | 记录保持「都是真译文」的语义；若反馈「想看到哪些区域试过」，可加 `status` 列后落库 |
| 重复框选重复计费 | 允许同区域多次请求 | 无缓存/去重逻辑，用户可控；后续可加「同 rect 命中已有记录时提示复用」 |
| 模型 OCR 与幻觉 | 提示词约束 + `text` 截断 + 结果纯文本渲染（不解析 HTML） | 输出可能漏字/错译，用户可删框重选；图文内容里的「指令」无法影响应用行为（只当文本展示） |
| `fontRatio` 估计偏差大 | 钳制 0.02~0.15 + 10~96px + 可手动调框 | 极端气泡（竖排小字）可能偏大/偏小；后续可加框内滚轮调字号（需扩 `font_ratio` 写入路径） |
| 单双页/缩放自适应 | 归一化坐标 + 百分比布局 | 完全依赖「页盒 = 图片显示盒」，PDF 页有内置白边时用户框选仍以页盒为准，不影响贴合 |
| 隐藏状态不持久 | `hiddenAll` 仅当前会话 | 重新打开书默认全部显示；如需持久可在 `ai_translations` 增加 `hidden` 列或按书记 flag |
| 选词模式禁用部分交互 | 停用热区翻页 / 拖拽平移 / 滚轮翻页 | 换取拖框稳定；键盘与底栏滑块仍可翻页，退出选词即恢复全部交互 |
| EPUB / ttb 不覆盖 | 本期只做横向单双页 | 扩展点：EPUB 走 `window.captureRegion` 合成截图 + 页级坐标即可复用本方案 §4.1 模型与全部 IPC；ttb 需把覆盖层挂到 `VerticalScrollView` 的 `.v-page`（已 `position: relative`），并处理窗口化挂载与滚动事件 |
| 在途请求不落库 | 切书/离开阅读页后返回的结果丢弃 | 避免在用户看不到的页上静默写入记录；代价是「翻译一半切走」需要重选（低频） |
| 服务列表规模 | 多条配置、无排序与分组 | 典型用户 1~3 条，不做拖拽排序；`activeProviderId` 单选已覆盖「切换模型」需求 |
| 工具栏层级调整 | `.top-bar` / `.bottom-bar` 的 `z-index` 2 → 3 | 适高模式页面贴满视口，页顶译文框与顶栏几何重叠时不得盖住工具栏；翻页动画（z1）与译文框（z2）仍在工具栏之下，翻页行为不变，需同步三处「低于控制栏（z2）」注释避免过期描述 |
