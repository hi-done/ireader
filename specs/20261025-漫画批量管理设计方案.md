# 漫画批量管理设计方案

> 状态：设计稿（待实现）
> 目标版本：v1.3.0（package.json 当前版本；版本号不变，发版时机由用户确定）
> 范围：设置页「数据」分组新增「漫画批量管理」入口、独立管理页（列表 / 筛选 / 批量选择 / 批量删除）、新增 `library:removeMany` IPC 能力
> 实现约束：遵循 `ireader-dev-tasks`（任务 A / D / F）与 `ireader-code-conventions`（Result 契约、中文注释、契约类型只定义在 `shared/types.ts`）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 设置「数据」栏增加「漫画批量管理」，点击进入新页面 | `SettingsView.vue` 的「数据」分组在「阅读时间统计」之后追加第二行 `.row-link` → `router.push('/manage')`；新路由 `/manage` → `LibraryManageView.vue` | 点击进入管理页；页头返回键回到设置页 |
| 2 | 展示漫画封面缩略图 | 行内 40×56 缩略图读 `book.coverUrl`（`ireader://cover/{id}`），无封面落折角书页 SVG 占位 | 有封面 / 无封面两类书均正常显示 |
| 3 | 展示漫画名 | 行主列，13.5px/600 单行省略 + 原生 `title` 提示 | 超长书名不撑破网格，悬浮可见全名 |
| 4 | 展示所属位置（主页或合集名） | `book.collectionId` 经 `collections` 映射为合集标题；`null`（或合集已失效）显示「主页」 | 未分组书显示「主页」，集内书显示对应合集名 |
| 5 | 展示导入时间 | `book.addedAt` 经 `formatAddedAt` 输出本地 `YYYY-MM-DD HH:mm` | 与系统时区一致，非 UTC 偏移 |
| 6 | 批量选择 | 每行 checkbox + 表头「全选当前」（支持 indeterminate）+ 底部常驻选择条（计数 / 清除 / 删除） | 全选、半选、跨筛选累积与清除计数均正确 |
| 7 | 批量删除 | 新增 `library:removeMany`（单 IPC + 单事务）；确认弹窗二选一：仅移除记录 / 同时删除文件 | 选 3 本删除后，管理页与主页同步少 3 本，封面缓存清除，统计行级联消失 |
| 8 | 按漫画名筛选 | 搜索框多词 AND 匹配书名（与 `AddBooksDialog` 同语义） | 输入「海 王」命中「海贼王」，不命中「海贼」 |
| 9 | 按合集名筛选 | 合集下拉：全部 / 主页（未分组）/ 各合集，与搜索框 AND 叠加 | 选「合集 A」后仅剩集内书；再叠加关键字为交集 |

**核心验收口径**：在含 ≥3 本未分组书、≥2 个合集的库中，选「合集 A」→「全选当前」→「删除所选」→「仅移除记录」，列表与主页同时少 N 本（N = 合集 A 书数），磁盘原文件仍在；同一流程改选「同时删除文件」后原文件消失，且弹窗已明示不可恢复。

## 二、非目标（本期不做）

- **不做批量移入 / 移出合集、批量重命名**：本期定位是「书库清理」；单本移入合集已有 `library:moveToCollection`，批量搬移会引入目标合集选择弹窗与跨页刷新，属独立需求。
- **不做删除的二次强确认（如输入书名）**：确认弹窗已标注本数与不可恢复提示，且默认视觉焦点在「仅移除记录」；更重的保护留待用户反馈。
- **不做分页 / 虚拟滚动**：行高固定、单库量级在千级以内，原生滚动足够；超过 2000 行再评估虚拟列表。
- **不做 DB 迁移**：批量删除复用 `books` 删除与既有外键 `ON DELETE CASCADE`。
- **不做管理页内的缺失文件重定位、封面重新生成**：缺失书只显示「文件缺失」徽章，仍可批量移除记录。
- **不改动 `library:remove` 单本通道语义**，不改动阅读器进度 / 阅读统计采集链。

## 三、总体设计

### 3.1 分层与数据流

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 列表数据来源 | 复用 `library:list` + `collection:list`（经 Pinia library store），不新增查询通道 | `Book` 已含 `coverUrl` / `addedAt` / `collectionId`，仅缺合集标题，由 `collections` 本地 join 即可；新增查询通道等于重复 `listAll + rowToBook` 链路 |
| 批量删除实现 | 新增 `library:removeMany`（单 IPC + 单事务） | 前端循环调 `library:remove` 会产生 N 次 IPC、N 次 `library:changed` 广播与 N 次 store 过滤，且没有事务边界；单通道可一次落库后统一广播 |
| 删文件时机 | DB 事务提交后再删磁盘文件与封面缓存 | 反序会在 DB 失败时已不可恢复地删掉文件；提交后删文件最坏是「记录没了、文件还在」，可手工清理 |
| 删除口径 | 确认弹窗二选一（**用户已确认**） | 与单本 `RemoveConfirmDialog` 语义一致；批量删文件风险高但清理场景确有需求，交由用户显式选择 |
| 筛选形态 | 搜索框（书名，多词 AND）+ 合集下拉（**用户已确认**） | 位置与书名是两个正交维度，叠加后可表达「清空某合集」；单一搜索框 OR 语义无法精确锁定合集 |
| 数据范围 | 全部书籍（PDF / EPUB / CBZ，**用户已确认**） | 项目把书籍统称漫画（PDF 漫画为主），管理页语义是「书库批量清理」，只列 CBZ 会让 PDF 漫画无法清理 |
| 筛选状态归属 | 页面局部 ref，不写 `library.keyword` | store 的 `keyword` 是文库主页搜索框的共享状态，复用会导致两页搜索互相污染 |
| 已选集合 | 页面局部 `number[]`，跨筛选保留 + 常驻底部选择条 | 批量管理常见动作是「选一批再改条件补选」；不保留会丢选择。跨筛选残留风险用「其中 M 本不在当前筛选结果中」提示消化 |
| 默认排序 | 导入时间降序（新→旧），同刻按 id 降序 | 清理心智是「最近导入的这批」；不复用主页排序偏好（该偏好属于浏览场景） |
| 列表渲染 | 普通卡片行，不复用 `BookCard` | 管理页要信息密度与选择效率；`BookCard` 带入 3D 倾斜、浮层提示、hover 操作按钮等浏览态交互 |

## 四、核心算法 / 口径

### 4.1 行构建与所属位置（`src/services/libraryManage.ts`）

```ts
export interface ManageBookRow {
  book: Book
  /** 所属位置：null = 主页（未分组） */
  collectionTitle: string | null
}

/**
 * 构建管理页行数据：一次性建立 合集 id → 标题 的 Map，避免逐行 find。
 * 排序：added_at 降序；同刻按 id 降序保证稳定。
 */
export function buildManageRows(
  books: readonly Book[],
  collections: readonly Collection[]
): ManageBookRow[]
```

口径：`collectionId !== null` 但在 `collections` 中找不到（合集刚被解散的竞态）时按 `null`（主页）处理，**不隐藏该行**——否则这本书在管理页永远删不掉。

### 4.2 筛选判定（两条件 AND 叠加）

```ts
/** 'all' = 全部；'ungrouped' = 主页（未分组）；number = 指定合集 id */
export type CollectionFilter = 'all' | 'ungrouped' | number

export function filterManageRows(
  rows: readonly ManageBookRow[],
  keyword: string,
  filter: CollectionFilter
): ManageBookRow[]
```

判定顺序：

1. 位置条件：`'all'` 直通；`'ungrouped'` 要求 `book.collectionId == null`（含 4.1 的失效兜底）；`number` 要求 `book.collectionId === filter`。
2. 关键字条件：按空白切词（`trim().toLowerCase().split(/\s+/)`），**每个词**都必须是书名子串（不区分大小写），与 `AddBooksDialog` 的多词语义保持一致。

### 4.3 导入时间格式化

```ts
/** 本地时间 'YYYY-MM-DD HH:mm'；非法 / 缺失时间戳返回 '—' */
export function formatAddedAt(ts: number): string
```

用 `getFullYear / getMonth / getDate / getHours / getMinutes` 手拼（与 `shared/types.ts` 的 `formatDayKey` 同口径），禁止 `toISOString()`——UTC 偏移会让「今天导入」显示成昨天。除年份外均 `padStart(2, '0')`。

### 4.4 全选 / 半选与跨筛选计数

- `allSelected`：当前筛选结果非空，且每本 id 都在 `selected` 中。
- `partiallySelected`：当前结果中至少一本被选且非全选 → checkbox 绑定 `:indeterminate`。
- `toggleSelectAll`：已全选则从 `selected` 移除当前结果 id，否则用 `new Set` 并入（去重），与 `AddBooksDialog.toggleSelectAll` 完全同构。
- `outOfViewCount`：`selected` 中不属于当前筛选结果的 id 数；>0 时底部条追加「其中 M 本不在当前筛选结果中」。

### 4.5 边界场景防护

| 场景 | 行为 |
|------|------|
| 删除时书已不存在（并发 / 竞态） | 主进程按 `findById` 逐个过滤，缺失即跳过；仍返回 `ok`，`removed` 只含真实删除项 |
| 删除时磁盘文件已被手工删掉 | `fs.existsSync` 守卫 + 单本 try/catch，跳过并 `logger.warn`，不让整批失败 |
| 删除正在阅读中的书 | 与单本一致：DB 行删除，阅读页下次进度保存因外键失败（既有行为），本期不处理 |
| 合集在选择期间被解散 | `watch(collections)` 校验当前筛选值是否仍存在，失效回退 `'all'`；已选 id 保留 |
| 500+ 本全选删除 | 单事务同步执行，毫秒级；不做分片 |
| 空库 | 整页空态（不渲染工具栏与选择条） |
| 筛选无命中 | 列表区提示「没有匹配的漫画」，「全选当前」禁用；不显示库空插画 |

## 五、数据模型

无 DB 迁移、无新表。复用既有结构：

- `books`：`id / title / file_path / cover_path / added_at / collection_id`（`BookRow` 已定义）。
- 级联：`reading_progress.book_id REFERENCES books(id) ON DELETE CASCADE`、`reading_stats.book_id REFERENCES books(id) ON DELETE CASCADE`，且 `initDatabase` 已设 `foreign_keys = ON`，批量删除无需手写级联。

`electron/db/repos/booksRepo.ts` 追加：

```ts
/** 批量删除书行（单事务；阅读进度 / 统计由外键 ON DELETE CASCADE 清理） */
removeMany(ids: number[]): void {
  const stmt = getDatabase().prepare('DELETE FROM books WHERE id = ?')
  const tx = getDatabase().transaction(() => {
    for (const id of ids) stmt.run(id)
  })
  tx()
}
```

## 六、IPC 契约

### 6.1 共享类型（`shared/types.ts` 追加）

```ts
/** 批量移除结果（library:removeMany 返回） */
export interface LibraryRemoveResult {
  /** 实际被移除的书 id；库中不存在的 id 被忽略，供渲染层精确同步本地列表与计数 */
  removed: number[]
}
```

### 6.2 通道定义

| 通道 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `library:removeMany` | `{ bookIds: number[]; deleteFile: boolean }` | `LibraryRemoveResult` | 批量移除：单事务删库 → 删文件 / 封面 → 一次 `library:changed` 广播 |

**服务层校验规则**（`libraryService.removeMany`）：

- `bookIds` 非数组、去重后为空 → 抛 `{ code: 'INVALID_PARAMS', message: 'bookIds 不能为空' }`。
- 逐项校验：仅保留正整数 id（非法项过滤而非抛错，避免一批里一个脏 id 让整批失败）；过滤后为空仍抛 `INVALID_PARAMS`。
- `deleteFile` 由 handler `Boolean()` 归一，服务层只接受 boolean。
- 不设数量硬上限（§11.2 以 500 本作为验收基线）。

**六步链路（任务 A）**：`shared/types.ts`（类型）→ `electron/preload.ts`（`library.removeMany`）→ `electron/ipc/handlers.ts`（`wrap` 注册，编排 service + `removeCover` + 广播）→ `src/services/ipc.ts`（`unwrap` 镜像）→ `src/stores/library.ts`（`removeMany` 动作）→ `src/views/LibraryManageView.vue`（消费 + `IpcError` 按 code 提示）。错误码复用 `INVALID_PARAMS` / `UNKNOWN`，不扩展 `ErrorCode`。

## 七、主进程实现

### 7.1 libraryService.removeMany（`electron/services/libraryService.ts` 追加）

```ts
/**
 * 批量移除书籍。
 * @param ids 待移除书 id（调用方已做非空 / 正整数过滤）
 * @param deleteFile 是否同时删除磁盘原文件
 * @returns 实际移除的 id 列表（库中不存在的 id 被忽略）
 */
removeMany(ids: number[], deleteFile: boolean): number[]
```

执行顺序：

1. `const rows = ids.map((id) => booksRepo.findById(id)).filter(Boolean)` —— 逐个确认存在，同时拿到 `file_path`。
2. `booksRepo.removeMany(rows.map((r) => r.id))`（单事务）。
3. 事务提交后逐本 `removeCover(id)`；`deleteFile` 时对 `fs.existsSync(row.file_path)` 的文件 `fs.unlinkSync`，每本包 try/catch + `logger.warn`，不中断批次。
4. 返回实际删除的 id 数组。

> 为什么不循环调用既有 `remove(id, deleteFile)`：`remove` 每本一次独立 DB 写 + 独立文件删除，没有事务边界；批量场景需要「一次落库、统一善后」。

### 7.2 handler 编排（`handlers.ts`，紧随 `library:remove` 之后）

```ts
ipcMain.handle(
  'library:removeMany',
  wrap(({ bookIds, deleteFile }: { bookIds: number[]; deleteFile?: boolean }) => {
    const removed = libraryService.removeMany(bookIds, Boolean(deleteFile))
    // 零变化不广播：避免空操作惊动文库 / 封面视图做无谓 refresh
    if (removed.length) notifyLibraryChanged(getWin(), { type: 'removed', bookIds: removed })
    return { removed } satisfies LibraryRemoveResult
  })
)
```

handler 只做编排：参数校验与文件处置在 service，事件广播在 handler（与 `library:remove` 既有分工一致）。

## 八、渲染层实现

### 8.1 library store 追加 `removeMany`（`src/stores/library.ts`）

```ts
/** 批量移除：本地只做集合过滤；library:changed 仍会驱动其他视图 silent refresh */
async function removeMany(bookIds: number[], deleteFile = false): Promise<number[]> {
  const removed = await ipc.library.removeMany(bookIds, deleteFile)
  const idSet = new Set(removed)
  books.value = books.value.filter((b) => !idSet.has(b.id))
  return removed
}
```

返回 `removed` 供页面 toast 精确计数（部分书可能已被别处删除）。

### 8.2 纯函数模块（新建 `src/services/libraryManage.ts` + `libraryManage.test.ts`）

导出 `ManageBookRow` / `CollectionFilter` / `buildManageRows` / `filterManageRows` / `formatAddedAt`。无 DOM、无 IPC 依赖，直接单测（任务 D 第 3 条：纯逻辑下沉 `src/services/`）。

### 8.3 页面（新建 `src/views/LibraryManageView.vue`）

- **数据**：`onMounted → void library.refresh()` + `library.subscribeChanges()`；`onUnmounted → library.unsubscribeChanges()`（与 `LibraryView` 同构，避免离开页面后仍持续 silent refresh）。
- **加载态**：首次进入用 store 的 `loading`（`refresh()` 非 silent）；删除后由 `library:changed` 触发的 silent refresh 不显示骨架屏。
- **错误态**：`refresh` 失败 catch 后展示 `localizeError(e)` + 重试按钮；IPC 删除失败同样按 `IpcError.code` 出提示。
- **派生行**：`rows = computed(() => filterManageRows(buildManageRows(library.books, library.collections), keyword, collectionFilter))`。
- **合集下拉失效兜底**：`watch(() => library.collections, ...)` 校验 `collectionFilter` 是否仍存在，失效回退 `'all'`。
- **删除**：`BatchRemoveDialog` 回传 `deleteFile` → 逐本 `removeFromQueue(id)`（`coverQueue` 既有导出）→ `library.removeMany(selected, deleteFile)` → 清空 `selected` → toast（按 `removed.length` 与 `deleteFile` 组合取文案）。
- **不新增 Pinia store**：页面状态（keyword / collectionFilter / selected / 弹窗开关）均为局部 ref，切走即释放。

### 9.5 空态 / 加载态 / 错误态

- **空态（库为空）**：居中内联 SVG 插画（书堆 + 垃圾桶轮廓，描边风 `var(--text-faint)` + 品牌色点缀，与 `StatsEmptyState` 同风格）+ 文案「书库还是空的」+ `primary`「去书架看看」（`router.push('/')`）。
- **筛选无命中**：列表区单行提示「没有匹配的漫画」，保留工具栏；不显示空态插画，避免误判库为空。
- **加载态**：6 行骨架（`var(--surface-2)` 圆角块 + `pulse 1.4s`，`prefers-reduced-motion` 时关闭动画）。
- **错误态**：居中错误文案 + `primary`「重试」按钮（重新 `library.refresh()`）。

### 9.6 批量删除确认弹窗（`BatchRemoveDialog.vue`）

Props：`{ books: Book[] }`（选中的行）。Emits：`{ cancel: []; confirm: [deleteFile: boolean] }`。

- 标题：「删除所选漫画」
- 正文：「确定从文库移除选中的 N 本漫画吗？」+ 前 5 本书名清单，>5 时追加「等 N 本」
- 提示：「同时删除文件」会把选中的 N 个原文件从磁盘一并删除，且无法恢复；阅读进度与阅读统计会随之清除。
- 按钮顺序：取消 / 仅移除记录 / 同时删除文件（`danger`）；`Esc` 与遮罩点击等同取消。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 批量删文件不可恢复 | 保留该选项，但默认动作为「仅移除记录」，弹窗标注数量与不可恢复提示 | 清理磁盘是真实需求；用文案与默认焦点控制风险，不做二次强确认 |
| 跨筛选保留已选 | 保留 + 「其中 M 本不在当前筛选结果中」提示 + 一键清除 | 误删不可见项的风险由提示兜底；若反馈仍易误操作，可改为「切换条件即清空选择」（只改一个 watch） |
| 单事务同步删除 | 500+ 本一次 `transaction`（better-sqlite3 同步） | 删除仅 1 次 IPC、毫秒级；未来万级库再改分批提交 |
| 事务后删文件失败 | 只 `logger.warn`，不回滚记录 | 最坏是「记录已删、文件残留」，可手工清理；反序会造成不可恢复的文件丢失 |
| 管理页与文库共享 store | `library.books` / `library.collections` 复用 | 少一条数据通道；搜索关键字刻意不复用 `library.keyword`（见 §3.2） |
| 不做虚拟滚动 | 原生滚动 + 固定行高 | 千级以内够用；后续接虚拟列表只需替换列表容器，行组件可原样复用 |
| 不提供批量移入合集 | 本期只做清理 | 与单本「移入合集」职责分离；`selected: number[]` 模型可直接扩展到其他批量动作 |
| 列表不复用 `BookCard` | 新建轻量行结构 | 管理页要高信息密度；`BookCard` 的倾斜 / 浮层 / hover 按钮在批量选择场景反而是干扰 |
| 删除后不清理 `library.changed` 之外的缓存 | 依赖 `library:changed` 驱动各视图 silent refresh | 与现有单本删除一致；管理页自身订阅后列表自动同步 |
