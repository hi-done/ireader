# 多语言界面切换设计方案

> 状态：设计稿（待实现）
> 目标版本：v1.2.6（package.json 当前版本，版本号不变，由用户自行发版时确定）
> 范围：设置页语言选择（跟随系统 / 中文 / English / 日本語）、渲染层全部内置 UI 文案三语化、主进程原生文件对话框过滤器本地化、日期/时长/排序的本地化格式
> 实现约束：遵循 `ireader-dev-tasks`（任务 A/C/D/E/F）与 `ireader-code-conventions`（Result 契约、中文注释、Vitest）；零新增 npm 依赖

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 设置中增加语言选择 | `SettingsView.vue` 新增「通用」分组与语言行，复用现有 `SelectMenu`，四档：跟随系统 / 中文 / English / 日本語 | 设置页第一分组可见语言行；选择后写入 SQLite，重启后保持 |
| 2 | 可切换中文、英文、日文 | 新增 `src/i18n/` 模块：`LocalePreference = 'system' \| 'zh-CN' \| 'en' \| 'ja'`，`AppLocale = 'zh-CN' \| 'en' \| 'ja'`，`resolveLocale()` 统一解析 | 三语言逐页巡检，界面文案与对应语言一致 |
| 3 | 软件除软件名外，内置文字都切换 | 5 个 view + 12 个组件 + service/store 用户可见错误全部走 `t()`；主进程仅原生文件对话框过滤器名需要本地化 | `grep` 审计硬编码中文清单归零（豁免项见 §2）；文件选择对话框过滤器名为对应语言 |
| 4 | 切换后即时生效 | `src/i18n/index.ts` 模块级 `ref`；`src/main.ts` 单点 `watch` + `languagechange` 监听；模板内 `t()` 自动依赖收集 | 不重启切换语言，当前页面（含已打开的阅读器顶/底栏、下拉选项、toast）立即更新 |
| 5 | 日期、时长等派生文案随语言 | `src/i18n/format.ts` 用 `Intl.DateTimeFormat` / `Intl.PluralRules`；`src/services/libraryList.ts` 用 `Intl.Collator` | 统计页 en 显示 `Today` / `46 min`、ja 显示 `今日` / `46分`；星期/月日/排序符合当前语言 |
| 6 | 默认值合理 | `DEFAULT_SETTINGS.locale = 'system'`；`resolveLocale`：`zh*→zh-CN`、`ja*→ja`、其余→`en` | 新装与旧数据升级后均跟随系统；系统语言切换后下次启动生效（运行中经 `languagechange`） |

**核心验收口径**：切换到 English 后，全应用（主页、合集、搜索、设置、统计、PDF/CBZ/EPUB 阅读器、全部弹窗与 toast、原生文件选择器）除 `IReader` 软件名、用户输入的书籍/合集名、第三方引擎（pdf.js / epub.js）错误原文外，不出现任何中文字符；日本語同理；三语言切换均不重启即时生效，重启后保持；时长/日期/复数/排序格式符合各语言习惯。

## 二、非目标（本期不做）

- 不翻译用户数据：书名、合集名、文件路径、Release Notes 均为用户或发布者内容，不属于内置文案。
- 不翻译第三方引擎错误原文（pdf.js / epub.js）：按用户决策原文透传，避免二次包装丢失诊断信息。
- 不翻译代码注释、主进程日志、DEV 诊断面板：开发者可见，保持中文以降低维护成本。
- 不改窗口标题 `IReader v版本号`（软件名，需求明确排除），不改 macOS 系统菜单（Electron 默认菜单随系统语言）。
- 不做繁体中文（zh-TW）、韩文及 RTL 语言；繁体系统暂回退简体中文。
- 不新增 npm 依赖（不引入 vue-i18n）：用户已确认自研轻量模块。
- 不做 DB schema 迁移：`settings` 表为 JSON key-value，新增字段由 `DEFAULT_SETTINGS` merge 补齐。
- 不做语言切换后的历史错误文案回溯刷新（错误快照在发生时刻生成）。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 实现方式 | 自研零依赖 i18n 模块 | 用户确认；文案量约 200 条，不需要 vue-i18n 的组件插值/懒加载/命名空间能力；守住不新增依赖的工程红线 |
| 语言档位 | 四档含「跟随系统」，默认 `system` | 用户确认；覆盖非中文系统用户，系统语言变化可自动跟随；非中/日系统回退英文 |
| 词典结构 | 扁平静态键 + `zh-CN.ts` 作为类型基准 | 编译期发现漏译/多译；`en`/`ja` 用 `satisfies Record<MessageKey, string>` 约束；运行时无查找开销 |
| 状态与响应 | `src/i18n` 模块级 `ref`，`main.ts` 单点 watch | 避免各组件各自监听设置导致重复更新；模板内 `t()` 读取 ref 自动建立依赖，切换语言全站刷新 |
| 持久化 | `Settings.locale`（SQLite settings JSON merge） | 无需 DB 迁移；旧数据自动补默认值；复用既有 `settings:all/patch` 通道 |
| 错误文案 | 渲染层按 `ErrorCode` 映射；第三方错误原文透传 | 用户确认；主进程中文 message 保留作日志与兜底，渲染层不再直接展示 |
| 原生对话框 | 主进程读 `settingsRepo` + `app.getLocale()` 本地化过滤器名 | 唯一必须由主进程产出的内置文案；原生对话框无法由渲染层控制 |
| 排序 | `Intl.Collator(当前语言)`，收敛 5 处硬编码 `zh-Hans-CN` | 英/日界面按对应语言字母序排列；避免 5 处各自实现导致口径不一致 |
| 格式化位置 | `formatDuration` 等迁入 `src/i18n/format.ts`，内部读 `appLocale` | 调用点零参数改动即可获得响应性；统计纯逻辑（取整/连续天数/排行）留在 `readingStats.ts` |

## 四、语言解析与格式化口径（核心）

### 4.1 语言解析 `resolveLocale`

```ts
// shared/types.ts（双进程共用纯函数，保证口径一致）
export const LOCALE_PREFERENCES = ['system', 'zh-CN', 'en', 'ja'] as const
export type LocalePreference = (typeof LOCALE_PREFERENCES)[number]
export type AppLocale = 'zh-CN' | 'en' | 'ja'

export function resolveLocale(preference: LocalePreference, systemLocale: string): AppLocale {
  if (preference !== 'system') return preference
  const tag = systemLocale.toLowerCase()
  if (tag.startsWith('zh')) return 'zh-CN'
  if (tag.startsWith('ja')) return 'ja'
  return 'en' // 其余语言（含空串/非法值）回退英文
}
```

边界场景防护：

| 场景 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 繁体系统 | `preference='system'`, `systemLocale='zh-TW'` | `zh-CN` | 本期只提供简体中文 |
| 日文系统 | `'system'`, `'ja-JP'` | `ja` | 前缀匹配，忽略地区 |
| 其他语言/空值 | `'system'`, `'ko-KR'` / `''` | `en` | 非中/日一律英文 |
| 用户显式选择 | `'zh-CN'` / `'en'` / `'ja'` | 原值 | 偏好优先于系统 |
| 旧数据无字段 | `undefined` | `system` | `settingsRepo.getAll()` 已与 `DEFAULT_SETTINGS` merge |
| 非法持久化值 | `'fr'` | `en` | `settings:patch` 白名单校验拦截；渲染层 `resolveLocale` 对非 system 值需再校验（见 §5.1） |

### 4.2 词典结构与键规范

- 扁平键，点分层级，语义化命名：`settings.general.language`、`library.empty.title`、`reader.prevPage`、`error.FILE_NOT_FOUND`。
- `src/i18n/locales/zh-CN.ts` 导出 `const zhCN = { ... } as const` 与 `export type MessageKey = keyof typeof zhCN`。
- `en.ts` / `ja.ts`：`export const en = { ... } satisfies Record<MessageKey, string>`，漏键/多键编译期报错。
- 插值统一 `{name}` 占位：`t('library.toast.imported', { count, skipped })`；禁止在代码中拼接句子片段（语序因语言而异）。
- 语言名称固定用本地语：`中文` / `English` / `日本語`；「跟随系统」等界面文案随界面语言变化。
- 复数键成对存在：`stats.dayCount.one` / `stats.dayCount.other`。中文与日文无复数变化，`.one` 与 `.other` 写相同值，以保证三词典键集合严格同构、coverage 测试可一刀切。

### 4.3 三语言格式口径

| 场景 | zh-CN | en | ja | 实现 |
|------|-------|----|----|------|
| 时长（统计卡） | `12 小时 30 分` | `12 h 30 min` | `12時間30分` | `formatDuration` |
| 时长不足 1 分 | `<1 分钟` | `<1 min` | `<1分` | `formatDuration` |
| 时长整小时 | `2 小时` | `2 h` | `2時間` | `formatDuration` |
| 紧凑刻度（Y 轴） | `20 分` / `1 时` / `1.5 时` | `20m` / `1h` / `1.5h` | `20分` / `1時間` / `1.5時間` | `formatDurationCompact` |
| 相对日期 | `今天` / `昨天` / `5 天前` | `Today` / `Yesterday` / `5 days ago` | `今日` / `昨日` / `5日前` | `formatRelativeDay` + `tp` |
| 超过 30 天的日期 | `2026/10/21` | `10/21/2026` | `2026/10/21` | `Intl.DateTimeFormat` |
| 星期 | `周一` | `Mon` | `月` | `Intl.DateTimeFormat({ weekday: 'short' })` |
| 月日 | `10月21日` | `Oct 21` | `10月21日` | `Intl.DateTimeFormat({ month: 'short', day: 'numeric' })` |
| 天数 | `3 天` | `3 days` | `3日` | `tp('stats.dayCount', n)` |

> 中文时长中的空格（`12 小时 30 分`）沿用现有实现，避免无关视觉变化；迁移时同步调整现有断言。

### 4.4 复数与排序

```ts
// tp：仅允许存在 .one / .other 的基础键
type PluralBase = { [K in MessageKey]: K extends `${infer Base}.other` ? Base : never }[MessageKey]

export function tp(baseKey: PluralBase, count: number, params?: Record<string, string | number>): string {
  const form = new Intl.PluralRules(locale.value).select(count)
  const dict = dictionaries[locale.value]
  const key = `${baseKey}.${form}` as MessageKey
  return t((key in dict ? key : `${baseKey}.other`) as MessageKey, { count, ...params })
}
```

排序统一收敛到 `src/services/libraryList.ts`：

```ts
const collators = new Map<AppLocale, Intl.Collator>()

export function titleCollator(locale: AppLocale): Intl.Collator {
  let c = collators.get(locale)
  if (!c) {
    // 仅切换 collation，不引入 numeric，保持现有书名排序语义
    c = new Intl.Collator(locale)
    collators.set(locale, c)
  }
  return c
}

export function compareTitles(a: string, b: string, locale: AppLocale): number {
  return titleCollator(locale).compare(a, b)
}
```

- `sortBooks` / `sortCollections` 增加末位参数 `locale: AppLocale = 'zh-CN'`（默认值保持现有测试与调用兼容）。
- `src/stores/library.ts` 的 `filteredBooks` / `sortedCollections` 是排序单点，传 `appLocale.value`，切换语言时 computed 自动重排。
- 其余 4 处独立排序（`LibraryView.vue`、`ReaderView.vue`、`EpubReaderView.vue`、`CollectionCard.vue`）统一改用 `compareTitles(a.title, b.title, appLocale.value)`。

### 4.5 组件响应性口径

模块级常量不会进入 Vue 响应式依赖，切换语言后不会刷新。硬性规则：

1. 所有含文案的 `const XXX_OPTIONS` 改为 `computed(() => [...])`（涉及 `SettingsView`、`LibraryView`、`ReaderView`、`EpubReaderView`）。
2. `withDefaults` 中的默认文案（如 `removeLabel: '从文库移除'`）改为可选 prop + 模板内 `t()` 兜底。
3. 模块级标签常量（`BookCard` 的 `MOVE_LABEL` / `RENAME_LABEL`、`DailyBarChart` 的 `WEEK`）改为 `computed` 或 `Intl` 函数调用。
4. `SelectMenu` 的 `aria-label` 由字符串拼接改为 `t('common.labelValue', { label, value })`，冒号随语言。

## 五、数据模型

### 5.1 共享类型（`shared/types.ts`）

```ts
/** 界面语言偏好；system = 跟随操作系统语言 */
export const LOCALE_PREFERENCES = ['system', 'zh-CN', 'en', 'ja'] as const
export type LocalePreference = (typeof LOCALE_PREFERENCES)[number]
/** 实际生效的界面语言（不含 system） */
export type AppLocale = 'zh-CN' | 'en' | 'ja'

export interface Settings {
  // ...现有字段不变
  /** 界面语言偏好 */
  locale: LocalePreference
}

export const DEFAULT_SETTINGS: Settings = {
  // ...现有字段不变
  locale: 'system',
}

/**
 * 解析生效语言：system 按系统语言前缀匹配，中文/日文以外回退英文。
 * 双进程共用（主进程 app.getLocale() / 渲染层 navigator.language）。
 */
export function resolveLocale(preference: LocalePreference, systemLocale: string): AppLocale
```

`resolveLocale` 内对 `preference` 再做一次白名单兜底：非 `system` 且不在 `['zh-CN','en','ja']` 内时回退 `en`，防止持久化脏数据导致 `dictionaries[locale]` 为 undefined。

### 5.2 持久化与兼容

- `settings` 表结构不变（`key` / `value` JSON），**无 DB 迁移**。
- `settingsRepo.getAll()` 已执行 `{ ...DEFAULT_SETTINGS, ...JSON.parse(row.value) }`，旧数据自动获得 `locale: 'system'`；JSON 解析失败同样回退默认值。
- `settingsRepo.patch()` 整体 JSON 写回，新增字段随 `Partial<Settings>` 落库，无需改 repo。
- 渲染层 `settingsStore.settings` 类型自动获得 `locale`，无需改 store 结构。

## 六、IPC 契约

### 6.1 通道变更（无新增通道）

| 通道 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `settings:all` | 无 | `Result<Settings>` | 返回值新增 `locale` 字段；旧渲染层忽略未知字段不受影响 |
| `settings:patch` | `Partial<Settings>` | `Result<Settings>` | 接受并校验 `locale`；其余字段行为不变 |
| `dialog:pickBookFiles` | 无 | `Result<string[] \| null>` | 过滤器名称按主进程当前语言产出，行为与返回值不变 |

服务层校验规则（`settings:patch` handler 编排层）：

```ts
ipcMain.handle('settings:patch', wrap((partial: Parameters<typeof settingsRepo.patch>[0]) => {
  if (partial.locale !== undefined && !LOCALE_PREFERENCES.includes(partial.locale)) {
    throw { code: 'INVALID_PARAMS', message: 'locale 取值无效' }
  }
  return settingsRepo.patch(partial)
}))
```

- `wrap` 已支持捕获 `throw { code, message }` 并转 `fail(code, message)`，无需新增基础设施。
- 主进程 message 为中文日志/兜底文案；渲染层不再直接展示，按 `ErrorCode` 映射。

### 6.2 ErrorCode 本地化映射（`src/i18n/errors.ts`）

| ErrorCode | zh-CN | en | ja |
|-----------|-------|----|----|
| `FILE_NOT_FOUND` | 文件不存在或已被移动 | File not found or moved | ファイルが見つからないか、移動されています |
| `PDF_INVALID` | PDF 文件无效或已损坏 | Invalid or corrupted PDF | PDF が無効か破損しています |
| `PDF_ENCRYPTED` | 该 PDF 已加密，暂不支持打开 | Encrypted PDF is not supported | 暗号化された PDF には対応していません |
| `PATH_EXISTS` | 目标位置已存在同名文件 | A file with the same name already exists | 同名のファイルが既に存在します |
| `INVALID_PARAMS` | 参数无效 | Invalid parameters | パラメータが無効です |
| `DB_ERROR` | 数据库操作失败 | Database operation failed | データベース操作に失敗しました |
| `UPDATER_UNAVAILABLE` | 当前环境不支持检查更新 | Updates are not available in this environment | この環境では更新を確認できません |
| `UPDATER_FAILED` | 检查更新失败，请检查网络后重试 | Failed to check for updates. Check your network and try again | 更新の確認に失敗しました。ネットワークを確認して再試行してください |
| `UNKNOWN` | 发生未知错误 | An unknown error occurred | 不明なエラーが発生しました |

```ts
// 渲染层统一错误入口
export function localizeError(e: unknown): string {
  if (e instanceof IpcError) return t(`error.${e.code}` as MessageKey) // 词典缺键时 t() 回退 error.UNKNOWN
  if (e instanceof Error) return e.message // 第三方引擎原文透传
  return String(e)
}
```

- `t()` 找不到键时回退规则：当前语言 → `zh-CN` → `error.UNKNOWN`，保证不出现裸键名。
- 更新功能的细分失败原因（如“请先检查更新”）不在 `ErrorCode` 内，渲染层沿用状态分支文案（`settings.update.*`），不再读取主进程 message。

## 七、主进程实现

### 7.1 新建 `electron/services/appLocale.ts`

```ts
import { app } from 'electron'
import { DEFAULT_SETTINGS, resolveLocale, type AppLocale } from '../../shared/types'
import { settingsRepo } from '../db/repos/settingsRepo'

/** 主进程当前界面语言：用户偏好优先，system 档读取 app.getLocale() */
export function getAppLocale(): AppLocale {
  const { locale } = settingsRepo.getAll()
  return resolveLocale(locale ?? DEFAULT_SETTINGS.locale, app.getLocale())
}

/** 原生文件对话框过滤器名称（三语言） */
export function getBookFilesFilterName(): string {
  const names: Record<AppLocale, string> = {
    'zh-CN': '书籍与漫画',
    en: 'Books & Comics',
    ja: '書籍とコミック',
  }
  return names[getAppLocale()]
}
```

- 调用时机均在 app ready 且数据库初始化之后（`dialog:pickBookFiles` 由用户操作触发），`settingsRepo` 可用。
- 每次打开对话框实时读取设置，语言切换后无需重启或缓存失效逻辑。

### 7.2 `electron/ipc/handlers.ts` 改动

## 八、渲染层实现

### 8.1 i18n 内核（`src/i18n/index.ts`）

```ts
import { computed, ref } from 'vue'
import { resolveLocale, type AppLocale } from '../../shared/types'
import { zhCN, type MessageKey } from './locales/zh-CN'
import { en } from './locales/en'
import { ja } from './locales/ja'

const dictionaries: Record<AppLocale, Record<MessageKey, string>> = {
  'zh-CN': zhCN,
  en,
  ja,
}

const locale = ref<AppLocale>(resolveLocale('system', navigator.language))

/** 当前生效语言（只读） */
export const appLocale = computed(() => locale.value)

/** 切换语言并同步 <html lang>（驱动日文字体栈与断词规则） */
export function setLocale(next: AppLocale): void {
  locale.value = next
  if (typeof document !== 'undefined') document.documentElement.lang = next
}

/** 取词并插值；缺失键按 当前语言 → zh-CN → 键名 回退 */
export function t(key: MessageKey, params?: Record<string, string | number>): string {
  const template = dictionaries[locale.value][key] ?? zhCN[key] ?? key
  if (!params) return template
  return template.replace(/\{(\w+)\}/g, (match, name: string) =>
    name in params ? String(params[name]) : match
  )
}

export function tp(baseKey: PluralBase, count: number, params?): string
```

要点：

- 初始值用 `resolveLocale('system', navigator.language)`，`main.ts` 在设置加载后覆盖；避免首屏空白。
- `typeof document !== 'undefined'` 防御：Vitest 默认 node 环境无 DOM，单测可直接调用 `setLocale`。
- `setLocale` 只写 ref 与 `<html lang>`，不碰持久化；持久化唯一入口是设置页 `settingsStore.patch`。

### 8.2 启动接线（`src/main.ts`）

现有文件为同步 `createApp(...).mount('#app')`。改为：

```ts
async function bootstrap() {
  const pinia = createPinia()
  const settingsStore = useSettingsStore(pinia) // 必须在 mount 前传入 pinia 实例
  try {
    await settingsStore.load()
  } catch {
    // 主进程不可用时以默认设置启动，避免白屏
  }
  setLocale(resolveLocale(settingsStore.settings.locale, navigator.language))

  watch(
    () => settingsStore.settings.locale,
    (preference) => setLocale(resolveLocale(preference, navigator.language))
  )
  window.addEventListener('languagechange', () => {
    if (settingsStore.settings.locale === 'system') {
      setLocale(resolveLocale('system', navigator.language))
    }
  })

  createApp(App).use(pinia).use(router).mount('#app')
}

void bootstrap()
```

- `tsconfig` target 为 ES2020，不能使用 top-level await，故用 `async function` + `void`。
- 全局 `error` / `unhandledrejection` 监听保持在文件顶部原样。
- 设置加载失败时以 `DEFAULT_SETTINGS`（`system`）启动，不阻塞应用。

### 9.2 交互行为

1. 选择语言 → `save()` → `settingsStore.patch({ ...form })` → 主进程落库并返回新设置 → `watch` 触发 `setLocale` → 全站即时刷新。
2. 无确认弹窗、无重启提示；与现有设置项（主题/阅读模式）一致的静默保存语义。
3. `patch` 失败时保持原语言（`settingsStore.settings` 未更新），不弹错误；与现有设置项一致。
4. 已打开的下拉菜单若在切换语言瞬间展开，选项文案随重渲染更新（computed 重新求值）。

7. **错误路径**：删除书籍原文件后打开 → 本地化“文件不存在”；损坏 PDF → 本地化 PDF 错误；EPUB HTTP 失败 → 本地化前置提示 + 引擎原文。
8. **更新路径**：开发模式检查更新 → 本地化 `UPDATER_UNAVAILABLE` 文案；模拟下载失败 → 本地化重试文案。
9. **布局适配**：900px / 1280px 窗口宽度 × 浅/深主题 × 三语言，检查设置页标签换行、阅读器顶栏按钮、统计卡不溢出。
10. **日文字形**：日本語界面下确认汉字为日文字形（`<html lang="ja">` 与字体栈生效）。
11. **审计**：`grep` 扫描 `src/` 中 `[\u4e00-\u9fa5]`，确认剩余中文仅注释、日志、`zh-CN.ts` 词典本身。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|-----------|
| 默认跟随系统 | 老用户升级后界面语言可能变化（如英文系统变英文） | 用户已确认；设置页可随时改回中文，改动即时生效 |
| 自研 i18n | 无 vue-i18n 的生态能力（懒加载、命名空间、复数引擎） | 用类型同构 + coverage 测试保证完整性；将来需要高级能力可在 `src/i18n/index.ts` 内部替换实现，调用方不变 |
| 模块级常量 | 含文案的常量必须改 computed，否则切换不刷新 | 已在 §8.6 列全；实施后以“切换语言不刷新”为缺陷重点排查 |
| 英文文案膨胀 | 长标签在 180px 固定列宽下换行/挤压 | `.row-label` 改弹性宽度；冒烟覆盖 900px 窗口；不追求单行省略号，允许换行 |
| 主进程错误仍为中文 | message 保留作日志/兜底，渲染层按 code 映射 | 未知 code 显示通用文案；细分原因可能丢失，将来可给 `AppError` 增加 `i18nKey` 扩展 |
| 第三方错误原文 | pdf.js / epub.js 英文错误直接展示 | 用户已确认；前置提示已本地化，不影响定位问题 |
| 错误快照不回溯 | `loadError` 在发生时刻本地化，之后切语言不刷新 | 错误是一次性状态，返回重进即可刷新；接受该偏差 |
| 排序 collation 随语言 | 中文书名在 en/ja 界面按字母/假名序，顺序与中文界面不同 | 符合当前界面语言习惯；不引入 `numeric`，保持现有数字排序语义 |
| 日文字形 | Han unification 下需 `lang='ja'` + 日文字体栈 | 已在 `style.css` 单点处理；Linux 缺字体时回退 `Noto Sans JP` |
| 繁体系统 | `zh-TW` 回退简体中文 | 本期不做 zh-TW；词典结构支持后续直接新增 `zh-TW` |
| 翻译质量 | 直译易生硬，尤其日文长句与英文按钮缩写 | 实施时按术语表统一（书籍/合集/阅读进度等）；完成后人工通读三语言 |
| Vitest 环境 | 默认 node 环境无 DOM | `setLocale` 内部做 `typeof document` 防御；不引入 jsdom 依赖 |
