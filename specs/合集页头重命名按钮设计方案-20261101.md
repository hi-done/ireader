# 合集页头重命名按钮设计方案

> 状态：已实现（M1~M4 完成：`npm run typecheck` / `npm test` 通过，手工冒烟已验证）
> 目标版本：v1.4.2（版本号沿用当前 package.json，具体发版由用户决定）
> 范围：合集视图页头新增「重命名」按钮 + 重命名对话框 + `collection:rename` IPC 能力
> 实现约束：遵循 `ireader-dev-tasks`（任务 A/D/F）与 `ireader-code-conventions`（Result 契约、中文注释、双进程共享类型）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 合集页面工具栏右上角增加重命名按钮 | `LibraryView.vue` 合集页头 `.collection-head` 内新增 `ghost` 文字按钮，位于「解散合集」左侧，二者并排 | 进入任一合集，页头右上角出现「重命名」「解散合集」两个按钮，间距与现有页头一致 |
| 2 | 与解散合集按钮并列 | 复用 `.collection-head` 的 `display:flex; gap:20px`（style.css 单点定义），按钮自身只加 `flex-shrink:0` | 窗口从 1200px 缩到 1000px，两按钮不换行、不被压缩变形 |
| 3 | 点击后可修改合集名称 | 复用 `TextPromptDialog.vue`（与「新建合集」同一组件），初始值 = 当前合集名，自动聚焦并全选 | 点击「重命名」弹出对话框，输入框预填当前名称且文本已选中 |
| 4 | 改名结果持久化并即时生效 | 新增 IPC `collection:rename`，store `renameCollection` 局部 patch `collections` | 改名后页头标题、主页合集卡片书名立即更新；退出重进应用后名称仍为新值 |

**核心验收口径**：在合集页点击「重命名」→ 输入新名称 → 确认，页头标题与主页对应合集卡片书名在同一帧内变为新名称，且无整页 loading 闪烁；重启应用后名称保持。

## 二、非目标（本期不做）

- 不在主页合集卡片、文库管理页加入重命名入口（已与用户确认，仅合集页工具栏）。
- 不提供图标按钮或「更多」聚合菜单（已确认采用与「解散合集」一致的文字按钮并排）。
- 不做重名冲突校验（已确认保持与「新建合集」一致：`trim` 后非空即可，DB 层 `collections.title` 无 UNIQUE 约束）。
- 不改动 `collections` 表结构、不新增 DB 迁移。
- 不修正 `collection:create` / `collection:list` 返回 DB 行（`created_at`）与 `Collection.createdAt` 命名不一致的既有问题，仅在本方案中规避其副作用（见 §13）。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ───────────────────────────────────────────────────────┐
│ LibraryView.vue（合集视图页头）                                │
│   「重命名」按钮 → askRenameCollection()                       │
│          │ 打开 TextPromptDialog（initialValue = 当前合集名）   │
│          ▼                                                     │
│   confirmRenameCollection(title)                               │
│          │ useLibraryStore().renameCollection(id, title)       │
│          ▼                                                     │
│ library store：collections 局部 patch 指定 id 的 title          │
│          │ ipc.collection.rename(id, title)                    │
└──────────┼─────────────────────────────────────────────────────┘
           ▼
┌─ 主进程 ───────────────────────────────────────────────────────┐
│ handlers.ts：collection:rename（trim 校验 → 空名抛 INVALID_PARAMS）│
│          ▼                                                     │
│ collectionsRepo.rename(id, title)：UPDATE + SELECT 回读         │
│          ▼                                                     │
│ SQLite collections 表（既有 title 列，无迁移）                  │
└────────────────────────────────────────────────────────────────┘
```

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 按钮形态 | 与「解散合集」一致的 `ghost` 文字按钮，放在其左侧 | 已验证页头布局为右侧按钮区（`.collection-head-info` 用 `flex:1` 顶开），追加同级按钮零布局成本；文字按钮自解释，无需悬停提示（符合「自带可见文字的控件不加悬停提示框」约定） |
| 输入方式 | 复用 `TextPromptDialog.vue` | 与「新建合集」「重命名书」完全同一交互与校验入口（组件内已 `trim` + 空值禁用确认按钮），不新造对话框 |
| IPC 返回 | 返回 repo 回读的合集行（与 `collection:create` 同形） | 保持合集域通道返回形态一致；渲染层只消费 `id` / `title` |
| store 更新方式 | 只 patch 命中的那条合集的 `title`，不整条替换 | 现有 `collection:list` 实际返回 `created_at`（渲染层类型声明为 `createdAt`），整条替换会把对象已有字段结构改掉；局部 patch 不扩大既有不一致的影响面（§13） |
| 是否需要广播 `library:changed` | 不需要 | 与 `collection:remove` / `collection:create` 现状一致：合集变更由 store 本地同步，`library:changed` 只服务书库数据变更；避免整页 silent refresh 造成无谓刷新 |
| 空名/重名校验 | 仅主进程校验非空，允许重名 | 与「新建合集」口径统一，不新增 ErrorCode 与三语言错误文案，改动面最小 |

## 四、交互口径与边界防护

### 4.1 交互口径

```
[← 返回]  合集名  合集 · 12 本 · 按名称排序        [重命名]  [解散合集]
```

- 「重命名」「解散合集」右侧对齐，间距沿用页头 `gap: 20px`；「解散合集」保持 `danger-text`，重命名用普通 `ghost`（与正在进行的解散二次确认文案相邻时视觉上主次清晰）。
- 对话框：标题「重命名合集」，初始值 = 当前合集名，占位符「输入合集名称」，空值或全空格时确认按钮禁用（组件既有行为）。
- 成功后 toast：`已将合集重命名为「{title}」`；页头标题、`library.collection.meta` 数量文案、主页合集卡片书名同步更新。
- 取消（点「取消」按钮 / 点遮罩空白处）不产生任何状态变更；`TextPromptDialog` 无 Esc 监听，本期不新增。

### 4.2 边界场景防护

| 场景 | 处理 |
|------|------|
| 输入为空或纯空格 | 对话框确认按钮禁用；主进程二次校验（`trim` 为空抛 `INVALID_PARAMS`） |
| 名称未变化（输入与原名相同） | 不做特殊判断，照常提交并 toast；避免多一条「无变化」分支与文案 |
| 对话框打开期间该合集在别处被解散 | 确认时 `ipc.collection.rename` 命中 0 行 → 主进程回 `INVALID_PARAMS`，渲染层 catch 后 toast 错误文案并关闭对话框；页头 `activeCollection` 变 null 自然回主页（既有行为） |
| 解散按钮已进入二次确认态（3s 内） | 打开重命名对话框不影响该计时器；对话框为模态遮罩，无法误触解散 |
| 重命名后回到主页再进入 | 名称取自 `library.collections`，已更新；URL query（`?collection=<id>`）不含名称，无需修改 |

## 五、数据模型

无 schema 变更，复用既有 `collections` 表（v2 迁移，`title TEXT NOT NULL`）：

```sql
-- 仅新增读写语句，不新增迁移项
UPDATE collections SET title = ? WHERE id = ?;
SELECT * FROM collections WHERE id = ?;
```

`electron/db/repos/collectionsRepo.ts` 新增方法（与 `booksRepo.rename` 同风格）：

```ts
/**
 * 重命名合集
 * @returns 更新后的合集行；合集不存在（已被解散）时返回 undefined
 */
rename(id: number, title: string): CollectionRow | undefined {
  const db = getDatabase()
  const { changes } = db.prepare('UPDATE collections SET title = ? WHERE id = ?').run(title, id)
  if (!changes) return undefined
  return db.prepare('SELECT * FROM collections WHERE id = ?').get(id) as CollectionRow
}
```

## 六、IPC 契约

`shared/types.ts` **不需要**新增类型（复用既有 `Collection`）；`ErrorCode` **不需要**扩展（复用 `INVALID_PARAMS`）。

| 通道 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `collection:rename` | `{ id: number; title: string }` | `Result<Collection>` | 合集重命名；`title` 由主进程 `trim`，空串抛 `INVALID_PARAMS`（message：合集名不能为空）；合集不存在时抛 `INVALID_PARAMS`（message：合集不存在） |

服务层校验规则（落在 handler，因合集域无 service 层，与 `collection:create` / `collection:remove` 同构）：

1. `title.trim()` 为空 → `throw { code: 'INVALID_PARAMS', message: '合集名不能为空' }`；
2. `collectionsRepo.rename` 返回 `undefined` → `throw { code: 'INVALID_PARAMS', message: '合集不存在' }`。

## 七、主进程实现

- `electron/db/repos/collectionsRepo.ts`：新增 `rename`，只做 UPDATE + 回读，不含校验（repo 层保持纯 SQL）。
- `electron/ipc/handlers.ts`：在 `collection:remove` 之后新增
  ```ts
  ipcMain.handle(
    'collection:rename',
    wrap(({ id, title }: { id: number; title: string }) => {
      const trimmed = String(title ?? '').trim()
      if (!trimmed) throw { code: 'INVALID_PARAMS', message: '合集名不能为空' }
      const updated = collectionsRepo.rename(id, trimmed)
      if (!updated) throw { code: 'INVALID_PARAMS', message: '合集不存在' }
      return updated
    })
  )
  ```
  handler 仍只做「校验 + 调用 + 返回」，不写业务规则。不调用 `notifyLibraryChanged`（理由见 §3.2）。
- `electron/preload.ts`：`collection` 域新增 `rename: (id: number, title: string): Promise<Result<Collection>> => ipcRenderer.invoke('collection:rename', { id, title })`。

## 八、渲染层实现

按 `ireader-dev-tasks` 任务 A 第 4~5 步、任务 D 归属：

1. `src/services/ipc.ts`：`collection` 域新增 `rename: (id: number, title: string) => unwrap(api().collection.rename(id, title))`，与 preload 同构。
2. `src/stores/library.ts`：新增
   ```ts
   /** 重命名合集：只 patch 命中的标题，保留对象既有字段（collection:list 返回 DB 行，整条替换会丢结构） */
   async function renameCollection(id: number, title: string) {
     const updated = await ipc.collection.rename(id, title)
     collections.value = collections.value.map((c) => (c.id === id ? { ...c, title: updated.title } : c))
   }
   ```
   并在 `return { ... }` 中导出 `renameCollection`（与 `createCollection` / `dissolveCollection` 相邻）。
3. `src/views/LibraryView.vue`：
   - 页头新增按钮：`<button class="ghost head-action" @click="askRenameCollection">{{ t('library.collection.rename') }}</button>`，置于「解散合集」之前；`scoped` 新增 `.head-action { flex-shrink: 0 }`；`script` 区在「解散合集」段落前新增 `renamingCollection` / `askRenameCollection` / `confirmRenameCollection`；
   - 新增 `<TextPromptDialog v-if="renamingCollection" ...>`（与「新建合集」对话框相邻），`initial-value` 取当前合集名；
   - 失败处理：`confirmRenameCollection` 内 `try/catch`，`e instanceof IpcError ? localizeError(e) : t('error.UNKNOWN')` 走 toast（需要新增 `IpcError` / `localizeError` 的 import，`src/i18n/errors.ts` 已提供 `localizeError`）。
   - `activeCollection` 是 `computed`（从 `library.collections` 派生），标题随 store patch 自动更新，无需额外同步。
4. `src/i18n/locales/zh-CN.ts` / `en.ts` / `ja.ts`：三语言同步新增 4 个键（必须三语言键集合相等，由 `i18n.test.ts` 强制）：

   | 键 | zh-CN | en | ja |

   | `library.collection.renameTitle` | 重命名合集 | Rename collection | コレクション名を変更 |
   | `library.collection.renamePlaceholder` | 输入合集名称 | Enter collection name | コレクション名を入力 |

   新建合集的 `library.newCollection.placeholder`（输入合集名称）可复用，但为避免「新建」与「重命名」文案将来分化，仍单独建 `renamePlaceholder`。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 合集域无 service 层 | 校验写在 `handlers.ts` | 与 `collection:create` / `collection:remove` 现状一致，不为单条通道新建 service；若后续合集域能力增多，再抽出 `collectionsService` |
| 不广播 `library:changed` | 由 store 局部 patch 同步 | 避免整页 silent refresh；代价是若将来出现「多个窗口同时打开同一合集」的场景需补广播，属可扩展点 |
| 已有 `created_at` ↔ `createdAt` 命名不一致 | 本方案只 patch `title`，不整体替换合集对象，也不修正类型 | 该不一致会让「按添加时间」排序对合集取到 `undefined`（`libraryList.sortCollections` 读 `a.createdAt`），属既有问题；在本方案内不扩大范围，避免波及卡片与排序链路；将来修时需同时调整 `handlers.ts` 的 create/list/rename 返回映射 |
| 允许重名 | 仅校验非空 | 与新建合集口径统一；若后续要求唯一性，需 DB 加唯一索引（迁移）+ 新 ErrorCode + 三语言文案 |
| 错误码复用 `INVALID_PARAMS` | 不为「合集不存在」新增 ErrorCode | 该场景只在并发解散时出现，错误文案对用户已足够（「参数错误」）；新增码需三端映射成本，收益低 |
