# 阅读页返回自动退出全屏设计方案

> 状态：已验证通过（2026-11-05）：全屏阅读页返回后主页已退出全屏、阅读页内切书与刷新保持全屏、非阅读页 Esc 兜底生效；`typecheck` 通过，`npm test` 29 文件 / 440 用例全绿
> 目标版本：沿用 package.json 当前 `1.4.2`，实际发版号由你自行确定
> 范围：阅读页（PDF / EPUB）全屏态下离开阅读页时的全屏收尾，以及非阅读页的 Esc 兜底出口
> 实现约束：遵循 `ireader-dev-tasks`（任务 E：渲染层功能接线）与 `ireader-code-conventions`（纯逻辑下沉可单测、中文注释、共享类型只进 `shared/types.ts`、不新增依赖）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 全屏阅读页按顶栏「← 返回」回到主页后，窗口仍全屏 | `src/router/index.ts` 新增 `beforeEach` 守卫：目标路由不是阅读页且当前全屏 → `exitFullscreen()`（复用 `services/fullscreen.ts` 单例，不新增状态源） | 全屏阅读页点返回 → 进入主页 500ms 内窗口退出全屏，系统标题栏与最小化 / 最大化 / 关闭按钮恢复 |
| 2 | 「连缩小按钮都没有」：非阅读页无任何退出全屏入口 | 由 #1 从根上消除：全屏只属于阅读页，主页永不处于全屏，故不需要缩小按钮（用户已确认不加主页按钮） | 遍历主页 / 合集视图 / 设置 / 统计 / 批量管理 / AI 配置：均不存在全屏入口，也不存在全屏落点 |
| 3 | 从合集进入的书返回合集视图时同样要收尾 | 守卫只按「目标路由名是否为 `reader`」判定，与 `?cid=` 无关 | 全屏阅读页（带 `?cid=`）点返回 → 合集视图非全屏 |
| 4 | 阅读页内切书 / 刷新不得误退全屏 | 纯函数 `isFullscreenOutsideReader()` 对 `to.name === 'reader'` 恒返回 `false` | 全屏下点「上一本 / 下一本」、或 F5 刷新阅读页：仍保持全屏 |
| 5 | 非阅读页若因系统级原因处于全屏，需有键盘出口 | `src/App.vue` 统一挂一处 `keydown`：非阅读页 + 全屏时 Esc → `exitFullscreen()`（对应《20261103-AI选词工具栏隐藏与Esc优先级修复设计方案》§12 记录的扩展点） | 人为让窗口在全屏态停在主页 → 按 Esc → 退全屏；非全屏时按 Esc 无任何副作用 |

**核心验收口径**：全屏阅读页点顶栏「← 返回」→ 进入主页 → 500ms 内窗口退出全屏且系统窗口按钮可用；全屏阅读页内「上一本 / 下一本」与刷新仍保持全屏；在主页 / 设置 / 统计 / 管理 / AI 配置任意页面按 Esc，非全屏时零副作用、全屏时只退全屏不跳路由。

## 二、非目标（本期不做）

- **不**在文库主页工具栏新增全屏 / 退出全屏按钮：主页本无全屏入口，修好后非阅读页不会再处于全屏；新增按钮会引入「主页全屏 → 进入设置被强制退出」的语义歧义（用户已确认）。
- **不**改 `src/services/fullscreen.ts` 的状态机：`isFullscreen` 单例、乐观置位、`selfExit` / `exitedFullscreenRecently()` 一律保持，守卫只读不新增第二个真相。
- **不**改两个阅读视图的 `goBack()` 与 `resolveReaderEsc()` 优先级：顶栏返回、错误态返回、Esc 非全屏分支、浏览器后退全部经由路由跳转，由守卫单点覆盖。
- **不**改主进程 / IPC 契约 / DB / i18n：复用既有 `window:setFullscreen`，无新增文案（Esc 兜底无提示）。
- **不**做「离开阅读页后恢复进入前的全屏态」：不存在非阅读页全屏入口，无恢复对象。
- **不**新增任何 npm 依赖，不引入网络资源。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ─────────────────────────────────────────────────────────────────┐
│ src/router/index.ts                                                      │
│   beforeEach(to) ──► isFullscreenOutsideReader(to.name, isFullscreen)    │
│                              │ true                                      │
│                              ▼                                           │
│                     void exitFullscreen()   ← 乐观置位 + 下发（不 await） │
│                                                                          │
│ src/App.vue                                                              │
│   window keydown(Escape) ──► isFullscreenOutsideReader(route.name, …)    │
│                              │ true                                      │
│                              ▼                                           │
│                     void exitFullscreen()                                │
│                                                                          │
│ services/fullscreenRoute.ts（新增，纯函数 / 无副作用）                    │
│   isFullscreenOutsideReader(routeName, fullscreen): boolean              │
│                                                                          │
│ services/fullscreen.ts（既有单例，不改）                                  │
│   isFullscreen（只读 ref） / exitFullscreen()                             │
└──────────────────────────────────┬───────────────────────────────────────┘
                                   │ ipc.window.setFullscreen(false)
                                   ▼
┌─ 主进程（零改动） ───────────────────────────────────────────────────────┐
│ handlers.ts: window:setFullscreen → win.setFullScreen(false)             │
│ main.ts: leave-full-screen → window:fullscreenChanged                    │
└──────────────────────────────────────────────────────────────────────────┘
```

时序（点返回）：

```
click ← 返回 → router.push('/') → beforeEach 判定（全屏 + 非 reader）
            → exitFullscreen()：state=false 置位，selfExit=true（不计「刚退过全屏」）
            → ipc.window.setFullscreen(false) → 主进程 setFullScreen(false)
            → 'leave-full-screen' → window:fullscreenChanged({fullscreen:false}) 幂等校正
```

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 收尾点位置 | 路由守卫单点（`router.beforeEach`），不在两个阅读视图的 `goBack()` 里各写一次 | 阅读页有 4 类出口（顶栏返回、错误态返回、Esc 非全屏分支、浏览器后退），逐处接必漏；读 `to.name` 一处覆盖全部，且 PDF / EPUB 零改动 |
| 退出范围 | 目标路由**不是阅读页**即退全屏（而非仅「来源是阅读页」） | 语义收敛为「全屏只属于阅读场景」，顺带兜住系统级 / 状态残留的全屏；比 `from.name === 'reader'` 少一个可失效条件（用户已确认） |
| 守卫阶段 | `beforeEach` 而非 `afterEach` | 退出请求与导航同时发出，主页不会先以全屏尺寸渲染一帧再收缩，观感更接近「窗口还原即页面到位」 |
| 是否 await 退出 | `void exitFullscreen()` 不阻塞导航 | 全屏是窗口态，不影响路由渲染；`exitFullscreen()` 内部已校验「已是目标态就直接 return」，重复调用幂等 |
| Esc 兜底落点 | `App.vue` 挂一处 `keydown`，复用同一纯函数 | 阅读页 Esc 由 `resolveReaderEsc()` 在视图内消费，`route.name === 'reader'` 时直接放行，二者不重叠；纯函数保证路由与按键判定同一口径 |
| 判定下沉 | 新增 `src/services/fullscreenRoute.ts` 纯函数 | 与 `readerEsc.ts` 同风格：可在 node 环境单测，避免把条件散在 router 与 App.vue 两处 |
| 主页按钮 | 不加 | 修复后非阅读页不会全屏，按钮无消费者；规则保持单一（用户已确认） |

## 四、核心口径（`src/services/fullscreenRoute.ts`）

```ts
/** 排除阅读页后，当前是否仍处于全屏：全屏只属于阅读场景，其余页面不该保持全屏 */
export function isFullscreenOutsideReader(
  routeName: string | symbol | null | undefined,
  fullscreen: boolean
): boolean {
  if (!fullscreen) return false
  return routeName !== 'reader' // 阅读页内切书 / 刷新 / 加载失败态都保持在 reader
}
```

调用点（两处，同一份判定）：

```ts
// src/router/index.ts
router.beforeEach((to) => {
  if (isFullscreenOutsideReader(to.name, isFullscreen.value)) void exitFullscreen()
})

// src/App.vue
function onGlobalEscape(e: KeyboardEvent): void {
  if (e.key !== 'Escape') return
  if (!isFullscreenOutsideReader(route.name, isFullscreen.value)) return
  void exitFullscreen() // 不 preventDefault：非全屏时完全不拦截
}
```

边界场景防护：

| 场景 | 行为 | 说明 |
|------|------|------|
| 全屏阅读页 → 顶栏返回（无 `?cid=`） | 路由到 `/`，退全屏 | 需求 1 |
| 全屏阅读页 → 返回（带 `?cid=`） | 路由到 `/?collection=<id>`，退全屏 | 守卫不看 query，只看路由名 |
| 全屏阅读页 → 「上一本 / 下一本」 | `reader` → `reader`，保持全屏 | 需求 4 |
| 全屏阅读页 → F5 刷新 | 初始导航 `to.name === 'reader'`，保持全屏 | 同一条判定 |
| 阅读页加载失败态点「返回文库」 | 走 `goBack()` → 守卫退全屏 | 错误态同样覆盖 |
| 阅读页 Esc（非选词、非全屏） | 返回文库时已非全屏，守卫空跑 | 与 `readerEsc` 无冲突 |
| 阅读页全屏下选词 + Esc | 视图内只退选词，不跳路由 | 守卫不参与 |
| 非阅读页（人为全屏）按 Esc | 只退全屏，不改变当前路由 | 需求 5 |
| 非阅读页非全屏按 Esc | 完全不拦截（不 `preventDefault`、不跳转） | 不影响 `SelectMenu` 收起、批量删除弹窗取消等既有 Esc 语义 |
| 启动首屏即全屏 | 首次导航落在 `getFullscreen()` 回填之前则放行；回填后由 Esc 兜底或下一次导航纠正 | 主进程不持久化全屏，实际不会出现；不为该极端场景在启动链路加分支 |
| 退出全屏 IPC 失败 | `setFullscreen` 内部回滚 `isFullscreen` 并 `console.warn` | 既有行为，不弹提示 |

## 五、渲染层实现

| 文件 | 接线 |
|------|------|
| `src/services/fullscreenRoute.ts` | **新增**：`isFullscreenOutsideReader()`（§4），无 IPC 依赖，可被 node 环境单测直接引入 |

## 六、页面 / 交互设计

```
全屏阅读页                          点击 ← 返回                 主页 / 合集视图
┌──────────────────────────┐      ┌──────────────────────┐    ┌──────────────────────────┐
│ ←书  ‹上 下一›  工具条 ⛶ │      │  路由切到 /          │    │ 系统标题栏（最小化/最大化）│
├──────────────────────────┤ ───▶ │  同时下发退全屏       │ ─▶ ├──────────────────────────┤
│        页面画面           │      └──────────────────────┘    │  工具栏 搜索/排序/设置    │
│                          │                                  │  书卡网格（非全屏）       │
└──────────────────────────┘                                  └──────────────────────────┘
```

- 无新增动效与文案：退全屏沿用 Windows / macOS 原生窗口还原动画，路由切换本身无过渡。
- 视觉过渡期可能有一帧主页按全屏尺寸布局，属窗口还原动画的自然表现，不阻塞交互、无需遮罩。
- 空态 / 加载态 / 错误态不受影响：判定只看路由名与全屏态，与页面内容无关。
- macOS 无标题栏窗口（`titleBarStyle: hidden`）红绿灯常驻，退全屏后位置不变；Esc 兜底与阅读页现有 Esc 语义一致，不做平台分支。

## 十、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 全屏语义收窄为「只属于阅读页」 | 非阅读页一律退全屏 | 收益：一处规则同时解决「返回后卡全屏」「无缩小按钮」「系统级全屏残留」；代价：将来若想在主页提供全屏，需把判定改为「允许全屏路由集合」或退回 `from.name === 'reader'`，属一行改动 |
| 不加主页全屏按钮 | 非阅读页不提供全屏入口 | 用户已确认；避免「主页全屏 → 进设置被退全屏」的歧义，也无需新增 i18n 文案与悬停提示 |
| 守卫用 `beforeEach` 且不 await | 退出请求与导航并行 | 避免主页先按全屏尺寸绘制再收缩；`exitFullscreen()` 幂等，「已是窗口态」时零操作 |
| 退出全屏为原生窗口动画 | 不做遮罩 / 过渡 | 过渡期一帧布局抖动属平台行为；加遮罩会增加视觉噪声，与「阅读器动画克制」的既有取舍一致 |
| Esc 兜底不 `preventDefault` | 非全屏时完全不拦截 | 保留 `SelectMenu` 收起、`BatchRemoveDialog` 取消、表单内 Esc 的既有语义；仅在全屏时消费一次按键 |
| macOS 上 Esc 也能退全屏 | 不做平台分支 | 与阅读页现有 Esc 优先级保持一致；macOS 红绿灯常驻，不依赖 Esc 退出全屏 |
| 不改 `services/fullscreen.ts` | 守卫只调用既有 API | 防止出现第二个全屏状态源；`selfExit` 机制天然区分「应用主动退出」，不会污染 `exitedFullscreenRecently()` 的返回文库判定 |
| 启动即全屏的极端残留 | 不额外加启动校正 | 主进程不持久化全屏态，实际不出现；若出现由 Esc 兜底处理，避免每次启动多一次 `getFullscreen` 语义分支 |
