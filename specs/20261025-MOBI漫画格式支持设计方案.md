# MOBI 漫画格式支持设计方案

> 状态：设计稿（待实现）
> 目标版本：不随本次改动更新（发版由维护者自行决定；当前 package.json version 1.3.0）
> 范围：`.mobi`（图片型漫画 MOBI）导入与建档、内嵌图片页序与封面、基于既有 Canvas 管线的完整阅读体验（单/双页、方向、缩放、翻页动画、预取、断点续读、阅读统计）、文字型 MOBI 的明确不支持提示
> 实现约束：遵循 `ireader-dev-tasks`（任务 A/D/E/F；无新增 IPC 通道、无 DB 迁移、零新增 npm 依赖为有意设计）与 `ireader-code-conventions`（Result 契约、中文注释、纯逻辑可测）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 支持 MOBI 文件导入管理 | `libraryService.SUPPORTED_EXTS` 增加 `.mobi`；`detectFormat` 派生 `'mobi'`（`BookFormat` 扩展）；`dialog:pickBookFiles` 过滤器增加 `mobi` | 导入一本 MOBI 后文库出现新书；文件夹递归扫描可收录 `.mobi`；改名 / 移动合集 / 批量删除 / 缺失检测 / 重新定位均按既有链路生效 |
| 2 | 页数与断点续读与现有格式一致 | 导入时 `mobiService.countPages` 统计内嵌图片页数写入 `books.total_pages`；`reading_progress` 链路零改动 | 卡片进度圆环 = page / totalPages；翻到第 60 页退出重进回到第 60 页 |
| 3 | 封面与现有格式一致 | 封面队列新增 mobi 分支：拉取 `ireader://mobi/{id}/1` → 480px JPEG → `cover:submit` 落盘 | 导入后封面自动出现且等于第 1 页；失败落占位、不阻塞队列 |
| 4 | 阅读界面、阅读方式、翻页动画与现有格式相同 | `PageDocument` 联合类型新增图片型分支 `{ kind: 'image'; format: 'cbz' \| 'mobi'; bookId }`；把 `src/services/cbz.ts` 泛化为 `imagePage.ts`（URL 由 format 构造），分发器 `pageRenderer.ts` 按 kind 分发 | 单/双页、封面单独成页、LTR/RTL/TTB、四档缩放、翻页动画、连翻补播、预取、热区/键盘/滚轮/滑块、上一本/下一本、全屏、阅读计时统计全部与 CBZ 行为一致 |
| 5 | 明确 MOBI 的支持边界（仅图片型漫画） | 文字型 / 加密 / 损坏 MOBI 打开时走既有错误页，文案「此 MOBI 中没有可识别的图片（当前仅支持图片型漫画 MOBI）」 | 打开文字型 MOBI 显示该错误页并可返回文库，应用不崩溃；导入阶段不报错、不弹窗 |

**核心验收口径**：导入一本 120 页图片型 MOBI → 自动封面 = 第 1 页、页数 = 120；打开后单页/双页、方向三态、四档缩放、翻页动画、预取、断点续读、阅读统计全部与 CBZ 一致；打开文字型 MOBI 命中错误页文案；`npm run typecheck`、`npm test` 通过。

## 二、非目标（本期不做）

- **不做文字型 MOBI 的重排阅读**：需要额外实现文本解压（HUFF/CDIC）+ MOBI 内嵌 HTML 的排版渲染环境，工作量≈再造一套 EPUB 引擎（步骤 3 已确认只做图片型）。
- **不支持 `.azw` / `.azw3`**：本期仅 `.mobi`（步骤 3 已确认）；`.azw3` 为 KF8 结构，头部与记录布局不同，需独立样本验证。
- **不解压 HUFF/CDIC 压缩的文本记录**（compression = 17480）：仅影响「页序推导」的文本来源，图片记录本身不压缩，回退到记录顺序（见 §4.4）。
- **不支持 DRM 加密 MOBI**（encryptionType ≠ 0）：解密涉及密钥分发与合规风险；按「无可读图片」处理。
- **不解析 KF8 段**：`.mobi` 若为 MOBI7+KF8 双格式（combo），只读 MOBI7 段（记录号 < EXTH 121 边界）的图片，KF8 段忽略。
- **不渲染 MOBI 内嵌字体与样式**：图片型漫画无文本层，与 CBZ 现状一致。
- **不新增 IPC 通道、不做 DB 迁移、不新增 npm 依赖、不更新版本号**：全部复用既有契约（步骤 3 已确认自研解析）。
- **不做解析结果缓存**：与 CBZ「每页请求重扫中央目录」同一取舍（§十三 记录扩展点）。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ─────────────────────────────────────────────────────────────┐
│ ReaderView.vue（Canvas 阅读器；除 EPUB 外所有格式共用，本次零改动）      │
│   │ reader.open(id)                                                  │
│   ▼                                                                  │
│ reader store（doc = PageDocument：{kind:'pdf'} | {kind:'image',format}）│
│   │ renderPageToCanvas(doc, page, opts) / cancelPageRender           │
│   ▼                                                                  │
│ pageRenderer.ts（单点分发）                                           │
│   ├─ pdf.ts（pdf.js 矢量渲染，既有）                                   │
│   └─ imagePage.ts（fetch 单页图片 → createImageBitmap → canvas）       │
└───────────────┬──────────────────────────┬───────────────────────────┘
                │ ireader://pdf/{id}        │ ireader://cbz|mobi/{id}/{page}
┌─ 主进程 ──────┼──────────────────────────┼───────────────────────────┐
│ protocol.ts：pdf/epub 直出原文件；cbz/mobi 逐页供给单张图片             │
│   ▼                                                                  │
│ mobiService.ts（PalmDB 记录表 → MOBI 头/EXTH → 页序 → 读单条记录）      │
│   ▼                                                                  │
│ 原 .mobi 文件（fs.read 按记录偏移直读，不整体载入内存）                  │
└──────────────────────────────────────────────────────────────────────┘

导入链路：library:import → libraryService.importPaths
          → mobiService.countPages → books.total_pages
封面链路：coverQueue mobi 分支 → ireader://mobi/{id}/1 → 480px JPEG → cover:submit
```

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 支持边界 | 仅图片型漫画 MOBI（步骤 3 已确认） | 图片型与 CBZ 同构，可完整复用既有 Canvas 管线；文字型需独立排版引擎，属另一量级需求 |
| 扩展名 | 仅 `.mobi`（步骤 3 已确认） | 避免无样本的格式假支持；`BookFormat` 联合类型已预留后续扩展位 |
| 解析实现 | 零新增依赖自研 PalmDB/MOBI 解析（步骤 3 已确认） | PalmDOC 解压与头部解析约 300~400 行纯函数，可造夹具全覆盖；不引入维护状态不明的解析库，守住纯离线与依赖红线 |
| 供给方式 | 主进程按需读取 + `ireader://mobi/{id}/{page}` 逐页供给 | 与 `ireader://cbz` 同心智：大文件不走 IPC、渲染层只见 id + 页码、不暴露本地路径 |
| 页序来源 | MOBI7 文本中的 `recindex` 引用顺序优先，记录顺序兜底 | `recindex` 是书的权威阅读顺序，且天然排除缩略图/未被引用的资源记录；解析失败时记录顺序仍可用（§4.4） |
| 渲染层抽象 | `cbz.ts` 泛化为 `imagePage.ts`（`imagePageUrl(format, bookId, page)`） | 两种格式的绘制/取消/DPR 逻辑完全相同，复制一份会产生双份维护成本；泛化后新增格式只扩 URL 与 union |
| 页数口径 | 导入时主进程统计写入 `books.total_pages` | 与 CBZ 一致，规避「封面队列未完成时页数为 0」的竞态；`cover:submit` 不再是页数来源 |
| 封面 | 取第 1 页（不单独读 EXTH 201） | 与 CBZ 完全一致，用户看到的第一页即封面；EXTH 201 仅用于诊断，不参与业务 |
| 记录读取 | 按记录偏移 `fs.read` 直读目标区间 | MOBI 记录表在文件头，单页读取量 = 一条记录；不需要把上百 MB 文件载入内存 |
| 错误码 | 不新增 `ErrorCode` | 打不开统一走「页数为 0 → 渲染层抛错」的既有错误页机制（与 CBZ 无图同构），避免契约面扩张 |

## 四、核心算法与口径（主进程）

### 4.1 PalmDB 记录表

```
偏移  字段
0x00  name[32]
0x3C  type[4]        = 'BOOK'
0x40  creator[4]     = 'MOBI'
0x4C  numRecords     u16 BE
0x4E  记录信息表      numRecords × 8 字节（offset u32 BE + attributes u8 + uniqueID u24）
```

```ts
/** 记录区间：record i = [offset[i], offset[i+1])，末条到 EOF */
export interface PalmRecord { offset: number; length: number }

/** 只读文件头（78 + 8×numRecords 字节）即可建表，不需要读入正文 */
export function parseRecordTable(header: Buffer, fileSize: number): PalmRecord[]
// 校验：header.length 足够、type === 'BOOK'、creator === 'MOBI'、numRecords ≥ 2、
//       记录表未越界、offset 单调不减且均 < fileSize；任一不满足 → 抛「MOBI 结构无效」
```

### 4.2 MOBI 头与 EXTH（record 0 内）

```ts
export interface MobiHeader {
  compression: number       // 1=无压缩 2=PalmDOC(LZ77) 17480=HUFF/CDIC
  textLength: number        // 解压后文本总长（用于截掉末尾 trailing 数据）
  textRecordCount: number
  encryptionType: number    // 0=未加密
  firstImageIndex: number   // 第一条图片记录号
  fullName: string          // 书名（诊断/日志用，标题仍取文件名）
  coverOffset: number | null // EXTH 201（相对 firstImageIndex）
  kf8Boundary: number | null // EXTH 121（combo 文件的 KF8 起始记录号）
}
```

字段位置（相对 record 0 起点）：PalmDOC 头 0~15（compression@0、textLength@4、textRecordCount@8、encryptionType@12）；MOBI 头自 16 起，`'MOBI'@16`、`headerLength@20`、`firstImageIndex@108`、`EXTHFlags@128`；EXTH 起始 = `16 + headerLength`，需 `'EXTH'` 魔数校验后再遍历（type u32 + length u32 + data[length-8]），仅保留 121 / 201 两类。

### 4.3 PalmDOC LZ77 解压（仅用于取页序）

```ts
export function decompressPalmDoc(input: Buffer): Buffer {
  const out: number[] = []
  let i = 0
  while (i < input.length) {
    const b = input[i++]
    if (b === 0 || b > 0x08 && b <= 0x7f) { out.push(b); continue }   // 0 与 0x09~0x7F：字面字节
    if (b <= 0x08) { for (let n = 0; n < b && i < input.length; n++) out.push(input[i++]); continue }
    if (b <= 0xbf) {                                                   // 0x80~0xBF：回溯复制
      const pair = (b << 8) | input[i++]
      const distance = (pair >> 3) & 0x7ff
      const length = (pair & 0x07) + 3
      if (!distance || distance > out.length) throw new Error('PalmDOC 回溯越界')
      for (let n = 0; n < length; n++) out.push(out[out.length - distance])
      continue
    }
    out.push(0x20, b ^ 0x80)                                           // 0xC0~0xFF：空格 + 单字符
  }
  return Buffer.from(out)
}
```

- 文本 = 依次解压记录 `1 .. textRecordCount` 并按 `textLength` 截断（末条记录把 trailing entry 拼在其后，截断即剔除）。
- `compression === 1` 时记录内容即原文，无需解压；`compression === 17480` 或解压抛错 → 放弃文本，走 §4.4 的兜底。

### 4.4 页序推导

```ts
const IMG_REF = /recindex\s*=\s*["']?(\d+)/g

/** 文本中以 recindex 引用顺序生成页表；越界/重复引用剔除（同一记录只出一次） */
export function orderedPagesFromText(
  html: string, firstImageIndex: number, imageRecords: Set<number>
): number[] {
  const seen = new Set<number>()
  const pages: number[] = []
  for (const m of html.matchAll(IMG_REF)) {
    const record = firstImageIndex + Number(m[1]) - 1
    if (!imageRecords.has(record) || seen.has(record)) continue
    seen.add(record)
    pages.push(record)
  }
  return pages
}
```

流程：

1. 计算图片记录集合 `imageRecords`：遍历 `[firstImageIndex, end)`（`end` = EXTH 121 边界，缺省为记录表末尾），对每条记录读前 32 字节嗅探图片魔数（§4.5），命中即入集合。
2. 若文本可解压：`orderedPagesFromText(...)`；结果非空则用它作页表（`orderFromText = true`）。
3. 否则回退：`imageRecords` 按记录号升序即页表（`orderFromText = false`）。
4. 页码口径：第 `p` 页（1 基）↔ `pages[p - 1]`（物理记录号），与 CBZ「排序后下标即页码」同构。

### 4.5 图片识别与 Content-Type

```ts
/** 在记录前 32 字节内嗅探图片魔数（MOBI 图片记录常带 4 字节前导）；返回起点与 MIME */
export function sniffImage(buf: Buffer): { start: number; contentType: 'image/jpeg' | 'image/png' | 'image/gif' } | null
// JPEG: FF D8 FF ；PNG: 89 50 4E 47 0D 0A 1A 0A ；GIF: 47 49 46 38
```

- 阅读页响应：从魔数处切片返回，MIME 由魔数决定（MOBI 记录无文件名，不能靠扩展名）。
- 仅支持 JPEG / PNG / GIF：Kindle Comic Converter 与 kindlegen 的漫画输出均为 JPEG/PNG；BMP/WebP 记录视为不可读。

### 4.6 边界场景防护清单

| 场景 | 行为 |
|------|------|
| 文字型 MOBI（文本可解压但无 `recindex`、且有图片） | 有图仍按记录顺序成页（可能把插图当页）；无图 → `total_pages = 0`，打开报「仅支持图片型漫画」 |
| 纯文字 MOBI（无任何图片记录） | 导入成功、`total_pages = 0`、占位封面（每次启动重试）；打开显示错误页 |
| HUFF/CDIC 文本（compression = 17480） | 跳过文本解析，页序回退记录顺序；图片页内容不受影响 |
| DRM 加密 MOBI（encryptionType ≠ 0） | 索引阶段判为不可读 → `countPages = 0`；页请求 404 |
| 非 PDB / type≠BOOK / 记录表越界 | 解析抛「MOBI 结构无效」；导入阶段记 warn 不中止（`total_pages = 0`）；页请求 500 |
| MOBI7 + KF8 combo | 只取记录号 < EXTH 121 边界的图片；KF8 段忽略 |
| 同一图片被重复引用（封面 + 首页） | 页表去重，只出现一次 |
| `recindex` 指向非图片记录 / 越界 | 该引用跳过，不影响其余页 |
| PalmDOC 回溯越界（文件损坏） | 解压抛错 → 放弃文本、回退记录顺序；不中断页读取 |
| 文件被外部替换（页数变化） | 越界页 404 → 单页报错；重新导入恢复（与 CBZ 同类边界） |
| 单页图片解码失败 | 该页 throw → `paintPage` catch 记 console，其余页正常 |

## 五、数据模型

**无 schema 变更，零迁移**：`MIGRATIONS` 不追加。

| 格式 | `books.total_pages` 来源 | 进度口径 |
|------|--------------------------|----------|
| PDF | 封面生成后经 `cover:submit` 回填 | 页组首页页码 |
| EPUB | 恒为 0（分页依赖视口，走 `percentage`） | CFI + 百分比 |
| CBZ | 导入时统计图片条目数 | 页组首页页码 |
| **MOBI（新增）** | **导入时 `mobiService.countPages` 统计页表长度** | 与 CBZ 完全一致 |

`books.file_path` 扩展名即格式来源（`detectFormat` 派生），无 `format` 列；`reading_progress` 复用既有字段，`cfi` / `percentage` 对 MOBI 保持 NULL。

## 六、IPC 与协议契约

### 6.1 共享类型（`shared/types.ts`）

```ts
export type BookFormat = 'pdf' | 'epub' | 'cbz' | 'mobi'

export interface ReaderOpenResult {
  format: BookFormat
  /** ireader://pdf/{id}、ireader://epub/{id}（直出原文件）或 ireader://cbz|mobi/{id}（逐页地址前缀） */
  fileUrl: string
  numPages: number
  progress: ReadingProgress | null

```

### 6.2 通道变更：零新增

- 不新增任何 IPC 通道：导入走 `library:import`、封面走 `cover:submit`、阅读走 `reader:open` / `reader:saveProgress`、页数据走协议 —— `electron/preload.ts` 与 `src/services/ipc.ts` **零改动**。
- `dialog:pickBookFiles` 过滤器：`extensions: ['pdf', 'epub', 'zip', 'cbz', 'mobi']`（名称「书籍与漫画」不变，由 `getBookFilesFilterName()` 提供）。
- `reader:open` 返回的 `fileUrl` 对 MOBI 为 `ireader://mobi/{id}`（仅作前缀，不直出文件）。

### 6.3 `ireader://mobi` 协议契约

| URL | 响应 | 说明 |
|-----|------|------|
| `ireader://mobi/{bookId}/{page}` | 200 + 图片二进制，`Content-Type: image/jpeg \| image/png \| image/gif` | `page` 为 1 基阅读页码 |
| 非法 URL（不匹配 `/^\/(\d+)\/(\d+)$/`） | 400 | 须在通用 `bookId` 解析之前分流（通用解析对 `/123/45` 得 NaN） |
| 书不存在 / 非 mobi 格式 / 文件缺失 / 页码越界 / 加密或无可读图片 | 404 | 渲染层 fetch 失败 → 单页报错 |
| 文件损坏（解析抛错） | 500 + 主进程日志留痕 | 渲染层 console 留痕 |

所有响应经既有 `withCors()` 附加 `Access-Control-Allow-Origin: *`。cbz 与 mobi 两个分支结构完全相同，抽出 `servePagedImage(kind, url, readPage)` 辅助函数复用（`cbzService.readPage` 与 `mobiService.readPage` 签名一致）。

> 实施回写：单页二进制入响应前复制为 `new Uint8Array(p.data)` —— Node 的 `Buffer` 以 `ArrayBufferLike` 为背景，直接作为 `BodyInit` 与 DOM 的 `ArrayBufferView<ArrayBuffer>` 不兼容（`vue-tsc` 报 TS2345）。

### 6.4 新增 i18n 键（`src/i18n/locales/{zh-CN,en,ja}.ts`）

| 键 | zh-CN | 用途 |
|----|-------|------|
| `reader.mobiNoImages` | 此 MOBI 中没有可识别的图片（当前仅支持图片型漫画 MOBI） | 打开无图片/文字型 MOBI 的错误页文案 |
| `reader.pageImageFailed` | 加载图片页失败（HTTP {status}） | 通用图片页失败文案；**替换** `reader.cbzPageFailed`（cbz/mobi 共用一份，删除旧键） |

> 实施回写：泛化后的 `renderImagePageToCanvas(url, options)` 只拿得到 URL、拿不到页码，故文案不含 `{page}`（初稿为「加载第 {page} 页失败（HTTP {status}）」）。

> 词典以 `zh-CN` 为 `MessageKey` 类型基准，三语言必须同步增删，否则 `vue-tsc` 直接报错。

## 七、主进程实现

### 7.1 mobiService（新建 `electron/services/mobiService.ts`）

职责：PalmDB/MOBI 解析、页表推导、单页读取、导入时页数统计。仅依赖 `node:fs`（不 import electron / logger / yauzl），保证 vitest 下可直接单测（与 `cbzService.ts` 同一约定）。

```ts
/** 读页表：返回物理记录号序列与顺序来源（文本 / 记录顺序兜底）；结构无效或加密抛错 */
export async function readIndex(filePath: string): Promise<{ pages: number[]; orderFromText: boolean }>

/** 导入时页数统计（= readIndex().pages.length；不可读时抛出，由调用方容错） */
export async function countPages(filePath: string): Promise<number>

/** 读取第 page 页（1 基）；越界/非图片返回 null；解析失败抛出 */
export async function readPage(
  filePath: string, page: number
): Promise<{ data: Buffer; contentType: string } | null>
```

实现要点：

- 文件只读必要区间：`fs.promises.open` → 读 78 + 8×numRecords 字节建记录表 → 读 record 0 解析头/EXTH → 读文本记录（图片型漫画通常几十 KB）→ 单页请求再读目标记录；全程 `finally` 关闭 fd。
- 页表推导见 §4.4；`readPage` 对目标记录整体读出后 `sniffImage` 定位起点与 MIME，`Buffer.subarray(start)` 返回。
- 不缓存解析结果（§3.2）；纯函数（`parseRecordTable` / `decompressPalmDoc` / `orderedPagesFromText` / `sniffImage`）全部导出以便单测。

### 7.2 protocol（`electron/services/protocol.ts`）

在 `kind === 'pdfjs'` 之后、通用 `bookId` 解析之前，新增 `mobi` 分流；与既有 `cbz` 分支合并为：

```ts
async function servePagedImage(
  kind: 'cbz' | 'mobi',
  url: URL,
  reader: (filePath: string, page: number) => Promise<{ data: Buffer; contentType: string } | null>
): Promise<Response> {
  const m = /^\/(\d+)\/(\d+)$/.exec(url.pathname)
  if (!m) return new Response(`Invalid ${kind} url`, { status: 400 })
  const [bookId, page] = [Number(m[1]), Number(m[2])]
  const row = booksRepo.findById(bookId)
  if (!row || detectFormat(row.file_path) !== kind || !fs.existsSync(row.file_path)) {
    return new Response('Not Found', { status: 404 })
  }
  try {
    const p = await reader(row.file_path, page)
    if (!p) return new Response('Not Found', { status: 404 })
    return withCors(new Response(p.data, { headers: { 'Content-Type': p.contentType } }))
  } catch (e) {
    logger.error(`[protocol] ${kind} 读取失败 bookId=${bookId} page=${page}: ${e instanceof Error ? e.message : String(e)}`)
    return new Response(`Bad ${kind} file`, { status: 500 })
  }
}
```

既有 cbz 分支改为调用该辅助函数（行为与错误语义不变），mobi 分支同理新增。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 仅图片型漫画 | 文字型 MOBI 明确报错（用户已确认） | 覆盖面小于「全 MOBI」，但避免了再造排版引擎；未来要做文字型，扩展点为「MOBI HTML → 独立渲染容器」，与本文案互不冲突 |
| HUFF/CDIC 文本不解压 | 页序回退记录顺序 | 图片记录本身不压缩，页内容不受影响；仅当书把图片记录乱序存放时页序可能不理想（KCC 产出为顺序存放） |
| 页序去重 | 同一记录只出现一次 | 漫画每页唯一，去重防止封面/缩略图重复成页；极端情况下书若刻意重复同一图会少页（可接受） |
| 仅 JPEG/PNG/GIF | BMP/WebP 记录视为不可读 | 覆盖 Kindle 漫画主流产出；缺失时表现为单页报错，不影响其余页 |
| 不缓存解析结果 | 每页请求重解析头 + 文本记录 | 记录表几 KB、漫画文本几十 KB，单请求毫秒级；若将来遇到超大文本 MOBI 变慢，扩展点 = 按 `path + mtime + size` 缓存页表 |
| 无 DRM 支持 | 加密书一律不可读 | 解密需密钥分发且合规风险高，明确列为非目标 |
| combo 只读 MOBI7 段 | KF8 段图片忽略 | 两段图片内容通常等价；只读一段避免页重复 |
| cbz.ts 泛化为 imagePage.ts | 触碰既有 CBZ 代码与测试 | 收益：MOBI 零重复绘制逻辑、后续格式只扩 URL；代价：CBZ 需回归冒烟（§11.2 步骤 10 专项） |
| 封面固定取第 1 页 | 不读 EXTH 201 | 与 CBZ 完全一致、实现最简；若遇首页为扉页的极端书，用户可在阅读中忽略（不影响功能） |
| 不新增 ErrorCode | 用 `total_pages = 0` + 渲染层抛错 | 契约面不扩张；错误文案可本地化，且与「CBZ 无图」同一路径 |
