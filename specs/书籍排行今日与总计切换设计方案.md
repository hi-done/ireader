# 书籍排行「今日 / 总计」切换设计方案

> 状态：设计稿（待实现）
> 目标版本：v1.2.0（经确认不为此功能递增版本号，随当前版本线迭代）
> 范围：统计页书籍排行新增「今日 / 总计」口径切换（含每书今日时长查询扩展与契约字段）；阅读时长采集链路零改动
> 实现约束：遵循 `ireader-dev-tasks`（任务 A 契约类型步、任务 D 渲染层、任务 F 验证）与 `ireader-code-conventions`（Result 契约、中文注释、双进程共享类型）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 书籍排行支持「今日 / 总计」切换，今日在左且默认选中 | ReadingStatsView 排行面板头新增 `.seg` 分段控件（复用柱状图「近 7 / 近 30 天」控件样式与交互范式），`rankMode` 本地状态，初始 `'today'` | 切换后列表范围、排序、时长列、占比条同步变化；进入页面默认展示今日在读 |
| 2 | 今日口径的每书时长数据 | `statsRepo.listByBook` 条件聚合返回 `todayMs`；`statsService.summary` 传入今日日期键；`BookReadingStat` 契约扩展 | 读 A 书 2 分钟、B 书 5 分钟后切「今日」：B 第一 A 第二，时长列分别为 5 / 2 分钟 |
| 3 | 「对应数据采集功能支撑」 | 调研结论：`reading_stats` 表已按 `(book_id, day)` 粒度由既有心跳链路（readingTimer → `stats:addTime` UPSERT）落库，今日口径**无需新增采集**，仅扩展查询与展示 | 采集链路文件零改动（见 §九「不改动」清单）；今日视图数值与概览卡「今日阅读」同源一致 |

**核心验收口径**：阅读两本书不同时长后切「今日」→ 仅出现今日在读的书、按今日时长降序、右侧时长为今日值、占比条按今日第一名归一；切回「总计」恢复全量列表且排序不变。

## 二、非目标（本期不做）

- 不做「近 N 天」等更多排行口径：今日 / 总计两档已覆盖核心诉求；推广为任意范围需 summary 返回每书逐日序列，成本收益不匹配（扩展点见 §十二）。
- 不新增数据采集逻辑：不改 `readingTimer.ts` / `readingTracker.ts` / `ReaderView.vue` 埋点，现有 `(book_id, day)` 粒度天然支撑今日口径。
- 不新增 IPC 通道、不做 DB 迁移：仅扩展 `stats:summary` 返回字段。
- 不做排行行点击跳转阅读页（现状亦无此交互）。
- 不改概览卡 / 柱状图 / 整页空态逻辑。

## 三、总体设计

└────────────┬─────────────────────────────────────────────┘

┌─ 主进程 ─────────────────────────────────────────────────┐
│ handlers.ts（stats:summary 编排，零改动）                  │

└──────────────────────────────────────────────────────────┘

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 数据获取方式 | 扩展 `stats:summary` 返回（books 每项 +`todayMs`），页面一次拉全量本地切换 | 与柱状图 7/30 天「切片不重复请求」同一哲学；书量级 < 千，返回体增量可忽略；新增排行通道会引入第二条链路，维护成本不成比例（经用户确认） |
| 今日视图口径 | 只显示今日在读（`todayMs > 0`），按今日时长降序 | 今日未读的书显示「0 分钟」只会稀释信息密度，今日视图的价值在回答「今天读了什么」（经用户确认） |
| 今日时长 SQL | 单查询条件聚合 `SUM(CASE WHEN day = ? ...)` | 与总计同一次 GROUP BY 同时返回双口径，避免两查两排；每组至少一行，SUM 无 NULL 风险 |
| 切换控件 | 复用 ReadingStatsView 现有 `.seg` 分段控件 | 同页同交互范式，视觉与代码双重一致；`.seg` 为同文件 scoped 样式，排行面板天然可用，零新增控件样式 |
| 口径切换体验 | `:key="rankMode"` 重挂载 BookRankingList | 与柱状图 `:key="range"` 同范式：重播行入场与占比条生长动画；展开状态随之重置（口径切换 = 重新审视列表） |
| 排序位置 | 渲染层本地排序（`pickRankingBooks` 纯函数） | 数据全量在手、量级小；与 `visibleDays` 切片同层级；纯函数可单测，符合「纯逻辑下沉 `src/services/`」惯例 |
| 默认口径与按钮顺序 | 「今日」在左且默认选中 | 进入统计页最关心「今天读了什么」；与柱状图短窗口（近 7 天）在左的直觉一致（经用户指定） |

## 四、口径规则与边界场景

### 4.1 口径规则

| 项 | 总计 | 今日（默认） |
|----|--------------|------|
| 列表来源 | `summary.books` 原样（服务端已按总时长降序） | 过滤 `todayMs > 0`，按今日时长降序 |
| 右侧时长列 | `formatDuration(durationMs)` | `formatDuration(todayMs)` |
| 占比条基准 | 第一名总时长 | 第一名今日时长 |
| 副文案 | 最近阅读：`formatRelativeDay(lastReadAt)` | 同左（今日读过的书自然显示「今天」） |
| panel-count | 共 N 本（N = 有记录书总数） | 今日 M 本（M = 今日在读书数） |
| Top 10 折叠 | 现状不变 | 同规则（今日在读书通常 ≤ 10，按钮自然隐藏） |

### 4.2 边界场景

| 场景 | 行为 |
|------|------|
| 今日无任何阅读记录 | 「今日」视图显示局部空态文案「今天还没有阅读记录，打开一本书开始吧」；「总计」视图不受影响 |
| 今日在读的书被删除 | `reading_stats` 行随外键 CASCADE 删除，下次 summary 不返回该书，今日 / 总计同步消失 |
| 今日时长相等的两本书 | 稳定排序维持总计降序的相对顺序（V8 sort 稳定） |
| 统计页驻留跨过午夜 | 今日口径的日期键在 summary 拉取时已固化（快照语义）；重进页面刷新。与既有「只读快照」行为一致 |
| 阅读中的心跳上报 | 统计页为进入时快照，停留期间数值不实时增长（现状一致）；退出重进可刷新 |

## 五、IPC 契约（`shared/types.ts` 扩展）

```ts
/** 阅读统计：单书累计 */
export interface BookReadingStat {
  bookId: number
  title: string
  /** ireader://cover/{id}；封面缺失时前端 onerror 落占位 */
  coverUrl: string
  /** 全部历史累计时长（ms） */
  durationMs: number
  /** 今日已读时长（ms）；今日未读为 0。排行「今日」视图按此过滤与排序 */
  todayMs: number
  /** 最近一次阅读时间戳（ms） */
  lastReadAt: number
}
```

- 通道表不变：`stats:summary` 入参 `{ days }`、返回 `ReadingStatsSummary`（仅 books 元素结构扩展），`stats:addTime` 不变。
- 增量字段向后兼容；`preload.ts` / `handlers.ts` / `src/services/ipc.ts` 对返回值均为 `ReadingStatsSummary` 类型引用，自动跟随，无逻辑改动。
- 按「任务 A」六步链路口径：本次不新增通道，仅涉及第 1 步（shared/types.ts 契约类型）与服务层组装，其余步骤零改动。
- `RankingMode` 为纯渲染层 UI 概念、不跨进程，定义在 `src/services/readingStats.ts` 而非 shared（shared 只放双进程契约）。

## 六、主进程实现

### 6.1 statsRepo.listByBook 扩展（`electron/db/repos/statsRepo.ts`）

```ts
/** 单书累计行（含 books 表 JOIN 出的标题） */
export interface BookStatRow {
  bookId: number
  title: string
  durationMs: number
  /** 今日已读时长（今日无记录为 0） */
  todayMs: number
  /** 最近一次阅读时间戳（= 最后一次累加的 updated_at） */
  lastReadAt: number
}

/** 每本书累计与今日时长（JOIN books 取标题），总时长降序 */
listByBook(today: string): BookStatRow[]
// SELECT s.book_id AS bookId, b.title AS title,
//        SUM(s.duration_ms) AS durationMs,
//        SUM(CASE WHEN s.day = ? THEN s.duration_ms ELSE 0 END) AS todayMs,
//        MAX(s.updated_at) AS lastReadAt
// FROM reading_stats s JOIN books b ON b.id = s.book_id
// GROUP BY s.book_id ORDER BY durationMs DESC
```

要点：

- 条件聚合与总计同查询返回，一次 GROUP BY 双口径，无二次查询；
- `CASE WHEN ... ELSE 0` 保证今日无记录的书 `todayMs = 0`（非 NULL，无需 COALESCE）；
- 参数风格沿 `listByDay` 的位置参数 `?`（`.all(today)`）。

### 6.2 statsService.summary 编排（`electron/services/statsService.ts`）

books 映射处传入今日日期键并补 `todayMs` 字段：

```ts
const books: BookReadingStat[] = statsRepo.listByBook(formatDayKey(today)).map((r) => ({
  bookId: r.bookId,
  title: r.title,
  coverUrl: getCoverUrl(r.bookId),
  durationMs: r.durationMs,
  todayMs: r.todayMs,
  lastReadAt: r.lastReadAt,
}))
```

`today` 变量（`new Date()`）已存在于 summary 内，`formatDayKey` 已从 shared/types.ts 导入，零新增依赖。每书 `todayMs` 与汇总级 `todayMs`（filledDays 末位）同源同表聚合、单进程同步执行无竞态，不做交叉校验。

## 七、渲染层实现

### 7.1 纯函数（`src/services/readingStats.ts` 追加）

```ts
/** 书籍排行展示口径（纯渲染层概念，不进 shared 契约） */
export type RankingMode = 'total' | 'today'

/**
 * 按口径派生排行列表：
 * - total：原样返回（stats:summary 已按总时长降序）
 * - today：过滤今日在读（todayMs > 0）并按今日时长降序；
 *   今日时长相同时维持原（总计降序）相对顺序（稳定排序）
 */
export function pickRankingBooks(books: BookReadingStat[], mode: RankingMode): BookReadingStat[]
```

实现：today 分支 `books.filter((b) => b.todayMs > 0).sort((a, b) => b.todayMs - a.todayMs)`——`filter` 产生新数组，就地 `sort` 不影响传入的原数组。

### 7.2 BookRankingList.vue

- props 追加 `mode?: RankingMode`（默认 `'total'`，未传时行为与现状完全一致，向后兼容）；
- 内部取值函数 `valueOf(b) = mode === 'today' ? b.todayMs : b.durationMs`：右侧时长列与 `fillStyle` 的 `max` / `percent` 全部改走 `valueOf`；
- 空列表渲染空态行：今日口径文案「今天还没有阅读记录，打开一本书开始吧」；总计口径兜底「暂无阅读记录」（正常被整页空态 `totalMs === 0` 拦截，实际不可达，仅防御）。

### 7.3 ReadingStatsView.vue

```ts
/** 排行口径（今日 / 总计），默认今日；数据一次拉取，切换仅本地过滤排序不重复请求 */
const rankMode = ref<RankingMode>('today')
const rankBooks = computed(() =>
  summary.value ? pickRankingBooks(summary.value.books, rankMode.value) : []
)
/** 排行面板计数文案：随口径联动 */
const rankCountText = computed(() =>
  rankMode.value === 'today' ? `今日 ${rankBooks.value.length} 本` : `共 ${summary.value?.books.length ?? 0} 本`
)
```

模板（排行面板头）：

```html
<div class="panel-head">
  <h2>书籍排行</h2>
  <div class="panel-head-right">
    <span class="panel-count">{{ rankCountText }}</span>
    <div class="seg">
      <button :class="{ on: rankMode === 'today' }" @click="rankMode = 'today'">今日</button>
      <button :class="{ on: rankMode === 'total' }" @click="rankMode = 'total'">总计</button>
    </div>
  </div>
</div>
<!-- key=rankMode：切换口径时重挂载，重播行入场与占比条生长动画（展开状态随之重置） -->
<BookRankingList :key="rankMode" :books="rankBooks" :mode="rankMode" />
```

## 十一、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| summary 返回体增大 | 每书 +1 个 number 字段 | 书量级 < 千，体积可忽略；换零新通道与零重复请求 |
| 今日排序在客户端 | 本地 sort，开销可忽略 | 与 7/30 天切片同哲学；书量暴涨再下沉服务端 |
| 快照不实时 | 统计页停留期间今日数值不增长 | 与既有只读快照行为一致；重进页面刷新 |
| 跨午夜驻留 | 今日日期键固化在拉取时刻 | 同上；如需实时可在口径切换时重拉 summary，本期不做 |
| 口径切换重置展开状态 | `:key` 重挂载 | 更符合「重新审视列表」预期；用户反馈需要保留时可改为 watch 重置 |
| 并列时长次序 | 依赖 V8 稳定 sort | 主流引擎均稳定；并列本无强语义，可接受 |
