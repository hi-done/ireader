# 阅读器工具栏提示框苹果风美化设计方案

> 状态：设计稿（v1，待用户确认）
> 目标版本：v1.2.6（沿用当前 package.json 版本，本次不改版本号、不打 tag，由用户自行发版时确定）
> 范围：PDF / EPUB 阅读器顶栏 2 处图标控件原生 `title`（缩放-字号 / 全屏）+ EPUB 底栏滑块「拖动跳页」；「上一本 / 下一本」自带可见文字，不设提示框；`SelectMenu` 由内联 `title` 改为透出触发器悬停事件；复用《图书卡片提示框苹果风美化设计方案-20261021》的 `CardTip` 浮层与 `--tip-*` 令牌
> 实现约束：遵循 `ireader-dev-tasks`（任务 D 渲染层归属、任务 E 阅读器行为、任务 F 验证流程）与 `ireader-code-conventions`（中文注释、样式取 CSS 变量、不新增依赖、纯逻辑入 `src/services/` 并补 Vitest）；本方案不涉及 IPC / DB / shared 类型

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 阅读器顶栏提示框与书卡同风格（用户确认：PDF + EPUB 都改） | `ReaderView` / `EpubReaderView` 顶栏「缩放（字号）/ 全屏」删除原生 `title`，改挂 `CardTip` 浮层，`placement="below"`、`align="center"`（§5.4 / §5.5）；「上一本 / 下一本」自带文字，仅移除 `title`（`aria-label` 保留）不做提示框 | 悬停缩放与全屏只出现自定义提示框（6px 圆角、无箭头、不透明底 + 描边 + 投影），无 Windows 系统白框；悬停上一本 / 下一本不弹任何提示 |

| 3 | 材质、字排、节奏与卡片完全一致 | 直接复用 `src/components/ui/CardTip.vue` 与 `src/style.css` 现有 `--tip-*` 令牌，不改任何提示框样式与默认 `delay=350`（§三） | 与文库页书卡提示框逐项比对：底色 / 文字 / 描边 / 投影 / 圆角 / 字号 / 350ms 延迟 / 140ms 淡入无差异 |
| 4 | 不出现原生提示叠弹 | 4 处 `title` 全部移除（其中上一本 / 下一本不再有替代提示）；`SelectMenu` 内部 `:title="title"` 渲染一并移除（§5.3） | 悬停 3 个带提示控件停留 2 秒，只有自定义提示框；上一本 / 下一本无提示；DevTools 中对应元素无 `title` 属性 |
| 5 | 键盘可达与读屏不退化 | 图标控件补 `aria-label`（与提示文案同 i18n 键）；滑块补 `aria-label`；上一本 / 下一本可见文本即名称，保留 `aria-label` 去掉箭头符号干扰；`:focus-visible` 时显示同一提示框（§5.2） | `Tab` 逐个聚焦顶栏图标控件与滑块，提示框出现；鼠标点击产生的聚焦不弹提示；上一本 / 下一本聚焦不弹提示 |
| 6 | 顶栏自动隐藏时提示框同步收起（用户确认） | 各视图 `watch(barsVisible)`，变 `false` 时 `closeTip()`（§4.2） | 鼠标停在上一个按钮上不动，顶栏淡出瞬间提示框同时消失，不悬浮在空处 |
| 7 | 下拉菜单与提示框不叠加 | `SelectMenu` 打开时 `emit('trigger-leave')`，展开期间不再上报 `trigger-enter`（§5.3） | 悬停缩放控件 0.35s 出现提示；点击展开下拉，提示立即消失且菜单展开期间不再出现 |
| 8 | 不改变任何阅读器业务行为 | 翻页 / 切书 / 缩放 / 字号 / 全屏 / 拖动跳页 / 顶栏显隐节奏与尺寸一律不动；只改提示承载方式 | 逐项回归 PDF 与 EPUB 两条链路：上一本 / 下一本 / 缩放档位 / 全屏切换 / 滑块跳页 / 顶栏 1.5s~3s 自动隐藏 |
| 9 | 其他页面下拉菜单零变化 | `SelectMenu` 删除未被使用的 `title` prop；设置页 4 处、文库页排序下拉均未传 `title`，行为与视觉不变（§5.3） | 设置页 4 个下拉、文库页排序下拉悬停 2 秒无任何提示框，视觉与改造前一致 |

**核心验收口径**：在 PDF 与 EPUB 阅读页，悬停顶栏「缩放（字号）/ 全屏」0.35s 后，控件下方 7px 出现与文库书卡完全同材质的提示框（浅色 `#fbfbfd` / 深色 `#2c2c2e`，12.5px/500，1px 描边 + 投影，无箭头）；「上一本 / 下一本」不出现任何提示；EPUB 底栏悬停滑块在上方 7px 出现「拖动跳页」；全部控件不再出现任何原生 tooltip；顶栏自动淡出时提示框同步消失；下拉菜单展开时提示框不残留、不重叠；键盘 `Tab` 与鼠标悬停看到同一提示框；`npm run typecheck` 与 `npm test` 通过，设置页 / 统计页 / 文库页视觉零变化。

## 二、非目标（本期不做）

- 不改 `BookCard` / `CollectionCard`：卡片提示框刚完成 v2 验收，本期不迁移到新 composable，两套实现并存（卡片侧后续可按同一 composable 收敛，列入风险与扩展点）。
- 不给顶栏「单页 / 双页」「方向」两个文字按钮新增提示（用户确认只替换现有 `title`）：按钮文本本身已是自解释标签，新增提示会扩大本期范围。
- 不给「上一本 / 下一本」提供提示框（用户确认）：这两个按钮自带可见文字（`‹ 上一本` / `下一本 ›`），提示框属重复信息；仅移除原生 `title`，`aria-label` 保留以提供干净的读屏名称。
- 不改阅读器顶栏 / 底栏的材质（`rgba(28,28,30,.6)` + `blur(20px)`）、`z-index: 2`、`opacity` 过渡、1.5s / 3s 自动隐藏节奏与按钮尺寸。
- 不改 `SelectMenu` 弹层的定位、`TRIGGER_GAP`、键盘导航、外部点击关闭等既有行为；只新增两个悬停事件透出并删除 `title` prop。
- 不改滑块 `input[type=range]` 的拖动逻辑、`sliderDragging` 会话、跳页补播动画与样式。
- 不做提示框跟随滚动 / 缩放 / 顶栏淡出重定位：沿用 `CardTip` 现有「滚动 / 缩放即收起」策略。
- 不做箭头、方向自动翻转、`aria-describedby` 关联；不新增任何 npm 依赖。
- 不改 `src/style.css` 的 `--tip-*` 令牌值（仅同步注释措辞，本期无新材质需求）。

## 三、总体设计

### 3.1 结构与数据流

```
ReaderView.vue（PDF）/ EpubReaderView.vue（EPUB）
  ├─ useHoverTip()（§5.2：tipAnchor / tipText / tipPlacement / tipAlign + openTip / openTipAt / closeTip）
  ├─ header .top-bar（z-index: 2，backdrop-filter）
  │    ├─ button.book-nav 上一本   :aria-label="t('reader.prevBookTitle')"（自带文字，无提示框）
  │    ├─ button.book-nav 下一本   :aria-label="t('reader.nextBookTitle')"（自带文字，无提示框）
  │    ├─ SelectMenu（缩放 / 字号）
  │    │    ├─ :title 删除
  │    │    └─ @trigger-enter="openZoomTip" / @trigger-leave="closeTip"
  │    └─ button 全屏 ⛶            :aria-label="t('reader.fullscreen')" + 4 个提示事件
  ├─ footer .bottom-bar
  │    └─ input.page-slider（仅 EPUB）：title → :aria-label="t('reader.dragToSeek')" + 4 个事件 + pointerdown 收起
  ├─ watch(barsVisible)：变 false → closeTip()
  └─ <CardTip :visible="tipAnchor !== null" … @dismiss="closeTip" />
       （Teleport 到 body，position: fixed，z-index: 40 > 顶栏 2）

SelectMenu.vue（通用下拉，3 个页面共用）
  ├─ triggerEl 的 pointerenter / focus → shouldShowTip 过滤（触屏、非 focus-visible、菜单展开中）
  │    → emit('trigger-enter', triggerEl)
  ├─ pointerleave / blur → emit('trigger-leave')
  └─ openMenu() → emit('trigger-leave')（下拉展开立即收起提示）

src/services/cardTip.ts（纯逻辑）
  └─ 新增 shouldShowTip(input)：触屏不触发、鼠标点击产生的 focus 不触发
```

关键点：
- 提示框本体、定位算法、过渡与主题令牌全部复用卡片方案，本期**零新增样式**；`CardTip` 只在阅读页多挂两个实例（每个视图一个）。
- `SelectMenu` 不自己渲染提示框：宿主（阅读页）持有唯一的提示状态，顶栏隐藏时只需一次 `closeTip()` 就能同时收起按钮与下拉的提示。通用组件因此不依赖 `CardTip`，仅透出「触发器被悬停」这一事实。
- 顶栏 `backdrop-filter` 会成为 `position: fixed` 的包含块，但 `CardTip` 已 `Teleport` 到 `body`，坐标仍是视口坐标，与 `SelectMenu` 弹层的处理方式一致。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 改造范围（用户确认） | 顶栏图标控件 2 处（缩放-字号 / 全屏）+ EPUB 底栏滑块 | 一次收口阅读器内全部原生 `title`；「上一本 / 下一本」自带可见文字（用户确认不加提示框），避免重复信息 |
| 代码组织（用户确认） | 新增 `src/components/ui/useHoverTip.ts`，两视图共用 | 两视图的事件过滤与状态写法完全相同；`BookCard` 本期不动以缩小回归面 |
| `SelectMenu` 提示归属 | 组件只透出 `trigger-enter` / `trigger-leave`，提示由宿主渲染 | 若在组件内挂 `CardTip`，阅读页会出现两套提示状态，顶栏隐藏时要额外通过 `ref` 调用组件方法才能收起；通用组件也不应依赖业务浮层 |
| 顶栏隐藏联动（用户确认） | `barsVisible` 变 `false` 时立即 `closeTip()` | 零行为变更：顶栏隐藏节奏保持现状，提示框不会悬浮在空处 |
| 展开方向 | 顶栏 `below`、底栏滑块 `above` | 顶栏下方是阅读区（充足空间）；滑块上方是阅读区、下方是屏幕边缘 |
| 触发过滤 | 纯函数 `shouldShowTip`（事件类型 + `pointerType` + `focusVisible`） | 触屏无 hover 语义、鼠标点击不应弹提示；抽成纯函数可在 Node 环境单测 |
| 文案来源 | 事件处理器内 `t('reader.*')`，与 `aria-label` 同一 i18n 键 | 视觉文案与读屏名称不会漂移；`SelectMenu` 的「缩放 / 字号」按 `isImageLayout` 分支取同一个键 |
| 禁用态处理 | 不显示提示（`disabled` 控件不派发指针事件） | 不额外包 wrapper；禁用按钮的原生 `title` 提示随之消失，列入风险 |
| 滑块拖动 | `pointerdown` 主动 `closeTip()` | 拖动中指针可能被 thumb 捕获、`pointerleave` 不触发，主动收起避免提示框停在底栏上方 |

## 四、交互口径与边界防护

### 4.1 状态与节奏

完全沿用 `CardTip`：`openTip` 只写锚点与文案，显示延迟 350ms、140ms 淡入 + 2px 位移、100ms 淡出、滚动 / 缩放 `dismiss`。

| 阶段 | 触发 | 表现 |
|------|------|------|
| 顶栏图标控件 hover / `focus-visible` | `@pointerenter` / `@focus` | 350ms 后按钮下方 7px 淡入 |
| 移出 / 失焦 | `@pointerleave` / `@blur` | 100ms 淡出 |
| 顶栏自动隐藏 | `watch(barsVisible)` → `false` | 提示框与顶栏同步消失 |
| `SelectMenu` 展开 | `openMenu()` → `trigger-leave` | 提示立即收起；展开期间 `trigger-enter` 不再上报 |
| 滑块 hover / `focus-visible` | `@pointerenter` / `@focus` | 350ms 后滑块上方 7px 淡入「拖动跳页」 |
| 滑块按下 | `@pointerdown` | 立即收起，拖动全程不出现 |
| 阅读区滚动 / 窗口缩放 | `CardTip` 内部监听 | 立即收起（与卡片一致） |

### 4.2 边界场景防护

| 场景 | 处理 |
|------|------|
| 顶栏不可见（`opacity: 0`）时鼠标进入顶部 | 浏览器先派发 `pointerenter` 再派发 `mousemove`：提示计时启动后顶栏被 `showBarsTemporarily` 点亮，350ms 后提示出现时顶栏已可见 |
| 鼠标停在按钮上不动 | 顶栏 1.5s（顶部边缘触发）或 3s 后隐藏 → `closeTip()` 同步收起；移动鼠标会重新点亮顶栏并重新计时 |
| `SelectMenu` 下拉展开中鼠标回到触发器 | `trigger-enter` 被 `open` 判断拦截，不会出现提示压在菜单上 |
| 下拉选中 / Esc / 外部点击收起 | `close()` 不改提示状态；鼠标仍在触发器上时重新悬停即可再次触发（与原生 tooltip 一致） |
| 滑块 `disabled`（`!store.locationsReady`） | `disabled` 控件不派发指针事件，不出现提示 |
| 拖动滑块中指针移出控件 | `pointerdown` 已收起；`onSlideChange` 后 `sliderDragging` 复位，重新悬停可再触发 |
| 全屏切换 | 触发 `window.resize` → `CardTip` 的 `dismiss` 收起 |
| 快速扫过顶栏按钮 | 350ms 内 `pointerleave` 清除计时，不出现、无补播 |
| 触屏设备 | `pointerType === 'touch'` 直接 return |
| 键盘 `Tab` | `focus` 事件匹配 `:focus-visible` 才显示；鼠标点击产生的 `focus` 被过滤 |
| 深色主题 | `--tip-*` 切深底白字；阅读器黑底上提示框对比正常 |
| 路由离开阅读页 | 视图卸载 → `CardTip` 卸载、`Teleport` 节点销毁；`useHoverTip` 状态随组件销毁 |
| 提示框遮挡顶栏按钮 | 提示框在按钮下方 7px、`pointer-events: none`，不拦截按钮与阅读区点击 |

## 五、渲染层实现

### 5.1 `src/services/cardTip.ts`（追加纯函数）

文件头注释同步改为「悬停提示框定位（书卡 / 阅读器工具栏共用）」，在 `resolveTipPosition` 之后追加：

```ts
/** 提示触发过滤的输入：从事件与元素状态中提取，便于 Node 环境单测 */
export interface TipTriggerInput {
  /** 事件类型（pointerenter / focus） */
  type: string
  /** PointerEvent.pointerType；非指针事件为空 */
  pointerType?: string
  /** 事件元素是否匹配 :focus-visible（仅 focus 事件有意义） */
  focusVisible?: boolean
}

/** 是否应触发提示：触屏无 hover 语义；鼠标点击产生的 focus 不匹配 :focus-visible */
export function shouldShowTip(input: TipTriggerInput): boolean {
  if (input.pointerType === 'touch') return false
  if (input.type === 'focus' && !input.focusVisible) return false
  return true
}
```

设计取舍：
- 只吃「已提取的特征」而不是事件对象：Vitest 默认 `environment: 'node'`，没有 `PointerEvent` 构造函数，纯特征入参才能单测。
- 与 `BookCard.vue` 现有内联判断（`event instanceof PointerEvent && pointerType === 'touch'`、`el.matches(':focus-visible')`）语义一致，后续卡片迁移时可直接替换。

### 5.2 `src/components/ui/useHoverTip.ts`（新增）

```ts
// 悬停提示状态：锚点 / 文案 / 展开方向 + 触发过滤（依赖 Vue，不查询 DOM）
// 对应设计文档 specs/阅读器工具栏提示框苹果风美化设计方案-20261021.md §5.2
import { ref } from 'vue'
import { shouldShowTip, type TipAlign, type TipPlacement } from '../../services/cardTip'

/** 提示选项：默认向下、居中（顶栏按钮形态） */
interface TipOptions {
  placement?: TipPlacement
  align?: TipAlign
}

export function useHoverTip() {
  /** 锚点即「是否触发」：置 null 收起，无需第二个布尔量 */
  const tipAnchor = ref<HTMLElement | null>(null)
  const tipText = ref('')
  const tipPlacement = ref<TipPlacement>('below')
  const tipAlign = ref<TipAlign>('center')

  /** 模板事件入口（pointerenter / focus 共用）：过滤触屏与鼠标点击产生的 focus */
  function openTip(event: PointerEvent | FocusEvent, text: string, options: TipOptions = {}) {
    const el = event.currentTarget as HTMLElement | null
    if (!el) return
    const visible = shouldShowTip({
      type: event.type,
      pointerType: event instanceof PointerEvent ? event.pointerType : undefined,
      focusVisible: event.type === 'focus' ? el.matches(':focus-visible') : undefined,
    })
    if (!visible) return
    apply(el, text, options)
  }

  /** 子组件上报锚点入口（SelectMenu trigger-enter）：过滤已由子组件完成 */
  function openTipAt(anchor: HTMLElement, text: string, options: TipOptions = {}) {
    apply(anchor, text, options)
  }

  function apply(anchor: HTMLElement, text: string, options: TipOptions) {
    tipAnchor.value = anchor
    tipText.value = text
    tipPlacement.value = options.placement ?? 'below'
    tipAlign.value = options.align ?? 'center'
  }

  function closeTip() {
    tipAnchor.value = null
  }

  return { tipAnchor, tipText, tipPlacement, tipAlign, openTip, openTipAt, closeTip }
}
```

- 放在 `src/components/ui/` 而非 `src/services/`：组合式函数依赖 Vue 响应式，`services` 目录只放可测试的纯逻辑（`shouldShowTip` 因此单独落在 `cardTip.ts`）。
- 不提供 `delay` / `maxWidth` 透传：阅读器工具栏没有三行书名与自定义延迟需求，保持最小 API。

### 5.3 `src/components/ui/SelectMenu.vue`

props / emits / 脚本改动（文件顶部 import 区追加 `shouldShowTip`）：

```ts
import { shouldShowTip } from '../../services/cardTip'

// props：删除 title，其余不动（仍需 const props 供 disabled / options 读取）
const props = defineProps<{
  modelValue: T
  options: SelectOption<T>[]
  /** 读屏名称：行内可见标签不属于按钮文本，需显式提供 */
  label: string
  disabled?: boolean
}>()

const emit = defineEmits<{
  'update:modelValue': [value: T]
  change: [value: T]
  /** 展开 / 收起：宿主可据此暂停自动隐藏工具栏等定时逻辑 */
  open: []
  close: []
  /** 触发器悬停 / 聚焦：透出锚点元素，宿主据此展示自定义提示框 */
  'trigger-enter': [anchor: HTMLElement]
  /** 触发器移出 / 失焦 / 菜单展开：宿主收起提示框 */
  'trigger-leave': []
}>()

/** 触发器悬停 / 聚焦：菜单展开中或不可见焦点不上报（触屏由 shouldShowTip 过滤） */
function onTriggerEnter(event: PointerEvent | FocusEvent) {
  if (open.value || !triggerEl.value) return
  const visible = shouldShowTip({
    type: event.type,
    pointerType: event instanceof PointerEvent ? event.pointerType : undefined,
    focusVisible: event.type === 'focus' ? triggerEl.value.matches(':focus-visible') : undefined,
  })
  if (visible) emit('trigger-enter', triggerEl.value)
}

function onTriggerLeave() {
  emit('trigger-leave')
}
```

`openMenu()` 开头追加一行（在 `open.value = true` 之前）：

```ts
// 下拉弹层紧贴触发器下方（gap 6px），提示框必须立即收起，避免两者叠在一起
emit('trigger-leave')
```

实现注意：
1. `trigger-enter` 传元素而非事件对象：宿主跨组件读取 `event.currentTarget` 依赖原生派发时序，传 `triggerEl.value` 语义明确、无时序陷阱。
2. 删除 `title` prop 后，`aria-label`（`t('common.labelValue', { label, value: selectedLabel })`）仍是触发器的可访问名称，读屏不受影响。
3. 设置页 4 处、文库页排序下拉均未传 `title`，改造后它们不会产生任何 `trigger-enter` 消费方，行为与视觉零变化。
4. `open` / `close` 事件语义不变，阅读页 `pinBars` / `unpinBars` 照旧接线。

## 十、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| **两套提示实现并存** | 阅读器走 `useHoverTip`，`BookCard` 保留内联写法（用户确认本期不动） | 短期内重复约 20 行样板；卡片侧刚验收、回归面优先。后续迁移只需把内联状态换成 composable，行为等价 |
| 顶栏隐藏即收起 | `barsVisible=false` → `closeTip()`（用户确认） | 鼠标静止在按钮上时提示可视窗口约 1.1s（1.5s 计时 - 0.35s 延迟）；移动鼠标会重置计时。相比「悬停锁定顶栏」不改现有显隐节奏 |
| 上一本 / 下一本无提示框（用户确认） | 按钮自带可见文字，不再提供任何悬停提示 | 少一处与按钮文本重复的信息；首本 / 末本禁用态无提示属预期，用户可从按钮置灰判断 |
| `SelectMenu` API 变更 | 删除 `title` prop，新增两个 emits | 仅阅读页两个使用处传过 `title`，设置页 / 文库页未使用，影响面已收敛；删除比保留一个「只用于提示文案」的 prop 语义更清晰 |
| 跨组件传元素而非事件 | `trigger-enter` 载荷为 `triggerEl` | 避免宿主依赖原生事件派发的 `currentTarget` 时序；过滤在子组件内一次做完 |
| 提示与下拉弹层同屏 | 打开菜单前收起 + 展开期间拦截 | 两者间距仅 1px（`TRIGGER_GAP 6` vs 提示 `gap 7`），不处理会直接重叠 |
| 滑块拖动收起 | `pointerdown` 主动收起 | 拖动中指针被 thumb 捕获、`pointerleave` 不可靠，主动收起最稳 |
| 深色阅读器 + 浅色主题 | 提示框跟随应用主题令牌，而不是阅读器深色材质 | 与系统 tooltip 一致；浅底提示在黑底阅读区上对比更强，无需为阅读页单独造一套深色令牌 |
| 不改 `--tip-*` 与 `CardTip` 样式 | 完全复用 | 视觉零新增风险；若后续觉得阅读页提示对比过强，可单点调 `--tip-bg`（会影响卡片，需另行评估） |
| 提示框不跟随顶栏淡出动画 | 顶栏 `opacity` 0.2s 过渡，提示框 100ms 淡出 | 两者同时开始、提示先结束，视觉上是「随顶栏一起消失」，无需同步动画曲线 |
