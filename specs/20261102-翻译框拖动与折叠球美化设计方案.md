# 翻译框拖动与折叠球美化设计方案

> 状态：设计稿（待实现）
> 目标版本：v1.4.2（版本号不变，发版时机由用户确定）
> 范围：译文框静默态/悬浮态视觉、框体整体拖动改位置、折叠球缩小与立体感强化、翻页停留 300ms 门控（仅渲染层；PDF 阅读页覆盖层）
> 实现约束：遵循 `ireader-dev-tasks`（任务 E：修改阅读器行为 / 渲染层组件）与 `ireader-code-conventions`（纯逻辑进 service、store 只做编排、中文注释）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 折叠后的圆图标小一点 | `.ai-ball` 直径 26px → 20px；`BALL_INSET_PX` 由固定 8px 改为 `BALL_SIZE × 0.3 = 6px`（锚点内收量随球径同步）；命中区用 `::before inset: -4px` 外扩到 28px，视觉变小但不影响点开 | 折叠任一译文框，球体肉眼小于现有版本；鼠标在球心附近 4px 外扩范围内点击仍能展开 |
| 2 | 折叠图标更有立体感 | 三层明暗叠加：① `radial-gradient` 左上高光 + 中段浅蓝 + 边缘深蓝的球面渐变；② `inset` 顶亮边 / 底反光 / 边缘折射环三组内阴影；③ `::after` 5×4px 镜面高光点 + 双层投影（接触影 + 悬浮影）；hover 放大 1.08、active 缩到 0.94 | 在深色漫画页与浅色漫画页各截一张折叠态截图，球体呈现明确的高光/明暗过渡与落地投影，不再是平涂半透明圆 |
| 3 | 翻译框只有鼠标悬浮才显示边框，且非悬浮时不显示阴影与右下角缩放图标（静默态淡化框的存在） | `.ai-box` 常态 `border: 1px solid transparent` + `box-shadow: none`；`:hover` / `:focus-within` 才显 `rgba(10,132,255,.45)` 描边 + `0 4px 16px rgba(0,0,0,.35)` 投影 + `0 0 0 3px rgba(10,132,255,.16)` 光晕环，`150ms` 淡入；`.ai-resize` 常态 `opacity: 0`，框 `:hover` / `:focus-within` / `.resizing` 时才浮现；规则限定 `:not(.ai-temp)`，加载/空/错误临时框保持既有常显描边 | 移入/移出译文框，边框、投影、右下角标三者同步淡入淡出；静默态框体无投影、无角标；框体尺寸与文字位置零抖动（`box-sizing: border-box` 已有） |
| 4 | 翻译框左键按住可拖动位置 | 框根节点 `@pointerdown.stop="startMove($event, rec)"`：按下记起点，位移超过 3px 才进入拖动；拖动期间只改本地 `previewRect` 内联百分比样式，`pointerup` 落库一次（`ai.applyMove`）；位置夹取到页盒内（`x + w ≤ 1`、`y + h ≤ 1`） | 拖动框到页面任意位置松手，框停留不动；重启应用/翻页后再回来，位置与拖动后一致；拖到页外时框边贴页边而不越界、宽高不变 |
| 5 | 折叠后的图标位置一并跟随 | 不新增字段：球的锚点本就由 `rec.rect.x/y` 推导（`ballStyle`），拖动改的是同一条 `rect` 并落库，故折叠/展开/重启后球与框始终同址 | 框拖到页面右下方 → 折叠，球出现在右下新位置 → 展开，框回到同一位置 |
| 6 | 翻页过程中，当前页停留 300ms 后再显示译文框，并防翻页抖动 | `ReaderView` 覆盖层门控升级为「持有计数 + 300ms 停留计时」（§8.4）：渲染中与卷曲动画在播期间一律隐藏，动画落定后当前页再稳住 300ms 才恢复；滑块逐帧跳页只重置计时；隐身期间同时屏蔽指针 | 连续快翻（热区连点 / 滚轮 / 方向键）时译文框全程不闪、不叠在卷曲上；停手后约 300ms 才淡入；翻页窗口内点击页面仍能正常翻页（不会点到隐形框）；缩放 / 单双页切换重排后同样只在稳定 300ms 后出现 |

**核心验收口径**：把任一译文框从页面左上拖到右下角松手 → 框体位置立即跟随且宽高不变 → 折叠后球出现在右下新位置 → 重启应用再打开该书，框与球仍在右下角，且框体宽高与拖动前一致（未被主进程 `resolveRect` 截窄）。

## 二、非目标（本期不做）

- **临时框不参与拖动**：加载 / 空兜底 / 错误框不落库、无稳定 id，拖动无持久化意义，保持现状（不可拖，也不会被误拖）。
- **折叠球本身不可拖**：用户诉求是「球位置跟随框」，球作为框的派生视图存在；球可拖会引入「球与框不同址」第二套位置语义，本期不做。
- 不做吸附对齐、网格对齐、多框一键排布、键盘方向键微调位置。
- 不改 `ai_translations` 表结构与 `ai:save` 契约：`rect_x / rect_y` 早已持久化，位置更新走既有整行覆盖语义。
- 不改 PDF / EPUB 阅读页的其他交互（热区翻页、拖拽平移、滚轮翻页逻辑），`ReaderView.onMouseDown` 已对 `.ai-layer` 内按下提前返回，无需改动。
- 不新增 npm 依赖（纯 CSS 渐变 + 阴影实现立体感）。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层：src/components/reader/AiTranslationLayer.vue ──────────────┐
│  pointerdown(框体) ─┬─ Shift 按下   → 直接 return（退化为文字选择）  │
│                     ├─ 滚动条按下   → 直接 return（交给滚动区）      │
│                     └─ 普通左键     → preventDefault + 记起点         │
│  pointermove        → 位移 > 3px 置 dragging，previewRect = moveRect()│
│  pointerup          → ai.applyMove(rec, previewRect.rect)             │
│                                                    │                  │
│  ballStyle(rec.rect) ←──────── rect 变化 ──────────┘（球自动跟随）    │
└────────────────────────────────────────────────────┼─────────────────┘
                                                     ▼
┌─ Pinia：src/stores/aiTranslation.ts ────────────────────────────────┐
│  applyMove() / applyResize() → commitRect()（本地先行 → 落库 → 回滚）│
│                                                    │                 │
│  ipc.ai.save({ ...fieldsOf(rec), rect })  （既有通道，整行覆盖）      │
└────────────────────────────────────────────────────┼─────────────────┘
                                                     ▼
┌─ 主进程：electron/services/aiService.ts ────────────────────────────┐
│  save() → resolveRect()（夹取 0~1；w 上限 = 1 - x）→ repo.update()   │
└─────────────────────────────────────────────────────────────────────┘
```

关键点：位置是**纯渲染层增量能力**，主进程与 DB 零改动；折叠球不做独立定位，永远由 `rect` 派生。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 拖动热区 | 整框可拖（除操作圆点、缩放手柄）；按住 **Shift** 拖动退化为文字选择 | 框内几乎被文字占满，若只留顶部拖动条则拖动热区过窄、不符合「按住翻译框」的直觉；Shift 作为显式逃生口保留复制译文的可能，代价是要记一个组合键（可发现性弱，接受） |
| 位置持久化 | 复用 `rect.x/y` + 既有 `ai:save` 整行覆盖，不新增字段/通道 | 位置与尺寸同属一个归一化矩形，拆字段会让「缩放/单双页切换后贴回原气泡」的换算逻辑分叉；现有 repo 已按 `rect_x/rect_y` 存取，零迁移成本 |
| 拖动落库时机 | 拖动中只改本地预览，`pointerup` 落库一次 | 与既有缩放手柄口径一致；拖动每帧写库会刷爆 IPC 且引入竞态覆盖 |
| 拖动与缩放预览状态 | 合并为单一 `previewRect`，`positionStyle` 一个数据源 | 两个独立 ref 会让「拖动中又拖手柄」这类交错手势产生优先级歧义，单源即天然互斥 |
| 折叠球尺寸 | 20px（命中区伪元素外扩到 28px） | 满足「小一点」观感，同时不牺牲点击性；球越小越需要在伪元素上补命中区 |
| 立体感实现 | 多层 `radial-gradient` + 三组 `inset` 阴影 + `::after` 高光点 + 双层投影，不用图片/滤镜画布 | 纯离线、零依赖；球要浮在任意漫画画面上，渐变 + 内阴影比位图更耐缩放，`backdrop-filter` 保留玻璃透感 |
| 悬浮边框风格 | 淡蓝描边 + 3px 光晕环，`150ms` 淡入，限定 `:not(.ai-temp)` | 品牌蓝同时承担「此处可按住拖动」的语义提示；排除临时框，避免不可拖的加载框也诱导弹出边框 |
| 边界夹取 | `x ∈ [0, 1-w]`、`y ∈ [0, 1-h]` | 主进程 `resolveRect()` 用 `w = min(w, 1-x)` 兜底，若渲染层允许 `x+w>1`，每次拖动都会把框**悄悄改窄**，必须在渲染层先保证不越界 |

## 四、核心算法与口径

### 4.1 拖动位移换算（`moveRect`）

```ts
// src/services/aiTranslation.ts（与 resizeRect 同文件、同风格）
export function moveRect(
  rect: AiRect,
  delta: { dx: number; dy: number },
  page: { width: number; height: number }
): AiRect {
  const { width, height } = page
  if (!(width > 0) || !(height > 0)) return rect   // 页盒未测量：原样返回
  const maxX = Math.max(0, 1 - rect.w)             // 必须扣掉宽高，否则主进程会截窄
  const maxY = Math.max(0, 1 - rect.h)
  return {
    x: clamp(rect.x + delta.dx / width, 0, maxX),
    y: clamp(rect.y + delta.dy / height, 0, maxY),
    w: rect.w,
    h: rect.h,
  }
}
```

口径说明：

- `delta` 为**相对按下点**的像素位移（不是逐帧增量），因此 `pointermove` 抖动或丢帧都不会累积误差。
- 宽高一律原样带回：拖动只改位置；`w = 1`（通栏框）时 `maxX = 0`，水平拖动自然失效（预期行为）。

### 4.2 手势判定顺序

```
pointerdown（框体，左键）
 ├─ e.shiftKey            → return（不 preventDefault，浏览器默认文字选择生效）
 ├─ 落在滚动区滚动条上     → return（长译文用滚动条查看时不被吞成拖动）
 ├─ preventDefault()      → 阻止拖选文字与原生拖拽
 ├─ getSelection().removeAllRanges() → 清掉按下前可能残留的选区
 └─ 记起点 { rect: {...rec.rect}, x: e.clientX, y: e.clientY, active: false }
pointermove → |dx| + |dy| >= 3px 才置 active 并写 previewRect（阈值内视为单击抖动，不落库）
pointerup / pointercancel → active 才 applyMove，否则只清理监听
```

### 4.3 边界场景防护清单

| 场景 | 行为 |
|------|------|
| 拖到页面左上/右下外侧 | 夹取到页盒边界，框体贴边停住，宽高不变 |
| 框宽/高等于 1（通栏） | 该轴不可移动（`maxX/maxY = 0`），不产生负值 |
| 拖动中页盒尺寸变化（缩放/单双页切换） | `pageSize` 由 ResizeObserver 更新，下一帧按新像素尺寸换算；`rect` 为归一化值，松手落库结果与视觉一致 |
| 拖动中换页/翻页动画淡出 | 覆盖层 `opacity: 0` 只影响显示；组件卸载时 `stopMove()` 清理监听，未落库的位移丢弃（与缩放一致） |
| 拖动中窗口失焦 / 指针被系统夺走 | `pointercancel` 兜底收尾，避免监听泄漏；不做落库 |
| 长译文出现滚动条后拖动滚动条 | `isScrollbarPress()` 判定按下点在 `clientWidth/clientHeight` 之外则 return，滚动条正常工作 |
| 拖动中按下右键 | 首帧 `e.button !== 0` 即 return，不进入拖动 |
| 按下左上角折叠 / 删除圆点 | `.ai-actions` 容器各挂 `@pointerdown.stop`，事件不冒泡到框根，既不进入拖动也不再 `preventDefault`（避免吞掉原有 click） |
| 按下右下角缩放手柄 | 手柄已有 `@pointerdown.stop="startResize(...)"`，与拖动互斥，同一时刻只有一个预览来源 |
| 缩放中指针拖出框外 | `resizingId` 驱动 `.resizing`，右下角标保持可见；收尾统一在 `stopResize` 清空 |
| 连翻（瞬切路径，`decision.burst`） | 每轮渲染的 release 与补播卷曲的 hold 交替重置计时，中间不出现「半隐半现」 |
| 卷曲被新一轮翻页揭除 | `cancelTurnCurl()` → 动画 `done` 兑现 → `releaseAiOverlay()` 正常退出，计数不泄漏 |
| 卷曲因无 2D 上下文同步结束 | `playPageCurl` 同步调 `onDone`，`done` 立即兑现，门控只存在一瞬 |
| 拖动底栏滑块连续跳页 | `renderSliderFrame` 只 `restartAiOverlaySettle()`：逐帧重置计时，停手 300ms 后才显示 |
| 渲染失败 / 被新一轮接管（`!painted`、`gen !== turnGen`） | `finally` 已 release，计时照常起算；新一轮 hold 会把它重置 |
| 门控期间点击页面 | `:deep(.ai-layer *)` 一并 `pointer-events: none`，不会点到隐形框，热区翻页照常 |
| 离开阅读页时正处停留窗口 | `onBeforeUnmount` 里 `clearAiOverlaySettle()`，rootEl 已空，无残留写 DOM |
| 选词模式（`selectable`）下拖框 | 框根 `@pointerdown.stop` 阻止冒泡，不会发起新框选；框仍可拖动 |
| 临时框（加载/空/错误） | 不绑定 `startMove`，不可拖动；且 `:not(.ai-temp)` 使其不弹悬浮边框 |
| 拖动落库失败 | `commitRect` 回滚到拖动前矩形并 `console.warn`，阅读不中断 |

## 八、渲染层实现

### 8.1 `src/services/aiTranslation.ts`（纯逻辑，新增 `moveRect`）

- 复用文件内已有的 `clamp`、`AiRect` 类型；注释风格与 `resizeRect` 对齐（中文说明「为什么必须扣掉宽高」）。

### 8.2 `src/stores/aiTranslation.ts`（编排层）

- 抽取私有 `commitRect(rec, rect, warnMsg)`：本地先行赋值 → `ipc.ai.save({ ...fieldsOf(target), rect: next })` → 失败回滚，逻辑取自现有 `applyResize`。
- `applyResize(rec, rect)` 保留原签名，内部委托 `commitRect(..., '[ai] 译文框尺寸保存失败')`（既有单测零改动）。
- 新增 `applyMove(rec, rect)`：委托 `commitRect(..., '[ai] 译文框位置保存失败')`；导出到 store return。
- 不做任何拖动状态持久化（拖动态属于组件本地 UI 状态）。

### 8.4 `src/views/ReaderView.vue`（覆盖层门控 + 300ms 停留）

把 `setAiOverlayFading(on: boolean)` 升级为「持有计数 + 停留计时 + 渲染门控」模型（单点接线，PDF 各翻页路径共用）：

```ts
const AI_OVERLAY_SETTLE_MS = 300
let aiOverlayHolds = 0                                   // 渲染 / 动画交错，计数归零才允许计时
let aiOverlayTimer: ReturnType<typeof setTimeout> | null = null
const aiOverlayHidden = ref(false)                       // 门控结果（响应式）：下发给子组件决定是否渲染

holdAiOverlay()          // 进门控：立即隐藏 + 作废未到期计时（新画面即将上屏）
releaseAiOverlay()       // 出门控：计数归零后重新起 300ms 停留计时
resetAiOverlayGate()     // 兜底：计数与计时一起归零（卸载）
```

**关键点：门控必须同步进入，并且要真正不渲染。** 只做淡出会留下「新页译文框先完整画一帧，再消失」的闪烁（120ms 淡出过程本身就是可见的），因此：

1. `runTurnPass` 拆成入口壳 + `runTurnPassInner`：壳在**第一个 `await` 之前** `holdAiOverlay()`，`finally` 收口。入口由 `currentDisplayPages` 的 pre-watch 调用，早于本次 DOM 更新，所以新页的框压根不会挂到 DOM 上。
2. `aiOverlayHidden` 通过 `:visible="!aiOverlayHidden"` 下发给 `AiTranslationLayer`，子组件用 `v-if` 整批不渲染（见 §8.3）；父级 `opacity: 0` 只作为橡皮筋等残留元素的兜底，并改成 `transition: none`（隐藏瞬时，恢复显示仍可淡入）。

接线位置：

| 位置 | 处理 |
|------|------|
| `runTurnPass` 入口壳 | 同步 `holdAiOverlay()`，`finally { releaseAiOverlay() }`，整轮（含渲染）都在门控中 |
| `playTurnCurl` 的 3 处调用（主翻页、连翻补播、滑块松手补播） | 统一走 `playTurnCurlHoldingAi(options)`：内部额外 `hold` + `curl.done.then(release)`，卷曲在播期间覆盖层保持隐藏（动画 z1、框 z2，否则新页框会叠在卷曲上） |
| 缩放重排（`watch` 内 `renderCurrentSpread`） | 在 `await nextTick()` **之前** hold，`try/finally` 收口；避免旧像素与新尺寸同帧出现 |
| 窗口 resize 防抖 | 回调开头 hold，`renderCurrentSpread().finally(release)` |
| 滑块逐帧贴图（`renderSliderFrame`） | 无需单独处理：它只在 `runTurnPassInner` 内被调用，已被入口门控覆盖（每帧 hold/release 即不断重置 300ms 计时） |
| `onBeforeUnmount` | `resetAiOverlayGate()`，避免卸载后触发残留状态 |

CSS 同步：`.reader-view.ai-overlay-fading .ai-layer { opacity: 0; transition: none }` 之外补

```css
/* 隐身期间也不吃指针：否则会点到看不见的框 / 选词热区，连带吞掉热区翻页（子元素各自声明了 auto） */
.reader-view.ai-overlay-fading :deep(.ai-layer),
.reader-view.ai-overlay-fading :deep(.ai-layer *) {
  pointer-events: none;
}
```
> 根节点也一并压制：`.ai-layer.selecting` 会把根重新设成 `auto`，只用后代选择器压不住它。

> 计时口径：**动画落定后再算 300ms**（不是翻页动作起算），因此连翻时每轮渲染 / 每次卷曲结束都会重置计时，只有真正停手满 300ms 译文框才出现。因为隐藏是「不渲染 + 瞬时」，这段时间屏幕上完全看不到框的残影。

### 9.3 交互说明

- 静默态刻意「隐身」：无描边、无投影、无操作圆点、无右下角标，只留白底与译文，避免译文框在画面上抢注意力；鼠标进入后才显描边 + 投影 + 光晕 + 操作圆点 + 缩放手柄。
- 悬浮边框只表达「可按住拖动」；操作圆点仍只在框 hover/focus 时浮现（既有规则不变）。
- 缩放中即使指针拖到框外，右下角标也保持可见（`.resizing`），不会出现「正在拖手柄而手柄消失」的断裂感。
- 单击框内文字不再产生选区；需要复制译文时按住 Shift 再拖动即可回到浏览器原生文字选择。
- 拖动距离小于 3px 视为单击，不写库；拖动结束后不再有额外视觉回弹（松手即定稿）。
- 长译文（框内出现滚动条）时，滚动条拖动不会被吞成框体拖动，可用滚轮或滚动条查看。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 框内文字不可直接选中 | 默认整框拖动，Shift 才恢复文字选择 | 「按住拖动」与「拖选文字」是同一手势，必须二选一；牺牲直接选字，换最大的拖动热区。若后续反馈强烈，可加「拖动仅从框顶 16px 起手」的开关 |
| Shift 逃生口可发现性 | 不加提示文案 / 不加 title | 按项目约定，自带可见文字的控件不加悬停提示；此处为图标框体，加 `title` 会与既有卡片提示语体系割裂；写入 §9.3 文档与发版说明即可 |
| 20px 球体命中区 | 视觉 20px，靠 `::before` 外扩到 28px | 外扩区在球体外仍属该球，两球相邻时可能互相争夺 8px 重叠——折叠球本就按框分散，实际重叠概率低，接受 |
| 球体在复杂画面上对比度 | 渐变 + 内阴影 + 白折射环 + 双层投影，保留 `backdrop-filter` | 极浅（纯白）画面上球体边缘仍靠 `inset` 深蓝边与投影区分；不使用位图，缩放后仍锐利 |
| 主进程 `resolveRect` 会截断宽高 | 渲染层 `moveRect` 保证 `x+w ≤ 1` | 若未来有其它入口绕过 `moveRect` 直接改 `x`，会出现「拖动后框变窄」的隐性缺陷；已在 §4.1 注释中固化原因 |
| 悬浮光晕与翻页淡出叠加 | 光晕走 `box-shadow`，淡出走父级 `opacity` | 两者不冲突；翻页期间覆盖层整体不渲染，光晕一并隐去，无需额外处理 |
| 门控期间框不渲染（`v-if`） | 用「不渲染」换「无闪烁」 | 代价：重排 / 翻页后长译文的滚动位置会回到顶部（DOM 重新挂载）；短译文无感，且门控只发生在画面本身在变的时刻，接受 |
| 静默态去投影后框体边界变弱 | 只保留白底与译文，靠明暗差区分；hover 才补投影 | 用户诉求是「淡化框的存在」，弱边界是预期效果；代价是在接近纯白的浅色画面上框缘不易辨认（文字仍清晰），若后续觉得过分，可只保留一层极淡 `0 1px 3px rgba(0,0,0,.12)` |
| 静默态隐藏缩放手柄 | `opacity: 0` 而非 `display: none`，且缩放中由 `.resizing` 保持可见 | 用 `opacity` 保留 150ms 过渡，避免 hover 瞬间闪断；手柄不隐藏指针事件（它在框内，不影响拖动热区），但静默态用户看不到它不会误触 |
| 拖动中丢失 `pointerup` | `pointercancel` 兜底，未落库位移丢弃 | 与缩放同口径；不引入 `setPointerCapture`，保持既有实现风格，风险为极小概率需重拖一次 |
| 不提供键盘微调 | 非目标 | 需求未涉及；将来若做可访问性增强，可在框 `focus` 时接方向键 ±1%（复用 `moveRect`） |
| 300ms 停留的体感延迟 | 计时从「动画落定」起算（卷曲 450ms + 停留 300ms ≈ 750ms） | 用户明确要求「当前页停留 300ms 后再显示」，宁可晚一点也不让框在动画里闪；若嫌慢，可把 `AI_OVERLAY_SETTLE_MS` 调到 150~200ms 或改成「动画一起算 300ms」（把 hold 换成 restart 计时） |
| 门控期间屏蔽指针 | 用 `:deep(.ai-layer *) { pointer-events: none }` | 否则隐身框会吞掉热区点击（比「看得见却点不动」更糟）；代价是 300ms 窗口内无法点折叠球，属预期 |
