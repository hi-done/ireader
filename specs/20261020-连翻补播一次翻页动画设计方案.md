# 连翻补播一次翻页动画设计方案

> 状态：已验证通过（2026-10-20，EPUB / PDF 连点均已实机确认：直达最终页、停手 ~220ms 后补播唯一一次卷曲；PDF 经渲染闸门后连点只渲染首末两页，卡顿消除）
> 目标版本：v1.2.6（沿用 `package.json` 当前 version，发版时由用户自行升级）
> 范围：PDF / EPUB 两个阅读引擎在「瞬间连续切换页」时的动画调度——连翻期间瞬切直达最终页，停手后补播唯一一次卷曲；不改卷曲视觉、滑块拖动主体逻辑与设置项
> 实现约束：遵循 `ireader-dev-tasks`（任务 E 阅读器行为 / 任务 F 验证流程）与 `ireader-code-conventions`（中文注释、纯逻辑单测、工程红线）；本次无 IPC / DB / 主进程改动

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|---|---|---|
| 1 | 瞬间按多次切换页时，直接跳转到对应页 | 沿用现有调度：EPUB 的净位移队列（`pendingDelta` 合并后一次 `goTo`）、PDF 的「世代号 + 最新请求胜出」（`turnGen`）；连翻期 `TurnPolicy` 返回 `snap`，不逐页播动画 | 1 秒内连点 10 次下一页，页码立即前进 10，中间页不出现逐页卷曲 |
| 2 | 与滑块翻页逻辑相同：跳到位后展示一次翻页动画 | 新增「连翻补播会话」：识别到连翻的第一刻截取起点画面（不阻塞导航），停手 `BURST_SETTLE_MS=220ms` 且队列空闲后，用该快照补播唯一一次 450ms 卷曲（不导航） | 连点 5 次停手：约 220ms 后出现一次卷曲，起点为连点前画面，终点为最终页；全程只有这一次动画 |
| 3 | 补播不得改变落点与进度 | 补播只做视觉回放：不调用 `goTo` / `next` / `prev`，不写 `navIndex`；终点透出实时 DOM（EPUB）或事后合成快照（PDF） | 补播前后页码、进度条、CFI 一致；退出重进恢复到最终页 |
| 4 | 与滑块、减弱动态、首尾页语义不冲突 | 滑块接管时清空补播会话（滑块自己松手补播）；`reducedMotion` 不补播；净位移为 0 / 首尾页无位移不补播 | 连翻后立即拖滑块只出现滑块补播一次；系统开启减弱动态时连翻全程无动画 |
| 5 | PDF 与 EPUB 表现一致 | 两端共用 `BURST_SETTLE_MS` 与 `canReplayBurst` 闸门、首帧快照口径、`zIndex: 1` 层级 | 两引擎分别按冒烟清单验证，观感一致 |

**核心验收口径**：1 秒内连点 10 次 → 画面立即到最终页（+10）；停手约 220ms 后播放唯一一次 450ms 卷曲，卷曲起点为连翻首帧画面；全程最多一条覆盖层、无冻结帧残留；补播前后页码 / CFI 完全一致。

## 二、非目标（本期不做）

1. **不改连翻判定阈值**：`RAPID_GAP_MS=160`、`RAPID_QUIET_MS=500`、动画启动预算（320 / 1200ms）与 `TurnPolicy` 状态机逻辑零改动。
2. **不做动画接力**：补播是一次独立卷曲，不从被打断动画的进度续播，也不为中间页补帧。
3. **不改滑块主体语义**：EPUB 仍 200ms 节流跳页、PDF 仍逐帧更新起点快照，松手补播唯一一次的现有行为不变；仅要求两者与连翻补播互斥。
4. **不新增设置项 / DB 字段 / 主进程代码**：无 IPC 通道、无 `shared/types.ts` 改动、无 `electron/**` 改动。
5. **不优化「第一下已起播动画被连点打断」的截图成本**：`capturePage` 不可取消，第一下的截图往返仍会发生；本文只规定后续补播行为。
6. **不改卷曲视觉参数**：450ms、`easeInOutCubic`、投影 / 暗化 / 高光参数不动。
7. **不做触摸手势与移动端适配**。

## 三、总体设计

### 3.1 分层数据流

```
┌─ 输入层 ──────────────────────────────────────────────────────────────┐
│ 键盘 / 热区点击 / 滚轮 / 底栏按钮（滑块单独会话，见 §4.4）              │
└───────────────┬───────────────────────────────┬───────────────────────┘
                │ EPUB                          │ PDF
                ▼                               ▼
   requestTurn(dir)                     reader.next() / prev()
   pendingDelta += ±1                   watch(currentDisplayPages)
   drainTurns() 串行消费                 runTurnPass()（turnGen 最新胜出）
                │                               │
                └──────────────┬────────────────┘
                               ▼
              TurnPolicy.decide → { mode: 'snap', burst: true }
                               │
                ┌──────────────┴───────────────┐
                │ 瞬切直达最终页（既有逻辑）     │
                │ + 首次 burst：建立补播会话      │
                │   记录起点页 / CFI，异步截首帧  │
                └──────────────┬───────────────┘
                               ▼
              停手 BURST_SETTLE_MS（220ms）且队列空闲
                               │
                               ▼
              canReplayBurst 闸门（无新输入 / 无卷曲 / 非拖动 / 有位移）
                               │
                               ▼
        playTurnCurl({ from: 首帧快照, zIndex: 1 }) → 唯一一次卷曲
                               │
                               ▼
        turnAnimator 单例（自然结束 / 新输入揭除，复用现有实现）
```

要点：

- **会话只在 burst 首帧建立一次**：会话记录「连翻序列起点页」与起点快照；后续每次输入只重置停手计时器，不重复截图。
- **补播不导航**：瞬切阶段已把页面推到最终页，补播只是把「起点画面 → 最终页」的卷曲视觉补回来，与滑块松手补播同构。
- **闸门纯函数化**：`canReplayBurst` 放 `turnPolicy.ts`，两端共用判据（EPUB 以 CFI + index 判重，PDF 以 index 判重），便于 Vitest 覆盖全部边界。
- **新输入优先**：补播在播时任何新翻页都会经 `discardTurn()` / `cancelTurnCurl()` 揭除覆盖层，队列继续消费，绝不阻塞输入。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 补播时机 | 停手 220ms | 略大于连翻判定阈值 `RAPID_GAP_MS=160`，停手即补播、观感贴近「本次翻页的动画」；取 500ms 会与停手明显脱节，像是迟到的动画 |
| 起点快照 | 连翻首帧，只截一次 | EPUB 全屏截图往返 200~300ms，逐轮截图会让连翻变卡；滑块会话同样是「首帧一拍」。首帧=连翻序列起点页，卷曲语义正确 |
| 会话建立点 | 首次识别为 `burst` 的那次瞬切 | 空闲后的第一下若播了完整动画，本身已有视觉交代；会话只需覆盖「被打断之后的瞬切序列」 |
| 补播内容 | 仅卷曲，不导航 | 页面已在最终页；再导航会破坏 `navIndex` 推演、触发多余的 epub.js 重建，还可能让进度回退 |
| 生效范围 | EPUB + PDF | 用户已确认；两端共用阈值与闸门，避免同一交互两种表现 |
| 会话清理 | 滑块首帧 / Home / End / 换书 / 尺寸变化 / 卸载 | 这些路径各自有明确落点或自己的补播，残留会话会导致双播或旧画面盖新页 |
| 端点层级 | `zIndex: 1` | 与现有主翻页、滑块补播一致：覆盖层低于工具栏 z2，卷曲期间工具栏保持可见 |
| PDF 快照方式 | `snapshotForTurn` canvas 合成 | 与现有 animate / 滑块补播同源，单次成本约 10~30ms；仅在会话首帧多付一次 |

## 四、核心算法与边界防护

### 4.1 会话状态与闸门

```ts
// turnPolicy.ts —— 阈值与闸门（纯逻辑，无 DOM 依赖）
/** 连翻停手到补播的静默时长（ms）：略大于 RAPID_GAP_MS，避免把连点误判为停手 */
export const BURST_SETTLE_MS = 220

export interface BurstReplayGate {
  /** 会话所属文档仍有效（token === openSeq / turnGen 未变） */
  tokenValid: boolean
  reducedMotion: boolean
  /** 起点快照是否拿到 */
  hasSnapshot: boolean
  /** 起点页索引；null = 未建立会话 */
  startIndex: number | null
  finalIndex: number
  /** 起点 / 终点 CFI（EPUB 用于识别「翻过去又翻回来」；PDF 传 null） */
  startCfi: string | null
  finalCfi: string | null
  /** 队列仍在消费 / 待执行净位移非 0 / 有卷曲在播 / 滑块拖动中 */
  queueBusy: boolean
  pendingDelta: number
  curlActive: boolean
  dragging: boolean
}

/** 补播闸门：只有「文档有效、有位移、无新输入、无在播动画」才允许补播 */
export function canReplayBurst(gate: BurstReplayGate): boolean {
  if (!gate.tokenValid || gate.reducedMotion || !gate.hasSnapshot) return false
  if (gate.startIndex == null) return false
  if (gate.queueBusy || gate.pendingDelta !== 0 || gate.curlActive || gate.dragging) return false
  if (gate.finalIndex === gate.startIndex) return false
  if (gate.startCfi != null && gate.startCfi === gate.finalCfi) return false
  return true
}
```

### 4.2 EPUB 会话与补播（`EpubReaderView.vue`）

```ts
let burstStartIndex: number | null = null
let burstStartCfi: string | null = null
let burstFromPromise: Promise<HTMLCanvasElement | null> | null = null
let burstSettleTimer: ReturnType<typeof setTimeout> | null = null

/** 连翻会话首帧：记录起点并异步截取起点画面，不 await（与导航并行） */
function beginBurstSession(startIndex: number): void {
  if (burstStartIndex != null) return
  burstStartIndex = startIndex
  burstStartCfi = store.current?.cfi ?? null
  const area = epubAreaEl.value
  if (!area || reducedMotion) return
  const rect = area.getBoundingClientRect()
  burstFromPromise = captureRegionToCanvas({ x: rect.left, y: rect.top, width: rect.width, height: rect.height })
    .catch(() => null)
}

/** 每次 burst 瞬切后重置停手计时；到期且队列空闲才走闸门 */
function scheduleBurstSettle(token: number): void {
  if (burstSettleTimer) clearTimeout(burstSettleTimer)
  burstSettleTimer = setTimeout(() => {
    burstSettleTimer = null
    if (token !== openSeq || burstStartIndex == null) return clearBurstSession()
    if (pendingDelta !== 0 || drainPromise !== null || isTurnCurlActive() || sliderDragging) return
    void finishBurstCurl()
  }, BURST_SETTLE_MS)
}

async function finishBurstCurl(): Promise<void> {
  const startIndex = burstStartIndex
  const startCfi = burstStartCfi
  const fromPromise = burstFromPromise
  const token = openSeq
  burstStartIndex = null; burstStartCfi = null; burstFromPromise = null
  if (startIndex == null || !fromPromise) return
  const from = await fromPromise            // 快照通常已就绪；未就绪则等它
  const area = epubAreaEl.value
  const root = rootEl.value
  const finalIndex = navIndex ?? store.current?.index ?? 0
  if (!canReplayBurst({
    tokenValid: token === openSeq,
    reducedMotion,
    hasSnapshot: !!from,
    startIndex,
    finalIndex,
    startCfi,
    finalCfi: store.current?.cfi ?? null,
    queueBusy: drainPromise !== null,
    pendingDelta,
    curlActive: isTurnCurlActive(),
    dragging: sliderDragging,
  }) || !from || !area || !root || !store.current) return
  const dir: 'forward' | 'back' = finalIndex > startIndex ? 'forward' : 'back'
  pushNavDiag(`[curl] burst play ${dir} from=${startIndex} to=${finalIndex}`)
  await playTurnCurl({
    container: root,
    target: area,
    from,
    fromRight: (dir === 'forward') === (store.direction === 'ltr'),
    zIndex: 1, // 低于控制栏 z2，与主翻页 / 滑块补播一致
  }).done
}

function clearBurstSession(): void {
  if (burstSettleTimer) { clearTimeout(burstSettleTimer); burstSettleTimer = null }
  burstStartIndex = null; burstStartCfi = null; burstFromPromise = null
}
```

接线位置：

- `doDrainTurns()`：`decision.burst === true && !snapOnce`（显式跳转不算连翻）时，在 `jumpTo` 之前调用 `beginBurstSession(from)`；每轮 burst 消费结束后调用 `scheduleBurstSettle(token)`；进入 `animate` 分支时先 `clearBurstSession()`——恢复正常单次翻页意味着上一段连翻序列已结束，残留会话不得跨段生效。
- `requestTurn()`：先 `if (burstSettleTimer) clearTimeout(burstSettleTimer)`，让新输入推迟补播（会话保留，继续累计）。
- `requestJump()`（滑块节流跳页 / Home / End）：`clearBurstSession()`——滑块有独立会话，显式跳转不补播。
- `onSlideInput()` 会话首帧：`clearBurstSession()`（双保险，滑块接管）。
- `doOpen()` / `onResize()` 防抖回调 / `onBeforeUnmount()`：`clearBurstSession()`。

### 4.3 PDF 会话与补播（`ReaderView.vue`）

```ts
let burstFromSnap: HTMLCanvasElement | null = null
let burstFromViewport: boolean | null = null
let burstStartIndex: number | null = null
let burstSettleTimer: ReturnType<typeof setTimeout> | null = null

// runTurnPass 内：cancelTurnCurl() 之后、nextTick() 之前（canvas 仍是旧画面）
if (decision.mode === 'snap' && decision.burst && !sliderActive && burstStartIndex == null) {
  const viewport = isVerticallyScrollable()
  burstFromSnap = snapshotForTurn(viewport)   // 瞬切路径仅此一次合成，成本 10~30ms
  burstFromViewport = viewport
  burstStartIndex = shown?.index ?? reader.currentIndex
}

// renderCurrentSpread 成功后
if (decision.burst) scheduleBurstSettle(gen)

function scheduleBurstSettle(gen: number): void {
  if (burstSettleTimer) clearTimeout(burstSettleTimer)
  burstSettleTimer = setTimeout(() => {
    burstSettleTimer = null
    if (gen !== turnGen) return                 // 新轮次接管：由它重新计时，不清会话
    if (sliderActive || !bookReady) return clearBurstSession()
    if (shown?.index !== reader.currentIndex) return // 最后一轮渲染未落定：放弃，避免旧画面卷曲
    finishBurstCurl()
  }, BURST_SETTLE_MS)
}

function finishBurstCurl(): void {
  const fromSnap = burstFromSnap
  const startIndex = burstStartIndex
  const viewport = burstFromViewport
  clearBurstSession()
  const finalIndex = reader.currentIndex
  if (!canReplayBurst({
    tokenValid: true,           // gen 已在 schedule 校验
    reducedMotion,
    hasSnapshot: !!fromSnap,
    startIndex,
    finalIndex,
    startCfi: null,
    finalCfi: null,
    queueBusy: false,           // PDF 无队列；新轮次由 gen 拦截
    pendingDelta: 0,
    curlActive: isTurnCurlActive(),
    dragging: sliderActive,
  }) || !fromSnap || viewport == null || !rootEl.value) return
  const target = viewport ? pageAreaEl.value : pageContentEl.value
  const toSnap = target ? snapshotForTurn(viewport) : null
  if (!toSnap || !target) return
  const dir: 'forward' | 'back' = finalIndex > (startIndex as number) ? 'forward' : 'back'
  playTurnCurl({
    container: rootEl.value,
    target,
    from: fromSnap,
    to: toSnap,
    fromRight: (dir === 'forward') === (reader.direction === 'ltr'),
    zIndex: 1,
  })
}
```

清理点：`doOpen`、`onResize` 防抖回调、`onSlide`（任何拖动输入）、`onBeforeUnmount`。PDF 的 `snapshotForTurn` 返回 null 时会话仍标记为已建立但无快照 → 闸门拒绝补播，整段连翻不补（比中途截到错误页更稳）。

**渲染闸门（PDF 连点卡顿修复）**：`pdf.js` 渲染任务不可取消，原实现对每次输入都提交整组渲染（双页 = 2 个任务），连点 10 次约 20 个任务排队抢主线程，是 PDF 连点明显卡顿、与 EPUB 观感不一致的根因。现将 `renderCurrentSpread` 串行化：每次调用同步递增 `renderSeq` 并挂在 `renderChain` 之后执行，排队期间序号已前移的调用直接返回 `false`；`runTurnPass` 在渲染前 `await renderChain` 并按世代号退出被接管的轮次。连点 10 次只有首、末两页真正执行，与 EPUB 净位移合并的效果对齐。

### 4.4 与滑块会话的边界

| 场景 | 处理 |
|---|---|
| 连翻后立即拖滑块 | `onSlide` / `onSlideInput` 清连翻会话与计时器；滑块松手只补播自己的一次 |
| 滑块松手补播期间按键盘翻页 | `requestTurn` 经 `discardTurn()` 揭除滑块补播；本次输入按 `TurnPolicy` 决定 animate / snap，必要时建立新的连翻会话 |
| 连翻会话存在时 Home / End | `requestJump` 清会话，全程无补播（显式跳转不播动画的既有语义） |
| 连翻会话存在时换书 / 改窗口尺寸 | `openSeq++` 后清会话，快照 Promise 结果直接丢弃 |

### 4.5 边界场景防护

| 场景 | 行为 |
|---|---|
| 净位移为 0（如连点 3 次下一页再 3 次上一页） | EPUB 以 CFI 判重、PDF 以 index 判重 → 不补播 |
| 首 / 尾页连点无位移 | `effective === 0` 不建立会话 → 不补播 |
| 系统减弱动态 | 不截图、不补播 |
| 起点快照失败 | 闸门拒绝，静默跳过（无日志噪音，仅 `[curl] burst skip` 诊断） |
| 补播等待快照期间又有输入 | 闸门 `pendingDelta !== 0` → 放弃本次补播；新输入继续瞬切并在停手后重新走流程 |
| 补播在播时又有输入 | `requestTurn` → `discardTurn()` 揭除覆盖层，队列继续；不叠层 |
| 补播期间换书 / 尺寸变化 | `openSeq` 变化 → token 失效，补播不进行 / 立即揭除 |
| PDF 补播时最后一轮渲染未落定 | `shown.index !== currentIndex` → 放弃，不做旧画面卷曲 |
| 连点停手后超过 `RAPID_QUIET_MS` 才再按 | 属正常单次翻页（animate），此时若旧会话仍在补播 → 新输入揭除补播，播新动画 |

## 九、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|---|---|---|
| 补播延迟 | 220ms + 等待快照（EPUB 全屏约 200~300ms） | 实际起播可能晚至 300~450ms，可能仍略带「迟到感」；若实机反馈明显，只调 `BURST_SETTLE_MS` 或改「快照未就绪即放弃」 |
| 起点页差一页 | 会话起点取「首次 burst 前的画面」 | 若第一下播了 animate，补播起点是该动画的终点页而非连点前页；卷曲视觉上不可辨，换来实现简单、无需复用被揭除的快照 |
| 连翻期多一次截图 | EPUB 会话首帧截图一次 | 与第一下 animate 的截图可能叠加（第一下 animate 被打断时仍付一次往返），但只发生在连翻第一拍；可接受 |
| PDF 瞬切路径多一次合成 | 会话首帧 `snapshotForTurn` | 单次约 10~30ms，仅首拍；不改变后续瞬切轮次零快照的既有原则 |
| PDF 渲染闸门 | 连点时只有首、末两页真正渲染 | 卡顿从「每输入一次整组渲染」降为两次；若首帧渲染恰在最后一轮输入前完成，仍会短暂显示首帧后再跳末页，属预期行为 |
| 补播被新输入打断 | 立即揭除，不做续播 | 与现有「动画中途翻页即揭除」语义一致；用户再点说明更关心跟手 |
| 补播丢失 | 队列忙 / 渲染未落定 / 截图失败时静默放弃 | 宁可不播，也不让旧画面卷到错误页面；诊断面板保留 `[curl] burst skip` 便于排查 |
| 快照内存 | 会话只持有一张 canvas | 补播结束或清理即释放，无累积 |
