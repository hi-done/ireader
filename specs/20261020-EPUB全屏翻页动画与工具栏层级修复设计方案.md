> 状态：已验证通过（2026-10-20，2K 全屏实机确认动画稳定播放、工具栏全程可见）。最终参数：预算 1200ms / 降采样 0.6 / 截图不隐藏工具栏
> 目标版本：v1.2.6（沿用 `package.json` 当前 version，发版时由用户自行升级）
> 范围：仅 EPUB 阅读页的翻页动画调度与截图链路（播前预算、主进程截图降采样、截图策略、卷曲覆盖层层级），不含卷曲视觉、PDF 侧与设置项改动
> 实现约束：遵循 `ireader-dev-tasks`（任务 E 阅读器行为 / 任务 F 验证流程）与 `ireader-code-conventions`（中文注释、纯逻辑单测、工程红线）；本次无 IPC 契约变更、无 DB 改动

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | EPUB 翻页动画在全屏显示下异常，会消失（用户确认：**每次都完全不出现**，直接切到新页） | `animatedTurn` 的播前预算由固定 `EPUB_ANIM_BUDGET_MS`（320ms）改为按视口物理像素面积分级：大面积视口用 `LARGE_VIEWPORT_ANIM_BUDGET_MS`（1200ms）；主进程 `window:captureRegion` 对大面积截图先 0.6 倍降采样再编码 PNG；截图失败重试一次；补齐 `[curl]` 耗时诊断 | 2K（2560×1440）或 1920×1080 全屏、图片型 EPUB 慢速翻页 10 次，10 次全部出现卷曲（无一次直接跳页）；DEV 面板 `[curl] play` 的 `d` < `budget`，`shot` 像素约为原截图的 60%（与窗口 DIP×DPR 同量级） |
| 2 | 让工具栏和 PDF 那样在最上层，而不是（翻页时）消失 | **截图不隐藏工具栏（与 PDF 一致）**；EPUB 两处 `playTurnCurl` 显式传 `zIndex: 1`，低于顶栏/底栏 `z-index: 2` | 翻页全程工具栏可见、叠在卷曲动画之上；快照中的工具栏像素被真实工具栏覆盖，无可见「幽灵栏」 |

**核心验收口径**：在 1920×1080 全屏、工具栏可见状态下慢速翻页 10 次 → 10 次卷曲全部播放，且卷曲播放期间顶栏/底栏始终可见、不被覆盖层遮挡；非全屏 1280×800 窗口的动画预算、截图分辨率与视觉行为与改动前完全一致。

## 二、非目标（本期不做）

1. **不改卷曲视觉**：`src/services/pageCurl.ts` 的 450ms 时长、缓动、投影/暗化/高光参数零改动；只改覆盖层 `zIndex` 传参（该参数已存在）。
2. **不改 PDF 侧**：`ReaderView.vue` 本就不隐藏工具栏、两处调用已传 `zIndex: 1`，行为已符合目标，本期不动。
3. **不改 IPC 契约**：`CaptureRegionRect` 不新增字段，`window:captureRegion` 的入参与返回类型不变（降采样在主进程按面积自动判定）。
4. **不引入 JPEG/WebP 截图编码**：已选「0.6 倍降采样」（实机全屏 0.75 时 `cap≈310~375ms` 仍偏慢后下调）；若 4K 高 DPI 下仍超预算，再把「改用 `nativeImage.toJPEG` 或按目标像素自适应降采样」作为后续优化另开方案。
5. **不新增设置项与 DB 字段**：不提供「翻页动画开关/速度」，不迁移数据库。
6. **不改快速连翻策略**：`RAPID_GAP_MS` / `RAPID_QUIET_MS` / `EPUB_ANIM_BUDGET_MS` 语义不变，只新增大面积视口的预算档位。
7. **不改滑块拖动节流与补播语义**：仍为 200ms 节流瞬切 + 松手补播唯一一次卷曲；首帧截图含底栏像素的既有取舍保留。
8. **不改 `document.fullscreenElement` / 窗口全屏相关行为**：预算按视口面积判定，不依赖全屏 API 状态；Esc 退出逻辑（`src/views/EpubReaderView.vue` 的 `onKeydown`）保持现状。

## 三、总体设计

### 3.1 分层数据流

```
┌─ 输入层 ──────────────────────────────────────────────────────────────┐
│ 热区点击 / 键盘 / 滚轮 / 底栏上一页下一页                              │
└───────────────────────────────┬───────────────────────────────────────┘
                                ▼
                 requestTurn → drainTurns → animatedTurn
                                │
        ┌───────────────────────┴────────────────────────┐
        │ ① rect = .epub-area.getBoundingClientRect()     │
        │ ② ipc.window:captureRegion（不隐藏工具栏）──────┼──► 主进程
        └───────────────────────┬────────────────────────┘   capturePage
                                ▼                             → 面积 > 200 万？
                  冻结帧上屏 → 导航 → relocated               → resize 0.6 → toPNG
                  → waitViewsSettled(250ms)                       │
                                ▼                                 │
                  播前检查：pendingDelta / sliderDragging          │
                           / d > 分级预算                          │
                                ▼                                 │
                  playTurnCurl({ zIndex: 1 }) ◄───────────────────┘
                                │
                                ▼
        覆盖层 z1 ＜ 顶栏/底栏 z2：工具栏始终叠在卷曲动画之上
```

要点：

- **动画消失的根因在「播前整体耗时检查」**：链路中唯一会因全屏而系统性变慢的环节是「截图 → PNG 编码 → IPC → 解码」，而 `animatedTurn` 在播放前用固定 320ms 整体预算判定，超过即静默 `skip play`。全屏面积使该段耗时按像素量近似线性增长，这解释了全屏下每次翻页都跳过动画。
- **成本从两头削**：主进程降采样（减少编码/传输/解码量）＋ 大面积视口放宽预算（容忍剩余成本）；两端用同一「物理像素面积 200 万」阈值，口径一致。
- **工具栏层级与截图彻底解耦**：覆盖层降到工具栏之下后，截图无需隐藏工具栏（与 PDF 一致）；快照里的工具栏像素被真实工具栏完全覆盖，工具栏全程可见。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 全屏动画消失的根因判定 | 全屏截图链路耗时超过固定 320ms 播前预算，被 `skip play` 静默跳过 | 用户确认症状为「完全不出现」；代码中唯一会静默放弃播放的整体耗时检查就是该预算，且该段成本随截图像素量近似线性增长。落地时以 `[curl] play/skip` 的 `d`、`cap`、`shot` 实测值复核 |
| 预算分级依据 | 视口物理像素面积 `innerWidth × innerHeight × dpr²`，≥200 万用 1200ms | 成本由像素面积而非「是否全屏」决定；同时覆盖最大化到 1080p 的窗口、高 DPI 小窗口；不依赖 `document.fullscreenElement` 与窗口全屏状态是否一致 |
| 降采样落点 | 主进程 `window:captureRegion` 内按面积自动降采样 | 成本发生在主进程编码与 IPC 传输，渲染层无法削减；不做契约扩展，避免 `shared/types.ts` / `preload.ts` / `ipc.ts` 三处连锁改动，也避免两侧各判一次「是否全屏」 |
| 降采样比例 | 0.6（面积阈值以上固定启用；实机全屏 0.75 时 `cap≈310~375ms` 仍偏慢，用户确认下调） | 像素量降至约 36%，2K 全屏快照 1536×864；旧页快照仅在卷曲位移/暗化中短暂可见，结束后新页为实时清晰视图 |
| 工具栏策略 | 截图不隐藏工具栏 + 覆盖层 `zIndex: 1`（与 PDF 一致） | 覆盖层在工具栏之下，快照中的工具栏像素被真实工具栏盖住；换来工具栏全程可见，并省去两帧等待 |
| 截图失败处理 | 立即重试一次，仍失败才降级无动画 | 全屏 `capturePage` 偶发空图会直接表现为「动画消失」；一次重试的成本远低于丢失动画，且不改变既有降级语义 |
| 滑块补播层级 | `finishSlideCurl` 同样传 `zIndex: 1` | 与主翻页统一「工具栏在最上层」的约定，避免松手补播时又一次遮住底栏 |
| 预算常量与选择函数位置 | `src/services/turnPolicy.ts` 新增常量与 `pickEpubAnimBudget` 纯函数 | 与 `RAPID_GAP_MS` / `EPUB_ANIM_BUDGET_MS` 同处集中调参；纯函数可进 Vitest，避免把「面积阈值」散落在视图三元表达式里 |

## 四、核心算法与边界防护

### 4.1 动画启动预算分级（`turnPolicy.ts`）

```ts
/** 目标页就绪超过该值则放弃补播动画（EPUB，ms）；非大面积视口沿用 */
export const EPUB_ANIM_BUDGET_MS = 320

/** 大面积视口判定阈值（物理像素 = DIP 宽 × 高 × DPR²，约等于 1080p） */
export const LARGE_VIEWPORT_PIXELS = 2_000_000

/**
 * 大面积视口（全屏 / 高 DPI 大窗口）的动画启动预算（ms）。
 * 全屏截图 → PNG 编码 → IPC → 解码的往返成本远超窗口模式，320ms 会让整段动画被跳过；
 * 放宽仅影响「无新输入的单次翻页」是否补播迟到动画，连翻仍由 pendingDelta 兜底瞬切
 */
export const LARGE_VIEWPORT_ANIM_BUDGET_MS = 1200

/** 按视口物理像素面积选择 EPUB 动画启动预算：达到阈值即放宽 */
export function pickEpubAnimBudget(viewportPixels: number): number {
  return viewportPixels >= LARGE_VIEWPORT_PIXELS
    ? LARGE_VIEWPORT_ANIM_BUDGET_MS
    : EPUB_ANIM_BUDGET_MS
}
```

视图侧采样（`animatedTurn` 开头，与 `t0` 同一时刻）：

```ts
const dpr = window.devicePixelRatio || 1
const viewportPixels = window.innerWidth * window.innerHeight * dpr * dpr
const budget = pickEpubAnimBudget(viewportPixels)
```

### 4.2 截图降采样尺寸计算（`electron/services/captureShot.ts`）

```ts
/** 截图降采样阈值（物理像素）：超过该面积的 PNG 编码/传输会拖垮全屏翻页动画 */
export const SHOT_DOWNSAMPLE_PIXELS = 2_000_000
/** 大面积截图降采样比例（0.6 → 像素量约 36%） */
export const SHOT_DOWNSAMPLE_SCALE = 0.6

export interface ShotSize {
  width: number
  height: number
}

/**
 * 按物理像素面积计算降采样后的截图尺寸；单位与入参一致（NativeImage 的 getSize 尺寸）。
 * 返回 null 表示无需降采样。dpr 由调用方传入（主进程取显示器实际缩放因子）。
 */
export function computeShotSize(width: number, height: number, dpr = 1): ShotSize | null {
  if (!Number.isFinite(width) || !Number.isFinite(height) || width <= 0 || height <= 0) return null
  const safeDpr = Number.isFinite(dpr) && dpr > 0 ? dpr : 1
  if (width * height * safeDpr * safeDpr <= SHOT_DOWNSAMPLE_PIXELS) return null
  return {
    width: Math.max(1, Math.round(width * SHOT_DOWNSAMPLE_SCALE)),
    height: Math.max(1, Math.round(height * SHOT_DOWNSAMPLE_SCALE)),
  }
}
```

主进程 handler 编排（`window:captureRegion`）：

```ts
const image = await win.webContents.capturePage({ x, y, width, height })
if (image.isEmpty()) {
  throw { code: 'UNKNOWN', message: '截图失败：未取到画面' }
}
// 大面积截图（全屏/高 DPI）先降采样再编码：PNG 编码 + IPC 传输 + 渲染层解码是
// 全屏翻页动画超出启动预算的主因；快照在卷曲中会被 pageCurl 归一化拉伸回目标尺寸。
// DPR 取显示器实际缩放因子而非 NativeImage.getScaleFactors()：
// capturePage 返回的 NativeImage 不可假定携带与屏幕一致的缩放标记，用它换算会低估物理像素面积
const size = image.getSize()
const dpr = screen.getDisplayMatching(win.getBounds()).scaleFactor || 1
const target = computeShotSize(size.width, size.height, dpr)
const shot = target
  ? image.resize({ width: target.width, height: target.height, quality: 'best' })
  : image
// 极端内存紧张时 resize 可能返回空图：回退原图，不阻断翻页
return (shot.isEmpty() ? image : shot).toPNG()
```

### 4.3 截图策略（`EpubReaderView.vue`）

与 PDF 一致：**截图不隐藏工具栏**。覆盖层 `zIndex: 1` 低于工具栏 `z-index: 2`，快照中的工具栏像素始终被真实工具栏盖住。

```ts
// 1. 截图不隐藏控制栏（与 PDF 一致）：覆盖层 z1 低于工具栏 z2，
//    快照里的工具栏像素始终被真实工具栏盖住；工具栏全程可见，也省去两帧等待
if (token !== openSeq) return
if (pendingDelta !== 0) {
  // 进入本函数后来了新输入：此时尚未截图，代价最小
  discardTurn()
  await jumpTo(target, delta, token)
  return
}

const shot = () => {
  const rect = area.getBoundingClientRect()
  return captureRegionToCanvas({ x: rect.left, y: rect.top, width: rect.width, height: rect.height })
}
let from: HTMLCanvasElement | null = null
try {
  from = await shot()
} catch {
  // 全屏 capturePage 偶发空图/失败：立即重试一次，仍失败才降级无动画
  pushNavDiag('[curl] capture fail → 重试一次')
  try {
    from = await shot()
  } catch {
    from = null
    pushNavDiag('[curl] capture fail → 无动画')
  }
}
```

### 4.4 边界场景防护

| 场景 | 防护 |
|---|---|
| 全屏截图链路耗时高于 320ms | 面积 ≥200 万物理像素时预算放宽到 1200ms；主进程先降采样再编码（双管齐下） |
| 4K/极慢机器降采样后仍超预算 | 放弃本次补播动画，页面已上屏不阻塞后续输入；`[curl] skip play` 输出 `d`/`budget`/`shot`，作为后续再优化依据 |
| 全屏 `capturePage` 返回空图/失败 | 立即重试一次；仍失败则不冻结帧、不播动画，正常完成导航 |
| 截图期间来了新输入 | 既有 `pendingDelta` 检查（截图前、截图后、播前）继续生效，代价最小处提前放弃 |
| 截图期间窗口 resize / 换书 | 既有 `openSeq` 检查点在每个 await 后退出；`discardTurn()` 揭除冻结帧并由新流程接管 |
| 工具栏可见时翻页 | 全程可见；快照中的工具栏像素被真实工具栏覆盖（与 PDF 同策略） |
| 工具栏本不可见时翻页 | 快照不含工具栏像素，无幽灵栏 |
| 卷曲期间工具栏自动隐藏计时到期 | 翻页操作会重置隐藏计时，卷曲 450ms 内不会到期；即使到期，真实工具栏淡出后短暂透出快照中的半透明栏位，约 0.2s 内结束 |
| 滑块松手补播 | 传 `zIndex: 1`；快照含底栏像素属既有取舍（spec 已接受 thumb 冻结），真实底栏覆盖其区域 |
| 系统「减弱动态效果」 | 直通瞬切，预算与截图均不参与 |
| 非全屏 1280×800 窗口 | 面积 <200 万 → 预算仍 320ms、不降采样，行为与改动前一致 |
| 组件卸载 / 跨书打开 / resize | 既有 `discardTurn()` 揭除冻结帧的逻辑保留；`animatedTurn` 的 `finally` 仅在 `freezeEl === from` 时清理，不误删后续流程的快照 |

## 十一、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|---|---|---|
| 0.6 倍降采样 | 用旧页快照的清晰度损失换截图链路提速 | 快照仅在卷曲位移/暗化中可见，结束后新页为实时清晰视图；2K 全屏快照 1536×864，若仍超预算可再下调或改 JPEG（另开方案） |
| 全屏预算 1200ms | 放宽到足以覆盖降采样后的剩余链路成本 | 最坏情况动画迟到约 1.2s 才播；期间若有新输入，`pendingDelta` 仍会直接瞬切，不会播迟到动画 |
| 面积阈值 200 万像素 | 用「成本代理」替代「是否全屏」判断 | 高 DPI 中等窗口（如 1600×1000@1.25）也会放宽预算并降采样——其截图成本确实同样高，属预期行为；1280×800 常规窗口不受影响 |
| 固定 0.6（非自适应） | 实现与解释都更简单 | 若 4K@2x 仍超预算，扩展点为「按目标像素自适应比例」或「改 JPEG 编码」，需另开方案 |
| 截图不隐藏工具栏 | 与 PDF 同策略，工具栏零闪烁 | 快照中的工具栏像素被真实工具栏覆盖；仅当工具栏恰好在卷曲 450ms 内淡出时，会短暂透出快照中的半透明栏位（翻页操作会重置隐藏计时，实际难触发） |
| 滑块补播快照含底栏像素 | 保留既有取舍（拖动首帧不能瞬隐底栏） | 覆盖层降到 z1 后，残影出现在半透明底栏下方、随翻起块移动；既有无此问题是因为覆盖层 z5 直接把底栏盖住，本期以「工具栏常驻置顶」优先 |
| 失败重试一次 | 异常路径额外增加一次截图耗时 | 仅在第一次失败时发生；重试期间工具栏不受影响 |
| 诊断仅 DEV | 沿用 `pushNavDiag` 的收集开关 | 正式版无 `[curl]` 日志，验证与阈值复核须在 `npm run dev` 下进行 |
| `NativeImage` 尺寸/DPI 语义 | 实测 2K 全屏（2560×1440）0.75 时输出 1920×1080，截图往返 `cap≈310~375ms`；DPR 统一取 `screen.getDisplayMatching(...).scaleFactor`，不依赖 NativeImage 自报的 scaleFactors | `resize` 后以 `shot.isEmpty()` 回退原图；实机日志用 `shot=` / `cap=` 复核输出像素与耗时 |
| 全屏动画消失的二次排查 | 本期以「预算 + 降采样 + 重试 + 诊断」四层兜底 | 若实测 `d` 未超预算而动画仍不出现，`[curl] capture fail` / `no-move skip` 可区分截图与位移原因；若两者皆无，则为 `token !== openSeq` 的换书/尺寸作废路径，需结合 resize 时序排查 |
