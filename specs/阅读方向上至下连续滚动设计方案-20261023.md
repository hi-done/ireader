# 阅读方向「上→下」连续滚动设计方案

> 状态：设计稿（待确认）
> 目标版本：v1.3.0（与 package.json 当前版本一致；本期不主动修改版本号，由发版时确定）
> 范围：新增阅读方向 ttb（上→下）：PDF / CBZ 与 EPUB 的纵向连续滚动、固定页间隙、禁用翻页动画、方向入口与三语文案
> 实现约束：遵循 `ireader-dev-tasks`（任务 D/E/F；本期无任务 A/B 改动）与 `ireader-code-conventions`（Result 契约、中文注释、纯函数可测、禁止新增网络依赖）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 阅读方向增加「上→下」 | `shared/types.ts` 的 `Direction` 增加 `'ttb'`；进度、设置、阅读页入口同步 | 设置页与阅读页均可选「上→下」，重开保持 |
| 2 | 上→下时页面纵向连续滚动 | 新增 `VerticalScrollView.vue` + `verticalLayout.ts`；按行自上而下排列，原生滚动 | 滚轮连续滚动，无分屏吸附、无整页跳变 |
| 3 | 上下页之间留固定间隙 | 行间常量 `VERTICAL_ROW_GAP = 16`，行内 0；文字型 EPUB 章节视图间 16px | 任意相邻行像素间距恒为 16px（含双页行） |
| 4 | 不播放翻页动画 | ttb 下短路 PDF/CBZ 与 EPUB 的 turn 管线；pageCurl、冻结帧、位图淡入均不参与 | 键盘、热区、滑块、连滚均无卷曲/淡入 |
| 5 | 沿用现有双页 | PDF/CBZ 与图片型 EPUB 每行两页并排，行高取行内较高页 | 双页行内 0 间隙、行间 16px、页垂直居中 |
| 6 | 沿用现有缩放 | `fitWidth / fitHeight / original / custom` 重新映射为行盒尺寸；EPUB 图片型缩放映射为行宽比例 | 四档切换后布局正确，滚动锚点不跳 |
| 7 | EPUB 也支持上→下 | 文字型走 epub.js 连续流；图片型走 canvas 纵向视图（支持双页） | 两类 EPUB 均可纵向阅读并恢复进度 |
| 8 | 进度可恢复 | 页码口径 = 视口顶部所在行的首页；`direction` 落盘为 `'ttb'` | 退出重进定位到同一行（误差 0 行） |

**核心验收口径**：在 1080p 窗口打开 200 页 CBZ，切到「上→下」后，任意相邻行间距恒为 16px；连续滚动 10 屏不出现整页卷曲/淡入动画；停止滚动 1s 内进度落盘；退出重进定位到同一行。

## 二、非目标（本期不做）

- 不做左→右 / 右→左的连续横向滚动（横向仍为分屏翻页）。
- 不做 `scroll-snap` 吸附、惯性曲线定制、双击缩放、页间阴影/标尺。
- ttb 下不做离屏位图缓存与预渲染：只渲染视口窗口内页面（原因见 §11 内存取舍）。
- 文字型 EPUB（reflowable）纵向不做双页：连续正文无页边界，epub.js 纵向连续流会强制 `layout.spread('none')`（见 §3.2）。
- 不新增 npm 依赖，不改数据库 schema，不新增/修改 IPC 通道。
- 不做按书的独立方向偏好：沿用现有「全局默认方向 + 每书进度内 direction」。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ────────────────────────────────────────────────────────────┐
│ ReaderView.vue（PDF / CBZ）                                         │
│   direction === 'ttb' ? VerticalScrollView.vue : 现有 page-area      │
│      │ rows / initialPage / sizing / source                         │
│      ▼                                                              │
│ VerticalScrollView（窗口化挂载 + 滚动定位 + 测量校正 + 进度上报）      │
│      │ verticalLayout.ts（纯函数：行盒 → tops / height / 窗口）       │
│      ▼                                                              │
│ VerticalPageSource.render(page, canvas, target)                     │
│      ▼                                                              │
│ pageRenderer.renderPageToCanvas → pdf.ts / cbz.ts → ireader://       │
│                                                                     │
│ EpubReaderView.vue（EPUB，按 layout 分引擎）                          │
│   ttb + reflowable   → epub.js manager:'continuous' + flow:'scrolled'│
│   ttb + pre-paginated → VerticalScrollView + epubVertical.ts         │
│                         section.load + book.archive.createUrl        │
│                         → ImageBitmap → canvas                       │
└─────────────────────────────────────────────────────────────────────┘
```

主进程、SQLite、IPC 均不参与本次改动：方向只是既有字段的新取值，渲染全部在渲染进程完成。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 适用范围 | PDF / CBZ + EPUB | 已与用户确认；EPUB 有独立阅读器，需按 layout 分引擎处理 |
| 滚动形态 | 连续滚动（非分屏吸附） | 已确认；条漫阅读习惯；虚拟化只渲染视口附近页面 |
| 双页语义 | 每行两页并排，行高取高者，行内 0 间隙 | 已确认；复用 `buildSpreads` / `buildPrePaginatedSpreads`，与横向双页贴齐 |
| 间隙 | 行间 16px，行内 0 | 需求「固定间隙」；与现有双页贴齐风格一致 |
| 翻页输入 | 保留热区/键盘/滑块/上下页按钮，瞬时滚到目标行顶部 | 已确认；无动画，不需要串行动画队列 |
| 动画 | ttb 全局禁用 pageCurl、冻结帧快照、位图淡入 | 需求原文「不播放翻页动画」 |
| EPUB 文字型双页 | 禁用（按钮置灰 + 提示） | epub.js 连续流 `updateAxis('vertical')` 强制 `layout.spread('none')`；连续正文无「页」概念 |
| EPUB 图片型双页 | 自建 canvas 纵向视图，行内两页并排 | 已确认；epub.js 连续流无法双页，图片型每 section 一张图可安全提取 |
| EPUB 图片型缩放 | 100% = 满行宽（单页视口宽/双页半宽），百分比缩放行宽，超出视口横向滚动 | 纵向连续滚动以宽度为基准最自然；与 PDF `fitWidth` 的视觉一致 |
| 进度口径 | 页 = 视口顶部所在行的首页（`firstPage`） | 与现有 `reading_progress.page` 存 `spread.firstPage` 的约定一致，重开可复现 |
| 方向入口 | 顶栏方向按钮改为三档 `SelectMenu`；`r` 键循环 ltr→rtl→ttb | 三态无法用二态切换按钮表达；与设置页交互一致 |
| 数据与 IPC | 无迁移、无新通道 | `reading_progress.direction` 为 TEXT 无 CHECK；settings 整体 JSON 存取 |

### 3.3 方向枚举与语义

```ts
// shared/types.ts
export type Direction = 'ltr' | 'rtl' | 'ttb'
// ltr = 左→右（韩漫）：横向分屏，向右翻页
// rtl = 右→左（日漫）：横向分屏，向左翻页
// ttb = 上→下（条漫）：纵向连续滚动，不播翻页动画，行间固定 16px
```

- 页组内显示顺序：`toDisplayOrder` 对 `ttb` 采用升序（行内从左到右），与 `ltr` 相同；不得走 `rtl` 的反转分支。
- `reading_progress.direction` 与 `settings.defaultDirection` 直接存 `'ttb'`，无需迁移（`electron/db/database.ts` v1 建表即为 `direction TEXT NOT NULL DEFAULT 'rtl'`）。
- EPUB 文字型纵向时内部强制 `direction('ltr')`：纵向滚动的滚动量计算依赖方向，统一 ltr 避免 RTL 反向滚动；`store.direction` 仍为 `'ttb'` 用于持久化。

## 四、纵向布局与虚拟化算法

### 4.1 行盒几何

输入：行 `row.pages`（1 或 2 个页 id，已按左→右排序）、页纵横比 `r = height / width`（未知时用估计值）、视口宽 `W`、视口高 `H`。

| 缩放模式 | 页宽 | 页高 | 说明 |
|----------|------|------|------|
| `widthScale(scale)` | `W * scale / cols` | `页宽 * r` | PDF/CBZ `fitWidth` → scale=1；EPUB 图片型 → `zoom / 100` |
| `fitHeight` | `H / r` | `H` | 每页等高，行宽可能超出视口 |
| `custom(scale)` | `H * scale / r` | `H * scale` | PDF/CBZ 顶栏 custom |
| `original` | 实际自然尺寸 | 实际自然尺寸 | 首次渲染前按 `widthScale(1)` 估计，渲染返回实际尺寸后回填 |

行盒与布局表：

```
rowH[i] = max(该行各页页高)
rowW[i] = Σ 该行各页页宽
contentWidth = max(W, max(rowW))
tops[0] = 0
tops[i] = tops[i-1] + rowH[i-1] + GAP       // GAP = 16
totalHeight = tops[n-1] + rowH[n-1]
```

- 行在内容列内水平居中；行内页垂直居中（不同比例的双页）。
- 内容列宽 `contentWidth > W` 时出现横向滚动（custom / fitHeight / original 的宽页场景）。
- 页 id 由调用方定义：PDF/CBZ 为 1 起页码；EPUB 图片型为 0 起 spine 索引。布局模块只透传，不解释。

### 4.2 布局表与渲染窗口

```ts
interface VerticalMetrics {
  tops: number[]      // 每行顶部 y
  heights: number[]   // 每行高度
  totalHeight: number
  contentWidth: number
}

// 窗口 = 视口上下各半屏：保证快速滚动时下一屏已挂载，同时把 canvas 数量限制在约 2 屏
function visibleRange(metrics, scrollTop, viewportH, overscan = 0.5) {
  const from = scrollTop - viewportH * overscan
  const to = scrollTop + viewportH * (1 + overscan)
  return [rowAtOffset(metrics, from), rowAtOffset(metrics, to)]
}

// 二分：最后一个 tops[i] <= y 的行；y < 0 返回 0
function rowAtOffset(metrics, y): number
```

- 行容器绝对定位在 `totalHeight` 高的占位层内，窗口变化只增删 DOM，不引发布局抖动。
- 渲染并发上限 2，按「距视口中心距离」升序排队；行离开窗口即卸载 canvas 并调用 `source.cancel`。
- 滚动监听用 `requestAnimationFrame` 合并；仅在顶部行变化时 emit `page-change`。

### 4.3 测量校正与锚点

```ts
// 1) 用估计比例排版并渲染窗口内页面
// 2) render 返回实际 CSS 尺寸后计算 r = height / width
// 3) 与排版用比例偏差 > 0.5% 时回填 ratios 并重算 metrics
const anchorRow = rowAtOffset(oldMetrics, scrollTop + 1)
const anchorOffset = scrollTop - oldMetrics.tops[anchorRow]
scrollTop = newMetrics.tops[anchorRow] + Math.min(anchorOffset, newMetrics.heights[anchorRow])
```

- 未测量页的估计比例：取已测页比例的中位数；一页未测时用 `1.4`（常见漫画页高宽比）。
- 校正后仅重渲比例变化超过 1px 的页，避免无限循环。
- 初始定位：`initialPage` 所在行的顶部；用户滚动后以顶部行为锚，测量回填不会把当前页顶出视口。

### 4.4 边界场景防护

| 场景 | 处理 |
|------|------|
| 页组为空 / 0 行 | 渲染空态，`totalHeight = 0`，不挂滚动监听 |
| 只有 1 行 | 无行间隙，`totalHeight = rowH` |
| 封面单页行（双页模式） | `cols = 1`，按整行宽渲染并居中 |
| 双页行两页高度不同 | 行高取高者，两页垂直居中 |
| 比例未知 | 估计值排版 → 渲染后回填 → 锚点校正，滚动位置不跳 |
| 单页渲染失败 | 该页绘制占位（页码 + 重试按钮），其余页不受影响 |
| 快速连滚 | 只挂载窗口内页面，离窗立即取消；允许短暂占位 |
| 容器首帧尺寸为 0 | `ResizeObserver` 等到非零尺寸再首次布局 |
| `initialPage` 不在任何行 | 取页 id 最接近的行作为初始行 |
| 窗口尺寸/DPR 变化 | 重排 + 重渲窗口内页面，锚点保持 |
| 末行不足一屏 | 允许底部留黑，不强制补白 |

### 6.3 PDF / CBZ：`src/views/ReaderView.vue`

1. 模板分支：`reader.doc && reader.direction === 'ttb'` 渲染 `VerticalScrollView`；否则保留现有 `.page-area` 结构。
2. 两侧热区从 `.page-area` 内移出，作为 `.reader-view` 的固定覆盖层（`position:absolute; z-index:1`），横向/纵向共用；顶栏 `z-index:2` 不变。
3. `runTurnPass`（L419）首行早退：`if (reader.direction === 'ttb') return`，不进入 policy / 快照 / pageCurl。
4. `onWheel`（L881）：ttb 下只处理 Ctrl/Cmd 缩放（`stepZoom`），其余直接返回、不 `preventDefault`，交给原生滚动。
5. `onMouseDown`（L1029）ttb 下早退，禁用拖拽平移；横向溢出用 Shift+滚轮与滚动条。
6. `onSlide` / `onSlideEnd`（L821 / L841）：ttb 下不截快照、不设 slider 状态，直接 `verticalRef.scrollToPage(reader.spreads[idx].firstPage)`；`onSlideEnd` 无动画收尾。
7. `onKeydown`（L1060）：ttb 下 `ArrowDown / PageDown / 空格` → `verticalStep(1)`；`ArrowUp / PageUp / Shift+空格` → `verticalStep(-1)`；`Home / End` → 首/末行；`ArrowLeft/Right` 保持上一页/下一页语义；`r` 键三态循环。
8. `onResize`（L1049）：ttb 下不做 `renderCurrentSpread`，由组件 `ResizeObserver` 处理。
9. 进度回写：组件 `page-change` → `reader.goTo(findSpreadIndexByPage(reader.spreads, page))`；`goTo` 的 `scheduleSave` 防抖落盘，`flushProgress` 存 `refs[firstPage]`。
10. 初始定位：`initialPage = reader.spreads[reader.currentIndex]?.firstPage ?? 1`。
11. 方向入口：原二态按钮替换为 `SelectMenu<Direction>`，选项 `ltr / rtl / ttb`；选择即 `reader.setDirection(value)`。
12. `verticalSizing` 由 `zoomMode / zoomScale` 映射：`fitWidth → widthScale(1)`、`fitHeight`、`original`、`custom → custom(scale)`。
13. `renderCurrentSpread`（L701）与 `schedulePrefetch`（L751）：ttb 下早退。纵向分支没有显示 canvas，继续执行只会做无意义的离屏渲染并污染 `pageCache`。


`manager:'continuous'` 是连续滚动的前提：`DefaultViewManager.updateFlow('scrolled')` 会 `updateAxis('vertical')` 并把容器设为 `overflow:auto`（`managers/default/index.js` L1018），但只有 ContinuousViewManager 会在滚动时前后拼接 section（`managers/continuous/index.js` L242 `check()`）。纵向轴下容器 `display:block`（`managers/helpers/stage.js` L293），`.epub-view` 为 `position:relative; display:block`（`managers/views/iframe.js` L63-L64），因此章节视图按文档流堆叠。

**`src/views/EpubReaderView.vue`**：

- 容器类：`ttb` 时给 `.epub-area` 加 `is-vertical`。
- 间隙：`:deep(.epub-container > .epub-view + .epub-view) { padding-top: 16px; }`。用 padding 而非 margin：`IframeView.bounds()` 取元素包围盒（含 padding），连续流 `erase()` 用 `bounds.height` 补偿滚动位置，padding 不会产生 16px 漂移。
- 滚动条：`:deep(.epub-container)` 设置 `scrollbar-width: thin` 与暗色 thumb，与纵向视图一致。
- 滚轮：`onFrameWheel`（L288）在 ttb 下不再走 `requestTurn`，改为把 `normalizeWheelDelta(e, scroller.clientHeight)` 转发给 `.epub-container` 的 `scrollTop`（iframe 内 wheel 不会冒泡到父文档，必须手动转发）。
- `requestTurn`（L467）：ttb 下不入队、不截冻结帧，直接 `await (dir === 'forward' ? store.next() : store.prev())`；`store.next/prev` 调 `rendition.next/prev`，连续流按 `layout.height`（一屏）滚动（`managers/continuous/index.js` L525）。
- `requestJump`（L478）：ttb 下直接 `await store.goTo(index)`（`displayPageIndex` → 连续流 `moveTo`），不进入动画队列。
- 滑块、Home/End 保持现有入口，走上面的 `requestJump` 分支。
- 双页按钮：`ttb && layout === 'reflowable'` 时 `disabled`，悬停提示 `reader.verticalTextSingle`；`toggleSpread` 在此条件下为空操作。
- `onResize`（L1019）：ttb 文字型仍调 `store.resize`（epub.js 重排），但不清理动画会话（本来就不存在）。
- 热区：ttb 下 `onHotzoneClick`（L371）统一「右 = 下一页、左 = 上一页」。

**`src/stores/epubReader.ts`**：

- `direction` 类型改 `Direction`；`open`（L100）归一化改为完整映射（`'ttb'` 保留，`'rtl'` 保留，其余 `'ltr'`）。
- 闭包持有 `hostEl`（`open` 时记录的宿主元素），供方向切换重建引擎时读取尺寸。
- 抽出 `mountEngine(element, pos)`：按 `layout + direction + spread` 决定创建分页 rendition、连续流 rendition，或（图片型 + ttb）不创建 rendition；`open` 与 `setDirection` 复用。
- `setDirection(next)`：`ltr ↔ rtl` 且非 ttb 时仍走 `rendition.direction(next)`（无重建）；跨 ttb 边界时先捕获 `current`，销毁引擎，更新方向，再 `mountEngine` 并按 `cfi / page / percentage` 还原。
- 文字型 ttb 不安装 `installPaginatedNavigation`；`generateLocations` 照常后台生成，滑块与页码可用。
- `flushProgress` 不变：`direction: 'ttb'` 直接落盘。

### 6.5 EPUB 图片型（pre-paginated）

图片型在 ttb 下不创建 rendition（避免连续流强制单列），改用 canvas 纵向视图支持双页。

**新增 `src/services/epubVertical.ts`**：

```ts
/** 把 section 内图片的相对 src 解析为压缩包内路径（纯函数，供单测） */
export function resolveEpubImagePath(sectionUrl: string, src: string): string | null

export function createEpubImageSource(book: EpubBook): VerticalPageSource
```

实现要点：

1. `const section = book.spine.get(pageId)`；`const doc = await section.load(book.load.bind(book))`（与 `detectImageBasedBook` L97 同一取文档方式）；取到 `src` 后 `section.unload()` 释放文档，避免整本 spine 常驻内存。
2. 取图：`doc.querySelector('img')`；没有则取 SVG `image`（`href` 或 `xlink:href`）。
3. `resolveEpubImagePath(section.url, src)`：`data:` / 远程 URL 原样返回或拒绝；相对路径用 `new URL(src, 'http://local/' + section.url)` 解出 pathname，去掉前导 `/` 并 `decodeURIComponent`。
4. `const url = await book.archive.createUrl('/' + path)`：`Archive.createUrl` 自带 `urlCache`（`archive.js` L183），同一页重复滚动不重复解压；`book.archive` 未在 epub.js 类型声明中，按局部接口断言。
5. `const image = new Image(); image.src = url; await image.decode()`，按 target 尺寸等比绘制到 canvas（黑底居中），返回实际 CSS 宽高。
6. 缓存仅保存 `pageId → { path, url, width, height }` 元数据（LRU 8）；位图由浏览器缓存托管，不长期持有 `ImageBitmap`。

**`src/stores/epubReader.ts` 图片型 ttb 分支**：

- `preSpreads` 改为 `shallowRef<number[][]>`（或新增 `verticalRows`），模板可响应单/双页切换；行由 `buildPrePaginatedSpreads(items, coverSinglePage)` 生成，按升序即左→右。
- `open`：图片型 + ttb 时不创建 rendition；`ready = true`、`locationsReady = true`、`totalPages = spinePageCount()`；`current` 由 `progress.page`（或 percentage）还原为 spine 索引并对齐组首。
- 新增 `setVerticalPosition(index)`：更新 `current = { index, cfi: section.cfiBase ?? '', percentage }` 并 `scheduleSave()`；`cfiBase` 仅作占位，重开时图片型走 `progress.page` 还原（现有逻辑）。
- `next / prev / goTo / turnTo / alignToSpread`：ttb 图片型不走 rendition 导航，由视图的 `step` / `scrollToPage` 直接驱动；`turnTarget` 仍供滑块上限计算。
- `toggleSpread`：ttb 图片型只改 `spread` 并落盘，行随 `verticalRows` 重算；不重建引擎。
- `setZoom`：ttb 图片型只改 `zoom` 并落盘，视图按 `zoom/100` 重排；不调用 `rendition.display`。
- `resize`：ttb 图片型为空操作（组件自行 `ResizeObserver`）。

**`src/views/EpubReaderView.vue` 图片型 ttb 分支**：

- `.epub-area` **保持布局占位**（不可 `v-show` / `display:none`：隐藏后矩形为 0×0，方向切回 `ltr/rtl` 时 `mountEngine` 取不到尺寸）；改由 `VerticalScrollView` 绝对覆盖其上，或给 `.epub-area` 保留 `visibility:hidden`（仍占布局）。
- `rows` = `preSpreads.map((pages, i) => ({ firstPage: pages[0], pages }))`；`initialPage = store.current?.index ?? 0`。
- `page-change` → `store.setVerticalPosition(index)`；页码指示与滑块沿用 spine 索引。
- 滑块 `onSlideInput` → `verticalRef.scrollToPage(alignToSpread(index))`；松手不补播卷曲。
- 热区/键盘：`requestTurn` 在图片型 ttb 下改为 `verticalRef.step(±1)`，不进入动画队列。

## 十一、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 纵向大页内存 | 只渲染窗口（约 2 屏）内页面，不复用 `pageCache`（LRU 12） | 1080p + DPR2 下单页约 20~35MB，峰值约 100~200MB；接受，后续可加「纵向降采样」设置 |
| 比例首测跳变 | 未知比例按中位数/1.4 估计，渲染后锚点校正 | 快速滚动时可能有轻微位移，但当前页不会被顶出视口 |
| EPUB 图片提取范围 | 只识别 `<img>` 与 SVG `<image>`；纯文本 section 显示占位 | 少数带 CSS 背景图/文字的 section 无法还原排版，列为已知限制 |
| epub.js 内部依赖 | 依赖 `continuous` 管理器与 `.epub-view` 结构（`epubjs ^0.3.93`） | 升级 epub.js 需回归连续流、间隙与 `erase` 补偿；版本已锁定 |
| 文字型 EPUB 无双页 | 连续正文无页边界，engine 强制 `spread('none')` | 与「EPUB 纵向也双页」的期望存在差异；图片型 EPUB 已满足双页诉求 |
| 方向切换重建引擎 | 跨 ttb 边界时销毁并重建 rendition（非全量重开书） | 约 100~300ms 黑屏，用加载态覆盖；位置按 CFI/page 还原 |
