## 一、需求拆解与验收标准

> 已与用户确认现象：**图片型漫画**、双页显示时**上一页/下一页都只翻一页**、修复范围包含**翻页与定位一起对齐**。

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 图片型 EPUB 双页模式，按下「下一页」一次应前进一个跨页（两页内容） | 翻页推演不再按 spine 单页 `±1`，改为按「跨页组」步进：`EpubReaderView.doDrainTurns` 用 `store.turnTarget(from, delta)` 取目标组首页；`store.turnTo` 单步走渲染层直通 `next()/prev()`（引擎自行配对），多步按组表推演后一次 `goTo`（§4.2、§5） | 双页模式连续点 5 次「下一页」：页码依次 `2 → 4 → 6 → 8 → 10`（组首页码），画面每次两页全新内容，无「右页挪到左页」的半跨页位移 |
| 2 | 上一页方向同样按跨页后退 | 同上，`prev()` 分支对称；组表倒退取上一组首页 | 从页码 10 连续点 5 次「上一页」：`8 → 6 → 4 → 2 → 1`（回到封面单独页），双向各重复 3 轮无错位 |
| 3 | 首屏封面、末组单页等边界不越界、不空跳 | 组表把封面（`coverSinglePage` 开启时的 spine 第 0 项）与奇数尾页建为单页组；`turnTarget` 夹取到首/末组首页（§4.1、§4.3） | 封面按「上一页」无变化、无动画；末组按「下一页」无变化；末组为单页时正常显示单页 |
| 4 | 定位（滑块 / Home / End / 断点续读 / 切单双页 / 缩放）不得停在错位半跨页 | `store.goTo` 内部对齐组首页；`open` 的图片型分支改用 `progress.page`/百分比换算后对齐；`toggleSpread`、`setZoom` 重渲染前同样对齐（§5.2） | 滑块拖到索引 4（thumb 第 5 格）→ 显示组 `[3,4]`（页码 4），不出现 `[4,5]`；End 落到末组首页；退出重进回到同一组；单页切双页后配对正确 |
| 5 | 不回归既有阅读行为 | 单页模式、文字型 reflowable、翻页动画/连翻补播、进度落盘语义保持现状（§6） | 单页模式逐页翻；文字型 EPUB 翻页与滑块正常；PDF/CBZ 零改动；`npm run typecheck`、`npm test` 通过 |

**核心验收口径**：打开一本 100 页、封面单独成页开启的图片型 EPUB → 双页模式下初始显示封面（页码 1/100）；连续 5 次「下一页」页码为 `2 → 4 → 6 → 8 → 10`；连续 5 次「上一页」回到封面；期间每屏两页内容均完整并排、无重复页、无半跨页错位；`npm run typecheck` 与 `npm test` 全绿。

## 二、非目标（本期不做）

1. **不修文字型 reflowable 双页的步进精度**：其翻页走 `locations` 索引（`generate(1024)` 按 1024 字符分块，与单/双页一屏字符量不是 1:1），双页下同样可能只前进约半屏。本次用户只报图片型，改动会牵涉连翻合并策略，单列风险（§10）后续处理。
2. **不改页码显示为跨页范围**：仍显示组首页码（如 `2 / 100` 表示组 `[2,3]`），不改成 `2-3 / 100`；滑块 `max` 仍为 spine 页数 - 1。
3. **不调整 `page-spread-right` 单页页的左右容器位置**：`installPrePaginatedFit.refitAll` 清 `marginLeft` 的既有取舍保留（该页在双页视口中贴左而非贴右），与本次步进问题独立。
4. **不改 `src/services/epub.ts` 的既有补丁**：`installPaginatedNavigation`（直通 `next/prev`）、`applyCoverSinglePage`（封面配对 patch）、`refitAll` 的布局收敛均已正确，本次只改调用时机与目标计算。
5. **不改 PDF/CBZ 页组**：`src/services/spread.ts` 的 `buildSpreads` 服务于 PDF/CBZ，语义与 EPUB spine 不同，不共用、不修改。
6. **不改翻页动画与连翻参数**：`turnPolicy.ts`、`pageCurl.ts`、截图预算等零改动；连翻仍是「净位移合并 + 停手补播一次」。
7. **不新增依赖、不改 IPC / DB / 设置项**：无 `shared/types.ts`、`electron/`、`package.json` 变更。

## 三、总体设计

### 3.1 现状与根因

图片型 EPUB 在 `pre-paginated` 布局下，**spine 的一项 = 一页**；双页显示由 epubjs 的配对逻辑追加相邻 section 组成（`manager.display` 的 `handleNextPrePaginated`）。但本项目翻页链路把它当成「页组」推演，逐次只推进一个 section：

1. `EpubReaderView.doDrainTurns`：`target = clampPageIndex(from + delta)`，图片型书每次 `delta = ±1`。
2. `jumpTo` / `animatedTurn`：`store.layout === 'pre-paginated'` 时走 `store.goTo(target)`。
3. `store.goTo`：`book.spine.get(index)?.href` → `rendition.display(href)`。
4. `rendition.display(a)` 会 `add(a)` 后再由 `handleNextPrePaginated` 追加 `a.next()`，所以实际显示 `[a, a+1]`。

于是当前显示 `[i, i+1]` 时按「下一页」得到 `[i+1, i+2]`：左页变成原来的右页，**视觉上只翻了一页**；「上一页」对称地只退一页。封面单独成页时，第一次翻页看起来正常（`[0] → [1,2]`），从第二次起暴露。

同一根因还影响定位：`goTo(4)` 在组 `[3,4]` 中会显示 `[4,5]`（组首错位），滑块、断点续读、切双页、缩放重渲染都会踩到。

### 3.2 目标数据流

```
┌─ 输入层 ──────────────────────────────────────────────────────────────┐
│ 热区 / 键盘 / 滚轮 / 底栏按钮 / 滑块 / Home / End                       │
└───────────────────────────────┬───────────────────────────────────────┘
                                ▼
                requestTurn → pendingDelta（翻页次数）
                requestJump → pendingJump（目标组首页索引）
                                │
                                ▼
                      drainTurns（串行队列）
                                │
        ┌───────────────────────┴────────────────────────┐
        │ 翻页：target = store.turnTarget(from, delta)     │
        │ 跳页：target = store.alignToSpread(index)        │
        └───────────────────────┬────────────────────────┘
                                ▼
                    store.turnTo(target, delta)
        ┌───────────────────────┴────────────────────────┐
        │ 图片型 + 双页 + |delta|=1 → next() / prev()      │
        │ 图片型 + 双页 + |delta|>1 → goTo(组表目标)       │
        │ 图片型 + 单页 / 文字型 → goTo / 逐次 next/prev   │
        └───────────────────────┬────────────────────────┘
                                ▼
           epubjs manager（配对、渲染）→ relocated 校正 navIndex
```

要点：

- **翻页的「一步」= 一个跨页组**，由组表统一表达；单步仍交给引擎的 `next()/prev()` 配对，避免自实现配对规则与引擎不一致。
- **跳页/恢复/切版式的「落点」= 目标页所在组首页**，避免 `display(组内第二页)` 重新配对成错位跨页。
- **两种量纲分离**：`pendingDelta` 表示翻页次数，`pendingJump` 表示目标页索引；修复前两者混用（`pendingDelta = index - from`），一旦按组步进会被放大成 2 倍跳页。

### 3.3 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 翻页步长来源 | 新增「跨页组表」纯函数，按 spine 元数据构建 | 步长取决于封面设置与 `page-spread-*` 属性，不能假设固定为 2；纯函数可单测，避免把规则散落在视图里 |
| 单步翻页执行方式 | 走 `installPaginatedNavigation` 的 `next()/prev()` | 配对规则完全由 epubjs 决定（含 `page-spread-left/right`、linear 跳过），零模拟风险；开销与一次 `goTo` 同级（都重建两页视图） |
| 连翻（`\|delta\|>1`）执行方式 | 组表推演目标组首页后一次 `goTo` | 保留「净位移合并、一次渲染」的既有性能设计；连翻时对精确配对的要求低于单次阅读，且 relocated 会校正落点 |
| 定位对齐范围 | 翻页 + 滑块 + Home/End + 断点续读 + 切单双页 + 缩放重渲染全部对齐组首页（用户确认） | 只修翻页会让跳页后停在错位跨页上，下一次翻页继续错位；一次性统一落点语义最省心 |
| 组表规则（封面开启） | 逐条照抄 epubjs：`index===0` 单独、`page-spread-right` 单独、`next` 带 `page-spread-left` 不并排 | 与 `installPaginatedNavigation` 在单步时用的原生逻辑保持同一份事实来源，避免两套规则打架 |
| 组表规则（封面关闭） | 无视元数据，线性序列两两成组 | `applyCoverSinglePage` 已把 `handleNextPrePaginated` 改成无条件追加，组表必须与 patch 后的实际行为一致 |
| 跳页量纲 | 新增 `pendingJump`，与 `pendingDelta` 分离 | 修复后「翻页 1 次」在双页下是 2 个 section，若继续用索引差当翻页次数会翻倍 |
| 页码与滑块语义 | 不变（组首页码、`max = spine 数-1`） | 与 PDF/CBZ 页码口径一致；改「跨页范围显示」属 UI 需求，另开方案 |
| 文字型路径 | 不动 | 用户只报图片型；reflowable 的 location 与屏不是 1:1，改法需重排连翻合并策略，风险独立 |

## 四、核心算法与边界防护

### 4.1 跨页组构建（`src/services/epubSpread.ts` 新增）

```ts
/** spine 项的最小元数据（来自 book.spine.get(i)） */
export interface EpubSpineItem {
  /** spine 原索引（section.index） */
  index: number
  /** itemref properties（page-spread-left / page-spread-right 等） */
  properties: string[]
  /** section.linear：false 的项不参与翻页（与 Section.next() 一致） */
  linear: boolean
}

/**
 * 按 epubjs pre-paginated 双页的实际配对规则构建跨页组。
 * 组内元素为 spine 索引、升序；单页组长度为 1。
 */
export function buildPrePaginatedSpreads(
  items: EpubSpineItem[],
  coverSinglePage: boolean
): number[][] {
  const linear = items.filter((it) => it.linear)
  const groups: number[][] = []
  let p = 0
  while (p < linear.length) {
    const cur = linear[p]
    if (coverSinglePage) {
      // 原生 handleNextPrePaginated：spine 第 0 项（封面）恒单独
      if (cur.index === 0) {
        groups.push([cur.index])
        p += 1
        continue
      }
      // 原生 display：带 page-spread-right 的 section 独占（forceRight）
      if (hasProp(cur, 'page-spread-right')) {
        groups.push([cur.index])
        p += 1
        continue
      }
      // 原生 handleNextPrePaginated：next 带 page-spread-left 则当前组不并排
      const next = linear[p + 1]
      if (next && !hasProp(next, 'page-spread-left')) {
        groups.push([cur.index, next.index])
        p += 2
      } else {
        groups.push([cur.index])
        p += 1
      }
    } else {
      // applyCoverSinglePage 的 patch：用户设置优先，线性序列一律两两并排
      const next = linear[p + 1]
      if (next) {
        groups.push([cur.index, next.index])
        p += 2
      } else {
        groups.push([cur.index])
        p += 1
      }
    }
  }
  return groups
}
```

`hasProp` 对 `properties` 缺失/非数组做兜底（返回 false）。

### 4.2 对齐与步进（`epubSpread.ts`）

```ts
/** 把任意页索引对齐到其所在组的首页；找不到（linear=no / 越界）时前向对齐到最近组 */
export function alignPrePaginatedPage(groups: number[][], page: number): number {
  if (groups.length === 0) return Math.max(0, page)
  const hit = groups.find((g) => g.includes(page))
  if (hit) return hit[0]
  const forward = groups.find((g) => g[0] > page)
  return (forward ?? groups[groups.length - 1])[0]
}

/** 从 page 所在组前进 delta 个跨页，返回目标组首页（夹取到首/末组） */
export function stepPrePaginatedPage(groups: number[][], page: number, delta: number): number {
  if (groups.length === 0) return Math.max(0, page)
  const aligned = alignPrePaginatedPage(groups, page)
  const gi = groups.findIndex((g) => g[0] === aligned)
  const target = Math.min(Math.max((gi === -1 ? 0 : gi) + delta, 0), groups.length - 1)
  return groups[target][0]
}
```

### 4.3 边界场景防护

| 场景 | 期望行为 | 实现约束 |
|------|----------|----------|
| 封面单独成页（默认） | 组 `[0]`，翻下一页到 `[1,2]` | `index===0` 优先于 `page-spread-*` 判定 |
| 封面不单独成页 | 组 `[0,1]`，之后 `[2,3]…` | 与 `applyCoverSinglePage` 的无条件配并对齐；不读元数据 |
| 奇数页数末组 | `[… [n-2,n-1]]` 配对，尾页单独成组 | 组表自然产生，无需特判 |
| `page-spread-right` 页 | 单独成组 | 与原生 `display` 的 `forceRight` 一致 |
| `next` 带 `page-spread-left` | 当前页单独成组，该页成为下一组组首 | 照抄 `handleNextPrePaginated` |
| `linear="no"` 的 spine 项 | 不参与翻页，组内索引可跨过它 | 组表按线性序列推进，组内值仍用 `section.index` |
| 空 spine / 组表为空 | 退化为原来的 `index ± 1` 步进 | `alignToSpread` 原样返回，`turnTarget` 用 spine 数夹取 |
| 旧进度落在组内第二页 | 打开后对齐到组首页（可能回退一页） | `open` 的图片型分支用 `page`/百分比换算后 `alignToSpread` |
| 到首组再按上一页 | `turnTarget === from` → `effective === 0`，不导航、不播动画 | 沿用 `doDrainTurns` 的边界短路 |
| 到末组再按下一页 | 同上；末组若为单页正常显示 | `stepPrePaginatedPage` 夹取到末组首页 |
| 单次翻页的动画判定 | 仍播单次卷曲 | `TurnPolicy.decide` 的 `indexDelta` 与 `Math.abs(effective) === 1` 改用**翻页次数 `\|delta\|`**；双页一次翻页的 section 差为 2，沿用 `effective` 会被误判为连翻、单次翻页永远瞬切 |
| 滑块与连翻并发 | 显式跳转优先：清空 `pendingDelta`，只消费 `pendingJump` | `requestJump` 内 `pendingDelta = 0` |
| 连翻跨末组 | 落点夹取到末组首页，不越界 | `turnTarget` 夹取 |

## 五、渲染层实现

### 5.1 store 组表缓存与导航 API（`src/stores/epubReader.ts`）

新增闭包状态与函数（非响应式，epubjs 实例同理）：

```ts
/** 跨页组表：仅图片型书构建；单页模式不参与推演 */
let preSpreads: number[][] = []

/** open 的图片型分支内调用：一次性收集 spine 元数据并构建组表 */
function rebuildPreSpreads(coverSinglePage: boolean): void { /* book.spine.get(i) 遍历 → buildPrePaginatedSpreads */ }

/** 图片型 + 双页 + 组表可用 */
function isDoubleImageLayout(): boolean

/** 对齐到跨页组首页；非图片型/单页/组表为空时原样返回 */
function alignToSpread(index: number): number

/** 翻页推演：图片型双页按组步进，其余按本帧步进（并用 spine 数夹取） */
function turnTarget(from: number, delta: number): number

/** 执行翻页：图片型双页单步走 next/prev，其余 goTo / 逐次 next/prev */
function turnTo(target: number, delta: number): Promise<void>
```

`turnTo` 分支：

```ts
if (layout.value === 'pre-paginated') {
  if (spread.value === 'always' && Math.abs(delta) === 1) {
    return delta > 0 ? next() : prev() // 配对交给直通补丁
  }
  return goTo(target) // 单页模式或连翻合并
}
for (let i = 0; i < Math.abs(delta); i++) {
  await (delta > 0 ? next() : prev()) // 文字型保持现状
}
```

`goTo` 改造（图片型分支）：先 clamp 到 `[0, spinePageCount()-1]`，再 `alignToSpread` 取组首页，最后 `display(section.href)`。

`open` 改造（图片型分支）：

- 删除「图片型也优先用 `progress.cfi`」的路径，统一按 `progress.page - 1` 还原索引；无 `page` 时用 `percentage` 换算；再 `alignToSpread` 对齐后 `display(href)`。
- 进度落盘不变：`page = current.index + 1`（`current.index` 由 relocated 给出组首页）。

`toggleSpread` / `setZoom`：重渲染目标索引统一过 `alignToSpread`（切到双页时对齐；切到单页时原样）。

### 5.2 视图队列改造（`src/views/EpubReaderView.vue`）

| 接缝点 | 现状 | 改动 |
|--------|------|------|
| `requestJump` | `pendingDelta = index - from`，借翻页队列执行 | 新增 `pendingJump = store.alignToSpread(clampPageIndex(index))`，并清空 `pendingDelta`；仍返回「队列空闲」Promise |
| `doDrainTurns` | 单一 `pendingDelta` 循环 | 优先消费 `pendingJump`（`jumpToIndex`，瞬切、无卷曲）；否则按 `pendingDelta` 走原动画/连翻分支；循环条件与 `finally` 兜底（`pendingDelta !== 0`）同步纳入 `pendingJump` |
| `doDrainTurns` 目标推演 | `clampPageIndex(from + delta)` | `store.turnTarget(from, delta)` |
| `doDrainTurns` 动画判定 | `policy.decide({ indexDelta: effective })` 且 `Math.abs(effective) === 1` | 改传翻页次数 `delta`（与 `TurnPolicy` 的「页组数」语义一致）；`effective` 只保留给边界短路与 `navIndex` 推演 |
| `jumpTo` | 按布局分流 `goTo` / 逐次 `next/prev` | 统一 `store.turnTo(target, delta)`；relocated 后校正 `navIndex` |
| `animatedTurn` 导航 | 同 `jumpTo` 的布局分流 | 统一 `store.turnTo(target, delta)` |
| `finishSlideCurl` | 以 `navIndex !== finalIndex` 判定未到位 | 以 `navIndex !== store.alignToSpread(clampPageIndex(finalIndex))` 判定，并同时要求 `pendingJump === null`；方向比较用对齐后的起点/终点 |
| `forceSnap` | 由 `requestJump` 设置，驱动 `snapOnce` | 随 `pendingJump` 独立分支一并删除（避免与翻页量纲混用）；`doOpen`、`onSlideInput`、`onResize` 中的重置赋值同时清理 |
| 诊断 | `[nav]` 系列 | `turnTarget`/`goTo` 增加 `[spread] groups=… align=… target=… delta=…`，供 DEV 面板验证 |

`jumpToIndex`（新增）：`waitNextRelocated()` → `store.goTo(target)` → 等 relocated → `navIndex` 校正。滑块拖动节流（200ms）与松手补播会话保持不变。

本方案不新增 UI，仅调整既有交互的落点语义：

|------|------|--------|
| 底栏「上一页 / 下一页」、热区、方向键、空格、PageUp/PageDown、滚轮 | 双页每次前进 1 个 section | 双页每次前进 1 个跨页组（2 个 section；封面与末组单页除外） |

### 8.2 手工冒烟

## 十、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 组表规则与引擎不一致 | 单步翻页仍走引擎 `next/prev`；组表只用于连翻与定位对齐 | 不一致最坏表现为连翻/跳页落点偏差一格，单次阅读始终正确；DEV 面板 `[spread]` 行可复核 |
| 连翻性能 | 图片型双页连翻仍一次 `goTo`（组表推演），不退化为逐次渲染 | 与修复前同量级；单步 `next` 也只是一次两页重建 |
| 动画判定量纲 | 以翻页次数 `delta` 取代 section 位移 `effective` | 若沿用 `effective`，双页一次翻页 = 2 会被 `TurnPolicy` 判为连翻，单次翻页动画全部消失；`delta` 与 `TurnPolicy` 的「页组数」注释一致，文字型也更准确 |
| 文字型双页仍可能半步 | 本期不改（非目标） | 后续可把 reflowable 翻页改为 `next/prev` 循环，需同时重估连翻合并；已在 §2 记录 |
| 旧进度/旧 CFI | 图片型恢复改用 `page`/百分比 + 组对齐 | 若旧数据落在组内第二页，首次打开会回退一页（一次性），之后落盘组首页 |
| 页码只显示组首页 | 不做 `2-3 / 100` | 与 PDF/CBZ 口径一致；如后续需要可只改 `locationLabel`，不涉导航 |
| `page-spread-right` 单页贴左 | 保留 `refitAll` 清 `marginLeft` 的既有取舍 | 该页在双页视口中贴左而非贴右；与步进无关，单列后续优化 |
| 滑块松手 thumb 回弹 | 拖动跟手、松落对齐组首 | 回弹幅度 ≤1 页；换取跳页后配对正确，避免「翻页只翻一页」复发 |
| 显式跳转丢弃未消费翻页 | `requestJump` 清空 `pendingDelta` | Home/End/滑块优先，符合用户「拖到哪就是哪」的预期；连翻输入丢失概率极低 |
| 无新增依赖 / 无 DB / 无 IPC | 全部在渲染层完成 | 打包体积、迁移与跨进程契约零风险 |
