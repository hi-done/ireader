# 适宽模式滚轮滚动与边缘翻页设计方案

> 状态：已实现（已验证）
> 目标版本：不锁定（版本号由用户自行修改；实施阶段不改动 package.json 与发布流程）
> 范围：PDF / CBZ（zip）阅读视图的纵向滚轮接管、边缘翻页、翻页落点复位、Shift+滚轮横向平移与到边转纵向、滚动模式卷曲动画；不涉及 EPUB、主进程、IPC、数据库
> 实现约束：遵循 `ireader-dev-tasks`（任务 E/F）与 `ireader-code-conventions`（中文注释、纯逻辑下沉 service、Vitest）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | PDF/ZIP 等阅读界面在适宽模式下，鼠标滚轮可以控制漫画上下滚动 | `ReaderView.onWheel` 在 `.page-area` 存在纵向溢出时接管纵向滚轮，手动更新 `scrollTop`（§4、§5.2） | 打开适宽高页：滚轮上下滚动，页码不变；未到边缘不翻页 |
| 2 | 到达最顶/最底部位后才进行对应翻页 | `stepWheelScroll`：仅当事件开始时已在顶/底才累计越界量，≥80px 触发 next/prev；同一手势最多翻一页（§4） | 滚到底继续向下 → 下一页；滚到顶继续向上 → 上一页；页面中间滚动不翻页 |
| 3 | 每次翻页后新页都停在视图最顶部 | 新页渲染完成后复位滚动位置：前进置顶、后退置底（用户决策），横向同时回左缘（§4.4、§5.2） | 下一页顶部贴视口顶；上一页底部贴视口底；滚轮/键盘/热区/滑块四条路径一致 |
| 4 | 保留现有翻页观感 | 旧页纵向溢出时用 `.page-area` 可视区快照，并以 `.page-area` 为卷曲目标；旧页不溢出时沿用完整内容快照（§5.3） | 滚动到底触发翻页仍播放卷曲动画，无旧页错位、无揭层跳顶 |
| 5 | 不破坏既有阅读交互 | 条件分支：Ctrl+滚轮、表单控件、横向滚动、不可滚动页全部保持原逻辑（§4.3） | 回归清单（§8.2）全过 |
| 6 | Shift+滚轮上下滑动 → 左右移动，到最左/最右后转为上/下移动 | `onWheel` 增加 Shift 分支，调用 `stepShiftWheelScroll`：横向未到边只移动 `scrollLeft`；贴边后下一次事件转纵向，复用 `stepWheelScroll`（§4.5、§5.2） | 横向溢出页：Shift+滚轮左右平移、页码不变；到右缘继续向下滚转向下移动，到左缘继续向上滚转向上移动；纵向到边后与普通滚轮一样翻页 |

**核心验收口径**：1080p 窗口下打开一页高度大于视口的 PDF/CBZ 适宽页面——从顶部向下滚只滚动不翻页；滚到底后继续向下累计 80px 翻到下一页，新页顶部对齐且卷曲正常；在新页顶部继续向上翻回上一页，上一页底部对齐；全程同一滚轮事件不会既滚动又翻页；按住 Shift 时同一页可左右平移，到右/左缘后转为向下/向上移动，纵向到边后的翻页与落点规则与普通滚轮一致。

## 二、非目标（本期不做）

- **不改造 EPUB**：`EpubReaderView` 是独立引擎，没有「适宽」缩放模式；滚轮语义维持现状。
- **不接管无 Shift 的横向滚轮/触控板横滑**：横向占主导的普通滚轮事件仍交给浏览器原生滚动与拖拽平移；只有按住 Shift 才进入横向平移逻辑。
- **不做横向到边的回弹/吸附动画**：到边即停，下一次事件直接转纵向，不引入新视觉元素。
- **不改键盘、热区、滑块的翻页语义**：它们仍直接翻页，只共享「翻页后落点复位」规则。
- **不持久化滚动位置**：每次翻页按规则回到顶部/底部；重开书仍从页首开始。
- **不新增设置开关**：纵向溢出时自动启用，不增加用户配置项。
- **不做平滑滚动动画/惯性模拟**：直接更新 `scrollTop`；触控板自身的惯性事件仍会被逐帧消费。
- **不改缩放模式、页组划分、进度保存**：`shared/types.ts`、`reader.ts`、`reading_progress` 均不动。
- **不重构滑块既有节流与缓存策略**：仅在松手收尾补上「渲染 + 复位」，使落点规则一致。
- **不新增 npm 依赖**：全部使用现有 DOM/Canvas 能力。

## 三、总体设计

### 3.1 分层与数据流

```
用户滚轮
  │  ReaderView.vue 根节点 @wheel
  ├─ Ctrl/Cmd+滚轮 ──────────────→ stepZoom（原逻辑，最高优先级）
  ├─ 目标是 input/select/textarea → 不接管，交给控件
  ├─ Shift+滚轮 ─────────────────→ stepShiftWheelScroll（§4.5）
  │    ├─ 横向可溢出且未到边 ────→ 只移动 scrollLeft，不翻页
  │    ├─ 已在左/右缘 ──────────→ 转为纵向，进入下方「有纵向溢出」分支
  │    └─ 横向无溢出 ───────────→ 等同普通滚轮，进入下方分支
  ├─ 横向分量占主导（无 Shift）──→ 不接管，保留原生横向滚动
  ├─ .page-area 无纵向溢出 ──────→ 原翻页逻辑（20px 阈值 + 250ms wheelLock）
  └─ .page-area 有纵向溢出
       ├─ preventDefault
       ├─ stepWheelScroll(state, { deltaY, scrollTop, scrollHeight, clientHeight, now })
       │      ├─ 返回 scrollTop → 写回 pageArea.scrollTop
       │      └─ 返回 turn      → reader.next() / reader.prev()
       └─ turn 触发 currentDisplayPages 变化
              │
              ▼
       watch(currentDisplayPages)
         ├─ snapshotForTurn(旧页是否纵向溢出)
         ├─ await renderCurrentSpread()
         ├─ resetPageScroll(前进 top / 后退 bottom)
         ├─ snapshotForTurn(同一快照模式)
         └─ playPageCurl(target = pageArea 或 pageContent)
```

本功能是**纯渲染层交互改造**，不经过 IPC、不落库、不新增共享类型。PDF 与 CBZ 共用 `ReaderView` 的 Canvas 管线（`src/services/pageRenderer.ts` L16-25），因此两条格式自动同时生效。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 生效条件 | 任意缩放模式下，`.page-area` 满足 `scrollHeight > clientHeight + 1` | 用户确认「所有纵向溢出场景」；以实际内容高度判定而不是按模式名硬编码，适高通常无溢出、行为自然不变 |
| 滚轮接管方式 | `preventDefault` + 手动写 `scrollTop` | 一次事件只做一个动作，避免原生滚动与翻页叠加；边缘判定可精确到像素，也便于纯函数单测 |
| 边缘翻页触发 | 事件开始时已在顶/底 → 累计越界量；≥80px 且不在本手势已翻页状态 → 翻页 | 先把页滚到边缘，再继续滚才翻页；80px 约等于鼠标一格（Windows 常见 100px），触控板需一次刻意滑动 |
| 手势节流 | 事件间隔 >200ms 视为新手势；同一手势翻页后剩余事件全部吞掉 | 防止触控板惯性一次翻多页，也防止翻页后惯性把新页滚走；鼠标连续滚轮同样最多一页 |
| 翻页落点 | 前进（next）置顶，后退（prev）置底 | 用户确认；符合纵向连续阅读方向，向上翻页后可继续向上阅读上一页底部 |
| 卷曲动画 | 旧页纵向溢出 → 可视区快照 + `pageArea` 为目标；否则沿用完整内容快照 + `pageContent` 为目标 | 用户确认保留卷曲；旧页在页底时完整内容快照会从页首开始绘制导致错位，可视区快照才能复刻用户当前看到的画面 |
| 复位时机 | 新页渲染完成后、`to` 快照/动画播放前 | 保证动画下方的新页已在落点，揭层时无跳动；无动画路径同样复位 |
| 数据模型 | 纯瞬态 UI 状态，不落库 | 不新增设置/IPC/DB；滚动位置不需要跨会话恢复 |
| Shift+滚轮方向 | 向下滚→右移，向上滚→左移 | 与 Chromium 原生 Shift+滚轮方向一致；到右缘继续向下滚自然接「向下移动」，形成右→下、左→上的蛇形动线 |
| 横向到边转纵向时机 | 事件开始时已在左/右缘才转纵向；跨边的那次事件只做横向并夹取 | 与纵向「先到边再翻页」同一哲学：先让用户看到边缘，避免一次事件中途变向造成跳变 |
| 横向无溢出 | 回退为普通滚轮（纵向滚动/边缘翻页/直接翻页） | 用户确认；适宽页面占多数，Shift 不产生死区 |
| Shift 路径纵向到边 | 沿用边缘翻页、落点与手势节流 | 用户确认；与普通滚轮共用一套翻页心智模型 |

## 四、核心算法 / 口径

### 4.1 滚轮增量归一化

`WheelEvent.deltaY` 的单位随 `deltaMode` 变化，统一换算为 CSS 像素：

```ts
function normalizeWheelDelta(e: WheelEvent, viewportHeight: number): number {
  switch (e.deltaMode) {
    case 1: return e.deltaY * 16          // DOM_DELTA_LINE：按一行约 16px
    case 2: return e.deltaY * viewportHeight // DOM_DELTA_PAGE：按一页 = 视口高
    default: return e.deltaY              // DOM_DELTA_PIXEL
  }
}
```

- `Math.abs(deltaY) < 0.5` 视为噪声，直接返回。
- 横向占主导（`|deltaX| > |deltaY|`）且未按 Shift 时不接管，交给原生横向滚动。

### 4.2 边缘翻页状态机

新建纯逻辑模块 `src/services/wheelScroll.ts`，不接触 DOM，输入当前滚动几何与时间，输出「下一 scrollTop + 是否翻页 + 新状态」。

```ts
export const GESTURE_GAP_MS = 200
export const EDGE_TURN_THRESHOLD_PX = 80

export interface WheelScrollState {
  /** 当前手势内累计的越界滚动量（CSS px，≥0） */
  edgeAccum: number
  /** 当前手势已触发过翻页：剩余事件全部吞掉 */
  turnedInGesture: boolean
  /** 上一次滚轮事件时间（performance.now） */
  lastEventAt: number
  /** 上一次滚动方向：1=向下 / -1=向上 / 0=无 */
  lastDir: -1 | 0 | 1
}

export interface WheelStepInput {
  deltaY: number        // 已归一化为 CSS 像素
  scrollTop: number
  scrollHeight: number
  clientHeight: number
  now: number
}

export interface WheelStepResult {
  /** 调用方写回 pageArea.scrollTop */
  scrollTop: number
  /** 需要翻页时非 null */
  turn: 'next' | 'prev' | null
  /** 滚动模式下恒为 true，调用方据此 preventDefault */
  consumed: boolean
  state: WheelScrollState
}

export function stepWheelScroll(
  state: WheelScrollState,
  input: WheelStepInput,
  thresholdPx = EDGE_TURN_THRESHOLD_PX
): WheelStepResult {
  if (input.deltaY === 0) return { scrollTop: input.scrollTop, turn: null, consumed: true, state }

  const max = Math.max(0, input.scrollHeight - input.clientHeight)
  const dir: 1 | -1 = input.deltaY > 0 ? 1 : -1
  const newGesture = input.now - state.lastEventAt > GESTURE_GAP_MS

  let next: WheelScrollState = newGesture
    ? { edgeAccum: 0, turnedInGesture: false, lastEventAt: input.now, lastDir: 0 }
    : { ...state, lastEventAt: input.now }

  if (next.lastDir !== 0 && next.lastDir !== dir) next.edgeAccum = 0
  next.lastDir = dir

  // 同一手势已翻过页：吞掉剩余事件，防止惯性滚走新页
  if (next.turnedInGesture) {
    return { scrollTop: clamp(input.scrollTop, 0, max), turn: null, consumed: true, state: next }
  }

  const raw = input.scrollTop + input.deltaY
  const clamped = clamp(raw, 0, max)
  // 只在「事件发生前已经贴边」时才开始累计；快速甩到边缘的那次事件不算
  const atEdge = dir === 1 ? input.scrollTop >= max - 0.5 : input.scrollTop <= 0.5

  if (!atEdge) {
    return { scrollTop: clamped, turn: null, consumed: true, state: { ...next, edgeAccum: 0 } }
  }

  const accum = next.edgeAccum + Math.abs(raw - clamped)
  if (accum < thresholdPx) {
    return { scrollTop: clamped, turn: null, consumed: true, state: { ...next, edgeAccum: accum } }
  }

  return {
    scrollTop: clamped,
    turn: dir === 1 ? 'next' : 'prev',
    consumed: true,
    state: { ...next, edgeAccum: 0, turnedInGesture: true },
  }
}

function clamp(v: number, min: number, max: number): number {
  return Math.min(max, Math.max(min, v))
}
```

关键口径：

- **先到边、再翻页**：`atEdge` 用事件前的 `scrollTop` 判断。一次快速滚动从页面中间直接冲到底时，本次只滚动不翻页；下一次在底部继续滚才累计，避免用户还没看到页底就被翻走。
- **同手势最多一页**：`turnedInGesture` 置位后，直到事件间隔 >200ms 才重置；触控板惯性不会连续翻页，也不会把新页滚离落点。
- **累计阈值 80px**：鼠标一格通常 100px，一次即触发；触控板小增量需要累计约一次刻意滑动。
- **方向反转**：未翻页时清空累计；已翻页状态仍吞掉至手势结束（保持新页停在落点）。

### 4.3 边界场景防护清单

| 场景 | 行为 |
|------|------|
| `.page-area` 无纵向溢出 | 不进入本算法，走原翻页逻辑（20px 阈值 + 250ms `wheelLock`） |
| 可滚动，位于页面中间 | 只滚动，`turn = null`，清空越界累计 |
| 已在底部，继续向下 | 累计 `deltaY`；达到 80px → `next` |
| 已在顶部，继续向上 | 累计 `|deltaY|`；达到 80px → `prev` |
| 已在底部，向上滚 / 已在顶部，向下滚 | 正常滚动，不累计 |
| 同一手势翻页后继续滚 | `consumed = true`、`turn = null`，不滚动、不翻页 |
| 手势间隔 >200ms | 重置 `edgeAccum` / `turnedInGesture`，允许新手势再次翻页 |
| 书首向上 / 书尾向下 | `reader.prev()/next()` 越界无操作；停留在边界，不报错 |
| 横向分量占主导（无 Shift） | 不接管，保留原生横向滚动（自定义/原始模式可能横向溢出） |
| 目标是 `input/select/textarea` | 不接管，交给控件（顶栏缩放 select、底栏滑块） |
| Ctrl/Cmd+滚轮 | 最高优先级，走 `stepZoom`，不滚动不翻页 |
| 溢出仅 1px（舍入） | `scrollHeight > clientHeight + 1` 判定为不可滚动，避免误接管 |
| 新页高度小于视口 | 复位 `scrollTop` 为 no-op；内容仍按现有 `margin:auto` 居中 |
| `prefers-reduced-motion` | 跳过卷曲动画，但新页渲染与落点复位照常执行 |
| 单页渲染失败 | `paintPage` 已 catch 单页错误；复位仍执行，画面保留旧页（现有容错） |
| Shift+滚轮，横向未到边 | 只移动 `scrollLeft`，页码不变，不触碰纵向手势状态 |
| Shift+滚轮，横向无溢出 | 回退为普通滚轮分支（纵向滚动 / 边缘翻页 / 纵向也不可滚时直接翻页） |
| Shift+滚轮，已在右缘继续向下 / 左缘继续向上 | 转为纵向移动（§4.5） |
| Shift+滚轮，右缘向上 / 左缘向下 | 正常横向移动，不转纵向 |
| Shift+滚轮跨边事件 | 本次只横向夹取到边，剩余量丢弃；下一次事件才转纵向 |
| Shift+滚轮转纵向后到顶/底 | 沿用 §4.2 的累计与翻页；同一手势最多翻一页 |

### 4.4 翻页落点矩阵

| 触发路径 | 落点 | 说明 |
|----------|------|------|
| 滚轮到底 → 下一页 | 顶部 | 新页从页首开始 |
| 滚轮到顶 → 上一页 | 底部 | 可继续向上阅读上一页 |
| 键盘 / 热区 / 底栏按钮：下一页 | 顶部 | 与滚轮一致 |
| 键盘 / 热区 / 底栏按钮：上一页 | 底部 | 与滚轮一致 |
| 滑块前进 / 后退 | 顶部 / 底部 | 松手收尾时复位 |
| Shift+滚轮转纵向后到边 → 翻页 | 顶部 / 底部 | 与普通滚轮共用翻页与复位；翻页后横向回左缘 |
| 打开 / 切换书籍 | 顶部 | 新书从页首开始；避免复用组件残留旧滚动位置 |
| 模式 / 方向 / 缩放切换 | 不复位 | 维持现有行为；缩放时保留用户正在看的位置 |
| 页面无纵向溢出 | 复位为 no-op | `scrollTop` 本来就是 0 |

### 4.5 Shift+滚轮：横向优先、到边转纵向

新增纯函数 `stepShiftWheelScroll`，入参同时携带横向与纵向几何，需要时在内部委托 `stepWheelScroll`：

```ts
export interface ShiftWheelInput {
  /** 已归一化的滚轮量（>0 向右/下，<0 向左/上） */
  delta: number
  scrollLeft: number
  scrollWidth: number
  clientWidth: number
  /** 纵向回退所需几何 */
  scrollTop: number
  scrollHeight: number
  clientHeight: number
  now: number
}

export interface ShiftWheelResult {
  scrollLeft: number
  scrollTop: number
  turn: 'next' | 'prev' | null
  consumed: boolean
  state: WheelScrollState
}

export function stepShiftWheelScroll(
  state: WheelScrollState,
  input: ShiftWheelInput
): ShiftWheelResult {
  const maxX = Math.max(0, input.scrollWidth - input.clientWidth)

  // 横向无溢出：Shift 回退为普通纵向逻辑
  if (maxX <= 1) {
    const r = stepWheelScroll(state, {
      deltaY: input.delta,
      scrollTop: input.scrollTop,
      scrollHeight: input.scrollHeight,
      clientHeight: input.clientHeight,
      now: input.now,
    })
    return { scrollLeft: input.scrollLeft, scrollTop: r.scrollTop, turn: r.turn, consumed: r.consumed, state: r.state }
  }

  // 只在事件开始前已贴边时才转纵向：跨边的那次事件只做横向
  const atRight = input.scrollLeft >= maxX - 0.5
  const atLeft = input.scrollLeft <= 0.5
  const toVertical = input.delta > 0 ? atRight : atLeft
  if (!toVertical) {
    return {
      scrollLeft: clamp(input.scrollLeft + input.delta, 0, maxX),
      scrollTop: input.scrollTop,
      turn: null,
      consumed: true,
      state, // 横向纯移动不写入纵向手势状态
    }
  }

  // 已贴边：整个增量转为纵向（右缘向下 / 左缘向上），复用纵向状态机
  const r = stepWheelScroll(state, {
    deltaY: input.delta,
    scrollTop: input.scrollTop,
    scrollHeight: input.scrollHeight,
    clientHeight: input.clientHeight,
    now: input.now,
  })
  return { scrollLeft: input.scrollLeft, scrollTop: r.scrollTop, turn: r.turn, consumed: r.consumed, state: r.state }
}
```

关键口径：

- **方向映射**：`delta > 0`（向下滚）先向右移动，贴右缘后继续向下滚即转为向下；`delta < 0`（向上滚）先向左，贴左缘后转为向上。
- **先到边、再转向**：用事件前的 `scrollLeft` 判断是否贴边；从中间一次冲到边缘的事件只做横向夹取，不把剩余量转成纵向，避免画面中途跳变。
- **横向不写纵向状态**：纯横向移动不改 `lastEventAt` / `edgeAccum` / `lastDir`；之后转纵向时按新手势从零累计，不会被横向事件误延续；与上一次翻页间隔 >200ms 时也不会被 `turnedInGesture` 吞掉。
- **纵向边翻页复用**：转纵向后完全交给 `stepWheelScroll`，80px 阈值、200ms 手势间隔、同一手势最多一页、书首书尾无操作等规则不变。
- **横向无溢出**：`maxX <= 1` 时等同于普通滚轮；若纵向也不可滚，视图层不接管，落入原翻页分支（20px + `wheelLock`）。

## 五、渲染层实现

### 5.1 新增纯逻辑模块 `src/services/wheelScroll.ts`

- 导出 `GESTURE_GAP_MS`、`EDGE_TURN_THRESHOLD_PX`、`normalizeWheelDelta`、状态/输入/输出接口、`stepWheelScroll`、`stepShiftWheelScroll`。
- 不引用 Vue、不访问 DOM；`now` 由调用方传入，便于注入假时钟单测。
- 常量集中在本文件，后续调手感只改一处。

### 5.2 `ReaderView.vue` 滚轮接线

改造 `onWheel`（现 L585-597），按以下顺序分支：

1. `Ctrl/Cmd` → `stepZoom`（原逻辑，`preventDefault`；Ctrl+Shift+滚轮同样走缩放）。
2. 目标是 `input/select/textarea` → 直接返回。
3. `Shift` → Shift 分支（必须先于「横向占主导」判定）：
   - 归一化 `deltaY`（为 0 时取 `deltaX`），小于 0.5px 返回；
   - `isHorizontallyScrollable() || isVerticallyScrollable()` 为 true → `preventDefault`，调用 `stepShiftWheelScroll`，写回 `scrollLeft` / `scrollTop`，按 `turn` 调 `reader.next()/prev()`；
   - 两者都不可滚 → 落到第 5 步的原翻页逻辑。
4. 横向占主导 → 直接返回（保留原生横向滚动）。
5. `isVerticallyScrollable()` 为 false → 保留原翻页逻辑（`wheelLock` + 20px 阈值）。
6. 为 true → `preventDefault`，调用 `stepWheelScroll`，写回 `scrollTop`，按 `turn` 调 `reader.next()/prev()`。

纵向与 Shift 共用一份状态：

```ts
let wheelScrollState: WheelScrollState = {
  edgeAccum: 0,
  turnedInGesture: false,
  lastEventAt: 0,
  lastDir: 0,
}
```

新增辅助函数：

```ts
function isVerticallyScrollable(): boolean {
  const area = pageAreaEl.value
  return !!area && area.scrollHeight > area.clientHeight + 1
}

function isHorizontallyScrollable(): boolean {
  const area = pageAreaEl.value
  return !!area && area.scrollWidth > area.clientWidth + 1
}

function resetPageScroll(anchor: 'top' | 'bottom'): void {
  const area = pageAreaEl.value
  if (!area) return
  area.scrollTop = anchor === 'bottom' ? area.scrollHeight : 0 // 浏览器自动夹取到最大值
  area.scrollLeft = 0 // 翻页后横向也回左缘，避免自定义/原始模式残留旧平移
}
```

新增/调整的复位调用点：

- `watch(currentDisplayPages)`（现 L283-336）：`isPageTurn` 为真且 `renderCurrentSpread()` 完成后，`resetPageScroll(turnDir === 'back' ? 'bottom' : 'top')`。
- `openBook()` 的渲染完成后：`resetPageScroll('top')`，覆盖打开/切换书籍。
- 滑块收尾（§5.4）：`resetPageScroll(dir === 'back' ? 'bottom' : 'top')`。
- 模式/方向/缩放切换不新增复位。

> 复位放在渲染完成之后：`renderCurrentSpread()` 已把新页 canvas 的 `style.width/height` 写好，此时 `scrollHeight` 才是新页高度；提前复位会被旧页高度夹取。

### 5.3 快照与卷曲动画改造（保留动画）

现有 `snapshotVisible()`（L341-374）以 `.page-content` 为坐标系合成整页快照。新增参数化 `snapshotForTurn(viewport: boolean)`：

- `viewport = true`：以 `.page-area` 的可视矩形为裁剪框，只绘制与视口相交的 canvas 区域，并用 `#000` 填底；输出尺寸 = 视口尺寸。
- `viewport = false`：维持 `.page-content` 完整盒子坐标系的既有行为。
- 快照遍历**当前仍挂载的 canvas**（`canvasEls` 中 `isConnected && width > 0`），而不是按新页组长度索引，避免单双页数量变化时漏拍旧页。
- 按 canvas 实际矩形整幅绘制、由画布自动裁剪到可视区（视口快照无需额外裁剪源区域）；目标坐标用 `dpr` 换算，避免 canvas 物理像素与 CSS 尺寸舍入不一致。

`from` 是否用视口快照的判定：**翻页前的旧页是否纵向溢出**（`isVerticallyScrollable()`）。

- `from` 在 `renderCurrentSpread()` 之前捕获；`to` 在复位之后捕获；
- 两者必须使用同一 `viewport` 模式，卷曲目标同步选择：
  - `viewport = true` → `target: pageAreaEl`
  - `viewport = false` → `target: pageContentEl`
- 旧页溢出的典型场景：用户在页底滚轮翻页，视口快照只含当前可见的页底切片；复位后 `to` 快照是新页顶部（前进）或上一页底部（后退），动画揭层时不会跳。
- 旧页不溢出的场景：沿用完整内容快照；若新页恰好更高，复位到顶/底后，完整内容快照的覆盖层坐标与落点一致，仍不会跳。
- `pageCurl.ts` 无需修改：它本来就以 `target.getBoundingClientRect()` 决定覆盖层位置与尺寸（L34-49），`pageAreaEl` / `pageContentEl` 都可作为 target。
- `zIndex: 1` 保持不变，控制栏仍在动画之上。
- 视口快照按 canvas 的实际 `getBoundingClientRect()` 与 `.page-area` 可视矩形求交，横向滚动偏移已包含在 rect 坐标中：Shift+滚轮平移后翻页，快照仍是用户当前看到的区块。

### 5.4 滑块路径收尾

现有 `onSlide` / `onSlideEnd` / `finishSlideWithCurl`（L532-583）需要同步落点规则：

- `onSlide` 首次/每次捕获起点快照时，同时记录 `slideFromViewport = isVerticallyScrollable()`，并调用 `snapshotForTurn(slideFromViewport)`。
- `onSlideEnd` 统一进入 `finishSlide`：**先 `renderCurrentSpread()`，再 `resetPageScroll(落点)`，再按条件播放卷曲**。
- 即使 `prefers-reduced-motion` 或没有起点快照，也必须完成「渲染 + 复位」，不能提前返回而停留在旧页/旧滚动位置。
- 动画目标与 `to` 快照按 `slideFromViewport` 选择 `pageAreaEl` / `pageContentEl`。

### 5.5 不改动的部分

- `src/stores/reader.ts`：页码/模式/方向/缩放的持久化不变。
- `src/services/pageCurl.ts`：target 仍是通用 HTMLElement，无需感知滚动。
- `src/services/pageCache.ts`：缓存签名已含视口/模式/缩放，滚动不影响位图。
- `src/services/pdf.ts` / `cbz.ts` / `pageRenderer.ts`：渲染尺寸口径不变。
- `shared/types.ts`、`electron/**`：无 IPC/DB/类型变更。

## 十、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 手动接管滚轮 | 放弃原生滚动，改为逐事件写 `scrollTop` | 换取「一次事件只做一件事」和精确边缘判定；触控板高频事件仍能平滑滚动，鼠标滚轮为逐格跳动（与 Chromium 默认一致） |
| 80px 阈值 | 鼠标一格（约 100px）即翻，触控板需累计 | 数值集中在 `EDGE_TURN_THRESHOLD_PX`；若实测过敏感/迟钝，只调一处 |
| 200ms 手势间隔 | 同一连续手势最多翻一页 | 防止惯性连翻；用户需短暂停顿再翻下一页，符合「先滚到边再继续」的预期 |
| 「先到边再翻页」 | 快速甩到边缘的那次事件不翻页 | 保证用户看到页底；代价是快速甩动后需再滚一次 |
| 旧页溢出才用视口快照 | 不改变适高/短页的既有卷曲观感 | 旧页不溢出、 新页更高时仍用完整内容快照：复位后覆盖层坐标与落点一致，不会跳 |
| 所有纵向溢出模式生效 | 不只适宽，自定义/原始也可能接管 | 用户确认；只有实际高于视口才生效，适高通常无变化；行为更一致 |
| 翻页后横向回左缘 | 需求只说「最顶部」，额外重置 `scrollLeft` | 新页从左上角开始；避免自定义/原始模式横向平移残留；Shift 平移后翻页同样回左缘 |
| 滚动位置不持久化 | 每次翻页按规则复位，重开书从页首 | 与需求一致；如未来需要「记住页内位置」，需扩展进度模型，不在本期 |
| 不改模式/缩放切换落点 | 保持现有行为 | 缩放时保留用户正在看的位置；切换模式后浏览器自动夹取 `scrollTop`，可能出现中间位置，属既有行为 |
| 动画无用例级自动化 | 视口快照/卷曲依赖真实 DOM 与 Canvas | 单测只覆盖状态机；动画走 §8.2 手工冒烟，沿用项目「纯逻辑单测 + 视觉手工验证」分工 |
| Shift 横向接管 | 放弃浏览器原生 Shift+滚轮横向滚动，改为手动写 `scrollLeft` | 换取「到边转纵向」能力；横向为逐事件跳格，与纵向手动接管手感一致 |
| 跨边事件不转纵向 | 到边当次只夹取，剩余增量丢弃 | 避免一次事件中途变向导致画面跳变；代价是到边后需再滚一次才开始上下移动 |
| Shift 横向无溢出回退 | 等同普通滚轮 | 用户确认；适宽页面不会出现 Shift 无响应 |
| Shift 到纵向边翻页 | 与普通滚轮共用翻页、落点与手势节流 | 用户确认；只保留一套翻页心智模型 |
| 无新增依赖 | 全部使用现有 DOM/Canvas | 守住纯离线与不新增依赖红线 |
