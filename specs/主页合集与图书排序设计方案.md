# 主页合集与图书排序设计方案

> 状态：已实现（已验证）
> 目标版本：不变更版本号（当前 package.json 为 1.2.5，发版由维护者自行执行）
> 范围：主页（文库页）合集卡片与图书卡片的排序规则、搜索关键字过滤范围
> 实现约束：遵循 `ireader-dev-tasks`（任务 D 渲染层功能 / 任务 F 验证流程）与 `ireader-code-conventions`（纯逻辑入 `src/services/` 并配 Vitest 中文用例、排序偏好继续走 localStorage）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 合集卡片都在图书卡片前 | `LibraryView.vue` 保持「合集 `v-for` → 图书 `v-for`」两个块的先后顺序，共用同一网格；合集占网格前部单元格 | 任意排序方式下，主页网格中所有合集卡连续位于所有图书卡之前 |
| 2 | 合集适用「书名」排序 | `sortCollections` 以 `collection.title` 为键，`localeCompare(..., 'zh-Hans-CN')` | 选书名 + 升/降序，合集块按名称拼音序正确排列 |
| 3 | 合集适用「添加时间」排序 | 合集无添加时间，取 `collection.createdAt`（创建时间）为键 | 选添加时间 + 升/降序，合集按创建时间排列，与 `collection.list()` 返回顺序一致（无额外过滤时） |
| 4 | 合集适用「最近阅读」排序 | 合集无自身阅读时间，派生为「集内书 `lastOpenedAt` 的最大值」，从未阅读/空合集记 0 | 阅读某合集内任意一本书后回到主页，该合集在「最近阅读」降序下排到合集块首位 |
| 5 | 图书适用「书名 / 添加时间 / 最近阅读」排序 | 沿用现有 `filteredBooks`，比较器抽到 `sortBooks` 纯函数，语义不变 | 三种键 × 升降序下未分组书排序正确，与改造前一致 |
| 6 | 搜索关键字同时过滤合集（本次确认补充） | `filterCollectionsByKeyword`：合集标题命中，或集内任意书名命中，即保留该合集 | 搜索合集名只剩该合集；搜索集内书名时所属合集仍展示；关键字为空时全部合集展示 |

**核心验收口径**：「书名 / 添加时间 / 最近阅读」×「升序 / 降序」共 6 种组合下，主页所有合集卡连续排在所有图书卡之前，且两类卡片各自严格按所选键排序；合集「最近阅读」以集内最新一次阅读时间为准，从未阅读的合集在降序下排最后。

## 二、非目标（本期不做）

- 不改合集详情页：详情页书列表保持固定「名称升序」，头部文案「按名称排序」不变；右侧「继续阅读」侧栏的上一本/下一本顺序不受影响。
- 不给 `collections` 表新增 `last_opened_at` 等字段：合集「最近阅读」为派生值即可满足需求，避免 DB 迁移与 IPC 契约变更（空合集的「阅读时间」语义本身也不成立）。
- 不做拖拽自定义排序、不做排序键多级组合配置。
- 不改合集封面取书规则（`CollectionCard` 仍按集内书名升序取第一本作封面）。
- 不改 `BookCard` / `CollectionCard` 的视觉与布局；不强制「合集块与图书块分行」，仅保证前后顺序。
- 不做合集嵌套、合集排序偏好与图书排序偏好分开配置。
- 不改排序偏好持久化方式：继续使用 `localStorage['ireader.sort']`。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层（本次改动全部集中在此；无 IPC、无 DB、无主进程改动）──────────┐
│ LibraryView.vue                                                       │
│   ├─ 合集块 v-for="c in library.sortedCollections" → CollectionCard   │
│   └─ 图书块 v-for="book in ungroupedBooks"          → BookCard        │
│                     ▲                        ▲                        │
│                     │                        │                        │
│ useLibraryStore（Pinia，src/stores/library.ts）                        │
│   keyword / sortBy / sortOrder（沿用 localStorage 'ireader.sort'）     │
│   ├─ filteredBooks     = 关键字过滤书名 + sortBooks(...)               │
│   └─ sortedCollections = filterCollectionsByKeyword(...)               │
│                          + sortCollections(...)                       │
│                     ▲                                                 │
│ src/services/libraryList.ts（纯函数，可单测）                          │
│   sortBooks / sortCollections / filterCollectionsByKeyword            │
└───────────────────────────────────────────────────────────────────────┘
```

数据来源仍是 `library.refresh()` 已拉取的全量 `books` / `collections`，排序与过滤在渲染层完成，不新增查询。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 排序实现位置 | 渲染层纯函数 `libraryList.ts` + store computed | 排序偏好是纯展示偏好，主进程 repo 不应感知；纯函数可单测，避免比较器散落在视图与 store 两处 |
| 合集「最近阅读」口径 | 派生集内书 `lastOpenedAt` 最大值（用户确认） | 免 DB 迁移与 IPC 变更；语义即「合集里有新阅读就前移」。空合集/从未阅读无值，落 0 |
| 合集「添加时间」口径 | `collection.createdAt` | 合集无其他时间字段；`createdAt` 即合集被创建（添加）的时间，语义直接 |
| 搜索过滤范围 | 合集标题或集内书名命中即保留合集（用户确认） | 只按合集标题匹配会让「搜索集内书」丢失入口；保留合集可进入后看到该书 |
| 详情页 | 不跟随排序偏好（用户确认） | 需求限定主页；详情页已用「按名称排序」明示规则，侧栏导航顺序也依赖该规则 |
| 排序键相同的兜底 | 保持入参顺序（`Array#sort` 稳定），不引入第三键 | 入参顺序来自 repo：书 `last_opened_at DESC NULLS LAST, added_at DESC`、合集 `created_at DESC`，可让「均未阅读」时仍按入库先后排，避免改变现有体验 |
| 标题比较 locale | 图书与合集统一 `localeCompare(title, 'zh-Hans-CN')` | 现状是书用默认 locale、合集用 `zh-Hans-CN`；统一后跨系统 locale 结果确定，且中英文混排一致 |

## 四、排序与过滤算法（核心）

### 4.1 排序键映射

| `sortBy` | `Book` 取值 | `Collection` 取值 |
|----------|-------------|-------------------|
| `title` | `book.title` | `collection.title` |
| `addedAt` | `book.addedAt` | `collection.createdAt` |
| `lastOpenedAt` | `book.lastOpenedAt ?? 0` | 集内 `book.lastOpenedAt` 最大值，无则 `0` |

方向统一为 `dir = order === 'asc' ? 1 : -1`，比较结果乘以 `dir`。

### 4.2 TS 伪代码

```ts
// src/services/libraryList.ts —— 文库列表过滤与排序的纯函数
import type { Book, Collection, SortBy, SortOrder } from '../../shared/types'

interface SortableItem {
  title: string
  addedAt: number
  lastOpenedAt: number | null
}

function compare(a: SortableItem, b: SortableItem, sortBy: SortBy, dir: 1 | -1): number {
  if (sortBy === 'title') return a.title.localeCompare(b.title, 'zh-Hans-CN') * dir
  if (sortBy === 'addedAt') return (a.addedAt - b.addedAt) * dir
  return ((a.lastOpenedAt ?? 0) - (b.lastOpenedAt ?? 0)) * dir
}

/** 图书排序：不修改入参，返回新数组 */
export function sortBooks(books: readonly Book[], sortBy: SortBy, order: SortOrder): Book[] {
  const dir = order === 'asc' ? 1 : -1
  return [...books].sort((a, b) => compare(a, b, sortBy, dir))
}

/** 合集排序：合集无自身阅读时间，取集内书 lastOpenedAt 最大值作键（单遍聚合） */
export function sortCollections(
  collections: readonly Collection[],
  allBooks: readonly Book[],
  sortBy: SortBy,
  order: SortOrder
): Collection[] {
  const lastRead = new Map<number, number>()
  for (const b of allBooks) {
    if (b.collectionId == null || b.lastOpenedAt == null) continue
    if (b.lastOpenedAt > (lastRead.get(b.collectionId) ?? 0)) {
      lastRead.set(b.collectionId, b.lastOpenedAt)
    }
  }
  const dir = order === 'asc' ? 1 : -1
  return [...collections].sort((a, b) =>
    compare(
      { title: a.title, addedAt: a.createdAt, lastOpenedAt: lastRead.get(a.id) ?? null },
      { title: b.title, addedAt: b.createdAt, lastOpenedAt: lastRead.get(b.id) ?? null },
      sortBy,
      dir
    )
  )
}

/** 合集关键字过滤：标题命中，或集内任意书名命中，即保留 */
export function filterCollectionsByKeyword(
  collections: readonly Collection[],
  allBooks: readonly Book[],
  keyword: string
): Collection[] {
  const kw = keyword.trim().toLowerCase()
  if (!kw) return [...collections]
  // 先单遍聚合「有书名命中的合集」，避免每个合集都全量扫描书列表
  const hit = new Set<number>()
  for (const b of allBooks) {
    if (b.collectionId != null && b.title.toLowerCase().includes(kw)) hit.add(b.collectionId)
  }
  return collections.filter((c) => c.title.toLowerCase().includes(kw) || hit.has(c.id))
}
```

### 4.3 边界场景防护清单

| 场景 | 行为 |
|------|------|
| 合集从未被阅读 / 空合集 | `lastOpenedAt` 记 0：降序排最后，升序排最前（与图书 `null → 0` 的既有规则一致） |
| 集内多本书均有阅读记录 | 取最大值，不累加、不平均 |
| 书被移入/移出合集 | 由 `library.books` 实时数据派生，computed 自动重算，无需额外存储 |
| 书被删除 / 合集被解散 | 同上，派生值随数据收缩，无脏数据 |
| 排序键完全相同（同名、同毫秒创建、均未阅读） | 保持入参顺序（`Array#sort` 在 V8 稳定）；入参顺序由 repo 决定，见 §3.2 |
| 关键字为空 / 纯空格 | 合集不过滤，返回全部 |
| 关键字命中集内书名 | 合集保留，徽章仍显示合集**总**书数（不随搜索变化） |
| 关键字大小写 / 前后空格 | `trim().toLowerCase()` 后 `includes` 比较，大小写不敏感 |
| 中文标题排序 | `localeCompare(..., 'zh-Hans-CN')`；Electron 渲染进程与 Node（Vitest）均带完整 ICU |
| 排序偏好损坏 | 沿用现有 `loadSortPref`：非法值回退「最近阅读 + 降序」，本次不改 |

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 合集「最近阅读」为派生值 | 不新增 `collections.last_opened_at` | 合集位置随集内阅读动态变化，符合「有新阅读就前移」直觉；空合集永远无阅读时间，排序时落两端。将来若需要「打开合集即前移」，再按 MIGRATIONS 追加式迁移扩展 |
| 搜索时合集命中集内书名即保留 | 不展开显示集内书 | 保留入口但不改动网格结构；用户需进入合集查看命中书。若将来要展示命中书，另立需求 |
| 同值兜底依赖 repo 入参顺序 | 不增加标题/ID 第三排序键 | 保持与现状一致的「均未阅读按入库先后」体验；注意：将来若修改 repo 的 `ORDER BY`，同值顺序会随之变化，需回看本文档 |
| 标题比较统一 `zh-Hans-CN` | 图书由默认 locale 改为显式 locale | 跨系统 locale 结果确定；极少数英文/符号书名次序可能与本机默认排序略有差异，接受 |
| 排版不强制合集块换行 | 合集与图书共用同一网格 | 严格满足「合集在图书前」的阅读顺序；若将来希望视觉分组，可单独加分隔行，不影响本次排序语义 |
| 无 IPC / DB 变更 | 排序完全在渲染层 | 改动面最小、可回退；书库规模为百级，computed 全量排序开销可忽略 |
