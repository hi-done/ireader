# 软件更新功能设计方案（设置页检查更新 + Windows 增量更新）

> 状态：设计稿（待实现）
> 目标版本：v1.2.0（当前 1.1.2，新功能按 minor 递增）
> 范围：设置页「关于」分组（版本展示 + 检查更新按钮 + 下载进度 + 重启安装）、主进程更新服务（electron-updater 封装）、发布链补齐（latest.yml / blockmap 上传）
> 实现约束：遵循 `ireader-dev-tasks`（任务 A/D/F）与 `ireader-code-conventions`（Result 契约、中文注释、双进程共享类型）；红线修订经用户确认（见 §3.2 决策 1）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 设置页增加「检查更新」按钮 | SettingsView 新增「关于」分组：当前版本行 + 检查更新按钮 + 状态区（§8） | dev 与打包模式下按钮可见、可点击、各状态文案正确 |
| 2 | 实现软件增量更新 | electron-updater（Windows 差量下载 + 静默安装）；主进程 updaterService 状态机（§6） | 发 v1.2.1 后，v1.2.0 客户端检查 → 下载 → 重启安装 → 标题栏变为 v1.2.1 |
| 3 | 增量：下载量显著小于全量包 | 差量基于 blockmap 内容哈希分块（§4），electron-updater 内置 | 发 v1.2.2 后，v1.2.1 客户端更新下载量明显小于安装包体积（136 MB 量级） |
| 4 | 对接 readme 发版方式（GitHub Releases） | package.json build 增加 publish（GitHub provider）；release.yml 补传 latest.yml 与 blockmap（§9） | v1.2.0 起 Release 资产含 `latest.yml` 与 `IReader-<版本>-win.exe.blockmap` |

**核心验收口径**：v1.2.0 安装包内嵌 GitHub 更新源（resources/app-update.yml）；发布 v1.2.1 后，Windows 客户端依次完成「检查 → 提示新版本与更新说明 → 手动下载（进度可见）→ 一键重启静默安装 → 版本号升级」，全程无手动去网页下载安装包；macOS 客户端检查到新版本后可一键跳转 Release 页下载。

## 二、非目标（本期不做）

- 不做启动时自动检查与后台轮询：用户已确认「仅手动触发」（§3.2 决策 1），不新增自动检查设置项。
- 不做 macOS 自动更新：构建未签名（`identity: null`），electron-updater 的 Squirrel.Mac 通道强制要求代码签名，属硬约束而非取舍；macOS 走「检测 → 跳转浏览器下载」降级路径。代码签名需购买证书，超出本期。
- 不做更新频道（beta / prerelease）：electron-updater 默认只认非 draft、非 prerelease 的最新正式 Release，维持默认。
- 不做下载暂停/取消：electron-updater 24 无公开取消 API；差量失败自动回退全量由其内置处理。
- 不做多架构 macOS 发版（x64 dmg）：现状仅 arm64（CI macos-latest），维持不变。
- 不做更新历史、版本回滚、强制更新。
- 不改数据库：本功能无持久化需求（无 DB 迁移、无 settings 新增项）。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ──────────────────────────────────────────────────────────┐
```

### 3.2 关键决策（均经用户确认）

| 决策 | 选择 | 理由 |
|------|------|------|
| 网络红线边界 | 仅手动触发：用户点击「检查更新」才访问 GitHub，其余时刻零网络 | 用户确认；核心阅读功能维持零网络，无后台轮询、无遥测。ireader-code-conventions 红线 1 的「纯离线」据此修订为「除用户主动检查更新外零网络请求」，readme 同步修订（§9.3） |
| 技术路线 | electron-updater@^6.8.9（新增依赖，已确认） | 6.x 为当前稳定版本线（npm latest；24.13.3 版本号系设计时笔误，实际版本线为 6.x），与 electron-builder 24 的 latest.yml 格式经生产项目广泛验证兼容；blockmap 差量下载、差量失败回退全量、sha512 完整性校验均内置，自研无法低成本复刻；Windows 未签名不影响差量下载 |
| macOS 策略 | 检查可用，下载/安装降级为跳转浏览器 | 未签名应用无法走 Squirrel.Mac 自动更新（技术硬约束）；checkForUpdates 仅查询 GitHub API + 版本比较，不受签名影响 |
| 构建配置归属 | package.json 的 build 字段为唯一真源，删除 electron-builder.json5 | 用户确认。实证：read-config-file 源码 `loadConfig`（packageKey='build'）package.json 的 build 字段优先于独立配置文件，且 v1.1.2 实际产物名 `IReader-1.1.2-win.exe`（单架构 mac dmg）只匹配 package.json build 的 artifactName——electron-builder.json5 从未生效且内容漂移（appId / 产物名 / mac 双架构均不一致），保留会持续误导 |
| 下载触发 | `autoDownload = false`，用户看到新版本说明后再点「下载更新」 | 网络行为最小化（与决策 1 同源）；用户对何时占用带宽有控制权 |
| 安装方式 | `quitAndInstall(true, true)` 静默装回原目录并自动重启 | 阅读器场景不打断用户；NSIS perMachine=false（per-user 安装）静默覆盖安装成熟可靠；如需安装向导改一行参数即可（风险表 §13） |
| 退出时自动安装 | `autoInstallOnAppQuit = false` | 避免用户正常退出应用时被突袭安装；安装只由「重启并安装」按钮显式触发 |
| 更新说明展示 | 轻量清洗为纯文本（cleanReleaseNotes 纯函数） | 不引入 markdown 渲染依赖；GitHub `generate_release_notes` 生成的 body 语法简单，清洗后可读性足够 |
| 进度通知 | `updater:progress` 单事件广播 + `updater:download` 的 invoke resolve 即完成 | 无需额外的 downloaded 事件；渲染层不在设置页时下载继续，回到设置页经 `updater:status` 恢复显示 |

## 四、增量更新机制与口径

### 4.1 版本发现与下载机制（全部由 electron-updater 内置，此处明确口径）

- **版本发现**：`checkForUpdates()` 请求 GitHub Releases 元数据，读取最新正式 Release（跳过 draft 与 prerelease）的 `latest.yml`，将其 `version` 与 `app.getVersion()` 做 semver 比较。
- **差量下载**：下载远端安装包的 `.blockmap`（内容分块的 sha512 清单），与本地缓存的上一版安装包 blockmap 对比，仅下载有变化的分块并在本地重组。未签名不影响差量（完整性由 sha512 校验，与 Authenticode 无关）。
- **冷启动口径（重要）**：差量依赖「上次由 updater 下载的安装包缓存」（`%LOCALAPPDATA%` 下 electron-updater 管理的目录）。用户手动安装的存量版本没有缓存，**首次更新必为全量下载，从第二次更新起才走差量**。UI 文案只展示下载进度，不向用户承诺「增量」字样。
- **失败回退**：差量下载失败自动回退全量下载（electron-updater 内置），无需自研重试逻辑。
- **安装语义**：差量只影响网络下载量；安装仍是 NSIS 对整个应用的覆盖安装，安装结果与全量更新完全一致。

### 4.2 边界场景防护清单

| 场景 | 行为 |
|------|------|
| 开发模式（`!app.isPackaged`）且无 dev-app-update.yml | `updater:check` 抛 `UPDATER_UNAVAILABLE`（中文提示「开发模式不支持检查更新」） |
| macOS 点「下载更新」 | updaterService 防呆：`autoUpdateSupported=false` 时抛 `UPDATER_UNAVAILABLE`；UI 层 macOS 本就不渲染下载按钮（双保险） |
| 检查中重复点检查 / 下载中重复点下载 | 状态机拒绝：抛 `INVALID_PARAMS`（中文提示「检查中，请稍候」/「正在下载中」） |
| 断网 / GitHub 不可达 / API 限流 | electron-updater 抛错 → updaterService 统一转 `UPDATER_FAILED`（中文 message，原始错误落日志文件）；UI 显示错误 + 「重试」 |
| latest release 是当前版本 | `isUpdateAvailable=false` → 显示「已是最新版本」 |
| 下载完成后退出应用（未点安装） | 不自动安装（`autoInstallOnAppQuit=false`）；已下载文件保留，下次检查后可直接重新进入 ready 流程（electron-updater 行为） |
| GitHub API 匿名限流（60 次/时/IP） | 仅手动触发，频率极低，不处理；将来若加自动检查需配 token（非目标） |

## 五、IPC 契约

### 5.1 共享类型（`shared/types.ts` 追加）

```ts
/** 更新检查结果（updater:check 返回） */
export interface UpdateCheckResult {
  /** 当前安装版本（app.getVersion()） */
  currentVersion: string
  /** 是否发现新版本 */
  isUpdateAvailable: boolean
  /** 新版本号（isUpdateAvailable 为 true 时有效，否则 null） */
  newVersion: string | null
  /** 更新说明（GitHub Release body 原文；渲染层经 cleanReleaseNotes 清洗后展示） */
  releaseNotes: string | null
  /** 新版本 Release 页地址（macOS 跳转下载 / 手动查看用；无更新时为 latest 页） */
  releaseUrl: string | null
  /** 当前平台是否支持自动下载安装（Windows=true，macOS=false） */
  autoUpdateSupported: boolean
}

/** 更新器状态（updater:status 返回；设置页进入时恢复 UI 用，纯本地无网络） */
export interface UpdateStatus {
  currentVersion: string
  autoUpdateSupported: boolean
  state: 'idle' | 'checking' | 'available' | 'notAvailable' | 'downloading' | 'ready'
  /** 新版本号（state 为 available / downloading / ready 时有效） */
  newVersion: string | null
  /** 最近一次下载进度（state 为 downloading 时非空） */
  progress: UpdateProgress | null
}

/** 下载进度（updater:progress 事件载荷） */
export interface UpdateProgress {
  /** 0-100 */
  percent: number
  /** 已传输字节 */
  transferred: number
  /** 总字节 */
  total: number
  /** 字节/秒 */
  bytesPerSecond: number
}
```

ErrorCode 联合类型追加两项（`shared/types.ts`）：

```ts
  | 'UPDATER_UNAVAILABLE' // 开发模式或当前平台不支持自动更新
  | 'UPDATER_FAILED'      // 检查/下载失败（网络异常、GitHub 不可达等）
```

### 5.2 通道定义

| 通道 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `updater:status` | 无 | `UpdateStatus` | 设置页进入时拉取，恢复状态显示；纯本地不联网 |
| `updater:check` | 无 | `UpdateCheckResult` | 手动检查（用户点击即发起 GitHub 网络请求；`updater:download` 同样仅由用户点击触发） |
| `updater:download` | 无 | `void` | 触发下载；invoke resolve 即下载完成（state → ready） |
| `updater:install` | 无 | `void` | 退出应用并静默安装重启；调用后应用随即退出，渲染层 fire-and-forget，不依赖返回值 |
| `shell:openExternal` | `{ url: string }` | `void` | 打开系统浏览器（macOS「前往下载」） |
| 事件 `updater:progress`（主→渲染） | 载荷 `UpdateProgress` | — | 下载进度广播，仅 downloading 状态期间发送 |

**服务层校验规则**（updaterService / handlers）：

- `shell:openExternal` 的 `url` 必须以 `https://github.com/hi-done/ireader/releases` 开头，否则抛 `{ code: 'INVALID_PARAMS', message: '不允许打开该链接' }`（安全防线：渲染层被注入时不能借通道打开任意 URL）。
- `updater:check`：非打包模式且未启用 dev 调试链 → `UPDATER_UNAVAILABLE`；`state` 为 checking/downloading → `INVALID_PARAMS`（防并发）。
- `updater:download`：`state` 不是 available → `INVALID_PARAMS`（「请先检查更新」）；`autoUpdateSupported=false` → `UPDATER_UNAVAILABLE`；downloading 中重复调用 → `INVALID_PARAMS`。
- `updater:install`：`state` 不是 ready → `INVALID_PARAMS`（「更新尚未下载完成」）。
- electron-updater 抛出的任何错误统一 catch 转 `{ code: 'UPDATER_FAILED', message: '检查更新失败，请检查网络后重试' / '下载更新失败，请检查网络后重试' }`，原始 error 经 logger.error 落 `{userData}/logs/ireader.log` 排障。

按「任务 A」六步落地：`shared/types.ts` → `electron/preload.ts`（updater 域 + shell.openExternal + onProgress）→ `electron/ipc/handlers.ts` → `src/services/ipc.ts` 镜像 → SettingsView 消费。

## 六、主进程实现

### 6.1 updaterService（新建 `electron/services/updaterService.ts`）

```ts
export function initUpdaterService(getWin: () => BrowserWindow | null): void  // main.ts whenReady 内调用
export function getStatus(): UpdateStatus                                      // 本地状态快照
export async function checkForUpdates(): Promise<UpdateCheckResult>
export async function downloadUpdate(): Promise<void>                          // resolve = 下载完成
export function quitAndInstall(): void
```

实现要点：

- **加载方式（关键工程点）**：electron-updater 是 CJS 包且 `autoUpdater` 为 getter 形式导出，ESM 具名导入依赖 cjs-module-lexer 静态分析（对 `Object.defineProperty` getter 不可靠）。用 `createRequire(import.meta.url)` 走 Node 原生 require，配合 `as typeof import('electron-updater')` 取回类型；vite.config.ts 将 `electron-updater` 加入 main 的 rollupOptions.external（与 better-sqlite3 同模式，运行时从 asar 内 node_modules 加载）。
- 初始化：`autoUpdater.autoDownload = false`、`autoUpdater.autoInstallOnAppQuit = false`、`autoUpdater.logger` 适配为项目 logger 的 info/warn/error；更新源不调用 setFeedURL（打包后读 resources/app-update.yml，由构建配置生成，见 §9.1）。
- **dev 调试链（官方机制）**：非打包模式下检测项目根是否存在 `dev-app-update.yml`（已 gitignore），存在则 `autoUpdater.forceDevUpdateConfig = true`，dev 也可完整走更新流程（指向本地静态服务，见 §11.2）；不存在则标记不可用。
- **平台能力**：`autoUpdateSupported = process.platform === 'win32'`（darwin 未签名不支持，linux 无发行版）。macOS 仍允许 checkForUpdates（纯 API 查询不受签名影响）。
- 状态机（模块级单变量）：`idle → checking → (available | notAvailable) → downloading → ready`；error 一律经 Promise reject 传出，state 回到检查/下载前的稳定态（available 或 idle），保证「重试」可用。
- 事件接线（订阅在 initUpdaterService 内一次完成）：
  - `download-progress` → 组装 UpdateProgress → `getWin()?.webContents.send('updater:progress', payload)`（无窗口时静默丢弃，状态机仍在记录，status 可恢复）；
  - `update-downloaded` → `state = 'ready'`（与 downloadUpdate 的 resolve 双通道同步，防渲染层不在线时状态丢失）；
  - `update-available` / `update-not-available` / `error` → 仅同步 state（主流程由各自 Promise 驱动，事件做兜底）。
- `checkForUpdates` 返回组装：`releaseUrl` 主进程拼接 `https://github.com/hi-done/ireader/releases/tag/v<newVersion>`（无更新时给 latest 页）；`releaseNotes` 取 updateInfo.releaseNotes（string 或 `Array<{note}>`，统一拍平为 string）。
- `quitAndInstall`：先 `logger.info('quit and install <version>')` 留痕，再 `autoUpdater.quitAndInstall(true, true)`（静默 + 装完自动启动）。

### 6.2 handler 编排（`electron/ipc/handlers.ts`）

现有 `wrap` 只包同步业务（其签名 `fn(...args) => T`，传入 async 函数会把 Promise 包进 Result）。updater 域为异步业务，在同文件内新增同构的 `wrapAsync`（await 后 ok，catch 转换逻辑与 wrap 一致），**不改动现有 wrap 与既有通道行为**：

```ts
ipcMain.handle('updater:status', wrap(() => updaterService.getStatus()))
ipcMain.handle('updater:check', wrapAsync(() => updaterService.checkForUpdates()))
ipcMain.handle('updater:download', wrapAsync(() => updaterService.downloadUpdate()))
ipcMain.handle('updater:install', wrap(() => updaterService.quitAndInstall()))
ipcMain.handle('shell:openExternal', wrap(({ url }: { url: string }) => {
  // 白名单：只放行本项目 GitHub Releases 页，防渲染层被注入后打开任意 URL
  if (!url.startsWith('https://github.com/hi-done/ireader/releases')) {
    throw { code: 'INVALID_PARAMS', message: '不允许打开该链接' }
  }
  shell.openExternal(url)
}))
```

`electron/main.ts` 仅加一行：whenReady 内 `initUpdaterService(() => win)`（置于 registerIpcHandlers 之后，订阅式初始化，无失败路径）。

## 七、渲染层实现

### 7.1 ipc 镜像（`src/services/ipc.ts` + `electron/preload.ts`）

### 7.2 updateFormat 纯函数（新建 `src/services/updateFormat.ts` + 同目录测试）

```ts
/** 字节数人性化（1024 进制）：'8.2 MB' / '136 MB' / '1.4 GB'（<1KB 取整 B，KB 起保留 1 位小数） */
export function formatBytes(bytes: number): string
/** 速度：'3.2 MB/s' / '512 KB/s'（0 → '0 B/s'） */
export function formatSpeed(bytesPerSecond: number): string
/** GitHub Release body 轻量清洗：去标题/加粗/链接 markdown 标记，连续空行折叠为单空行 */
export function cleanReleaseNotes(raw: string): string
```

cleanReleaseNotes 规则（覆盖 GitHub `generate_release_notes` 常见语法）：行首 `#{1,6} ` 去标记；`**text**` → `text`；`[text](url)` → `text`；`` `code` `` → `code`；行内 `-` 列表保留；≥2 连续空行折 1。此文件为纯函数，配 Vitest（§11.1），符合「只测纯逻辑」要求。

### 7.3 SettingsView 接线（`src/views/SettingsView.vue`）

- 「数据」分组之后新增「关于」分组（本功能唯一渲染层入口，无路由、无新 store——更新状态为页面局部 ref 状态，经 `updater:status` 恢复即可）。

## 九、发布链改造

### 9.1 构建配置（package.json 的 build 字段，实际生效处）

```json
"build": {
  ...现有内容不动...,
  "publish": {
    "provider": "github",
    "owner": "hi-done",
    "repo": "ireader"
  }
}
```

依据（node_modules/app-builder-lib 源码核实）：只要 build 配置含 publish——

- afterPack 阶段会把更新源写入 `resources/app-update.yml`（electron-updater 运行时读取），该写入**不受 `--publish never` 影响**（PublishManager 中位于 isPublish 判断之外）；
- NSIS 产物的 artifactCreated 事件带 `isWriteUpdateInfo`，latest.yml 的生成同样不受 isPublish 限制——即 **release/ 目录会多出 `latest.yml` 与 `IReader-<版本>-win.exe.blockmap`，但 electron-builder 不会自行上传**（isPublish=false），发布仍由 action-gh-release 统一完成，现有「禁止自动发布」注释的行为保持不变。

同时删除 `electron-builder.json5`（从未生效的死配置，§3.2 决策 3）。macOS 的 dmg target 不生成 update-info（差量更新要求 zip target 且需签名），无需为 mac 追加产物。本地 `npm run build`（非 CI、无 tag）时 isPublish 判定为 false，不会触发任何上传，行为安全。

### 9.2 CI（`.github/workflows/release.yml`）

「发布到 GitHub Releases」步骤的 files glob 追加两行：

```yaml
files: |
  release/**/*.dmg
  release/*/IReader-*-win.exe
  release/*/IReader-*-win.exe.blockmap
  release/*/latest.yml
```

### 9.3 readme 与红线文档同步

- `readme.md`：「纯离线 — 零网络请求」亮点行修订为「零网络请求（应用内手动检查更新为唯一例外）」；「下载安装」段补一句「Windows 用户可在 设置 → 关于 → 检查更新 内完成增量更新；macOS 因未签名跳转浏览器下载」。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| electron-updater 6.8.9 与 Electron 42 兼容性 | 6.x 稳定线 + 仅用稳定 API（app/net/BrowserWindow/webContents.send） | 6.x 跨多个 Electron 大版本发布、API 面稳定；M1 本地构建 + M2 dev 调试链双重冒烟兜底；若有运行时报错可升级 electron-updater 版本线（latest.yml 格式向后兼容，不影响已发版本） |
| 首次更新为全量下载 | 接受冷启动口径 | 差量收益从 v1.2.1 起生效；UI 不出现「增量」承诺字样，预期管理靠文案 |
| GitHub API 匿名限流（60 次/时/IP） | 仅手动触发，不处理 | 频率极低；将来若加自动检查需配 token（本期非目标） |
| Windows 未签名 → SmartScreen | 维持未签名 | 手动下载安装已有同等拦截说明（readme）；自动更新安装为同目录覆盖，风险不高于现状；证书费用超本期 |
| 静默安装过程不可见 | quitAndInstall(true, true) | 出错时用户感知弱；NSIS 安装失败不影响旧版本继续使用（覆盖装中途失败不删旧文件）；如需可见过程改 `quitAndInstall()` 一行即回向导模式 |
| 更新说明清洗不完美 | 纯文本容忍残留符号 | 仅展示用途；不引入 markdown 渲染依赖（零依赖红线优先） |
| 删除 electron-builder.json5 | 无运行时影响 | 已实证从未生效（read-config-file 源码 + v1.1.2 产物名双重证据）；产物命名与 CI glob 零变化 |
| updater:install 无返回确认 | fire-and-forget | 应用随即退出，返回值无消费方；失败场景由 NSIS 侧兜底（见静默安装行） |
| dev-app-update.yml 调试后门 | 仅 !app.isPackaged 时生效且已 gitignore | 不构成线上风险；文件不存在时该逻辑完全短路 |
