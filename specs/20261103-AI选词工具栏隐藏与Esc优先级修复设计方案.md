# AI 选词工具栏自动隐藏与 Esc 优先级修复设计方案

> 状态：已验证通过（2026-11-03）：选词期工具栏隐藏且不可唤出、选词态 Esc 不再误退全屏/返回文库、全屏改为纯 Electron 原生窗口全屏；`typecheck` 通过，`npm test` 28 文件 / 430 用例全绿
> 目标版本：沿用 package.json 当前 `1.4.2`，实际发版号由你自行确定
> 范围：阅读页（PDF 横向 / 纵向）AI 选词期的工具栏抑制、Esc 优先级单点化、全屏状态源统一为 Electron 原生窗口全屏
> 实现约束：遵循 `ireader-dev-tasks`（任务 C/D/E）与 `ireader-code-conventions`（Result 契约、中文注释、共享类型只进 `shared/types.ts`、纯逻辑下沉可单测）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 点击「AI 翻译」进入选词时自动隐藏工具栏 | `ReaderView.vue` `toggleAiSelect()` 进入选词即置 `barsSuppressedByAi = true` 并立即淡出顶栏 / 底栏（不再 `pinBars()`） | 点击按钮或按 `A` 后 200ms 内顶栏与底栏淡出，画面只剩页面与底部提示胶囊 |
| 2 | 选词期间工具栏不得被唤出 | `showBarsTemporarily()` 开头门控：抑制期内任何唤出请求（鼠标移到上/下 64px 边缘、下拉/菜单回调）一律丢弃 | 选词态下把鼠标贴顶 / 贴底停留，工具栏始终不出现，框选不被遮挡 |
| 3 | 退出选词后回到正常自动隐藏体系 | `watch(ai.selecting)` 收尾调用 `exitAiSelectUi()`：解除抑制、清计时、**保持隐藏**，不主动浮现 | 按 Esc / 再按 `A` / 框选完成后无工具栏闪现；鼠标移到边缘 1.5s 后工具栏出现 |
| 4 | 选词态按 Esc 只退出 AI 翻译，不退全屏、不返回文库 | 新增纯函数 `resolveReaderEsc()`；PDF **横向与纵向两个分支**统一走同一判定（当前纵向分支完全没判 `ai.selecting`） | 窗口态与全屏态各测一次：选词态 Esc → 十字光标消失、仍停在阅读页、全屏态仍全屏 |
| 5 | 全屏不再被系统层面的 Esc 抢占 | 去掉 `document.requestFullscreen/exitFullscreen`，全屏唯一由 `ipc.window.setFullscreen` + 主进程事件回传承载，渲染层用 `isFullscreen` 单例状态判定 | 全屏后窗口标题栏消失；`document.fullscreenElement` 恒为 null；Esc 行为与改造前一致（非选词态：全屏→退全屏，非全屏→返回文库） |

**核心验收口径**：全屏状态下点击「AI 翻译」→ 顶栏与底栏立即消失（鼠标贴边唤不出）→ 按 Esc 第一下只取消选词（十字光标消失、窗口仍全屏、仍停在阅读页）→ 再按一次 Esc 退出全屏但仍停留在阅读页 → 再按一次才返回文库。

## 二、非目标（本期不做）

- **不**让「页面上已有译文框」时 Esc 去隐藏译文：已确认只有选词态消费 Esc，其余保持「退全屏 → 返回文库」原语义。
- **不**改纵向（上→下）模式 AI 入口的可用性：按钮仍可点、`A` 仍可进（联动缺陷仅在切入纵向时顺手清掉无效选词态，见 §4.2）。
- **不**改 `AiTranslationLayer.vue` 的框选 / 拖动 / 折叠 / 落库逻辑，不动 `ai_translations` 表与 `ai:*` 通道。
- **不**在文库页做「Esc 退出全屏」：现状由浏览器 HTML 全屏行为兜着，改造后该动作消失（记为风险与扩展点，见 §12）。
- **不**新增任何 npm 依赖，不引入网络资源。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ────────────────────────────────────────────────────────────────┐
│ src/main.ts  bootstrap() → initFullscreenSync()（唯一初始化点）          │
│                                                                         │
│ services/fullscreen.ts（单例）                                           │

│ ReaderView.vue（PDF）          EpubReaderView.vue（EPUB） │               │

│   ├─ 选词进/出 → barsSuppressedByAi 门控工具栏             │               │
│   └─ F 键 / ⛶ 按钮 → toggleFullscreen()                  │               │
└────────┬─────────────────────────────────────────────────┼───────────────┘
```

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 选词期工具栏策略 | 完全隐藏且**不可唤出**，退出后保持隐藏、恢复边缘唤出 | 框选常拖到页面边缘，边缘唤起会直接用工具栏盖住选区；「退出后保持隐藏」让画面停在干净态，十字光标消失本身即反馈（不额外浮现 3 秒） |
| Esc 语义边界 | 仅 `ai.selecting` 消费 Esc；其余仍为「全屏→退全屏，否则返回文库」 | 选词是显式模式，Esc 退模式符合肌肉记忆；译文框是内容而非模式，Esc 不该让内容消失（隐藏译文已有下拉「全部隐藏」） |
| 全屏实现 | 去掉 HTML Fullscreen API，只走 Electron 原生窗口全屏 + 状态广播 | 双写会留下两个真相（`document.fullscreenElement` 与窗口态）；HTML 全屏下 Esc 可能被系统层抢先处理，应用无法保存全屏。单源后 Esc 完全归应用语义 |
| 全屏状态判定 | 渲染层单例 `isFullscreen`：切换时乐观置位 + 主进程事件校正 + 启动查询兜底 | 乐观置位保证「刚按 F 立刻按 Esc」也走退全屏分支；事件校正覆盖 macOS 红绿灯、系统级全屏变化；启动查询覆盖「已在全屏时进入阅读页」 |
| Esc 判定下沉 | 纯函数 `services/readerEsc.ts`：`(selecting, fullscreen) → 'exitAiSelect' \| 'exitFullscreen' \| 'backToLibrary'` | 横向 / 纵向 / EPUB 三处分支共用同一口径，避免再次漏判（本次缺陷根因就是纵向分支漏判）；纯函数可在 node 环境单测 |
| 纵向切向守卫 | `watch(isVertical)` 转为 `true` 且 `ai.selecting` 时 `ai.endSelect()` | 纵向不渲染覆盖层，选词态无效却会连带禁用滚轮翻页；只清状态、不改入口可用性 |

## 四、核心口径与算法

### 4.1 Esc 优先级（`src/services/readerEsc.ts`）

```ts
export type ReaderEscAction = 'exitAiSelect' | 'exitFullscreen' | 'backToLibrary'

export interface ReaderEscState {
  /** AI 选词态（十字光标 / 拖框进行中） */
  selecting: boolean
  /** 窗口是否处于全屏（services/fullscreen 的 isFullscreen，非 document.fullscreenElement） */
  fullscreen: boolean
}

/** Esc 唯一优先级：选词 > 全屏 > 返回文库 */
export function resolveReaderEsc(state: ReaderEscState): ReaderEscAction {
  if (state.selecting) return 'exitAiSelect'
  if (state.fullscreen) return 'exitFullscreen'
  return 'backToLibrary'
}
```

调用点（三处，全部走同一函数，不再各自 if/else）：

```ts
// ReaderView.vue：onKeydown 的纵向分支与横向分支
case 'Escape':
  onReaderEscape()
  return // 纵向分支原为 return，横向分支为 break

function onReaderEscape(): void {
  switch (resolveReaderEsc({ selecting: ai.selecting, fullscreen: isFullscreen.value })) {
    case 'exitAiSelect':
      ai.endSelect() // 只退选词：watch 收尾负责解除工具栏抑制
      return
    case 'exitFullscreen':
      void exitFullscreen()
      return
    case 'backToLibrary':
      goBack()
  }
}

// EpubReaderView.vue：无 AI 入口，传 selecting: false 保证口径一致
const action = resolveReaderEsc({ selecting: false, fullscreen: isFullscreen.value })
```

边界场景防护：

| 场景 | 行为 | 说明 |
|------|------|------|
| 选词态 + 全屏 | 只 `endSelect()`，保持全屏 | 需求核心；纵向同源 |
| 选词态 + 非全屏 | 只 `endSelect()`，停在阅读页 | 不再误 `goBack()` |
| 框选完成（`onDragEnd` 已 `endSelect`）后按 Esc | 走全屏/返回原语义 | 已确认：只有选词态消费 Esc |
| AI 下拉开着时按 Esc | 先由 `onMenuKeydown`（capture）收起菜单 | 现有逻辑不动，优先级高于选词 |
| 焦点在 `INPUT/SELECT/TEXTAREA`（如底栏滑块） | 提前 return，不改 Esc 语义 | 沿用现有早退 |
| 快速 F→Esc | 乐观置位让 `isFullscreen` 已是新值，走退全屏 | 见 §4.3 |

### 4.2 选词期工具栏抑制（`ReaderView.vue`）

```ts
/** 选词期间抑制工具栏：框选需要完整画面，这段时间任何唤出请求都丢弃 */
let barsSuppressedByAi = false

function showBarsTemporarily(ms = 3000) {
  if (barsSuppressedByAi) return   // ← 唯一门控点，onMouseMove 边缘 / 菜单回调全部经过这里
  barsVisible.value = true
  // …原有计时逻辑不变
}

/** 进入选词：立即淡出顶/底栏并接管抑制（替代原来的 pinBars()） */
function enterAiSelectUi(): void {
  closeAiMenu()
  closeTip()
  barsPinned = false
  barsSuppressedByAi = true
  hideBarsNow()                    // 清 hideTimer + barsVisible = false
  panning = false                  // 原 pinBars 里的「结束拖拽平移」职责挪到这里
  panMoved = false
  document.body.classList.remove('panning')
}

/** 退出选词：解除抑制但保持隐藏（不主动浮现），边缘唤出照旧 */
function exitAiSelectUi(): void {
  barsSuppressedByAi = false
  barsPinned = false
  hideBarsNow()
}

function toggleAiSelect(): void {
  if (ai.selecting) { ai.endSelect(); return }
  ai.beginSelect()
  enterAiSelectUi()
  showAiNotice(t('ai.selectHint')) // 「拖拽框选要翻译的文字，Esc 取消」——选词期唯一的退出指引
}

watch(() => ai.selecting, (on) => {
  if (!on) { clearAiNotice(); exitAiSelectUi() }   // 原为 unpinBars()（会浮现 3 秒）
})

// 纵向不渲染覆盖层：切入纵向时清掉无效选词态，避免连带禁用滚轮
watch(isVertical, (vertical) => {
  if (vertical && ai.selecting) ai.endSelect()
  // …原有清连翻 / 撤卷曲 / 作废预取逻辑不变
})
```

| 入口 / 出口 | 工具栏 | 说明 |
|-------------|--------|------|
| 顶栏「AI 翻译」按钮 | 立即隐藏 | 点击即进入选词 |
| 快捷键 `A` | 立即隐藏 | 与按钮同一条 `toggleAiSelect()` |
| 快捷键 `A` 再按一次 | 保持隐藏 | `endSelect()` → watch 收尾 |
| Esc | 保持隐藏 | 同上 |
| 框选提交（`onDragEnd`） | 保持隐藏 | 一次框选自动退出选词，属正常流程 |
| 切入纵向方向 | 保持隐藏 | 守卫 `endSelect()` 走同一收尾 |

### 4.3 全屏状态单源（`src/services/fullscreen.ts`）

```ts
const state = ref(false)
export const isFullscreen = readonly(state)

export function initFullscreenSync(): void {
  // 主进程广播（含 macOS 红绿灯 / 系统级全屏变化）
  ipc.window.onFullscreenChanged(({ fullscreen }) => { state.value = fullscreen })
  // 启动查询兜底：已在全屏时进入阅读页也能读到正确值
  void ipc.window.getFullscreen().then((on) => { state.value = on }).catch(() => undefined)
}

export async function toggleFullscreen(): Promise<void> { await setFullscreen(!state.value) }
export async function exitFullscreen(): Promise<void> { await setFullscreen(false) }

async function setFullscreen(next: boolean): Promise<void> {
  const before = state.value
  if (before === next) return
  state.value = next                        // 乐观置位：Esc 紧随其后读到正确值
  try {
    await ipc.window.setFullscreen(next)
  } catch (e) {
    state.value = before                    // 失败回滚，避免状态与窗口脱节
    console.warn('[fullscreen] 切换失败', e)
  }
}
```

时序：`F 键 → 乐观置 true → ipc.window.setFullscreen(true) → 主进程 setFullScreen(true) → 'enter-full-screen' → 事件回传 true（与乐观值一致，幂等）`。事件是校正而非唯一来源，故不存在「事件延迟期间 Esc 判错」的窗口。

## 五、IPC 契约

`shared/types.ts` 新增（中文 JSDoc 风格，与既有 `LibraryChangedPayload` 一致）：

```ts
/** 窗口全屏状态（window:fullscreenChanged 事件载荷） */
export interface WindowFullscreenState {
  /** 窗口当前是否处于全屏（Electron 原生窗口全屏，非 HTML Fullscreen） */
  fullscreen: boolean
}
```

| 通道 | 方向 | 入参 | 返回 | 说明 |
|------|------|------|------|------|
| `window:setFullscreen` | invoke | `{ fullscreen: boolean }` | `Result<void>` | **已存在**，语义不变：主进程 `win.setFullScreen` |
| `window:getFullscreen` | invoke | 无 | `Result<boolean>` | 新增：读取 `win.isFullScreen()`，供渲染层启动同步（窗口缺失返回 `false`） |
| `window:fullscreenChanged` | 主 → 渲染 | — | `WindowFullscreenState` | 新增：`enter-full-screen` / `leave-full-screen` 广播 |

六步链路（`ireader-dev-tasks` 任务 A）：`shared/types.ts` 类型 → `electron/ipc/handlers.ts` handler → 事件发送点 `electron/main.ts` → `electron/preload.ts`（`getFullscreen` / `onFullscreenChanged`，仿 `library.onChanged` 返回取消函数）→ `src/services/ipc.ts` 解包封装 → `src/services/fullscreen.ts` 消费。

服务层校验规则：`window:getFullscreen` 窗口不存在时返回 `false`（不抛错，全屏状态属环境事实）；`window:setFullscreen` 保持现有 `wrap` 契约，不新增校验。

## 六、主进程实现

- `electron/main.ts` `createWindow()`：注册 `win.on('enter-full-screen' | 'leave-full-screen')`，回调里 `win.webContents.send('window:fullscreenChanged', { fullscreen })`（先判 `win` 非空且 `!webContents.isDestroyed()`）。
- `electron/ipc/handlers.ts`：在 `window:setFullscreen` 旁新增 `window:getFullscreen`（`wrap(() => getWin()?.isFullScreen() ?? false)`），handler 只做取值编排。
- 主进程不感知 AI / 选词：工具栏抑制与 Esc 优先级全部留在渲染层，避免出现第二条判定源。

## 八、页面 / 交互设计

```
阅读页（非选词）                       点击「AI 翻译」/ 按 A        选词态
┌────────────────────────┐          ┌────────────────────────┐   ┌────────────────────────┐
│ ←书  ‹上 下一› 工具条  │          │                        │   │                        │
├────────────────────────┤   ──▶    │      （工具栏淡出）     │   │     十字光标 + 拖框     │
│        页面画面         │          │                        │   │                        │
│                        │          │                        │   │                        │
├────────────────────────┤          │                        │   │   ┌ 拖拽框选…Esc 取消 ┐ │
│ 12/120 ──●────  上一页 │          └────────────────────────┘   └────────────────────────┘
└────────────────────────┘
```

- 进 / 出均无新增动画：顶栏与底栏沿用既有 `opacity 0.2s` 过渡（`.top-bar.visible` / `.bottom-bar.visible`），只改 `barsVisible`。
- 选词期唯一提示是既有 `.ai-notice` 胶囊（底部 64px，3 秒自动淡出）：`t('ai.selectHint')` 已说明「拖拽框选要翻译的文字，Esc 取消」，无需新增文案，也不新增 i18n key。
- 工具栏隐藏后 `watch(barsVisible)` 现有的 `closeTip()` 会收起悬停提示浮层，不会留下悬浮在空处的提示框。
- 淡出态的顶栏 / 底栏同时置 `pointer-events: none`：否则它们虽然不可见，但 z3 的 `header` / `footer` 仍盖在页面上，选词时从顶部起手拖框会命中不可见按钮（含「返回」），既框不住也误触发。
- 空态 / 加载态 / 错误态不受影响（选词层与工具栏无耦合）。

## 十二、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 去掉 HTML Fullscreen | 全屏只走 `BrowserWindow.setFullScreen` | 收益：Esc 完全归应用语义，两套全屏状态不再脱节；代价：文库页全屏下按 Esc 不再退出（现状由浏览器 HTML 全屏兜底）。扩展点：若需要，在 `App.vue` 挂一处 `resolveReaderEsc({ selecting: false, fullscreen })` 即可 |
| 全屏状态靠事件同步 | 乐观置位 + 事件校正 + 启动查询 | 三条来源互相兜底；万一事件丢失，用户下一次 `F` 仍能通过乐观值正确翻转，且启动查询会重新对齐 |
| 选词期完全隐藏工具栏 | 不做「边缘唤出」逃生口；淡出态两栏置 `pointer-events: none` | 用户已确认；退出方式为 Esc 或再按 `A`，底部胶囊有文案指引。若将来需要工具栏，可把抑制改为「边缘唤出时先退出选词」；`pointer-events` 顺带修掉「点到不可见按钮」的旧隐患 |
| 退出选词后不浮现工具栏 | 保持隐藏 | 若实测觉得「不知道是否退出」，可改为 `unpinBars()` 短暂浮现 3 秒（一处改动） |
| 有译文时 Esc 不隐藏译文 | 仅选词态消费 Esc | 已确认；隐藏译文仍走 AI 下拉「全部隐藏」，两者不冲突 |
| 纵向切向自动退出选词 | 只清状态，不改入口可用性 | 用户已确认入口保持可点；该守卫避免「纵向无效选词态把滚轮翻页一起禁掉」的连带缺陷 |
| 全屏切换失败 | 回滚 `isFullscreen` 并 `console.warn` | 不弹错误提示：全屏是视图偏好，失败时用户再按一次即可，与项目「版式操作不阻断阅读」一致 |

## 十三、迭代补记：EPUB 下 A / F 失效与 Esc 误返回（实测回归后追加）

### 13.1 现象与根因

实测反馈两条：① EPUB 阅读页 `A` / `F` 快捷键「完全没反应」；② EPUB 全屏时按一次 Esc 不退全屏、直接跳回文库。

两者同源：`ReaderView.vue` 的模板按格式二选一渲染子视图（`<EpubReaderView v-if="isEpub" />` / `<div v-else>`），但**父组件自身仍处于挂载态**，`onMounted` 里无条件注册的 `window.addEventListener('keydown', onKeydown)` 在 EPUB 下没有按格式早退。同一次按键被父子两套 handler 各执行一遍：

| 按键 | 第一遍（EpubReaderView） | 第二遍（ReaderView） | 用户观感 |
|------|--------------------------|----------------------|----------|
| `F` | `toggleFullscreen()` 进全屏 | 再进一次 → 退出 | 「F 键没用」 |
| `A` | `toggleAiSelect()` 进选词 | 再调一次 → 结束 | 「A 键没用」 |
| `Esc` | `exitFullscreen()`（乐观把 `isFullscreen` 置 false） | 读到 false → `goBack()` | 「Esc 退全屏却回了主页」 |

排查中先后排除的假设：iframe 抢焦点、`SelectMenu` / `AiReaderMenu` 的 `stopPropagation` 吞键、epub.js `passEvents` 缺失、主进程未广播 `fullscreenChanged`。教训是：**toggle 类快捷键「毫无反应」首先要怀疑重复派发，而不是事件没送达。**

### 13.2 修改点

| 文件 | 改动 |
|------|------|
| `src/views/ReaderView.vue` | `onKeydown` 首行 `if (isEpub.value) return`（核心修复）；`onResize` 同步加 `\|\| isEpub.value`；表单控件早退收窄为导航键集合（见 13.3）；删除 `watch(isEpub)` 内的 `ai.reset(null)`（见 13.4） |
| `src/views/EpubReaderView.vue` | iframe 的 `wheel` 通道扩展为 `wheel + keydown`（capture 直挂）；新增 `handledKeyEvents: WeakSet<Event>` 去重；`case 'f'` 改 `void toggleFullscreen()`；`case 'a'` 在文字型书上给 `ai.textUnsupported` 提示，不再静默无反应；Esc 传 `justExitedFullscreen` |
| `src/services/fullscreen.ts` | 新增 `watch(state)` 记录「被动退出」时刻、`selfExit` 标记与 `exitedFullscreenRecently(ms = 400)`；`toggleFullscreen()` 结束后 400ms 读一次 `getFullscreen()` 校正（`syncSeq` 防旧结果覆盖新状态） |
| `src/services/readerEsc.ts` + 单测 | `ReaderEscState` 增可选 `justExitedFullscreen`；优先级变 `选词 > 全屏 > 刚退过全屏（仍返回 exitFullscreen） > 返回文库`，新增 2 个用例 |
| `electron/ipc/handlers.ts` / `electron/main.ts` | `window:setFullscreen` 主动回显 `window:fullscreenChanged` 请求值并打 `[window] setFullscreen` 日志；`relayFullscreen` 加 `[window] relay fullscreen=` 日志 |
| `src/i18n/locales/{zh-CN,en,ja}.ts` | 新增 `ai.textUnsupported` |

### 13.3 焦点在表单控件时的按键让位口径

原实现是「`target.tagName` 是 INPUT / SELECT / TEXTAREA 就直接 return」，导致拖过底栏字号滑块后焦点留在滑块上、`A` / `F` 全部失效。现改为只让位导航键：`FORM_NAV_KEYS = { 方向键 ×4, Home, End, PageUp, PageDown, 空格, Enter }`，其余快捷键照常生效。两个视图各持一份同名常量（`<script setup>` 无法共享非组件导出）。

### 13.4 「刚退过全屏」兜底的边界

Windows 上窗口全屏时 Esc 可能先被窗口层处理，等 `keydown` 到达渲染层时 `isFullscreen` 已变假，原来的判定会落到「返回文库」——这正是现象 ②。补 `exitedFullscreenRecently()` 后必须区分**谁退的**：应用自己调 `exitFullscreen()` 时置 `selfExit`，不记时间戳，否则「主动退全屏后 400ms 内再按一次 Esc」会把本该返回文库的那次吞掉。`ipc` 调用失败回滚状态时同步复位 `selfExit`。

### 13.5 顺带修复：EPUB 译文被清空

`ReaderView.vue` 的 `watch(isEpub)` 原本在切到 EPUB 时调 `ai.reset(null)`。冷启动直达 EPUB 路由时，文库 `refresh` 完成后格式才由「未知」变为 epub，该 watch 此时触发，会把 `EpubReaderView` 刚 `ai.load(id)` 的译文清掉（表现为「EPUB 没有 AI 翻译」）。现只保留 PDF 侧资源收尾，不动共享的 AI 记录。

### 13.6 回归验证

- `npx vue-tsc --noEmit` → 0 错误；`npm test` → 28 个文件 / 435 用例全绿。
- 手工冒烟通过：EPUB 全屏下 Esc 一次只退全屏（再按才回文库）；`F` 进出全屏；图片型 `A` 进退选词、文字型 `A` 出提示条；滑块聚焦后 `A` / `F` 仍生效；PDF 侧 A / F / Esc 行为无回退。
