# 封面单独成页失效修复与漫画单本封面开关设计方案

> 状态：设计稿（已实现，M1~M5 完成；GUI 冒烟待人工确认）
> 目标版本：v1.4.2（package.json 当前版本；版本号不变，发版时机由用户确定）
> 范围：设置页「双页模式封面单独成页」勾选不落库的根因修复、漫画阅读工具栏新增单本封面按钮、`reading_progress` 新增单本封面列；后续迭代已扩展到图片型 EPUB（见 §十四）
> 实现约束：遵循 `ireader-dev-tasks`（任务 A / B / D / F）与 `ireader-code-conventions`（Result 契约、中文注释、契约类型只定义在 `shared/types.ts`）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 设置页勾选「双页模式封面单独成页」后离开设置，返回时又变成未勾选 | 根因不是勾选状态没读到，而是**整条保存链在渲染进程侧就失败了**：`SettingsView.save()` 把含 Vue 响应式代理的整表 `{ ...form }` 直接交给 `ipcRenderer.invoke`，结构化克隆抛 `An object could not be cloned.`，`settingsStore.patch` 永不成功（不落库、store 不更新）。修复：新增纯函数 `toIpcPayload()`，在 `settingsStore.patch` 单点做深纯化后再过 IPC | 勾选 → 返回主页 → 再进设置：仍勾选；重启应用：仍勾选；`settings` 表 JSON 内 `coverSinglePage` 与勾选一致 |
| 2 | （同源缺陷）设置页其它保存项是否也失效 | 同一 `save()` 出口，同一修复点；不做逐项特殊处理 | 模式 / 方向 / 预加载 / 主题 / 语言逐项改一次 → 退出返回 → 值均保持 |
| 3 | 漫画阅读工具栏增加「封面单独成页」按钮 | `ReaderView.vue` 顶栏 `.controls` 内、「单页/双页」按钮右侧新增文字按钮；仅 `reader.mode === 'double'` 时渲染；文案显示当前生效状态 | 双页下按钮出现、单页下隐藏；点击后页组即时在 `[1][2,3]…` 与 `[1,2][3,4]…` 之间切换 |
| 4 | 按钮对单本漫画单独生效（PDF / CBZ / MOBI） | `reading_progress` 新增可空列 `cover_single_page`（NULL = 跟随全局）；`reader` store 新增 `coverSingleOverride` 与 `setCoverSinglePage()` | 书 A 设为「封面并排」后打开书 B，仍按全局值；重开书 A 保持并排 |
| 5 | 单本设置需要记住（跨会话） | 复用既有进度落盘通道：`setCoverSinglePage()` → `scheduleSave()`（1s 防抖）→ `flushProgress()` → `reader:saveProgress` | 关闭该书重开、重启应用后单本值仍在；DB 中该书 `cover_single_page` 有值 |

**核心验收口径**：设置页勾选「双页模式封面单独成页」→ 退出到主页 → 再进设置（仍勾选）→ 重启应用（仍勾选）；打开一本 ≥10 页的 CBZ/MOBI/PDF → 切双页 → 顶栏点按钮：页组在 `[1][2,3][4,5]…` 与 `[1,2][3,4]…` 之间即时切换且停留在当前页所在组 → 退出重开该书保持 → 打开另一本仍按全局值；`npm run typecheck` 与 `npm test` 全绿。

## 二、非目标（本期不做）

- **本期不含 EPUB 阅读器**（已由后续迭代补齐，见 §十四）：本方案落地时 `EpubReaderView.vue` 不加按钮，`src/stores/epubReader.ts` 的封面取值链仍只读全局设置。
- **不做「恢复跟随全局」的三态按钮或重置入口**：单本值一旦点击即固化（详见 §13 扩展点）。需要回到全局行为时，改设置页全局值或删除该书进度。
- **不新增键盘快捷键**（如 `c`）：避免把未确认的交互扩散到快捷键提示与顶栏文案体系（现有 `d` / `r` / `f` / `a` 说明保持原样）。
- **不改 `settings:patch` 的整表 patch 语义**：设置页仍提交整份 form，只是过 IPC 前被纯化；不改成按字段 diff。
- **不给设置页新增保存失败提示**：保持既有「静默保存」语义，仅补 `catch` 日志消除未处理 rejection。
- **不改 `src/services/spread.ts` 页组算法**：`coverSinglePage` 语义（封面单页 / 无条件两两成组）已满足需求。
- **不做其它 IPC 通道的批量净化**：`library:*` / `collection:*` / `ai:*` 现有调用均传原始值，本次不收口到全局拦截层。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ──────────────────────────────────────────────────────────────┐
│ ① 设置页保存链路（本次修复）                                          │
│ SettingsView.vue: form = reactive({ ...settingsStore.settings })       │
│   └─ save() → settingsStore.patch({ ...form })                        │
│        └─ toIpcPayload(partial)   ← 新增：深纯化，去掉 Vue 代理        │
│             │                                                         │
│ ② 阅读页单本覆盖链路（本次新增）                                       │
│ ReaderView.vue 顶栏按钮（仅 mode === 'double' 渲染）                   │
│   └─ reader.setCoverSinglePage(next)                                  │
│        ├─ coverSingleOverride = next（落库值，null = 跟随全局）        │
│        ├─ coverSinglePage = next（生效值，喂给 buildSpreads）          │
│        ├─ rebuildSpreads(当前页)                                      │
│        └─ scheduleSave() → flushProgress()                            │
└──────────────────────────────┬────────────────────────────────────────┘
                               ▼  ipc.settings.patch / ipc.reader.saveProgress
┌─ 主进程 ──────────────────────────────────────────────────────────────┐
│ handlers.ts                                                           │
│   ├─ settings:patch：locale / direction / ai 校验（不变）              │
│   └─ reader:saveProgress：新增 coverSinglePage 类型校验（boolean|null）│
│        ▼                                                              │
│ settingsService.patch（方向变更同事务同步零进度书，不变）              │
│ progressRepo.upsert（INSERT ... cover_single_page + ON CONFLICT 更新） │
└──────────────────────────────┬────────────────────────────────────────┘
                               ▼
┌─ SQLite ──────────────────────────────────────────────────────────────┐
│ settings(key='app', value=JSON)                                        │
│ reading_progress(+cover_single_page INTEGER NULL)  ← 迁移 v7           │
│   NULL = 跟随全局；0 = 封面与第 1 页并排；1 = 封面单独成页              │
└───────────────────────────────────────────────────────────────────────┘
```

### 3.2 关键决策

| 决策 | 选择 | 理由（取舍依据） |
|------|------|------------------|
| 设置页保存失败的修法 | 在 `settingsStore.patch` 单点调用 `toIpcPayload()` | 若在每个调用方各自 `JSON.parse(JSON.stringify())`，每新增一个设置入口就多一次复发机会；store 是全站唯一出口，且不改 IPC 契约、不改主进程 |
| 纯化实现方式 | JSON 往返（`JSON.parse(JSON.stringify(v))`） | 实测 `toRaw()` 只解顶层，`{ ...form }` 的嵌套 `ai.providers[]` 元素仍是代理、克隆依旧失败；`Settings` 全部为 JSON 安全值（string/number/boolean/数组/对象），往返零信息损失 |
| 单本设置的存放位置 | `reading_progress` 新增可空列 | 与 `mode` / `direction` / `zoom` / `row_order` 同表同通道，一次 `reader:saveProgress` 即落盘；不新增表、不新增 IPC 通道 |
| 「跟随全局」的表达 | 列值 NULL（不写布尔快照） | 若首次打开就把全局值写死，会出现「设置页改了全局、老书不跟随」的语义冲突；NULL 让全局设置始终对未固化的书生效 |
| 按钮可见条件 | 仅 `reader.mode === 'double'` 显示 | 单页模式 `buildSpreads` 的 single 分支忽略该值，显示按钮等于提供一个点了没有视觉反馈的控件 |
| 按钮文案 | 显示当前生效态（封面单页 / 封面并排） | 与相邻「单页/双页」按钮「文字即当前状态」的语义一致；按项目约定，自带可见文字的控件不加悬停提示框 |
| 快捷键 | 本期不加 | 新增 `c` 会带来提示文案与文档扩散（快捷键说明、i18n），属未经确认的交互增量 |

## 四、核心算法与口径

### 4.1 根因定位（Electron 实机验证，非时序推断）

现状代码：

```ts
// src/views/SettingsView.vue:199
const form = reactive({ ...settingsStore.settings })   // settingsStore.settings 是 ref，ai 被深层代理
// src/views/SettingsView.vue:239-241
async function save() {
  await settingsStore.patch({ ...form })               // ({ ...form }).ai 仍是 Proxy
}
```

用 Electron 42 隐藏窗口 + `nodeIntegration` + `ipcMain.handle('echo')` 实测三条路径：

| 传入 `ipcRenderer.invoke('echo', payload)` 的 payload | 结果 |
|------------------------------------------------------|------|
| `{ ...form }`（含 `form.ai` 代理） | **FAIL `Error: An object could not be cloned.`** |
| `JSON.parse(JSON.stringify(form))` | OK，值完整 |
| `toRaw(form)` | OK，值完整（仅因本探针的 `form` 由原始对象直接构造；调用方传入的 `{ ...form }` 经 `toRaw` 无法解嵌套） |

同时实测 `v-model` 复选框 + `@change="save"` 的时序：`save()` 内读到的**已是点击后的新值**（第一次点 `[true]`、第二次点 `[false]`）——**排除**「v-model 回写晚于 change 导致读到旧值」的假设。

引入时间：`git log -S "ai: AiSettings" -- shared/types.ts` 指向提交 `7086a67`（新增 AI 框选翻译）。该提交给 `Settings` 增加了嵌套对象 `ai`，使设置页整表 patch 的 payload 从「扁平原始值」变成「含代理的嵌套结构」，序列化开始失败。设置页 6 个保存项共用同一 `save()`，因此一并失效。

失败链（与用户现象一一对应）：

```
点击勾选框 → v-model 已写入 form.coverSinglePage = true（DOM 也显示勾选）
  → save() → ipcRenderer.invoke 在渲染进程序列化阶段抛错（未到主进程）
    → settingsStore.patch 抛错，settingsStore.settings 保持旧值（false）
      → 页面局部 form 仍是 true，看起来「已勾选」
        → 离开设置页，组件卸载；再进入时 Object.assign(form, settingsStore.settings) 取到 false
          → 复选框显示未勾选（用户看到的现象）
```

### 4.2 修复后的保存链

```ts
// src/services/ipcPayload.ts（新增，纯函数）
/** 深纯化为结构化克隆安全值：去掉 Vue 响应式代理（代理对象过 IPC 会抛 DataCloneError） */
export function toIpcPayload<T>(value: T): T {
  return JSON.parse(JSON.stringify(value)) as T
}

// src/stores/settings.ts
async function patch(partial: Partial<Settings>) {
  settings.value = await ipc.settings.patch(toIpcPayload(partial))
}
```

### 4.3 单本封面值的解析与页组重建

```ts
// src/stores/reader.ts：open() 内
coverSingleOverride.value = progress?.coverSinglePage ?? null          // 落库值
coverSinglePage.value = coverSingleOverride.value ?? settingsStore.settings.coverSinglePage

/** 工具栏点击：写入本书覆盖值并立即重建页组，页码按当前页重新定位（与 setMode 同口径） */
function setCoverSinglePage(next: boolean) {
  const page = spreads.value[currentIndex.value]?.firstPage ?? 1
  coverSingleOverride.value = next
  coverSinglePage.value = next
  rebuildSpreads(page)   // 内部 findSpreadIndexByPage(page)
  scheduleSave()         // 1s 防抖 → flushProgress → reader:saveProgress
}

// flushProgress() 内追加
ipc.reader.saveProgress(bookId.value, { ...existing, coverSinglePage: coverSingleOverride.value })
```

### 4.4 边界场景防护表

| 场景 | 期望行为 | 依据 |
|------|----------|------|
| 首次打开、无进度行 | 跟随全局设置 | `progress === null` → override 为 null |
| 老库升级 / EPUB 写入的进度行 | 跟随全局设置 | `cover_single_page` 为 NULL，`??` 回退全局 |
| 单页模式 | 按钮不渲染；页组仍为每页一组 | `buildSpreads` 的 `mode === 'single'` 分支忽略该值 |
| 上→下（ttb）纵向 | 行 = 页组，切换后立即按新行分段渲染 | `ReaderView.verticalRows` 直接读 `reader.spreads` |
| 切换时页码跳动 | 停留在原首页所在页组 | `rebuildSpreads(page)` 内 `findSpreadIndexByPage` |
| 上一本 / 下一本 | 使用新书自己的进度值 | `switchBook()` → 路由跳转 → `openBook()`：`reader.close()`（落盘上一本）→ `reader.open(id)` 重新解析 |
| 设置页修改全局值 | 已固化的书不变；未固化的书下次打开跟随新值 | NULL 语义（§3.2） |
| 其它写入方未带该字段 | 写 NULL，不误伤其它书 | `upsert` 用 `progress.coverSinglePage ?? null` |
| `coverSinglePage` 传入非布尔 | 主进程拒绝并报 `INVALID_PARAMS` | handler 显式校验（§6） |

### 5.1 迁移（`electron/db/database.ts` 末尾追加，不外改已发布项）

## 六、IPC 契约

无新增通道；扩展一个入参字段，并明确一条入参规范。

```ts
// shared/types.ts
export interface ReadingProgress {
  // ...既有字段
  /** 本书是否单独指定「双页封面单独成页」；null / 缺省 = 跟随全局设置（仅双页模式生效） */
  coverSinglePage?: boolean | null
}
```

| 通道 | 入参 | 返回 | 本次变化 |
|------|------|------|----------|
| `settings:patch` | `Partial<Settings>`（**渲染层必须传结构化克隆安全值**） | `Settings` | 渲染层前置 `toIpcPayload()` 纯化；通道名、主进程校验、返回契约均不变 |
| `reader:saveProgress` | `{ bookId: number; progress: ReadingProgress }` | `void` | `progress` 新增 `coverSinglePage?: boolean \| null`；handler 增补类型校验 |

handler 校验规则（`electron/ipc/handlers.ts`）：

```ts
ipcMain.handle(
  'reader:saveProgress',
  wrap(({ bookId, progress }: { bookId: number; progress: ReadingProgress }) => {
    const cover = progress?.coverSinglePage
    if (cover !== undefined && cover !== null && typeof cover !== 'boolean') {
      throw { code: 'INVALID_PARAMS', message: 'coverSinglePage 取值无效' } as AppError
    }
    progressRepo.upsert(bookId, progress)
  })
)
```

## 七、主进程实现

- `electron/db/database.ts`：仅追加 v7 迁移。
- `electron/db/repos/progressRepo.ts`：`ProgressRow` 补字段、`upsert` 增列、`toReadingProgress` 增映射。

## 九、页面 / 交互设计

### 9.1 顶栏布局（单页模式 → 双页模式）

```
单页：  [返回] 书名        [单页] [阅读方向▾] [缩放▾] [AI▾] [⛶]
双页：  [返回] 书名        [双页] [封面单页] [阅读方向▾] [缩放▾] [AI▾] [⛶]
双页（已并排）：[返回] 书名 [双页] [封面并排] [阅读方向▾] [缩放▾] [AI▾] [⛶]
```

### 9.2 交互行为

1. 点击按钮 = 取反当前生效值 → `setCoverSinglePage()`；无确认弹窗，与「单页/双页」按钮一致的即时生效语义。
2. 点击后文案立即翻转（`封面单页` ⇄ `封面并排`），页组立即重建；1s 防抖后落库。
3. 按钮只在双页模式渲染；切回单页时按钮消失，单本值保留在进度里。
4. 无悬停提示框（按项目约定，自带可见文字的控件不加 tip）；`aria-label` 用同一文案。
5. 样式复用 `.controls button`（描边小按钮），仅新增一条 `.controls .cover-single { white-space: nowrap }`，避免英文/日文文案换行撑高顶栏（与 `.book-nav` 的 `nowrap` 一致）。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|-----------|
| JSON 往返纯化 | 只保留 JSON 安全值（丢弃 `Date` / `undefined` / `Buffer`） | `Settings` 当前只含 string/number/boolean/数组/对象，往返零损失；若将来给设置加二进制（如封面字节）必须改为显式字段映射 |
| 保留整表 patch 语义 | 不改成按字段 diff | 单窗口、单入口修改设置，理论上仍可能与阅读页改 `epubFontSize` 并发覆盖；本地 IPC 毫秒级完成，接受该风险；出现多入口并发时再改按字段 patch |
| 单本固化后无法「恢复跟随全局」 | 只做两态 | 单本语义需要显式值；三态按钮增加一次点击成本与文案复杂度。扩展点：后续可在设置页提供「清除单本阅读偏好」（清 NULL） |
| 只收口 `settingsStore.patch` | 不做全局 IPC 净化层 | 现有其它调用均传原始值；全局拦截会把「序列化失败」变成静默类型转换，掩盖未来真实错误 |
| EPUB 单本接入 | 后续迭代补齐（§十四） | 补丁改为常驻 + 实时读取，默认路径（封面单页）委托原生实现，保持原行为不变 |
| 迁移为可空列 | 老行 NULL，不回填 | 与「未固化的书跟随全局」一致，无需数据回填；回填反而会让全局设置对老书失效 |
| 设置页 save 仍静默 | 只补日志，不加错误提示 | 与既有设置项语义一致；根因修复后失败概率仅剩主进程异常，届时可通过日志定位 |

## 十四、后续迭代：图片型 EPUB 接入单本开关

用户反馈「EPUB 格式漫画在阅读界面没有该按钮」，因此把同一能力接入 EPUB 阅读器（仅图片型书生效，文字型书该值无视觉效果）。

### 14.1 交互

- `EpubReaderView.vue` 顶栏 `.controls` 内、「单页/双页」按钮右侧新增同款文字按钮，复用 `reader.coverSolo` / `reader.coverPair` 文案。
- 可见条件：`store.layout === 'pre-paginated' && store.spread === 'always'`——文字型书（reflowable）与单页模式都不渲染。
- 点击立即生效：重建跨页组表 → `rendition.clear()` + `display(组首 href)` 重渲当前屏 → 1s 防抖落盘。

### 14.2 关键取舍：封面策略补丁改为常驻 + 实时读取

原 `applyCoverSinglePage(rendition, coverSinglePage)` 在 `coverSinglePage === true` 时直接 return，靠「是否安装补丁」表达状态；运行时关→开无法撤销补丁，会导致按钮只在部分方向生效。改为传入取值函数：

```ts
export async function applyCoverSinglePage(
  rendition: EpubRendition,
  getCoverSingle: () => boolean
): Promise<void>
// 补丁（handleNextPrePaginated / prev）常驻，每次调用读当前值：
//   开启 → 原样委托原生实现（与原行为等价）
//   关闭 → 走「封面与第 1 页并排」映射逻辑
// 用 WeakSet 记录已装饰的 manager，避免 prev 被层层包装
```

### 14.3 数据与落盘

复用 v7 迁移与 `reader:saveProgress`，无新增列/通道：`coverSingleOverride` 在 `open()` 由 `progress?.coverSinglePage ?? null` 还原，`flushProgress()` 写回（null = 继续跟随全局），`close()` 重置。

### 14.4 冒烟补充

打开图片型 EPUB → 切双页 → 顶栏出现按钮 → 点击后 `[1][2,3]…` ⇄ `[1,2][3,4]…` 切换且停在当前组 → 翻到封面再向前翻（应显示 `[封面, 第1页]` 或封面单页）→ 退出重开保持、另一本仍按全局；文字型 EPUB 与单页模式确认按钮不出现。
