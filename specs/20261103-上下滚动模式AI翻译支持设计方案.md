# 上下滚动模式 AI 翻译支持设计方案

> 状态：已实现（M1~M3 完成，`npm run typecheck` / `npm test` 全绿；待 §8.2 手工冒烟）
> 目标版本：沿用 package.json 当前 `1.4.2`，实际发版号由你自行确定
> 范围：PDF / CBZ / MOBI 的上→下连续滚动（`VerticalScrollView`）与 EPUB 图片型上→下模式的 AI 框选翻译；AI 入口（按钮 + 动作下拉 + 提示胶囊）抽成两个共用件供 PDF / EPUB 两个视图使用
> 实现约束：遵循 `ireader-dev-tasks`（任务 C/D/E）与 `ireader-code-conventions`（Result 契约、中文注释、共享类型只进 `shared/types.ts`、纯逻辑下沉可单测）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 上下阅读模式也要有 AI 翻译 | `VerticalScrollView.vue` 在每个 `.v-page` 内挂 `AiTranslationLayer`（页盒已是 `position: relative`，与 canvas 同尺寸） | PDF 书切到上→下模式，按 `A` 拖框后原地出现译文框 |
| 2 | 纵向也能进入/退出选词 | `ReaderView.vue` 纵向键位分支补 `case 'a' / 'A'`（当前纵向分支完全没有该键）；顶栏 AI 按钮本来就常显 | 纵向按 `A` 进选词（按钮同步按下态），再按 `A` 或 `Esc` 退出 |
| 3 | 选词期工具栏隐藏、不可唤出（沿用既有口径） | 复用 `enterAiSelectUi()` / `exitAiSelectUi()` 与 `barsSuppressedByAi` 门控，纵向无需新逻辑 | 纵向进选词后顶/底栏 200ms 内淡出，鼠标贴顶/贴底不唤出 |
| 4 | 滚动时译文框必须跟着页面走，不能漂移 | 覆盖层在 `.v-page` 内，几何全部百分比、字号按页盒高度换算 | 滚动过程中框与气泡始终贴合；滚出视口再滚回，框原位复原 |
| 5 | 选词态仍要能滚到远处页面再框选 | 纵向滚动是原生滚动，`onWheel` 的选词早退不 `preventDefault`，天然保留 | 选词态下滚轮可滚动，滚动后拖框正常发起翻译 |
| 6 | 纵向窗口化挂载不应出现闪烁 | `AiTranslationLayer` 新增 `animateIn` prop，纵向传 `false`，禁用 pop-in | 快速滚动时译文框直接显示，无「弹出」动画与闪烁 |
| 7 | 纵向与横向共享同一批译文记录 | 页码口径就是页 id，复用 `ai_translations`（无迁移、无新通道） | 纵向框选的译文，切回左→右时同页仍显示；反之亦然 |
| 8 | EPUB 图片型纵向也要支持 | `EpubReaderView.vue` 接入同一套（按钮只在 `isVerticalImage` 时出现） | EPUB 图片书 ttb 模式下框选翻译通过 |
| 9 | EPUB 页码不能越界（其页 id 是 0 基 spine 索引） | `VerticalScrollView` 新增 `aiPageOffset`，EPUB 传 `1` | 落库 `page ≥ 1`；重开书译文仍在同一页 |
| 10 | 纵向点击译文框不能顺带翻一行 | `VerticalScrollView.onClick` 加 `e.target.closest('.ai-layer')` 早退 | 点译文框 / 折叠球 / 选词层均不触发行翻页 |
| 11 | 切离 EPUB 图片型纵向不留下「看不见的选词态」 | `watch(isVerticalImage)` 收尾：`endSelect()` + `prunePending([])` | 切回 EPUB 横向：无十字光标、滚轮/热区行为正常 |

**核心验收口径**：一本 PDF 漫画切到上→下模式 → 按 `A`（或点「AI 翻译」）→ 顶/底栏立即淡出 → 在某页拖框 3 秒内出现白框译文且贴合气泡 → 滚过两屏再滚回，译文框原位复原且全程无弹入动画 → 切回左→右，同一页译文框仍在原气泡位置；EPUB 图片型书重复同一流程同样通过；`npm run typecheck` 与 `npm test` 全绿。

## 二、非目标（本期不做）

- **EPUB 文字型（reflowable）纵向不做**：正文是重排文本、没有页面 canvas，框选对象不是图片；要做必须另建「文本选区 → 纯文本请求」的新链路（复用不了截图与归一化坐标模型）。
- **EPUB 横向（ltr / rtl，含双页）不做**：本期只覆盖「上下阅读模式」，EPUB 横向顶栏不出现 AI 按钮。
- **不做跨页框选**：一次框选仍限定在被拖的那一页内（坐标夹取到该页盒），与横向一致。
- **不改数据与主进程**：`ai_translations` 表、`ai:*` 通道、`aiService` / `aiReply` 提示词一律不动。
- **不做纵向性能专项优化**：不引入「只给有记录的页挂覆盖层」这类按页剪枝（列入 §13 扩展点）；也不改纵向的窗口化策略与渲染队列。
- **不做整屏识别、批量翻译、滚动位置自动翻译**。
- **不新增 npm 依赖，不新增任何网络行为**。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ──────────────────────────────────────────────────────────────────┐
│ ReaderView.vue（PDF 横向 + 纵向）        EpubReaderView.vue（EPUB 图片型纵向）│
│   ├─ AiReaderMenu.vue（按钮组 + 动作下拉，抽出复用）                       │
│   ├─ useAiNotice.ts（底部提示胶囊，抽出复用）                              │
│   ├─ 选词态 / 工具栏抑制 / Esc / A 键（各视图自己的门控）                   │
│   ▼                                                                       │
│ VerticalScrollView.vue（纵向唯一滚动容器，PDF 与 EPUB 共用）               │
│   └─ .v-page（行内页盒，position: relative，窗口化挂载）                    │
│        ├─ canvas（渲染层写入 style.width/height）                          │
│        └─ AiTranslationLayer.vue（page = 页 id + aiPageOffset）            │
│             ├─ 选词态：拖框 → 归一化矩形                                  │
│             └─ 常态：本页译文框（白框 / 折叠球 / 缩放手柄）                 │
│   ▼                                                                       │
│ stores/aiTranslation.ts（本书记录 + pending + 选词态 + 隐藏态）── 既有实现   │
│   ▼                                                                       │
│ ipc.ai.*（list / translate / save / remove）── 既有通道，零改动             │
└────────┬──────────────────────────────────────────────────────────────────┘
         ▼
┌─ 主进程 ──────────────────────────────────────────────────────────────────┐
│ aiService / aiReply / aiTranslationsRepo ── 全部不动（page 校验仍为 ≥ 1）    │
└───────────────────────────────────────────────────────────────────────────┘
```

三条要点：

1. **覆盖层挂在页盒里，而不是挂在滚动容器上**：`.v-page` 已经同时满足「`position: relative`」「宽高 = canvas 显示尺寸」两个前提（`VerticalScrollView.vue` 的 `.v-page` 样式），因此横向那套「归一化矩形 + 百分比定位 + 页高 × fontRatio」全部原样成立；窗口化挂载还顺带解决了「滚动偏移」——滚出视口即卸载，滚回来即按库重画，不需要任何滚动补偿计算。
2. **纵向视图是 PDF 与 EPUB 共用的**：`createPageDocumentSource`（PDF / CBZ / MOBI）与 `createEpubImageSource`（EPUB 图片型）只是页面源不同，覆盖层加在 `VerticalScrollView` 里即「一次实现，两处生效」。
3. **数据侧零改动**：页码就是页 id（PDF 1 基真实页码 / EPUB spine 索引 +1），坐标是页内归一化值，记录天然与横向互通。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 覆盖层挂载位置 | 挂进 `VerticalScrollView` 的 `.v-page`（页盒内） | 页盒已 `position: relative` 且与 canvas 同尺寸，坐标/字号/裁剪全部复用横向实现；窗口化卸载天然让框「随页出现/消失」，滚动偏移无需补偿。若挂在 `.v-scroll` 上则要自己维护每个页盒相对滚动容器的实时偏移，滚动每帧都要重算 |
| 纵向视图改造方式 | 新增 4 个 AI props（书名 / 选词态 / 可见门控 / 页码偏移），不感知 store | 该组件目前是「愚视图」（只吃 rows + source 回调），保持这一契约；AI 语义仍留在两个路由视图里，避免组件与 store 耦合 |
| 记录口径 | 复用 `ai_translations`，不改表 | 页码 = 页 id，坐标 = 页内归一化，两者在纵向与横向完全同口径；新建表只能得到「同样字段 + 一张重复表」 |
| EPUB 页码偏移收口点 | 视图层传 `aiPageOffset = 1` | EPUB 纵向页 id 是 0 基 spine 索引，而 DB 与 `aiService` 要求 `page ≥ 1`；偏移只发生在「渲染覆盖层 + 剪裁 pending」两个出口，不污染 store 与契约 |
| 选词期滚轮 | 纵向允许原生滚动 | 横向禁滚轮是为了禁「翻页副作用」（框选与翻页抢事件）；纵向滚动是阅读本体，禁掉会让用户无法框选当前屏以外的对白。且拖框时指针已按下，不会与滚轮同时发生 |
| 入场动画 | 纵向禁用 pop-in（`animateIn=false`） | 纵向窗口化挂载在滚动时会反复挂载/卸载，保留 180ms scale 动画会让译文框在滚动中反复「弹出」，视觉噪声明显 |
| AI 入口 UI | 抽 `AiReaderMenu.vue`：按钮组 + Teleport 动作下拉 + 外部点击/Esc 捕获 | 这套下拉的行为细节很多（顶栏毛玻璃包含块、Teleport 定位、document 捕获阶段截 Esc、禁用态），复制两份必然分叉。组件只负责「按钮组 + 动作菜单」，语义（能否进入选词、未启用提示、工具栏 pin）仍留在视图 |
| 提示胶囊 | 抽 `useAiNotice.ts` composable | 两个视图都需要「底部胶囊 + 3 秒自动淡出 + 立即清除」，与既有的 `components/ui/useHoverTip.ts` 同构；composable 落在组件目录、内部 `onScopeDispose` 清计时器 |
| EPUB AI 入口可见性 | 仅 `isVerticalImage` 时渲染按钮 | 需求只覆盖上下模式；横向/文字型纵向不出现按钮，比「按钮在但点了报错」更清晰（EPUB 的 `.controls button:disabled` 还带 `pointer-events: none`，点不到也提示不了） |
| 离开纵向的清理 | EPUB：`endSelect()` + `prunePending([])`；PDF：不清理 | PDF 横向同样有覆盖层，切到横向后选词态继续有效（可接着框选）；EPUB 横向没有覆盖层，留着选词态会变成「看不见的模式」并把滚轮/热区一起吃掉 |
| 点击与行翻页冲突 | `VerticalScrollView.onClick` 里 `closest('.ai-layer')` 早退 | 覆盖层在选词态铺满页盒、常态覆盖译文框；一处守卫同时解决「拖框时被翻行」与「点译文框顺带翻行」 |

## 四、核心口径与算法

### 4.1 页码与坐标口径（纵向 vs 横向）

| 项 | PDF / CBZ / MOBI 纵向 | EPUB 图片型纵向 | 与横向是否同口径 |
|----|----------------------|-----------------|------------------|
| 行表来源 | `reader.spreads` → `rows = { firstPage, pages: displayOrder }` | `store.verticalRows`（spine 索引，双页按跨页组） | 同（都用 `displayOrder` 语义的页 id） |
| 页 id 基数 | 1 基真实页码 | 0 基 spine 索引 | EPUB 需 `+1` 后才是 AI 页码 |
| 覆盖层参照系 | `.v-page` 显示盒（= canvas 显示尺寸） | 同 | 同 |
| 裁剪取位 | `rootEl.parentElement.querySelector('canvas')` 的位图 | 同 | 同（`AiTranslationLayer.onDragEnd` 既有取法） |
| 字号 | `fontRatio × 页盒显示高度`，钳到 10~96px 后再按框内空间收缩 | 同 | 同 |

结论：**纵向框选的记录与横向完全互通**（同一本书、同一页、同一归一化坐标）。EPUB 的 `+1` 只发生在覆盖层页码与 pending 剪裁两处，DB 里仍然是「1、2、3…」的连续整数。

### 4.2 可见窗口页码（新增纯函数）

临时框（loading / empty / error）不落库，规则是「离开可视范围即丢弃」，与横向 `prunePending(displayOrder)` 同构。纵向的可视集合是「窗口内全部行 × 行内页」：

```ts
// src/services/verticalLayout.ts 追加（纯函数，可 node 环境单测）
/** 收集渲染窗口内所有页 id（按行序、行内序展开；越界索引忽略） */
export function collectVisiblePages(
  rows: readonly VerticalRow[],
  indices: readonly number[]
): number[] {
  const out: number[] = []
  for (const i of indices) {
    const row = rows[i]
    if (!row) continue
    out.push(...row.pages)
  }
  return out
}
```

`VerticalScrollView` 暴露给父级：

```ts
defineExpose({
  scrollToPage, step, currentRow,              // 既有
  /** 当前渲染窗口内的 AI 页码（已加 aiPageOffset），供父级剪裁临时框 */
  visibleAiPages,
})
function visibleAiPages(): number[] {
  return collectVisiblePages(props.rows, visibleRows.value).map((p) => p + props.aiPageOffset)
}
```

调用点（两个视图的 `page-change` 回调，`syncScroll` 内已先 `updateWindow()` 再 emit，取到的是新窗口）：

```ts
function onVerticalPageChange(page: number): void {
  // …既有：同步 currentIndex / setVerticalPosition
  ai.prunePending(verticalRef.value?.visibleAiPages() ?? [page + offset])
}
```

### 4.3 纵向交互矩阵（选词态 vs 常态）

| 手势 / 输入 | 纵向常态 | 纵向选词态 | 实现位置 |
|-------------|----------|-----------|----------|
| 拖拽框选 | — | 起橡皮筋、松手发起翻译、自动 `endSelect()` | `AiTranslationLayer`（既有） |
| 滚轮 / 触控板 | 原生滚动 | **仍可原生滚动**（`onWheel` 选词早退未 `preventDefault`） | `ReaderView.onWheel`（现状即满足） |
| Ctrl/Cmd + 滚轮 | 缩放步进 | 缩放步进（早退条件排除 ctrl/meta） | `ReaderView.onWheel` / `EpubReaderView.onWheel` |
| 左/右 1/3 热区点击 | 上一行 / 下一行 | 不翻行（点在覆盖层上即被守卫拦下） | `VerticalScrollView.onClick` |
| 点击译文框 / 折叠球 | 不翻行 | 不翻行 | 同上（`closest('.ai-layer')`） |
| 框内滚轮（长译文） | 只滚译文 | 只滚译文 | `AiTranslationLayer` 的 `@wheel.stop`（既有） |
| 键盘方向键 / 空格 | 滚一行 | 滚一行（不退出选词） | 各视图 `onKeydown` 纵向分支（既有） |
| `A` | 进入选词 | 退出选词 | 新增（PDF 纵向分支） |
| `Esc` | 退全屏 / 返回文库 | **只退出选词** | `resolveReaderEsc`（既有，PDF 两分支已接入，EPUB 本次接入） |
| 鼠标贴顶 / 贴底 | 唤出工具栏 | 不唤出（`barsSuppressedByAi` 门控） | 两视图 `showBarsTemporarily` |
| 拖拽平移（PDF） | 纵向本就禁用 | 禁用 | `ReaderView.onMouseDown`（既有早退） |

### 4.4 边界场景防护清单

| 场景 | 行为 |
|------|------|
| 页滚出视口（窗口化卸载） | 覆盖层随 `.v-page` 卸载；记录仍在 store，滚回来按页码重画（百分比定位，无偏移误差） |
| 滚出视口的临时框（loading / empty / error） | `prunePending(visibleAiPages())` 丢弃；在途请求因 pending key 失效被 `isLive` 拦下，不落库 |
| 快速滚动 | 无入场动画；每页覆盖层仅在挂载时做一次 `ResizeObserver` 测量，无持续开销 |
| 缩放切换（含 Ctrl+滚轮） | 组件 `relayout` → 页盒尺寸变化 → 覆盖层 `ResizeObserver` 重算字号、百分比重贴，无需额外接线 |
| 单/双页切换 | 行表重建、行内出现两页 → 每页各自一个覆盖层，页码独立命中 |
| 拖框越出所在页 | 坐标夹到该页盒内（`onDragMove` 既有夹取），不产生负宽高，也不跨页 |
| 误触（< 24 × 16 px） | `normalizeRect` 返回 `null`：不发请求、**不退出选词**（与横向一致） |
| 页码为 0（EPUB 首页） | `aiPageOffset = 1` 使其落库为 1，满足 `aiService` 的 `page ≥ 1` 校验 |
| 切离 EPUB 图片型纵向 | 守卫 `endSelect()` + `prunePending([])`：不留隐形选词态，在途结果全部作废 |
| 切离 PDF 纵向（转横向） | 不清理：横向同样有覆盖层，选词态继续有效，工具栏抑制延续 |
| 换书 / 离开阅读页 | 既有 `ai.load(id)` / `ai.reset(null)` 收口，纵向复用（EPUB 本次补上这两个调用） |
| 书被删除 | `ai_translations` 行随外键 CASCADE 删除（既有） |

## 五、渲染层实现（接缝点）

### 5.1 共用件抽取（先做，保持现有 PDF 横向行为不变）

**新建 `src/components/reader/AiReaderMenu.vue`**

```ts
const props = defineProps<{
  /** AI 可用：总开关开启且选中了有效 provider */
  ready: boolean
  /** 选词中：按钮显示按下态 */
  active: boolean
  /** 本书记录数 > 0：动作项可用 */
  hasRecords: boolean
  /** 全部隐藏中：「全部隐藏」置灰 */
  hiddenAll: boolean
}>()

const emit = defineEmits<{
  toggle: []                       // 点主按钮：视图决定「提示未启用」还是进/退选词
  hideAll: []
  collapseAll: []
  expandAll: []
  open: []                         // 下拉展开：视图 pinBars()
  close: []                        // 下拉收起：视图 unpinBars()
  triggerEnter: [anchor: HTMLElement]  // 悬停提示锚点（仿 SelectMenu）
  triggerLeave: []
}>()
```

内部职责（全部从 `ReaderView.vue` 平移，行为逐条对齐）：

- 按钮组：`AI 翻译` 主按钮 + `▾` caret；`ready=false` 时主按钮视觉禁用但仍可点（点击后由视图弹「未启用」提示），caret `disabled`。
- 动作下拉：`Teleport to="body"` + `position: fixed` + 按 caret 的 `getBoundingClientRect` 定位（顶栏 `backdrop-filter` 会改变 fixed 包含块，不能就地绝对定位）。
- 关闭路径：动作点击、点外部、`document` 捕获阶段 `Escape` 三处统一 `close → emit('close')`。
- 样式自带（组件内部按钮不再继承视图的 `.controls button`）：26px 高、`1px solid rgba(255,255,255,.4)`、圆角 4px、主按钮右侧不带圆角与描边，拼成一组。

## 十、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 覆盖层每页常驻挂载 | 可视窗口内每页都挂一个 `AiTranslationLayer`（约 2 屏 ≈ 2~6 个），不按「是否有记录」剪枝 | 挂载成本是「一个 div + 一个 ResizeObserver + 一次空测量」，无记录时空转可忽略；换来「进入选词即可框选任意页」的简单语义。若实测滚动掉帧，扩展点：给 `VerticalScrollView` 传 `aiPageNeeded(page)` 判断函数，仅在选词态或有记录时挂载 |
| 选词期允许纵向滚动 | 与横向「选词期禁滚轮」不同口径 | 横向禁的是翻页副作用，纵向禁滚动会直接失去「框选远处对白」的能力；拖框期间指针已按下，不会与滚轮并发。代价：若用触控板两指在拖框中滚动，橡皮筋会按「按下点 + 当前指针」下的页盒坐标夹取，极端情况下选区会偏——这属于用户主动叠加操作，不做额外防护 |
| 纵向禁用入场动画 | 与横向不一致（横向保留 pop-in） | 窗口化挂载让动画每次滚动都重播，观感更差；横向页盒稳定重挂次数少，保留动画收益更高。若反馈纵向"太生硬"，可改为「首次挂载播放、滚动重挂不播」（需记录已播过的页码集合） |
| 抽取 `AiReaderMenu` 属重构风险 | 对已验证的 AI 下拉做行为平移 | 组件只搬「按钮组 + 弹层 + 关闭路径」，语义仍留视图；M1 用 §8.2 第 2 条守住回归。附带归一：所有关闭路径统一 `unpinBars()`（原「点 caret 关闭」未解除 pin，顶栏会一直显示） |
| EPUB 仅图片型纵向可用 | 文字型纵向与横向不出现按钮 | 文字型正文是重排文本，框选截图翻译会与文本选择冲突，须另建文本链路；横向不在本次需求内。两处都以「不渲染」而非「置灰」处理，避免无法提示的禁用态 |
| EPUB 页码 `+1` 偏移 | 偏移只在视图层两个出口发生 | 代价：EPUB 与 PDF 的「AI 页码」语义不同（spine 索引 vs 真实页码），读码时需记住该偏移；收益是 DB 与契约零改动（`page ≥ 1` 依旧成立）。若将来 EPUB 也需要"页码"概念，再在 store 层统一归一 |
| 离开纵向的清理不对称 | PDF 切横向保留选词态；EPUB 切横向强制退出 | 依据是「切过去还有没有覆盖层」这一客观事实；PDF 保留让用户可以从纵向开始框选、到横向继续对页框选 |
| 纵向临时框剪裁依赖窗口 | `prunePending(visibleAiPages())` 只在 `page-change`（顶部行变化）时执行 | 同一行内滚动不会触发剪裁，行内两页的临时框会同时存在——这正是期望行为（两页都在可视范围内）。极快滚动时可能短暂保留一张已离开窗口的兜底框，下次行切换即清 |
| 页盒与 canvas 尺寸舍入差 | `.v-page` 的宽高来自 `computePageBox`，canvas 的 CSS 尺寸来自渲染层 `style.width/height`，两者可能有 <1px 差异 | 影响仅限于译文框贴合（<1px），裁剪取的是 canvas 位图 × 归一化矩形，不受该差异影响 |

## 十一、实施记录（与设计稿的差异）

实现过程中的三处补充，均已回写到对应源文件注释：

1. **`AiReaderMenu` 增加 `defineExpose({ closeMenu })`**：视图侧原有 `closeAiMenu()` 有两个调用点（进入选词前强制收起、卸载时清理），不能随逻辑一起删除。改为组件暴露句柄：进选词走 `aiMenuRef.value?.closeMenu()`（仍 `emit('close')` → `unpinBars()`，保持关闭路径唯一）；卸载点删除——组件与视图同生共死，其 `onBeforeUnmount` 已摘掉文档级监听。
2. **`watch(currentDisplayPages)` 在纵向跳过剪裁**：该 watch 原先无条件 `prunePending(pages)`，纵向屏内可同时有多页，会把非顶行的在途翻译误判为「已离开」而丢弃。现改为 `if (!isVertical.value) ai.prunePending(pages)`，纵向统一由 `onVerticalPageChange` 按可见行集合剪裁；`watch(isVertical)` 在离开纵向时按当前显示页补剪一次。
3. **EPUB 提示胶囊 `z-index: 3`（PDF 为 4）**：两视图工具栏层级不同（PDF z3、EPUB z2），胶囊只须高于本视图工具栏即可。

另：`AiTranslationLayer` 内「canvas 是 `.page-wrap` 的兄弟节点」的注释已更新为「canvas 与覆盖层同属页盒（横向 `.page-wrap` / 纵向 `.v-page`）」——`parentElement.querySelector('canvas')` 两种结构下都成立。

## 十二、补充：EPUB 图片型横向接入（本轮追加）

原方案只覆盖纵向。实际使用反馈需要「左右翻页」也能框选翻译，故按「图片型横向也支持、文字型仍不做」的范围补齐。

### 12.1 与纵向的三处差异

| 差异 | 纵向（PDF / CBZ / MOBI / EPUB 图片型） | EPUB 图片型横向 |
|------|------------------------------------|------------------|
| 页盒来源 | `VerticalScrollView` 的 `.v-page`（尺寸全由本地布局算出） | epub.js 的 iframe：取 `contents.document.querySelector('img, svg')` 的矩形，**不能用 iframe 矩形**（`fitPrePaginatedContents` 把图片按 fit 尺寸居中，iframe 留有黑边，归一化坐标会带留白误差） |
| 位图来源 | 页盒内的 `canvas` | 无 canvas：`captureRegionToCanvas` 区域截图（主进程合成，含 iframe 内容），坐标用窗口 CSS 像素（`frameRect.left + rect.left`） |
| 页码 | 传 `aiPageOffset`（EPUB 为 `1`） | `contents.sectionIndex + 1`，与纵向 `+1` 口径一致，**共用同一条 DB 记录** |

### 12.2 实现要点

1. **覆盖层容器**：`.page-area` 内新增 `.ai-stage`（`inset: 0`、`z-index: 2`、常态 `pointer-events: none`），其中按页盒绝对定位若干 `.ai-stage-page`，每个页盒内挂一个 `AiTranslationLayer`（`animateIn=false`、`captureSource=captureAiPage`）。
2. **几何跟随**：epub.js 自行重建 iframe，没有可订阅的几何事件，故 `AI_BOX_POLL_MS = 180` 轮询重算页盒；`sameAiPageBoxes` 以 0.5px 容差比较，位置未变则不写响应式状态，避免无谓重渲染。
3. **门控**：`aiOverlayVisible = !switching && !isTurnCurlActive()`，在轮询内同步——重建引擎与卷曲动画期间不渲染译文框。
4. **选词态接管**：`.ai-stage.selecting` 置 `pointer-events: auto`，拖框不会穿透到 iframe / 热区触发翻页；`onWheel` 在 `ai.selecting` 时早退，滚轮不翻页。
5. **临时框剪裁**：轮询里按「当前挂载页集合」剪裁 `pending`（仅集合变化时写 store，`lastPrunedKey` 去重），翻走那页的在途翻译立即作废。
6. **截图失败**：`captureAiPage` 吞错返回 `null`；`AiTranslationLayer.onDragEnd` 在位图为空时**仍调用 `ai.endSelect()`**，避免十字光标卡在选词态。
7. **`A` 快捷键**：条件由 `isVerticalImage` 放宽为 `isImageLayout`（横向 / 纵向都可进退选词）；ESCAPE 三分支、工具栏抑制、提示胶囊与纵向共用同一套。
8. **遗留改动**：原 `watch(isVerticalImage, ...)` 离开守卫改为 `watch(isImageLayout, ...)`——横向 ↔ 纵向互切不再打断选词，只有切回文字型书才退出并清空临时框。

### 12.3 仍不支持

- 文字型（reflowable）EPUB：无论横向还是纵向，正文是重排文本，框选截图会与文本选择冲突，需另建文本链路；顶栏不渲染 AI 按钮。
- 无 `img/svg` 的图片型章节（如纯文字封面页）：该页不产出页盒，覆盖层缺失，属预期。
