# 阅读时间统计功能设计方案

> 状态：设计稿（待实现）
> 目标版本：v1.2.0
> 范围：阅读时长采集（PDF / EPUB 通用）、数据持久化、统计页面（图表可视化）、设置页入口
> 实现约束：遵循 `ireader-dev-tasks`（任务 A/B/D/F）与 `ireader-code-conventions`（Result 契约、中文注释、双进程共享类型）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 统计每本漫画的总阅读时间 | `reading_stats` 表按 (book_id, day) 聚合；`stats:summary` 返回每书累计值 | 阅读两本书各 N 分钟，排行中各书时长分别正确 |
| 2 | 统计每天的阅读时间 | 同上表按 day 聚合；跨天自动切分归属 | 单测覆盖跨天切分；手动改系统时间冒烟 |
| 3 | 设置界面添加「阅读时间统计」按钮 | SettingsView 新增「数据」分组行，点击跳转 `/stats` | 点击后进入统计页，返回键回到设置 |
| 4 | 统计页展示总时长 / 每本漫画时长 / 当日时长，图表化，越好看越好 | 3 张概览卡 + 每日柱状图 + 书籍排行条形图，全部 SVG/CSS 自绘，贴合现有 Apple 风主题 | 深浅主题下视觉检查；空数据、多数据两种场景 |

**核心验收口径**：真实阅读页停留 3 分钟 → 统计页「今日阅读」显示 2~3 分钟（误差 ≤1 个心跳周期）；窗口最小化/失焦期间不计时。

## 二、非目标（本期不做）

- 不做空闲检测（mousemove 长时间无操作暂停计时）：漫画以「看」为主，盯着画面不动属正常阅读行为，空闲判定误伤率高。
- 不保留会话明细（每次打开书的起止时间）：需求仅要日粒度聚合；将来需要「时段分布/习惯分析」时再追加会话表（扩展点见 §5）。
- 不做统计清空/导出、阅读目标设置、阅读界面内的时长悬浮展示。
- 不改动 `reading_progress` 表与既有进度保存链路。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 计时位置 | 仅 ReaderView.vue（路由级） | PDF/EPUB 共用同一路由视图，避免两个引擎各自埋点导致双计/漏计 |
| 计时方式 | 心跳结算（30s）+ 事件兜底结算 | 崩溃最多丢 30s；失焦/隐藏/卸载/换书时立即结算，不依赖单一出口 |
| 数据模型 | 日粒度聚合表（book_id, day 唯一键 UPSERT 累加） | 数据量 = 书数 × 天数，极小；查询直接 GROUP BY，无需明细表 |
| 图表实现 | SVG + CSS 自绘，不引入图表库 | 纯离线红线 + 不新增依赖；数据规模与交互复杂度低；样式完全贴合现有设计语言 |
| 上报失败 | 静默忽略（fire-and-forget） | 统计是可丢弃数据，绝不能影响阅读主流程（参考 `log.write` 模式） |

## 四、统计口径与计时算法（核心）

### 4.1 活跃阅读的判定

**计入阅读时间**：停留在 `/reader/:bookId` 且满足以下全部条件——

1. 路由有效（bookId 为有限数字）；
2. `document.visibilityState === 'visible'`（窗口未最小化、未隐藏）；
3. `document.hasFocus()`（窗口为前台焦点）；
4. 未处于加载失败状态（`loadError` 为空）。

**不计入**：切到其他应用、最小化、加载错误页停留（尽力而为联动，见 §8.3）。

> 取舍说明：失焦即暂停与主流阅读器一致；多窗口对照阅读的场景会被少记，接受此偏差。不做空闲检测的理由见 §2。

### 4.2 心跳与结算

- 心跳周期 `heartbeatMs = 30_000`：每 30s 结算一次增量并上报。
- 手动结算时机（立即 flush，不等心跳）：暂停（失焦/隐藏）、恢复、换书、离开阅读页。
- **单次结算上限 `maxStepMs = 2 × heartbeatMs = 60s`**：结算时增量超过上限的部分丢弃。目的：系统休眠/进程被冻结后，定时器恢复时的超大增量不被计入；正常 30s 心跳调度抖动（远小于 60s）不受影响。
- 时钟回拨保护：增量 ≤ 0 时丢弃本段，并重置基准时间。
- 上报粒度：书 id + 本地日期 + 毫秒增量；主进程做累加 UPSERT。

### 4.3 跨天切分

结算时若增量区间跨越本地午夜，按午夜边界切分为多段，分别归属各自日期（心跳 30s 粒度下通常只切一次，算法天然支持多段）：

```ts
// 伪代码：flush(now)
const from = lastTs
lastTs = now
if (now <= from) return                       // 时钟回拨，丢弃
const capped = Math.min(now, from + maxStepMs) // 休眠保护
let cursor = from
while (cursor < capped) {
  const midnight = nextLocalMidnight(cursor)   // 下一个本地 00:00 的时间戳
  const segEnd = Math.min(capped, midnight)
  onReport({ bookId, day: formatDayKey(new Date(cursor)), deltaMs: segEnd - cursor })
  cursor = segEnd
}
```

- 日期键 `formatDayKey` 一律取**本地时区** `YYYY-MM-DD`（用 `getFullYear/getMonth/getDate` 拼接，禁止用 `toISOString()` 的 UTC 日期）。
- `formatDayKey` 双进程共用，放 `shared/types.ts`（该文件已有 `ok/fail` 共享函数先例）。

### 4.4 异常场景防护清单

| 场景 | 行为 |
|------|------|
| 窗口最小化 / 切换应用 | 事件触发立即结算并暂停；恢复可见+聚焦后重新开始累计 |
| 系统休眠 / 进程冻结 | 恢复后首次结算按 `maxStepMs` 截断，最多多记 60s |
| 系统时钟回拨 | 丢弃该段增量并重置基准 |
| 应用崩溃 / 强杀 | 丢失 ≤30s（最后一个心跳窗口） |
| 窗口关闭（X） | 渲染进程不保证执行卸载钩子，丢失 ≤30s，接受（不做主进程 close 握手，YAGNI） |
| 阅读中删除当前书 | 心跳上报时主进程校验书存在，不存在则静默忽略 |
| 书被删除 | `reading_stats` 行随外键 CASCADE 删除，排行与总量同步减少 |

## 五、数据模型

### 5.1 v4 迁移（追加到 `electron/db/database.ts` MIGRATIONS 末尾）

```sql
-- v4: 阅读时长统计（日粒度聚合：每本书每天一行，累加毫秒）
CREATE TABLE IF NOT EXISTS reading_stats (
  book_id     INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  day         TEXT    NOT NULL,              -- 本地日期 'YYYY-MM-DD'
  duration_ms INTEGER NOT NULL DEFAULT 0,    -- 当日累计阅读毫秒
  updated_at  INTEGER NOT NULL,              -- 最后一次累加时间（= 最近阅读时刻）
  PRIMARY KEY (book_id, day)
);

CREATE INDEX IF NOT EXISTS idx_reading_stats_day ON reading_stats(day);
```

说明：

- 复合主键 (book_id, day) 支撑 `INSERT ... ON CONFLICT` 原子累加，天然幂等防并发重放。
- `updated_at` 兼作「最近阅读时刻」（排行副文案用），不单独加列。
- 外键 CASCADE：删书即删统计，与 `foreign_keys=ON` 既有基线一致。
- 未来扩展：如要做「时段分布」，追加 `reading_sessions` 明细表，本表保留为聚合缓存，不冲突。

  /** 全部书籍累计（ms） */
  totalMs: number
  /** 今日累计（ms） */
  todayMs: number
  /** 最近 days 天逐日序列（升序、已补齐零值日、含今天） */

  books: BookReadingStat[]

### 6.2 通道定义

| 通道 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `stats:addTime` | `{ bookId: number; day: string; deltaMs: number }` | `void` | 心跳累加；非关键路径 |
| `stats:summary` | `{ days: number }` | `ReadingStatsSummary` | 统计页一次性拉全量 |

**服务层校验规则**（`statsService.addTime`）：

- `bookId`：正整数且 `booksRepo.findById` 存在，否则**静默忽略**（返回 ok；书可能刚被删除，心跳在途，属正常竞态，不打日志不报错）。
- `day`：匹配 `/^\d{4}-\d{2}-\d{2}$/`，否则抛 `{ code: 'INVALID_PARAMS' }`。
- `deltaMs`：`(0, 300_000]` 的整数，否则抛 `{ code: 'INVALID_PARAMS' }`（5 分钟上限留出聚合余量，正常心跳 30s 远低于此）。
- `days`：收敛到 `[1, 365]`，非法值回退 `30`。

按「任务 A」六步落地：`shared/types.ts` → `electron/preload.ts`（stats 域，`invoke('stats:addTime', { bookId, day, deltaMs })`）→ `electron/ipc/handlers.ts`（wrap 注册，编排 statsService）→ `src/services/ipc.ts` 镜像封装。ErrorCode 复用既有 `INVALID_PARAMS`，不扩展。

## 七、主进程实现

### 7.1 statsService（新建 `electron/services/statsService.ts`）

职责：参数校验（§6.2）+ summary 汇总编排。summary 算法：

1. `days` 收敛；`today = formatDayKey(new Date())`；
2. `fromDay = ` 今天回溯 `days - 1` 天的日期键（用 `new Date(y, m, d - (days - 1))` 逐日运算，禁止用固定 86400000 毫秒回退，避开时区/夏令时边界）；
3. `statsRepo.listByDay(fromDay)` + `statsRepo.listByBook()` + `statsRepo.totalDuration()`；
4. **补齐零值序列**：从 `fromDay` 到今天逐日生成完整 `days` 数组，查不到的天补 `durationMs: 0`（保证 IPC 契约返回完整序列，渲染层零加工）；
5. `todayMs` 从补齐后的序列末位取；
6. `books` 映射时用 `getCoverUrl(bookId)` 组装 `coverUrl`（逻辑地址，不校验文件存在，前端容错）。

handler 编排（`handlers.ts`）：

```ts
ipcMain.handle('stats:addTime', wrap((p: { bookId: number; day: string; deltaMs: number }) =>
  statsService.addTime(p)))
ipcMain.handle('stats:summary', wrap(({ days }: { days: number }) => statsService.summary(days)))
```

## 八、渲染层计时采集

### 8.1 readingTimer.ts（新建 `src/services/readingTimer.ts`，纯逻辑可测）

```ts
export interface ReadingReport {
  bookId: number
  day: string      // 'YYYY-MM-DD'
  deltaMs: number  // 本段增量
}

export interface ReadingTimerOptions {
  now?: () => number          // 注入时钟（测试用），默认 Date.now
  heartbeatMs?: number        // 心跳周期，默认 30_000
  maxStepMs?: number          // 单次结算上限，默认 2 × heartbeatMs
  onReport: (report: ReadingReport) => void  // 可能一次触发多段（跨天切分）
}

export class ReadingTimer {
  constructor(options: ReadingTimerOptions)
  start(bookId: number): void  // 开始；重复调用 = 先结算旧书再切新书
  pause(): void                // 结算后暂停（幂等）
  resume(): void               // 恢复（重置基准时间，暂停期不计；幂等）
  stop(): void                 // 结算 + 清理心跳 + 回到 idle（幂等）
  get running(): boolean
}
```

内部状态机 `idle | running | paused`；核心结算算法见 §4.3；关键实现要点：

- `start` 时若已有书在计时，先 `flush` 旧书再切书（换书不丢段）。
- `pause/resume` 先结算再改状态；`resume` 时 `lastTs = now()`。
- 心跳 `setInterval` 仅在首次 `start` 创建一次，`stop` 清理；tick 时非 running 直接返回。
- 内部私有函数 `nextLocalMidnight(ts)`：`new Date(y, m, d + 1).getTime()`。

### 8.2 readingTracker.ts（新建 `src/services/readingTracker.ts`，单例接线）

职责：把 ReadingTimer、DOM 事件、IPC 上报粘合为 3 个入口函数，视图层不写事件监听细节。

```ts
export function startTracking(bookId: number): void   // 阅读页打开/换书
export function stopTracking(): void                  // 离开阅读页
export function setTrackingPaused(paused: boolean): void // 加载失败等临时挂起
```

实现要点：

- 模块级单例 `timer`；`onReport` 回调中 `ipc.stats.addTime(...).catch(() => undefined)`（静默，见 §3.2）。
- 事件绑定只做一次：`document.visibilitychange`、`window.blur`、`window.focus`，统一走 `sync()`：
  `active = !suspended && visibilityState === 'visible' && document.hasFocus()` → `resume()` / `pause()`。
- `setTrackingPaused(true)` 置 `suspended` 标志后 `sync()`——解决「错误页手动暂停后，focus 事件误恢复」的问题。
- 此文件含 DOM/IPC 副作用，不做单测；纯逻辑全部下沉到 readingTimer.ts。

### 8.3 ReaderView.vue 接线（仅此一处埋点，禁止在 EpubReaderView 重复埋点）

| 位置 | 代码 | 说明 |
|------|------|------|

### 9.4 每日柱状图（`src/components/stats/DailyBarChart.vue`）

**Props**：`{ days: DailyReadingStat[]; height?: number /* 默认 220 */ }`（接收已补齐升序序列）。

实现要点：

- **坐标系**：SVG 像素坐标直绘。`ResizeObserver` 监听容器宽度 → 计算 `svgWidth` → 布局函数产出柱位/柱宽（7 天柱宽增大间距收窄；30 天细柱），不做 viewBox 等比缩放（避免文字被拉伸）。
- **Y 轴**：`niceMax(maxMs)` 取阶梯上限（阶梯序列：5/10/15/20/30/45/60/90/120/180/240/360/480/720/1080/1440 分钟 …取第一个 ≥ 最大值，兜底 ≥ 30 分钟），4 档刻度；3 条水平虚线网格 `stroke: var(--border); stroke-dasharray: 3 6`；刻度文案用紧凑格式（`formatDurationCompact`）。
- **柱子**：圆角顶（`rx ≈ 柱宽/4`，上限 6px）；填充 `linearGradient`（品牌蓝 55% → 100% 透明度渐变，垂直）；**今日柱**用高饱和品牌色 + 顶部圆点标记。
- **入场动画**：柱子从底部生长（`transform: scaleY(0→1)`，`transform-origin: bottom`，500ms ease-out，逐柱 delay = i×15ms）。
- **交互**：每根柱覆盖全高透明热区（拉大命中面积），hover 时柱色加深、tooltip 跟随（`position: fixed` 小卡片：`M月D日 周X · 1 小时 20 分钟`；7 天视图显示星期字样，30 天视图显示日期）。
- **X 轴标签**：7 天视图全标（周一~周日），30 天视图每隔 5 天标注 `M/D` + 首末各一，`fill: var(--text-muted)`、11px、居中。
- 零值日不画柱（或 2px 矮条淡显，二选一以实现视觉为准，推荐不画）。

### 9.5 书籍排行（`src/components/stats/BookRankingList.vue`）

**Props**：`{ books: BookReadingStat[] }`。

- 行结构：排名徽章 + 封面缩略图（40×56，圆角 6px，`object-fit: cover`，`onerror` 落主题色占位块显示书名首字）+ 书名与副文案（最近阅读：今天/昨天/N 天前，`formatRelativeDay`）+ 右侧时长（`formatDuration`）。
- 进度条：行下方细条（4px 圆角），宽度 = `durationMs / books[0].durationMs × 100%`，品牌渐变填充，入场时从 0 过渡到位。
- 排名徽章：前三名品牌色圆点数字（1/2/3），其余 `var(--text-faint)`。
- 折叠：默认显示 Top 10，超出显示「展开全部（共 N 本）」/「收起」。
- hover：行背景 `var(--surface-2)`，过渡 150ms。

### 9.6 空态 / 加载态 / 错误态

- **空态**（`totalMs === 0`）：整页显示一张空态卡——内联 SVG 插画（半开的书 + 时钟轮廓，描边风 `var(--text-faint)` + 品牌色点缀）+ 文案「还没有阅读记录，打开一本书，时长会自动记录在这里」+ 「去书架看看」按钮（`router.push('/')`）。
- **加载态**：3 个卡片位 + 2 个图卡位显示骨架屏（灰色圆角块 `animation: pulse 1.4s ease-in-out infinite`）。
- **错误态**：`IpcError` catch 后显示居中错误文案 + 「重试」按钮（重新拉取 summary）。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 心跳 30s | 崩溃/关窗最多丢 30s | 统计场景可接受；如需更高精度可下调周期，代价是 IPC 频次 |
| 休眠截断 60s | 睡眠恢复那次最多多记 60s | 宁多勿少 vs 宁少勿多中选择了「少测漏、温和多记」，80 小时睡眠只会多记 60s |
| 失焦即停 | 多窗口对照阅读少记 | 与主流阅读器口径一致；后续如收到反馈可改为「仅隐藏时暂停」 |
| 不做空闲检测 | 挂机不动也会累计 | 漫画阅读的正常行为；如未来接入小说类长文本可再评估 |
| 日粒度聚合表 | 无会话明细 | 无法回溯「几点在看书」；扩展会话表时不影响本表 |
| 图表零依赖（SVG 自绘） | 开发成本略高于引库 | 守住纯离线/不新增依赖红线；数据规模小，自绘完全可控 |
| 删书即删统计 | 历史总时长会减少 | 与 CASCADE 数据一致性优先；如需「保留历史」需软删除书，超出本期范围 |
