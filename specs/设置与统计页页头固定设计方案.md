# 设置与统计页页头固定设计方案

> 状态：已实现（已验证）
> 目标版本：v1.2.6（小改 / 体验修复：仅提交代码，不 bump 版本、不打 tag，由发版流程统一处理；当前 package.json 为 1.2.5）
> 范围：设置页 / 阅读统计页页头（`.page-head`）滚动吸顶固定
> 实现约束：遵循 `ireader-dev-tasks`（任务 D 第 4 条：样式跟随主题体系，兼容 light/dark；任务 F 验证流程）与 `ireader-code-conventions`（中文注释、与相邻文件风格一致）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 设置页页头保持固定 | `style.css` 全局 `.page-head` 增加 `position: sticky; top: 0`，滚动时贴顶不随内容走 | 设置页滚动到「关于」分组时，页头完整可见，返回按钮 / 标题始终可点 |
| 2 | 统计页页头保持固定 | 同一全局规则（两页共用 `.page-head`，已核实仅此两处使用），页面内零改动 | 统计页在骨架屏 / 错误态 / 空态 / 正常内容四种状态下滚动，页头均吸顶 |
| 3 | 吸顶后视觉不脏、层级不乱 | 沿用既有毛玻璃配方（`--surface-alpha` + `blur(20px) saturate(180%)` + 底部 1px 分割线）；补 `z-index: 10` 使页头压住内容层 | 内容从页头下方穿过时被模糊遮挡、无文字穿透；图表 tooltip（30）/ 对话框（100）/ toast（200）层级不受影响 |

**核心验收口径**：两页在浅色 / 深色主题下，内容滚动到任意位置页头恒贴窗口顶部、宽度撑满且无位移抖动；`npm run typecheck`、`npm test` 通过；文库页、阅读页、各对话框视觉零变化。

## 二、非目标（本期不做）

- 不做文库页（`LibraryView.vue` 的 hero / `.collection-head` / `.top-bar`）吸顶——本次需求仅限设置页与统计页。
- 不做滚动感知阴影（滚动后才出现的页头投影）——需 `scroll` 监听或 scroll-driven animation，增加状态与验证成本，与现有 `border-bottom` 分层的克制风格不符。
- 不做结构分层（页头固定占位 + 内容区独立滚动容器）——用户已选定 sticky 吸顶方案（见 §3.2），避免改两页模板与空态 / 错误态的滚动归属。
- 不改页头尺寸、内边距、背景配方与标题排版（沿用《设置与统计页视觉优化设计方案》§4.4 规范）。
- 不做路由滚动位置恢复 / 页面切换滚动重置。
- 不新增 npm 依赖；不涉及 IPC 契约、DB、共享类型。

## 三、总体设计

### 3.1 层级与滚动结构（现状 + 变更点）

```
SettingsView.vue / ReadingStatsView.vue
 └─ .settings-view / .stats-view          （height:100vh; overflow-y:auto ← 页内唯一滚动容器）
      ├─ header.page-head  ← 变更：style.css 全局规则新增 sticky 三行
      │      position: sticky; top: 0; z-index: 10
      └─ .groups（设置）/ .content、StatsEmptyState（统计）  ← 内容随滚动从页头下方穿过
```

纯渲染层样式改动：无 IPC / 数据流 / 路由变更，CSS 变量全部取自 `style.css` 既有令牌，深浅主题自动兼容。

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 实现形态 | sticky 吸顶（用户确认） | 一处全局选择器三行改动即可达成；内容穿行毛玻璃是 iOS 既定观感；结构分层方案需改两页模板并为骨架屏 / 错误态 / 空态各自确定滚动归属，回归面明显更大 |
| 样式归属 | 全局 `.page-head` 单点（`style.css`），页面内不加修饰类 | 该类当前仅两页使用（已 grep 核实：`style.css` 定义 + 两视图引用 + macOS 避让规则），且未来二级页大概率同样需要吸顶，单点维护避免复制 |
| `z-index` 取值 | `10` | 需高于内容层（文库 hero 1 / 书封 2~3 / 阅读工具栏 2；统计页内容无 z-index），且低于图表 tooltip `30`、对话框 `100`、toast `200`——浮层语义上仍压过页头，沿用既有刻度不新立层级 |
| 背景配方 | 沿用 `--surface-alpha` + `blur(20px) saturate(180%)` + `border-bottom: 1px solid var(--border)` | 与 `.collection-head` 同一配方；吸顶后内容穿过时靠既有 72% 不透明 + 模糊自然遮挡，不新增底色、深浅主题零额外维护 |
| macOS 红绿灯 | 保持 `.platform-mac .page-head { padding-left: 84px }` | 吸顶后页头常驻顶部，红绿灯始终落在页头左侧留白区（页头高 72px > 红绿灯 12~38px），无需额外改动 |
| 版本节奏 | v1.2.6（patch），本次仅提交代码不 bump | 属小改 / 体验修复；文档未指定时按 package.json 1.2.5 推导为下一个 patch，版本号与 tag 由发版流程统一处理 |

## 四、核心变更：页头吸顶规则

`style.css` 现有块（第 115-124 行）追加三行并更新注释：

```css
/* 页面头（设置 / 阅读统计等二级页）：与 .collection-head 同规范；
   吸顶固定：滚动容器为 .settings-view / .stats-view，内容从毛玻璃下穿过 */
.page-head {
  position: sticky;
  top: 0;
  z-index: 10;
  display: flex;
  align-items: center;
  gap: 20px;
  padding: 18px 40px;
  background: var(--surface-alpha);
  backdrop-filter: blur(20px) saturate(180%);
  border-bottom: 1px solid var(--border);
}
```

### 4.1 边界场景防护

| 场景 | 行为 |
|------|------|
| sticky 定位参照 | `.settings-view` / `.stats-view` 自身即滚动容器且无 padding，页头直接贴容器顶；祖先 `body` / `#app` 的 `overflow: hidden` 不破坏 sticky（包含块就是页内滚动容器） |
| 内容滚动到页头下层 | 被 72% 不透明 + `blur(20px)` 毛玻璃遮挡，与 `.collection-head` 观感一致，无文字穿透 |
| 图表 tooltip（`z-index: 30`） | 高于页头，悬停柱子时浮层仍在最上（浮层 > 页头，语义正确）；滚轮滚动后浏览器重新派发 hover，tooltip 随柱子移出而消失 |
| 对话框 `100` / toast `200` / debug 面板 `9999` | 全部高于页头，弹层行为零变化 |
| 内容区首块间距 | `.groups` / `.content` 顶部 `padding: 20px` 保持不变：初始页头与首块间距不变，滚动后内容贴页头下沿（预期观感） |
| 页面高度不足（空态 / 错误态） | 无法滚动时 sticky 元素自然停在原位，表现与改动前一致 |
| macOS 红绿灯 | `.platform-mac .page-head` 选择器优先级高于 `.page-head`，`padding-left: 84px` 继续生效 |
| `prefers-reduced-motion` | 纯定位改动、无动画，不涉及 |

## 九、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| sticky + `backdrop-filter` 合成层 | 采用默认合成行为，不做额外 hack | Chromium 124（Electron 30）下一般正常；若极端情况出现边缘 1px 缝，可对 `.page-head` 加 `transform: translateZ(0)` 或加深分割线，回退成本 1 行 |
| 滚动条贯穿页头右侧 | 保持整窗滚动（滚动条在最右侧全高） | Electron 默认滚动条样式下观感可接受；若要求滚动条仅内容区，需改结构分层（已列非目标） |
| 内容从毛玻璃下穿过 | 靠 72% 不透明 + 模糊遮挡，与 `.collection-head` 同配方 | 极高对比度大图滚动经过时仍会透出轮廓，属既定 iOS 观感；不接受时改为接近不透明底色（一行改动） |
| 无滚动感知阴影 | 只用 `border-bottom` 表达分层 | 观感克制、无滚动监听开销；后续若反馈层次不足，可单独用 scroll-driven animation 补 |
| 全局选择器影响未来页面 | 直接给 `.page-head` 加吸顶 | 当前仅两页使用；未来若出现不希望吸顶的页面，可加修饰类覆盖 `position: static`，成本极低 |
