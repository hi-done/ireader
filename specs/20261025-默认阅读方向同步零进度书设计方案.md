# 默认阅读方向同步零进度书设计方案

> 状态：已实施（2026-10-25）
> 目标版本：v1.3.0
> 范围：设置页「默认阅读方向」变更时，主进程把零进度书的 `reading_progress.direction` 批量对齐到新值；纯数据层改造，无 UI 变更
> 实现约束：遵循 `ireader-dev-tasks`（任务 A 的 handler 编排、任务 F 验证流程）与 `ireader-code-conventions`（Result 契约、中文注释、双端共享纯函数放 `shared/types.ts`）

## 一、需求拆解与验收标准

| # | 原始需求 | 设计落点 | 验收方式 |
|---|----------|----------|----------|
| 1 | 设置里的「默认阅读方向」每次变更都要对所有「阅读进度为 0」的书应用 | `settings:patch` 检测到 `defaultDirection` 实际变化后，在**同一事务**内把零进度行的 `direction` 列改为新值 | 打开过但停在第一页的书，改默认方向后重新打开即为新方向；翻过页的书保持原方向 |
| 2 | 「进度为 0」的判定要可解释、可测试 | `shared/types.ts` 新增纯函数 `isUnstartedProgress(page, percentage)`：`page ≤ 1` 且 `percentage` 为空或 ≤ 0 | 单测覆盖 page=0/1/2 与 percentage=null/0/0.4 组合 |
| 3 | 只改方向，不动读者的页码、模式、缩放 | repo 仅 `UPDATE reading_progress SET direction = ?`，其余列与 `updated_at` 均不写 | 改设置后重开书：页码/单双页/缩放与改前一致，方向为新值 |
| 4 | 未打开过的书同样要吃到新默认方向 | 该书无 `reading_progress` 行，`open()` 的 `progress?.direction ?? settings.defaultDirection` 兜底天然覆盖，无需插行 | 新导入未打开的书，改设置后打开即为新方向 |
| 5 | 设置写入与批量同步不能出现中间态 | 两件事放进 `db.transaction()`：设置 JSON 与进度批量更新要么都成功、要么都回滚 | 事务内抛错（模拟）后 `settings` 与 `reading_progress` 均未变化 |

**核心验收口径**：把默认方向从「右→左」改为「上→下」后，所有 `page ≤ 1` 且 `percentage` 为空/0 的书重开即进入纵向滚动；任一 `page ≥ 2` 的书的 `direction` 在数据库中保持原值不动。

## 二、非目标（本期不做）

- **不同步「默认阅读模式」**：用户确认本期只处理方向；`defaultMode` 仍维持「仅无进度时兜底」的现状（若要一致化，可在同一 service 内加一段同构逻辑）。
- **不引入「已开始」标记（v6 迁移）**：不新增 `started` / `first_read_at` 列，因此「读过但翻回第一页」的书会被视为零进度并被覆盖，详见 §13。
- **不新增 IPC 通道、不改 `settings:patch` 返回契约**：仍返回 `Result<Settings>`，渲染层零改动。
- **不做设置页提示「已同步 N 本」**：项目没有通用 toast 组件（`showToast` 是 `LibraryView.vue` 内的局部函数），为一句日志级反馈新建提示基建不划算；同步数量只写主进程日志。
- **不广播 `library:changed`**：渲染层 `books[].progress.direction` 不参与任何展示（`BookCard` 只用 `page/totalPages` 与 `percentage`），阅读器打开时经 `reader:open` 重新读库，不会读到陈旧值。
- **不回溯升级前的历史状态**：升级后首次修改默认方向即会全量对齐零进度书，无需一次性数据修补脚本。

## 三、总体设计

### 3.1 分层与数据流

```
┌─ 渲染层 ────────────────────────────────────────────────────────┐
│ SettingsView.vue（方向下拉 @change="save"）                      │
│   │ settingsStore.patch({ ...form })                            │
│   ▼                                                             │
│ src/services/ipc.ts  settings.patch ──┐                         │
└───────────────────────────────────────┼─────────────────────────┘
                                        ▼
┌─ 主进程 ────────────────────────────────────────────────────────┐
│ handlers.ts  settings:patch                                     │
│   │ 1) 参数白名单（locale / defaultDirection）                    │
│   ▼                                                             │
│ settingsService.patch(partial)                                  │
│   └─ db.transaction()                                           │
│        ├─ settingsRepo.getAll()   → prev                        │
│        ├─ settingsRepo.patch()    → next（设置 JSON 落库）        │
│        ├─ defaultDirection 未变 → 直接返回（零额外写）            │
│        └─ progressRepo.listForDirectionSync()                   │
│             → isUnstartedProgress(page, percentage) 过滤         │
│             → progressRepo.updateDirection(bookId, next)        │
│   ▼                                                             │
│ SQLite：settings（JSON）+ reading_progress.direction             │
└─────────────────────────────────────────────────────────────────┘
                                        │
阅读时：reader:open 回传 progress ───────┘
reader.ts / epubReader.ts 仍按「进度优先、设置兜底」取方向
```

### 3.2 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 零进度口径 | `page ≤ 1` 且 `percentage` 为空或 0 | 「进度为 0」在 UI 上就是进度环 0%、停留首页；仅「无进度行」会把「打开过没翻页」的书排除在外，而那正是最常见的零进度形态；引入 `started` 标记需 v6 迁移 + 两个阅读 store 改写入时机，本期性价比不足 |
| 生效方式 | 设置变更时批量落库 `direction` 列 | 数据即事实：打开时无需任何特判，阅读器沿用现有「进度优先」逻辑即可；且可用 SQL/日志直接核验，比渲染层动态判定更好验收 |
| 执行位置 | 新增 `settingsService.patch()`，handler 只做参数校验与调用 | 现有 `settings:patch` 直接调 repo 是因为没有副作用；本次引入业务规则（方向变更触发批量同步），按规范上收 service，避免业务塞进 handler |
| 事务边界 | 设置写入 + 批量更新同事务 | 防止「设置已生效、书未同步」，也防止同步中途异常留下半批书 |
| 批量方式 | 事务内 `SELECT` 全量进度 → 纯函数过滤 → 逐条 `UPDATE direction` | 单一口径来源（`isUnstartedProgress` 可单测），避免 SQL 里再写一遍 `page<=1 AND COALESCE(...)` 造成两处漂移；书数量级为百，逐条更新开销可忽略 |
| 是否动 `updated_at` | 不改 | 方向同步不是阅读行为；`updated_at` 不参与文库排序（排序用 `books.last_opened_at`），改了只会制造假象 |
| 渲染层改动 | 零 | 契约不变、方向不展示；改多了反而要处理「设置页与阅读页互斥」之外的边界 |

## 四、核心算法 / 口径

### 4.1 零进度判定（`shared/types.ts`）

```ts
/**
 * 是否为零进度（默认阅读方向同步口径，双进程共用）。
 * 口径为「当前位置」而非「是否读过」：停在第一页且无百分比即视为零进度，
 * 因此翻回首页的已读书也会被默认方向覆盖（见设计文档 §13 风险）。
 */
export function isUnstartedProgress(page: number, percentage?: number | null): boolean {
  if (page > 1) return false
  return percentage == null || percentage <= 0
}
```

### 4.2 同步算法（`electron/services/settingsService.ts`）

```ts
function syncUnstartedDirection(direction: Direction): number {
  let changed = 0
  for (const row of progressRepo.listForDirectionSync()) {
    if (!isUnstartedProgress(row.page, row.percentage)) continue
    if (row.direction === direction) continue   // 已是目标值，跳过写入
    progressRepo.updateDirection(row.book_id, direction)
    changed++
  }
  return changed
}

export const settingsService = {
  patch(partial: Partial<Settings>): Settings {
    const run = getDatabase().transaction((p: Partial<Settings>) => {
      const prev = settingsRepo.getAll()
      const next = settingsRepo.patch(p)
      const directionChanged = next.defaultDirection !== prev.defaultDirection
      const synced = directionChanged ? syncUnstartedDirection(next.defaultDirection) : 0
      return { next, directionChanged, synced }
    })
    const { next, directionChanged, synced } = run(partial)
    if (directionChanged) {
      logger.info(`[settings] 默认阅读方向 → ${next.defaultDirection}，同步零进度书 ${synced} 本`)
    }
    return next
  },
}
```

### 4.3 边界场景防护

| 场景 | 行为 |
|------|------|
| `settings:patch` 只带 `epubFontSize`（`EpubReaderView` 调字号） | `defaultDirection` 未变 → 不做任何进度写入 |
| 设置页每次提交完整 `form`（含未改动的方向） | 与 `prev` 比对值相等 → 跳过，不产生无意义写入 |
| 同一值重复提交（前端连点/重复保存） | 值相等 → 跳过 |
| 书从未打开（无进度行） | 不插入行；打开时由 `progress?.direction ?? settings.defaultDirection` 兜底 |
| PDF 书 `percentage` 为 `NULL` | `percentage == null` 分支判为零进度（只看 `page`） |
| EPUB 书首页 `percentage = 0` | 判为零进度；`cfi` 等字段原样保留 |
| EPUB `percentage = 0.4`（同节第二屏） | 非零进度，不覆盖 |
| 书中手动改过方向但停在第一页 | 下次默认方向变更仍会覆盖（符合「进度为 0 都应用」的诉求） |
| 事务内异常 | 设置与进度一起回滚，`wrap()` 转 `Result` 失败，设置页维持原值 |
| 当前正打开的书 | 设置页与阅读页路由互斥，此时无活动阅读器；即便存在也不会被实时改写，下次打开生效 |
| 旧库脏值 `direction`（非法字符串） | 仅对零进度行写入合法新值；其余行不动 |

## 五、数据模型

**无 schema 变更**：不追加 v6 迁移，`reading_progress` 表沿用 v1/v3/v5 结构（`electron/db/database.ts` 的 MIGRATIONS 数组保持 5 项）。

### 5.1 repo 新增接口（`electron/db/repos/progressRepo.ts`）

```ts
/** 方向同步用精简行（书数量级小，一次性读取后在事务内过滤） */
export interface DirectionSyncRow {
  book_id: number
  page: number
  percentage: number | null
  direction: Direction
}

listForDirectionSync(): DirectionSyncRow[]
// SELECT book_id, page, percentage, direction FROM reading_progress

/** 仅更新方向列：不触碰 page/mode/zoom/cfi/percentage/updated_at */
updateDirection(bookId: number, direction: Direction): void
// UPDATE reading_progress SET direction = ? WHERE book_id = ?
```

说明：不复用 `upsert`，因为 `upsert` 会整行覆盖 `page/mode/zoom/updated_at`，而方向同步必须保证其他进度字段零改动。

## 六、IPC 契约

**不新增通道、不新增 shared 类型**，复用现有 `settings:patch`。

| 通道 | 入参 | 返回 | 变更说明 |
|------|------|------|----------|
| `settings:all` | 无 | `Result<Settings>` | 不变，仍直接调 `settingsRepo.getAll()` |
| `settings:patch` | `Partial<Settings>`（`SettingsView` 传全量 `form`） | `Result<Settings>` | 返回值不变；内部改由 `settingsService.patch()` 编排，并新增方向白名单校验 |

参数校验（handler 内，与既有 `locale` 校验并列）：

```ts
if (partial.defaultDirection !== undefined && !VALID_DIRECTIONS.includes(partial.defaultDirection)) {
  throw { code: 'INVALID_PARAMS', message: 'defaultDirection 取值无效' } as AppError
}
```

- `VALID_DIRECTIONS: Direction[] = ['ltr', 'rtl', 'ttb']`（`Direction` 字面量联合无运行期值，需本地数组）。
- 校验属于防脏值加固：`epubReader` 的 `normalizeDirection()` 会把非法值静默改成 `ltr`，写库前拦掉更可控。
- `electron/preload.ts`、`src/services/ipc.ts` 均无需改动。

## 八、渲染层实现

**无代码改动**。理由：

- `SettingsView.vue` 的 `save()` 已把整份 `form` 交给 `settingsStore.patch()`，方向变更天然经由 `settings:patch`；
- `src/stores/settings.ts` 的 `patch()` 用返回值覆盖 `settings.value`，契约不变即无需调整；
- `src/stores/reader.ts`（`progress?.direction ?? defaultDirection`）与 `src/stores/epubReader.ts`（`normalizeDirection(progress?.direction ?? defaultDirection)`）的读取逻辑保持原样——批量落库后进度已是新方向，走「进度优先」分支即可；
- `BookCard` 的进度环只读 `percentage` / `page/totalPages`，方向变更不影响显示，故不刷新文库缓存。

## 九、页面 / 交互设计

无 UI 变更：设置页「阅读偏好 → 默认阅读方向」下拉的交互、文案与空态/错误态全部沿用现状（`SelectMenu` + `settings.direction.*` 文案）。用户感知为「改完默认方向后，没读过的书都按新方向打开」。

## 十三、风险与取舍记录

| 项 | 取舍 | 影响与备注 |
|----|------|------------|
| 口径采用「当前位置」而非「是否读过」 | 接受覆盖翻回首页的书 | 读到第 5 页又翻回第 1 页的书，会被后续默认方向变更覆盖；若将来需要精确区分，追加 v6 迁移列 `started`（首次翻页或手动改方向时置 1），把 `isUnstartedProgress` 换成读该列即可，service 结构不变 |
| 首页手动改方向也会被覆盖 | 接受 | 与「进度为 0 都应用」的诉求一致；手动改方向后只要翻过一页即脱离零进度集合 |
| 事务内逐条 `UPDATE` | 接受 | 书数量级百级，单事务内毫秒完成；若书架增长到万级，可退化单条 `UPDATE ... WHERE page<=1 AND COALESCE(percentage,0)<=0`，但需承担口径双写风险 |
| 不广播 `library:changed` | 接受内存 `progress.direction` 短暂陈旧 | 无 UI 读取方向；阅读器打开走 `reader:open` 重新读库；后续若出现「文库卡片展示方向」需求，再补广播与 `LibraryChangedPayload` 类型 |
| 不提示同步结果 | 只写日志 | 避免为单句反馈新建 toast 基建；错误仍经 `wrap()` 走设置页既有错误提示 |
| `settings:patch` 返回值不变 | 渲染层零改动 | 将来若要在设置页显示「已同步 N 本」，需扩返回类型并在 preload/ipc.ts 同步镜像，属于独立小需求 |
