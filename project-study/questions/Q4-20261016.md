# Q4-20261016 PDF 翻页动画中与结束后新页面缩放感的成因

## 问题

为什么 PDF 翻页动画过程中和结束后新页面会有缩放的感觉？是渲染的问题么

## 回答

**结论：不是 pdf.js 位图渲染的质量问题，而是"同一张位图、两条显示路径尺寸不一致"的界面层问题**——静态显示用的画布被一条遗留 CSS 钳制压低了 24px，翻页动画覆盖层则按完整尺寸绘制。翻页开始时画面被"拉大"（最底部 24px 被裁掉），动画结束揭层瞬间又"缩回"，因此过程中和结束后各出现一次缩放感。默认「适高」模式下每次翻页必现。

### 一、静态显示路径：渲染尺寸 = 视口高度，但 CSS 把显示盒压低了 24px

- 渲染目标尺寸（`ReaderView.vue` L388-408 `zoomRenderOptions`）：fitHeight（默认）→ `targetHeight = window.innerHeight`（即 100vh）；注释明确"不留边距：适高填满视口高度，页面贴边 100% 显示"。
- canvas 尺寸落地（`pdf.ts` L133-145）：`canvas.style.height = viewport.height / dpr` ≈ `window.innerHeight`（如 1040px）；位图按 devicePixelRatio 高清渲染。
- CSS 钳制（`ReaderView.vue` 原 L876-880，20261016 修复已移除）：`.page-wrap canvas { max-height: calc(100vh - 24px); }`。由于 `100vh == window.innerHeight`，**显示盒高度永远是 1040 − 24 = 1016px** → 整页位图被纵向压扁约 2.3%（1040 → 1016）。
- 默认缩放即 fitHeight（`stores/reader.ts` L20、L51），所以默认状态下阅读时画面本就一直处于被压扁显示。

### 二、翻页动画路径：按"未压扁"尺寸绘制、顶左对齐

- 快照合成（`ReaderView.vue` 的 `snapshotVisible`，修复前 L338-372）：彼时从显示 canvas 的 `style.width/height`（= 未钳制的 1040px 渲染尺寸）取尺寸，把位图 1:1 画进快照，纵向按 `(cssH - cssHeights[i]) / 2` 排布（等高时顶部对齐）；合成高度 cssH = 1040。修复后已改为按实际显示矩形合成（L337-373），见 §六。
- 覆盖层（`pageCurl.ts` L32-55）：尺寸取 `pageContentEl`（`.page-content`）的 `getBoundingClientRect()`——修复前即**钳制后的显示盒**（高 1016px），定位在内容盒位置，`ctx.scale(dpr)`。
- 底图/翻起块绘制（`pageCurl.ts` 修复前 L76-79、L97-98、L115-140）：彼时 `drawBmp()` 按快照自身的 CSS 尺寸（1040px 高）在覆盖层 (0,0) 处 1:1 绘制 → 超出覆盖层底边的 24px 被直接裁掉。修复后底图按覆盖层尺寸 (w, h) 铺满绘制（L69-73），见 §六。

### 三、感知结果：起翻"向下拉伸"、结束"回缩"

以 1040px 高视口为例（同一内容行 r 在屏幕上的纵向位置）：

| 状态 | 位置公式 | 特点 |
|---|---|---|
| 静止显示（覆盖层不存在） | `y = 12 + 0.977r` | 顶偏移 12px（居中留白）+ 压扁系数 0.977 |
| 动画覆盖层存在期间 | `y = 12 + r` | 1:1 顶对齐（未压扁） |

差值在页面底端最大：约 24px（顶部为 0）。由此产生两段变化：

1. **翻页开始瞬间**：覆盖层接管画面 → 当前页自上而下"拉伸变大"至多 24px，同时页面最底部 24px 内容被裁掉；
2. **450ms 卷曲动画期间**：旧页/新页都按这个"放大、底部裁切"状态显示；
3. **动画结束揭除覆盖层瞬间**：回到被压扁的静态显示——画面底端回缩至多约 24px，被裁的底部内容同时补回。

三段时间轴上共出现"放大一次、缩小一次"，被感知为"动画过程中和结束后新页面有缩放感"。

### 四、为什么不是 pdf.js 渲染问题（排除项）

- 位图渲染一次性完成且各页一致（按 dpr 高清渲染），快照与显示来自同一 canvas 位图，缓存命中/未命中不改变尺寸（同一 `zoomRenderOptions`）；
- 卷曲动画覆盖层内部绘制是 1:1 平移、不镜像不压缩（`pageCurl.ts` L3、L86-87），动画自身几何自洽；
- canvas 上屏的短淡入（`canvas-in`，160ms，仅 opacity）在覆盖层出现前就已播放完（被覆盖层遮蔽），与缩放无关；
- 唯一的尺寸差发生在"覆盖层坐标系 vs 静态显示盒坐标系"之间——属于界面层尺寸不一致，而非渲染器问题。

### 五、成因溯源（推断）

`max-height: calc(100vh - 24px)` 与 `cacheSignature()` 中"v2 前缀：渲染尺寸去掉 MARGIN 边距后与旧位图不兼容"的注释（L416-420）同时存在于首个提交 89d103f（v1.0.0，`git log -S` 检索确认）。推断：这行 CSS 是"渲染尺寸还带 24px 边距"时代的遗留——当时渲染尺寸 ≤ 钳制值，二者恰好无冲突；渲染尺寸改为"贴满视口"后未同步更新该 CSS，留下了当前的不一致。

### 六、影响范围与修复实施（20261016 已落地）

> 上文 §一~§三 为**修复前**的问题状态描述。影响范围：默认适高恒定 24px（约 2.3%）拉伸/回缩、每次翻页必现；适宽/原始/自定义下 canvas 的 style 高度可能远超 `100vh - 24px`（如适宽单页时高度 ≈ 视口宽 × 页面纵横比），动画与静态之间的落差更大、更明显。

- **方案 A（消除不一致的源头）**：采取「删除钳制」变体而非 `max-height: 100vh`——100vh 会把自定义/适宽下超出视口的渲染尺寸再次强制压扁（且与拖拽平移设计冲突）；删除后 canvas 尺寸完全由渲染层决定，超出视口的内容由 `.page-area` 滚动/拖拽平移承接（`ReaderView.vue` L877-882）。
- **方案 B（结构性保证动画与静态一致）**：`snapshotVisible` 改按各 canvas 的实际显示矩形（`getBoundingClientRect`）合成快照（`ReaderView.vue` L337-373）；`pageCurl` 底图按覆盖层尺寸 (w, h) 归一化铺满绘制（`pageCurl.ts` L69-73，原 `cssSize()` 辅助函数随之删除）。即使未来渲染尺寸/布局再变化，翻页动画也不会再出现伸缩/缩放感。
- 验证：`npm run typecheck` 通过、`npm test` 59 用例通过；动画观感需人工翻页确认。
