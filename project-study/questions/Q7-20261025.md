# Q7-20261025 设置中的默认阅读方向在何时生效

## 问题

设置页里的「默认阅读方向」是否只在漫画（书籍）刚被添加到文库时才生效？之后修改它还有用吗？

## 回答

### 结论

不是「添加时」生效，而是**每本书第一次被打开、且该书尚无阅读进度记录（`reading_progress` 行）时**才作为兜底值生效。一旦某本书产生过进度记录，它的方向就被进度里的 `direction` 永久固化，之后再改全局「默认阅读方向」对这本书不再有任何影响。

### 1. 添加（导入）阶段完全不读取该设置

导入链是 `libraryService.importPaths()`：只写 `books` 表（标题、路径、大小、`total_pages`、`added_at`、`collection_id`），**不写 `reading_progress`，也不读 `settings.defaultDirection`**。所以「添加漫画」这一步与默认方向无关。

### 2. 真正的读取点只有两处，都在 open 时

- PDF / CBZ：`readerStore.open()` 里 `direction.value = progress?.direction ?? settingsStore.settings.defaultDirection`。即「有进度用进度，没进度用设置」。
- EPUB：`epubReaderStore.open()` 里 `normalizeDirection(progress?.direction ?? settingsStore.settings.defaultDirection)`，随后据此决定 `spread`、`direction`，并写进 `renderEpub()` 的 `defaultDirection`。
- `defaultMode`（默认单/双页）走完全相同的兜底逻辑，二者是一对。

搜索全仓库，`defaultDirection` 只在这两个 store 的 open 与 `SettingsView` 的绑定中出现，没有任何导入链、文库列表或封面队列引用它——这印证了「只在打开时读一次」。

### 3. 为什么「打开过一次」就不再跟随设置

进度记录写入时机比直觉早，用户无需翻页或改方向：

- PDF / CBZ：`ReaderView` 的 `onBeforeUnmount`、切书 `doOpen()` 都会先调 `reader.close()`，`close()` 内部 `flushProgress()` 无条件 upsert 一条进度（含当前 `direction`）；翻页/切模式/切方向也会 `scheduleSave()`（1s 防抖）落库。所以**打开即返回**也会把默认方向写死成这本书的进度方向。
- EPUB：首次 `rendition.display()` 触发 `relocated` → `onRelocated()` → `scheduleSave()`，约 1s 后 `flushProgress()` 写入进度；切单双页、切方向同样会保存。所以 EPUB 打开约 1 秒后方向就被固化。

### 4. 书内切方向会覆盖到该书进度，且不回写设置

阅读器工具栏的「阅读方向」（PDF 与 EPUB 都有，PDF 还可用 `r` 键三态循环）调用 `setDirection()`，只改本 store 的 `direction` 并 `scheduleSave()` 写进**该书的**进度，不会改动 `settings.defaultDirection`，也不会影响其它书。

### 5. 修改设置时不会实时套用到已打开的阅读器

open 时读取的值只赋给当次 store 状态，之后没有 watch 监听设置变化；`SettingsView` 的 `SelectMenu` 只做 `@change="save"` 持久化。因此即使当前打开的书恰好没有进度，改设置也要**重新打开**才生效（而重新打开时又会被上一轮落库的进度顶掉，见第 3 点）。

### 6. 想重新套用默认方向的唯一办法

项目没有「清除本书阅读进度」的 UI，全仓库也没有 `DELETE FROM reading_progress` 语句；进度只能通过 `books` 外键 `ON DELETE CASCADE` 随书籍删除一起消失。所以要让某本书重新吃到默认方向，只能把书从文库移除（会产生无进度记录的新书行），再重新导入；`relink`（重链缺失文件）只更新路径，保留原进度。以上「只能」为基于现有代码的推断，未找到其它重置入口。

### 7. 两个易踩的细节

- EPUB 侧 `normalizeDirection()` 只保留 `rtl` / `ttb`，其余（含 `ltr`、空值、非法值）一律回退 `ltr`；PDF 侧无归一化，直接使用进度/设置值。
- `reading_progress` 表的 `direction TEXT NOT NULL DEFAULT 'rtl'` 只是建表列默认，正常写入路径（`progressRepo.upsert`）都会显式带 `direction`，因此这条默认值通常不参与实际生效判定（推断）。
